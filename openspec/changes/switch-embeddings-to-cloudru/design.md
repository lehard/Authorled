# Design

## Context

Мотивация — proposal.md, раздел Why. Требования — дельты `integrations` и `llm-gateway`.

Сейчас три псевдонима эмбеддингов в `agno/litellm/config.yaml` указывают на шлюз Sber500: `openai/<модель>` с `api_base: os.environ/SBER500_API_BASE` и `api_key: os.environ/SBER500_API_KEY`, у каждого `drop_params: true`. Приложение (`agno/app/settings.py`) знает только имена псевдонимов, берёт активный из `EMBEDDINGS_MODEL` по белому списку и проверяет, что вектор из 1024 чисел. `agno/compose.yaml` передаёт ключи прокси через `${VAR:?...}`, поэтому без ключа compose не стартует. Продовый `compose.prod.yaml` наследует окружение прокси из `agno/compose.yaml`; `.env` на сервере — ссылка на `/etc/authorled/authorled.env`.

Живая проверка Cloud.ru 2026-11-08 (`https://foundation-models.api.cloud.ru/v1`, ключ владельца):
- `GET /models` отдаёт 114 моделей, среди них `ai-sage/Giga-Embeddings-instruct-480M`, `BAAI/bge-m3`, `Qwen/Qwen3-Embedding-0.6B`;
- у всех трёх 1024 измерения, пакетный запрос работает, кусок в 5000 символов проходит; у Giga и bge-m3 предел 8192 токена, у Qwen больше;
- параметр `dimensions` все три отклоняют (`400`, «does not support Matryoshka embeddings»);
- сертификат `*.api.cloud.ru` выдан GlobalSign; `openssl s_client -CAfile agno/litellm/certs/ca-bundle.pem` даёт `Verify return code: 0`.

`shared_knowledge` пуста локально и на сервере (0 строк, 2026-11-08).

## Goals / Non-Goals

**Goals:**
- Рабочие эмбеддинги без изменения кода приложения: меняется только конфигурация прокси и окружение.
- Те же имена псевдонимов, тот же `EMBEDDINGS_MODEL`, та же проверка размерности.
- Явный отказ при отсутствии ключа и при ошибке Cloud.ru, без перехода на другой провайдер.

**Non-Goals:**
- Изменения в `agno/app/settings.py`, `agno/db/`, размере чанков и читателях.
- Учёт стоимости эмбеддингов в журнале расхода ядра.

## Decisions

1. **Псевдонимы сохраняют имена и переходят на Cloud.ru.** `giga-embeddings` → `openai/ai-sage/Giga-Embeddings-instruct-480M`, `bge-m3-embeddings` → `openai/BAAI/bge-m3`, `qwen3-embeddings` → `openai/Qwen/Qwen3-Embedding-0.6B`. Приложение и спека «Выбор модели эмбеддингов» не меняются, `.env` с `EMBEDDINGS_MODEL=giga-embeddings` продолжает работать.
   - Альтернатива: новые имена вроде `cloudru-giga-embeddings`. Отклонена: пришлось бы менять белый список в коде, спеку выбора модели и `.env` на сервере ради одного переименования, а модели те же.
   - LiteLLM отделяет провайдера по первому `/`, поэтому имя модели со слешем (`ai-sage/...`) уходит в Cloud.ru целиком. Это проверяется запросом через прокси (задача 2.x); если LiteLLM исказит имя, решение возвращается владельцу, адаптер не добавляется.

2. **Адрес Cloud.ru — в `config.yaml`, не в переменной.** `api_base: https://foundation-models.api.cloud.ru/v1` записан прямо у трёх псевдонимов. Это постоянный публичный адрес провайдера, не секрет и не настройка среды; одинаков локально и на сервере.
   - Альтернатива: `CLOUDRU_API_BASE` по образцу `SBER500_API_BASE`. Отклонена: ещё одна обязательная переменная без пользы, а адрес шлюза Sber500 был переменной потому, что это был чужой хост с портом, а не адрес провайдера.

3. **Ключ — `CLOUDRU_API_KEY`, обязательный в `agno/compose.yaml`** (`${CLOUDRU_API_KEY:?CLOUDRU_API_KEY must be set in .env}`), читается только прокси (`api_key: os.environ/CLOUDRU_API_KEY`). API ключ не видит.

4. **`drop_params: true` остаётся у трёх псевдонимов.** `OpenAIEmbedder` всегда отправляет `dimensions`, Cloud.ru его отклоняет; размерность моделей фиксирована 1024, что совпадает с `EMBEDDING_DIMENSIONS`. Проверено прошлым change: прокси отбрасывает параметр для этих имён.

5. **Sber500 удаляется полностью.** Из `agno/compose.yaml`, `example.env`, документов и спек уходят `SBER500_API_BASE`, `SBER500_API_KEY` и адрес `shared1.multitool.works`. Держать обязательным заведомо мёртвый ключ противоречит правилу «явный отказ при неверной конфигурации», а оставить его необязательным — значит ввести молчаливое пустое значение. Архив прошлого change не трогается.

6. **TLS — общий бандл прокси.** Прокси работает с `SSL_CERT_FILE=/certs/ca-bundle.pem`; бандл проверяет цепочку GlobalSign Cloud.ru (проверено). Отдельных настроек TLS не нужно; `ssl_verify: false` не используется.

7. **GigaChat не трогаем.** `gigachat-embeddings`, `GIGACHAT_*` и бандл Russian Trusted CA остаются, как решено в интенте. Их ключи по-прежнему обязательны в compose.

8. **ADR-003 дополняется («Amendment 2026-11-08»)**, прошлое дополнение про Sber500 не переписывается, а помечается заменённым этим дополнением.

## Risks / Trade-offs

- [Баланс Cloud.ru кончится] → эмбеддинги отвечают ошибкой, загрузка знаний получает статус `failed` (спека). Владелец ставит бюджет и уведомление в «Контроле затрат» Cloud.ru; автоматического перехода на другой провайдер нет.
- [Выкладка без ключа на сервере] → новый `agno/compose.yaml` требует `CLOUDRU_API_KEY`, и релиз уронит прокси. Ключ кладётся в `/etc/authorled/authorled.env` до релиза (с подтверждения владельца); строки `SBER500_*` удаляются только после успешного релиза, чтобы откат на прошлый релиз не упал из-за них.
- [Цена Giga-Embeddings не опубликована в тарифной таблице] → владелец смотрит «Потребление» после первых запросов; при объёмах базы знаний администратора это копейки.
- [Каталог Cloud.ru переименует модель] → явная ошибка от провайдера, правка — одна строка в `config.yaml`.
- [Утечка ключа] → расход с баланса владельца; ключ ограничен ролями Foundation Models, в логи и чат не выводится, перевыпуск в консоли.

## Migration Plan

1. Локально: `CLOUDRU_API_KEY` уже в `.env` (2026-11-08). После правки конфигурации — `docker compose up -d --build`, проверка трёх псевдонимов через прокси и загрузки в `shared-knowledge`; затем строки `SBER500_*` из локального `.env` удалить.
2. Сервер, до релиза (с подтверждения владельца): добавить `CLOUDRU_API_KEY` в `/etc/authorled/authorled.env`.
3. Релиз из `main` по README «Deploy by release».
4. Сервер, после релиза: эмбеддинг через прокси, загрузка и поиск в базе знаний; затем (с подтверждения) удалить `SBER500_*` из `/etc/authorled/authorled.env`.
5. Откат: прошлый релиз требует `SBER500_*`, поэтому до шага 4 они остаются в env; но прошлый релиз даёт только неработающие эмбеддинги, так что откат возвращает состояние «эмбеддинги не работают», а не рабочее.
