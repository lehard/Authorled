## Context

GigaChat API по ключу физлица отвечает `402` на эмбеддинги. Каталог Cloud.ru не содержит `Embeddings-2`; ключ, лежавший в `.env` как `CLOUDRU_API_KEY`, на самом деле ключ шлюза Sber500 (проверено: `foundation-models.api.cloud.ru` его отклоняет, `shared1.multitool.works` принимает). Прокси LiteLLM остаётся единственным путём к моделям (ADR-003), приложение знает только псевдонимы. Владелец хочет быстро переключать модели эмбеддингов, поэтому прежняя настройка не удаляется.

Проверено живыми запросами 2026-10-29 (ключ не печатался):

| Модель на шлюзе | Размерность |
| --- | --- |
| `giga-embeddings-instruct-480m` | 1024 |
| `bge-m3` | 1024 |
| `qwen3-embedding-0.6b` | 1024 |
| `giga-embeddings-instruct-3b` | 2048 |

- Вход: тексты до 40 000 символов (≈6 700 токенов) принимаются.
- TLS шлюза: сертификат Let's Encrypt, проверяется обычным certifi.
- Параметр `dimensions` шлюз отклоняет (`UnsupportedParamsError`), а `OpenAIEmbedder` отправляет его всегда.
- Адрес шлюза `158.160.233.163` по префиксу похож на Yandex Cloud (РФ); размещение подтверждает владелец (вопрос 1).

## Goals / Non-Goals

**Goals:** рабочие эмбеддинги 1024 измерения без нового платного ключа; переключение модели одной строкой в `.env`; прежние правила: только через прокси, без значений по умолчанию, явный отказ при неполной конфигурации.

**Non-Goals:** смена чат-моделей; смена размера чанков; автоматический переход на резервную модель; модели не с 1024 измерениями.

## Decisions

1. **Все варианты настроены одновременно, активный выбирает `EMBEDDINGS_MODEL`.** Псевдонимы в `litellm/config.yaml`: `gigachat-embeddings` (как сейчас), `giga-embeddings`, `bge-m3-embeddings`, `qwen3-embeddings`. Приложение читает переменную при старте; значения вне белого списка псевдонимов с 1024 измерениями — ошибка с именем переменной. Переменная обязательна и без значения по умолчанию.
2. **Переключение: одна строка плюс перезапуск API, но не бесплатное.** Векторы разных моделей несовместимы, даже при одинаковых 1024 измерениях. После каждой смены `EMBEDDINGS_MODEL` нужно пересоздать `shared_knowledge` и загрузить документы заново. Это ограничение нельзя обойти без хранения нескольких индексов или повторной индексации; такой механизм вне scope. Пока таблица пуста, цена нулевая; после загрузки реальных документов цена растёт.
3. **Явная проверка размерности.** Эмбеддер падает ошибкой, если вектор не из 1024 чисел, и называет ожидаемую и полученную размерность. Это защищает от псевдонима, настроенного на модель с другой размерностью. Реализация (обёртка над `OpenAIEmbedder` или проверка при старте) выбирается по закреплённой версии Agno; если ни один способ не укладывается в тонкую обёртку, решение возвращается владельцу.
4. **Провайдер шлюза в LiteLLM — `openai/<модель>`** с `api_base: os.environ/SBER500_API_BASE` и `api_key: os.environ/SBER500_API_KEY`. Имя переменной отражает источник, а не `CLOUDRU_*`.
5. **`drop_params: true` только у псевдонимов эмбеддингов**, как и раньше: `dimensions` приходит от `OpenAIEmbedder`, размерность моделей фиксирована. Нужно проверить на деле, что прокси отбрасывает параметр для имён, не относящихся к `text-embedding-3`; если нет — решение возвращается владельцу, адаптер не добавляется.
6. **Ключи всех настроенных провайдеров обязательны в compose (`${VAR:?...}`).** Компромисс: нельзя запустить стек без ключа GigaChat, даже если выбран шлюз Sber500. Альтернатива: делать ключ неиспользуемого провайдера необязательным (пустое значение допускается, ошибка возникает при вызове). Она вводит молчаливые пустые значения и противоречит правилу «без значений по умолчанию», поэтому не выбрана. Если ключ GigaChat перестанет быть доступен, придётся временно вписать любое непустое значение или убрать псевдоним из конфигурации отдельным изменением.
7. **Сертификаты Russian Trusted CA, `scripts/build_ca_bundle.sh`, монтирование и переменные TLS остаются.** Они нужны псевдониму `gigachat-embeddings`, а удалить их означало бы закрыть обратный переход. Шлюз Sber500 работает по публичному сертификату, и пакет ему не мешает (проверка в задачах).
8. **Размер чанка 1200 символов не меняется.** Он был вызван лимитом 512 токенов `Embeddings-2`, которое остаётся для `gigachat-embeddings`; у остальных моделей лимит выше (приняты 40 000 символов), но смена влияет на качество поиска и вынесена в отдельный change.
9. **ADR-003 дополняется («Amendment 2026-10-29»), решения не помечаются устаревшими.** Добавляется описание шлюза Sber500 и переключателя `EMBEDDINGS_MODEL`.

## Risks / Trade-offs

- **Доступ к шлюзу не принадлежит проекту.** Ключ выдан стартапу менторами Sber500, хост общий; после программы доступ могут отозвать, лимиты и доступность не гарантированы. Запасного провайдера в автоматическом режиме нет (запрещено правилами); при потере доступа остаётся ручное переключение на другой настроенный псевдоним с пересозданием `shared_knowledge`.
- **Тексты документов уходят на внешний общий хост.** `05-security-and-compliance.md` допускает эмбеддинги только в РФ или свои. Размещение шлюза по IP похоже на РФ, но не подтверждено; шлюз проксирует и зарубежные модели, а какая именно модель обслуживает псевдонимы, мы не знаем. Статус согласования с ИБ — «не согласовано». Модели `qwen3-embedding-0.6b` и `bge-m3` — зарубежные разработки, но запускаются на шлюзе; для политики «не зарубежные эмбеддинги» это нужно оценить отдельно.
- **Лишняя поверхность конфигурации.** Четыре псевдонима вместо одного и общий белый список в коде и в конфигурации прокси могут разойтись. Смягчение: проверка при старте API и сценарий проверки в задачах.
- **Секрет шлюза в `.env`.** Остаётся вне git (`.env` в `.gitignore`); в логи и чат не выводится.

## Migration Plan

1. В `.env`: переименовать `CLOUDRU_API_KEY` в `SBER500_API_KEY`, добавить `SBER500_API_BASE=https://shared1.multitool.works:4000/v1` и `EMBEDDINGS_MODEL=giga-embeddings`; `GIGACHAT_*` не трогать.
2. Применить изменения конфигурации, пересобрать стек (`docker compose up -d --build`).
3. Пересоздать только таблицу `shared_knowledge` (не `reset-db`, он стирает данные Authentik) и загрузить документы заново.
4. Переключение позже: изменить `EMBEDDINGS_MODEL`, перезапустить API, повторить пункт 3.
5. Откат: `EMBEDDINGS_MODEL=gigachat-embeddings` при рабочем ключе GigaChat.

2. Устраивает ли общий шлюз без SLA как постоянный источник эмбеддингов или это временное решение до получения собственного платного доступа.
3. Нужно ли после выбора основной модели менять размер чанка (отдельный change).
