# Design

## Context

- Текст сценария — `Script.text` (`ScreenplayDoc`), рабочая копия в `ProjectScreen` с отложенным сохранением (`useAutosave("scripts", …)`); экран `TextDoc` с `ScreenplayEditor`, меню «⋯» (импорт, экспорт, печать), комментарии и предложения соавтора.
- Адреса — `docRef.ts` (`parseDoc`, `docPath`), документы — `DocView`, «Не найдено» — при `null` из `parseDoc` или нет документа.
- Навигатор — дерево `Row` с `kids`, `menu` (`NodeMenu`), `drill` у «Текста сценария» и «Поэпизодника».
- Корзина истории — `BinDoc` по `trash: Record<EntityKind, Entity[]>` контекста, ресурсы с `deletedAt`, действия `useEntityActions`.
- Данные — Refine и `fixtures` в памяти с каскадным удалением истории.
- Образец — макет v2: драфт `{ id, name, locked, created, blocks }` в `sp.drafts`; диалог «Создать драфт» (название, «На основе», «Запретить правку»); экран драфта с баннером; `compareHTML` — LCS по ключу «тип|текст» абзаца, две колонки, `.del` / `.add` на токенах `--deco-delete` / `--deco-insert`; меню узлов «Сценарий» и драфта; драфты в корзине.

## Goals / Non-Goals

**Goals:** драфты и сравнение как в макете, на фронте; текст сценария не меняется от действий с драфтами.

**Non-Goals:** см. proposal.

## Decisions

1. **Ресурс `drafts`.** Запись: `id`, `projectId`, `name`, `locked`, `createdAt` (ISO), `text` (`ScreenplayDoc`), `deletedAt` (ISO или `null`). Источник `fixtures` получает ресурс и удаляет драфты вместе с историей. Запрос `useDrafts(projectId, inTrash)` по образцу `useEntities`; контекст окна истории получает `drafts` и `trash.draft`.

2. **Копия без пометок.** `stripMarks(doc, ["comment", "suggestion"])` в `web/src/editor/document.ts` возвращает документ без этих меток: ветки и предложения принадлежат текущему тексту, в копии они были бы метками без данных. Драфт на основе драфта копирует его текст как есть (в драфтах пометок нет).

3. **Сравнение — `compareDocs(a, b)` в `web/src/editor/compare.ts`.** Без DOM, для `check:editor`. Абзацы сравниваются по ключу «тип + текст» самой длинной общей подпоследовательностью (как `compareHTML` макета); результат — абзацы каждой стороны с флагом `changed`. Абзацы, переставленные местами, получаются убранными и добавленными — так же в макете. Пустые абзацы участвуют как обычные.

4. **Экран сравнения — статичная разметка, не редактор.** Колонки рисуют абзацы с классами типов редактора (`elementClass`) внутри `.pw-editor .ProseMirror` в режиме чтения; лист уже 840 px сплошной (контейнерный запрос редактора), поэтому две колонки помещаются. Пометки — классы `pw-diff-del` (зачёркнуто, `--deco-delete`) и `pw-diff-add` (подчёркнуто, `--deco-insert`). Заголовки колонок: «Текущий текст» или «Драфт «…»». Заголовки колонок начинаются с «Было:» и «Стало:». Кнопка «Закрыть сравнение» ведёт на «Текст сценария». Когда область документа уже 560 px (контейнерный запрос, а не ширина окна: на 1440 px между навигатором и чатом остаётся ~670 px), колонки идут одна под другой.

5. **Экран драфта — `DraftDoc`.** `ScreenplayEditor` в режиме `text` с `readOnly={locked}`, без комментариев и предложений; меню «⋯» — экспорт и печать драфта (имя файла — название драфта). Правка разрешённого драфта сохраняется `useAutosave("drafts", id)`; статус — в шапке. Баннер над редактором: значок, «Драфт «…» · создан …», «· правка запрещена», «Сравнить с текущим», «Запретить правку» / «Разрешить правку» (сохраняется сразу).

6. **Диалоги.** «Создать драфт»: `Input` названия (ошибка «Назовите драфт.»), `Select` «На основе» (текущий текст и живые драфты), `Checkbox` «Запретить правку текста драфта» (включено); после создания — уведомление в диалоге не нужно: драфт открывается. «Сравнить драфты»: два `Select` («Было» — первый драфт, «Стало» — текущий текст), одинаковый выбор — ошибка «Выберите два разных текста.». «Переименовать» — существующий `NameDialog`.

7. **Навигатор.** Драфты — дети «Сценария» после частей, по времени создания; значок `Copy`, у запрещённых — `Lock` справа. Меню «Текста сценария»: «Создать драфт», «Сравнить драфты» (неактивно без драфтов). Меню драфта — по спеке. В «⋯» редактора текста — «Создать драфт…».

8. **Корзина.** `BinDoc` показывает драфты рядом с персонажами, локациями и мирами («Драфт», число абзацев вместо описания); «Восстановить» снимает `deletedAt`, «Удалить навсегда» и «Очистить корзину» удаляют запись. Открытый удалённый драфт и сравнение с ним — «Не найдено».

9. **Соавтор видит драфт и сравнение.** Контекст чата (`docContext.ts`) получает текст драфта и, для сравнения, убранные и добавленные абзацы обеих сторон — иначе «Видит: …» не совпадало бы с тем, что отправлено.

10. **Проверки.** `check:editor`: `compareDocs` (одинаковые тексты — без пометок; замена реплики — один убранный и один добавленный; добавленный в конец абзац; перестановка сцены), `stripMarks` (метки комментариев и предложений сняты, жирный и цвет остались). Экраны — в браузере.

## Risks / Trade-offs

- [Сравнение по абзацам: правка одного слова помечает весь абзац] → как в макете; сравнение по словам — позже, если понадобится.
- [Драфты живут в памяти до перезагрузки, как весь источник `fixtures`] → версии на бэкенде — ядро.
- [Большие тексты: LCS — O(n·m) по абзацам] → для полнометражного сценария (до ~3000 абзацев) это миллионы шагов; приемлемо для разового сравнения, при необходимости — алгоритм Майерса.

## Migration Plan

Только фронтенд; новых полей в существующих записях нет. Архивация — после `coauthor-suggestions`.
