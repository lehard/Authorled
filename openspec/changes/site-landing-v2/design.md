# Design: вторая версия лендинга «Соавтора»

## Context

Мотивация — `proposal.md`. Что важно для подхода:

- Сайт `site/` (архив `2026-11-08-product-site`): Vite 8 + React 19 + Tailwind 4, страницы пререндерятся (`scripts/prerender.mjs`), клиент гидрирует (`src/entry-client.tsx`), токены и шрифты — из `web/src/design-system`, тема «Утро». Сейчас скрипты главной ≈ 77 КБ gzip (React + форма). Без новых зависимостей: анимации пишем сами.
- Материал уже есть:
  - демо-история «Тихая вода» в `web/src/data/demo.json`: сцены и предложения соавтора (`water-5`: «Он утонул. Всё.» → «Утонул. Всё.», с полем `why`);
  - кликабельный макет «Кабинет» (`openspec/context/_raw/design/kabinet/index.html`): данные экрана `impact` — `IMPACT` (Тональный манифест и Концепт-вектор «устарело», Скелетная карта «противоречит», с цитатами и причинами), `UNTOUCHED` (4 проверенных документа), `SCAN` (шаги проверки), схема `graphSvg()`; «Варианты» реплики в голосе персонажа;
  - кадры концепта в glavai `public/cases/authorled-concept-{path,impulses,relations,rhythm,timeline,impact,home}-{720,1080,1440}.webp` и их подписи (`src/content/site.ts`, блок `concept`);
  - скиллы glavai: `design-to-motion` (раздел Website: появление первого экрана, запуск по `IntersectionObserver`, пауза вне экрана, истории визуалов), `stageshow` (макет интерфейса с курсором), `chukovsky` (редактура русского текста).
- Спека `web/site` требует готовый HTML со всем текстом, токены вместо цветов, отсутствие хранилища в браузере и счётчиков.

## Goals / Non-Goals

**Goals:**
- Каждый новый блок — живой и при этом читается целиком без JavaScript и без движения.
- Одна система движения на весь сайт: несколько хуков и CSS-классов, без библиотек.
- Бюджет скриптов главной под проверкой сборки.

**Non-Goals:**
- Курсор-демо, который сам кликает в первом экране: посетитель нажимает сам (это сильнее и проще); курсор `stageshow` — только если владелец попросит.
- Переписывание политики, 404, формы и маршрута заявки.

## Decisions

### D1. Видимость без JavaScript и без движения
В шаблон `index.html` до стилей ставится одна строка: `document.documentElement.classList.add("js")`. CSS скрывает начальное состояние только под `.js` и только вне `@media (prefers-reduced-motion: reduce)`: `.js [data-reveal]:not([data-in]) { opacity: 0; transform: translateY(24px) }`. Пререндер отдаёт конечный вид, поэтому без скриптов и при «уменьшить движение» всё видно сразу; с JavaScript блок получает `data-in` при появлении на экране.
*Альтернатива:* скрывать через React-состояние — тогда без JS блоки пустые, а при гидрации мигают.

### D2. Хуки движения (`site/src/motion/`)
- `useInView(ref, { threshold: 0.3, once: true })` — один `IntersectionObserver` на блок, ставит `data-in`.
- `useOnScreen(ref)` — видим ли блок сейчас: повторяющиеся истории (печать ответа, прорисовка) ставятся на паузу вне экрана.
- `prefersReducedMotion()` — чтение `matchMedia` один раз на компонент; при `reduce` компоненты сразу ставят конечное состояние.
- Кривые — как в `design-to-motion` B6: вход `cubic-bezier(0.16,1,0.3,1)`, прозрачность `cubic-bezier(0.33,1,0.68,1)`, заливки `cubic-bezier(0.65,0,0.35,1)`; объявляются в `styles.css` как утилиты рядом с `ease-base`.
- Анимируемые свойства — по спеке: `transform`, `opacity`, `filter` до 2 px, `clip-path`, `stroke-dashoffset`.
*Альтернатива:* `motion`/`framer-motion` (~30–40 КБ gzip, новая зависимость без согласия владельца).

### D3. Первый экран и живая правка
- Появление первого экрана (`design-to-motion`, «hero appear»): CSS-анимации с задержками 50–70 мс в порядке чтения, подъём на 6 px и размытие 2 px → 0, один раз при загрузке. Заголовок по выбору владельца — две фразы без зачёркивания («Сценарий пишете вы. ИИ помнит всё остальное.»), вторая проявляется следом; зачёркнутое и новое остаются на листе сценария живой правки.
- `LiveEdit`: лист сценария (шрифт `--font-script`, бумага `bg-paper`) с двумя-тремя абзацами сцены `water-5` из `demo.json` и плашкой предложения (вид — как в сервисе: зачёркнутое, вставка, `why`). Состояния: `offered → accepted | rejected`, кнопка «Показать снова» возвращает `offered`. Вставка и удаление размечены `<del>`/`<ins>`, плашка — `role="group"` с подписью. Без JS — состояние `offered`, кнопки видны, но ничего не делают (они `type="button"` внутри статичного HTML).
- Тексты сцены копируются в `site/src/content/demo.ts` вручную (не импортом `web/src/data`: спека запрещает подключать `web/src/data`).

### D4. Крупная фраза
Каждое слово — `<span>` в готовом HTML. Один `IntersectionObserver` на все слова с `rootMargin: "0px 0px -45% 0px"`: слово, пересёкшее линию на ~55% высоты экрана, получает `data-lit` и переходит к основному цвету (`text-foreground` из `text-muted-foreground/40`) за 400 мс. Без JS и при `reduce` — сразу основной цвет (D1).

### D5. Песочница
Компонент `Sandbox`: слева фрагмент сцены (те же данные, что D3), справа чат в виде панели соавтора сервиса. Три кнопки-вопроса; ответ — заранее написанный текст (в `site/src/content/sandbox.ts`), печатается по словам через `requestAnimationFrame` (~30 слов/с), пауза вне экрана (`useOnScreen`), при `reduce` — сразу целиком. Подпись «пример ответа» у каждого ответа. Ответы опираются на настоящие свойства соавтора (противоречия по сценам со ссылкой на сцены, сокращение реплики правкой, «что знает зритель» по таймлайну — последнее помечено как концепт, если опирается на будущий таймлайн). Сетевых запросов нет; в готовом HTML — вопросы и первый ответ, остальные ответы тоже в HTML под `hidden`, чтобы текст был индексируем.

### D6. Вкладки беты
Паттерн ARIA Tabs: `role="tablist"`, `tab`, `tabpanel`, стрелки влево/вправо, Home/End, `aria-selected`, фокус по табу только на активной вкладке. Пять вкладок: Сценарий (`workspace`), Карточки (`character`), Драфты (`drafts`), Рецензирование (`comments`), Соавтор (`coauthor-answer` + `suggestion`). Смена — перекрёстное затухание скриншотов. Пререндер отдаёт все пять панелей в HTML: первую видимой, остальные с атрибутом `hidden` — их текст в разметке и индексируется, как требует спека.

### D7. «Путь истории»
SVG-линия пути (змейка из трёх рядов, как на кадре `path`), 22 узла-кнопки с номерами и названиями из глоссария. При появлении: `stroke-dashoffset` линии от длины до 0 за 1.2 с, узлы проявляются по порядку. Группы и кадры:
| Этапы | Кадр концепта |
|---|---|
| 1 Карта импульсов | `impulses` |
| 2–12 замысел | `path` |
| 13–14 Скелетная карта, Поэпизодник | `timeline` |
| 15–17 Кастинг, профили, партитура | `relations` |
| 18–21 Ансамбль, биты, черновик, протокол | `rhythm` |
| 22 Финальный текст | `home` |
Выбор узла открывает кадр группы в рамке и подпись из glavai, кадр сменяется затуханием. По умолчанию выбран этап 1. Пометка «Концепт: в бете этого пока нет» над блоком и в подписи. Кадры копируются в `site/public/concept/` (720/1080/1440), `srcset`, ленивая загрузка.

### D8. Схема последствий
По данным `IMPACT`, `UNTOUCHED`, `SCAN` макета (перенесены в `site/src/content/impact.ts`): в центре «Тема», вокруг 7 документов. Кнопка «Изменить решение» показывает было → стало для главного вопроса, затем шаги `SCAN` по очереди, затем линии к задетым документам окрашиваются (`stroke-dashoffset`), узлы получают пометки «устарело»/«противоречит» (цвета — токены статусов `status-stale`, `status-conflict`), итог «Задето 3 документа из 7» и список задетых с цитатами. «Вернуть» — исходный вид. SVG рисуется в React из данных, без `innerHTML`. Пометка «Концепт».

### D9. Вопросы и ответы
Нативные `<details>`/`<summary>`: раскрываются с клавиатуры и без JS, текст в HTML. Плавное раскрытие — `interpolate-size`/`::details-content` там, где браузер умеет; иначе без анимации (это не подмена поведения, а отсутствие украшения).

### D10. Тексты
Сначала — черновик всех текстов в одном файле `site/src/content/copy.ts` по `copywriting` (диагноз A: «пусто/сухо», отсюда право на угол подачи, но не на факты), затем проход `chukovsky` (режим Правка). Для заголовка первого экрана — два-три варианта; выбор владельца фиксируется в задаче. Все тексты главной живут в `content/`, компоненты их только выводят — так их можно править без OpenSpec (правило `AGENTS.md`).

### D11. Бюджет и проверки
`check-build.mjs` дополняется:
- бюджет: сумма gzip (`zlib.gzipSync`) всех `.js`, на которые ссылается `index.html` (`<script src>`, `modulepreload`), ≤ 120 КБ, иначе ошибка с размером;
- текст: в `index.html` есть фраза о видении, вопросы песочницы, подписи «пример ответа», названия 22 этапов, пометки «Концепт» у двух блоков, все вопросы FAQ;
- кадры: файлы `concept/*` и `shots/*`, на которые ссылается HTML, существуют.
Поведение (клики, клавиатура, «уменьшить движение», телефон) проверяется Playwright-скриптом из `site/scripts/` против `npm run preview` — локальная проверка, не часть `validate.sh` (браузеров в CI нет).

### D12. Скиллы
`design-to-motion`, `stageshow`, `chukovsky` копируются из `/Users/lehard/glavai/.claude/skills/` с лицензиями; заметки «В проекте ГлавAI» заменяются заметками про этот проект (дизайн-система `web/src/design-system`, иконок-библиотек нет и без согласия не добавлять, плейграунд `stageshow` не ставить в `site/`).

## Risks / Trade-offs

- [Концепт примут за готовое] → пометка «Концепт» над блоками и в подписях, текст «в бете пока нет», тест в `check-build`.
- [Бюджет скриптов] → без библиотек, данные ответов и схемы — небольшие модули; проверка сборки.
- [Слишком много движения] → только первый экран при загрузке, остальное — один раз при появлении; истории на паузе вне экрана; режим без движения.
- [Мигание при гидрации] → D1: начальное состояние только под `.js`, пререндер — конечный вид.
- [Тексты ответов песочницы обещают больше, чем умеет соавтор] → ответы опираются на то, что соавтор уже делает в бете; всё про таймлайн — с пометкой концепта.
- [Кадры концепта из другого репозитория] → копия в `site/public/concept/`, источник указан в README кадров.
