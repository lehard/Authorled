# Proposal: учёт расхода соавтора, тарифы и подписки с лимитом

Бизнес-интент: `business-intents/usage-limits.md` (согласован владельцем 2026-11-07).

## Why

Продукт выходит к бета-тестерам, а каждый запрос к соавтору стоит денег у DeepSeek. Владелец не видит, кто сколько тратит, и ничто не мешает одному человеку израсходовать много. Ограничение сразу строится как при продаже: у каждого пользователя подписка на тариф с периодом и лимитом, бета-тестеры получают бесплатный тариф `beta`. Оплата (`payments-tochka`) потом только добавит платные тарифы и второй источник подписки.

## What Changes

- Ядро ведёт журнал расхода соавтора: после каждого запуска записываются пользователь, подписка, запуск, модель, токены (вход, вход из кэша, выход), стоимость в рублях по своим ценам и стоимость в долларах от LiteLLM для сверки. Повтор того же запуска дубля не создаёт.
- Цены моделей в рублях за миллион токенов и тарифы лежат в файлах данных ядра. Модель соавтора без цены, неизвестный тариф или файл с ошибкой останавливают старт API с ошибкой, которая их называет.
- Тариф `beta`: 0 ₽, период — месяц, лимит 500 ₽ за период, купить нельзя. Он же тариф новых аккаунтов.
- У каждого пользователя ровно одна действующая подписка: тариф, текущий период, статус, источник (сейчас только «выдана»). `GET /api/v1/me` создаёт её вместе с аккаунтом; существующие аккаунты получают её миграцией.
- Выданная подписка в конце периода продлевается сама, и расход начинается с нуля.
- Перед запуском соавтора проверяется расход за текущий период. Если лимит исчерпан, модель не вызывается, а в чате видно «Лимит соавтора на этот период исчерпан. Он обновится 7 декабря.» Сбой проверки, подписки или журнала — явный отказ запуска, а не запуск без лимита.
- Скрипт администратора `scripts/usage.sh` на сервере: `report` (расход каждого пользователя за его период) и `set-plan <почта> <тариф>`.

## Capabilities

### New Capabilities
- `core/subscriptions`: тарифы и цены моделей как данные, подписки и их периоды, журнал расхода, проверка лимита, отчёт и смена тарифа администратором.

### Modified Capabilities
- `core/database`: новые требования «Таблица подписок» и «Таблица журнала расхода».
- `api/me`: «GET /api/v1/me» — подписка на тариф новых аккаунтов при создании.
- `api/agents`: «Соавтор» — проверка лимита до запуска и запись расхода после.
- `web/workspace`: «Чат с соавтором» — сообщение об исчерпанном лимите.

## Scope

- `agno/core/`: файлы `plans.toml` и `model_prices.toml`, модули `plans.py`, `subscriptions.py`, `usage.py`; таблицы в `tables.py`; подписка при создании аккаунта в `users.py`.
- `agno/migrations/`: миграция `0009_subscriptions_usage` с подписками для существующих аккаунтов.
- `agno/agents/`: pre-hook и post-hook соавтора (`coauthor_usage.py`), подключение в `coauthor.py`, проверка цены модели при старте.
- `agno/admin/`: команды `report` и `set-plan`; `scripts/usage.sh` запускает их в контейнере API.
- `web/src/screens/project/chat/`: сообщение об исчерпанном лимите.
- `agno/tests/`: тесты ядра, хуков и миграции на чистой базе.
- Мастер-спеки по дельтам, `AGENTS.md` (новые файлы ядра), `tmp/VERIFY.md`.

## Non-goals

- Оплата, платные тарифы, источник подписки «Точка», платное продление и история платежей — интент `payments-tochka`.
- Личные лимиты отдельных пользователей: меняется только тариф.
- Страница администратора и показ остатка лимита пользователю (отложено до страницы тарифа в `payments-tochka`).
- Учёт платформенных агентов (OS Manager, Company Manager, `claude-engineer`) и эмбеддингов.
- Перенос старых запусков из `ai.agno_runs`.
- Точная стоимость до запуска: последний запрос может немного выйти за лимит; одновременные запросы одного пользователя тоже.

## Impact

- База: две новые таблицы в схеме `authorled`, одна миграция вперёд; схемы `ai` и `authentik` не трогаются.
- API: `GET /api/v1/me` дополнительно создаёт подписку; форма ответа не меняется. Запуск соавтора может завершиться событием `RUN_ERROR` с `error_id` `usage_limit_reached`.
- Старт API читает два файла данных; ошибка в них останавливает старт.
- Зависимостей не добавляется: файлы данных в TOML читает стандартный `tomllib`.
