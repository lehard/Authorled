## MODIFIED Requirements

### Requirement: Интерфейс биллинга
Публичный интерфейс биллинга MUST давать операции: выдать подписку при входе, проверить лимит, дать место для файлов по тарифу, записать расход запусков, найти беседу запуска пользователя, построить отчёт по расходу и сменить тариф. Операции MUST принимать и возвращать простые значения (идентификаторы, числа, строки, время, неизменяемые записи) и MUST NOT принимать соединение с базой. Каждая операция MUST выполняться в своей транзакции: при ошибке её изменения MUST NOT сохраняться.

#### Scenario: Ошибка посреди записи расхода
- GIVEN запись расхода двух запусков, второй из которых нарушает ограничение журнала
- WHEN вызывается операция записи расхода
- THEN операция MUST завершиться ошибкой
- AND в журнале MUST NOT появиться строки ни одного из двух запусков

#### Scenario: Пользователь в отчёте по идентификатору
- GIVEN у пользователя есть подписка и расход
- WHEN вызывается операция отчёта
- THEN строка отчёта MUST называть пользователя его идентификатором ядра и MUST NOT содержать почты

#### Scenario: Беседа чужого запуска
- GIVEN в журнале есть запуск `r1` пользователя А
- WHEN беседу запуска `r1` ищут для пользователя Б
- THEN операция MUST завершиться отказом «запуск не найден», как для несуществующего запуска

#### Scenario: Место по идентификатору
- GIVEN у пользователя действующая подписка
- WHEN вызывается операция места для файлов с его идентификатором ядра и временем
- THEN операция MUST вернуть число байт и MUST NOT обращаться к схеме ядра
