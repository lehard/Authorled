# Design: задание на исследование как документ

## Context

- Первая версия (v0.3.19, архив `2026-11-11-research-brief`):
  - `create_research_brief` создаёт обычную заметку «Исследование: <тема>» через `notes.create_note`;
  - вложения живут только в аргументах вызова;
  - чат рисует `ResearchCard` вместо строки о сделанном (`ActionLines.tsx`), беседа из истории восстанавливает её из `tools` запуска.
- Заметка в ядре (`agno/core/tables.py`, `notes`): название, текст, ревизия, корзина, необязательный `file_id`. Ответ API — `NoteOut` (`agno/app/api/schemas.py`). Фронтенд читает его в `readNote` (`web/src/data/apiProvider.ts`) в модель `Note` (`web/src/data/model.ts`); `fixturesProvider.ts` даёт `file: null`.
- Экран заметки — `NoteDoc.tsx`: шапка `DocHead`, строка оригинала `OriginalLine`, поле текста с автосохранением.
- Результат меняющего вызова приходит в живом ходе событием `onToolCallResultEvent` (`CoauthorChat.tsx`).
- Последняя миграция ядра — `0015_note_files`.

## Goals / Non-Goals

**Goals:** одно место для задания — его заметка; признак задания в ядре, не в названии; задание сильнее за счёт уточнений и каркаса; без замеров.

**Non-Goals:** свой Deep Research, перевод старых заметок, сохранность строк других действий при пересоздании чата.

## Decisions

1. **Признак — один столбец `research` JSONB.** Значение `{"screenplay": bool, "note_ids": [uuid, …]}` или `NULL`; проверка базы `research IS NULL OR jsonb_typeof(research) = 'object'`. Миграция `0016_note_research`, вперёд, без данных. Альтернатива — отдельный `kind` и таблица вложений; отвергнута: два значения на одну сущность, а вложений одно-два. Ссылки на заметки — без внешнего ключа: удалённая навсегда заметка должна не ломать задание, а давать «Вложения нет».
2. **Ядро.** `Note` получает `research: NoteResearch | None` (`screenplay: bool`, `note_ids: tuple[UUID, ...]`). `create_research_note(connection, project_id, title, body, research, user_id)` вставляет заметку с признаком; проверки истории, названия и текста — те же, что у `create_note`. Обновление заметки автором и соавтором `research` не трогает. Маршруты автора уже отвечают `422` на неизвестное поле, поэтому `research` в `POST` и `PATCH` отклоняется без новой логики (проверить тестом).
3. **API.** `NoteOut.research: NoteResearchOut | None` с `screenplay` и `note_ids`. Других маршрутов нет.
4. **Инструмент.** `create_research_brief` создаёт заметку через `create_research_note` с `research` из аргументов. Проверки вложений (история, корзина, оригинал) и предел 8 000 знаков остаются. Результат — тот же `_done(…, "note", id)`.
5. **Чат — обычная строка.** `ResearchCard.tsx` удаляется; `ActionLines` больше не особый случай для задания, строка «Создано задание на исследование «…»» со ссылкой рисуется `Outcome`. Восстановление из истории (`actionsOf`) не меняется: строка восстанавливается как у других действий.
6. **Задание открывается.** В `onToolCallResultEvent` живого хода, если результат — сделанное `create_research_brief` (по имени вызова из сообщений агента и `readOutcome`), чат переходит к `docPath(draft, {kind: "note", id})`. Беседа из истории событий хода не получает, поэтому ничего не открывает. Шторка не закрывается: переход не трогает её состояние.
7. **Плашка в заметке.** Новый `docs/ResearchHead.tsx` переносит из `ResearchCard` ссылки на сервисы, подсказки и вложения (`DownloadButton`, «Открыть сценарий», «Вложения нет»); вложения берутся из `note.research`, файлы — из `ProjectData.notes`. `NoteDoc` показывает плашку между шапкой и текстом, только если `note.research !== null`. «Скопировать задание» берёт текущее значение поля текста (состояние редактирования), а не сохранённое. Только семантические токены.
8. **Промпт.** Раздел «Задание на исследование» в `SKILL.md` переписывается по требованиям «Задание на исследование у соавтора» и «Состав задания на исследование»:
   - уточнения по умолчанию;
   - расхождение с историей;
   - два вида «для чего»;
   - каркас и «где искать»;
   - инструкции для исследования;
   - формат отчёта;
   - разбиение широкой темы;
   - короткий ответ без «карточки».

   Описание инструмента повторяет каркас кратко. Справка о сервисе: плашка в заметке вместо карточки.
9. **Замер действий.** Просьбы `research-*` в `actions.toml` переписываются: две полностью названные — ожидают задание, две с недостающим или противоречащим — ожидают `none` (уточнение). Набор не прогоняется (владелец, 2026-11-11).

## Risks / Trade-offs

- **Модель создаёт задание без уточнений.** Правило в промпте, не в коде: вопрос «всё ли названо» — смысловой, код его не решит. Проверяется глазами на стенде.
- **Переход прерывает работу автора.** Это итог его же просьбы; ввод в других документах защищён автосохранением.
- **Плашка над длинной заметкой.** Задание не длиннее 8 000 знаков, режим просмотра длинных материалов его не касается.
