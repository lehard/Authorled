# Design

## Context

- `deploy/deploy.sh` идёт по SSH под пользователем `deploy` (группы `deploy`, `docker`), всегда в версии выкладываемого релиза. `check_inputs` проверяет входы до `fetch_tag`, копии базы и `up -d --build`; сейчас для сертификата там только `[[ -f "${ADMIN_CLIENT_CA}" ]]`.
- Права сервера по README: `/etc/authorled` — `root:deploy 0750`, `authorled.env` — `root:deploy 0640`; сертификат — `root:root 0644` (README, скилл, подсказка `admin_cert.sh`). Caddy — пакет Ubuntu, пользователь `caddy` в группах `caddy` и `www-data`.
- У `deploy` из `sudo` есть только `systemctl reload caddy`; `caddy validate` в деплое идёт под `deploy` и потому файл читает.
- На сервере сейчас `0751` у каталога и `0644` у файла (исправлено 2026-11-10).

## Goals / Non-Goals

**Goals:**
- Деплой с правами, при которых Caddy не прочитает сертификат, останавливается до любых изменений.
- Новый сервер по README получает рабочие права с первого раза.

**Non-Goals:**
- Проверка от имени самого `caddy` и общая проверка всех файлов, которые читает Caddy.

## Decisions

### D1. Проверка по битам «остальные»

Новая функция `check_admin_ca_readable` в `deploy.sh`, вызов в `check_inputs` сразу после проверки наличия файла:

- права читаются `stat -c '%a'` (GNU coreutils сервера);
- у каталога `dirname "${ADMIN_CLIENT_CA}"` должен быть бит `o+x` (`(( 8#mode & 1 ))`), у файла — `o+r` (`(( 8#mode & 4 ))`);
- нет бита → `fail "<путь> has mode <права>: Caddy reads <файл> as its own user; run chmod 751 <каталог>"` (для файла — `chmod 644 <файл>`).

Альтернативы:
- `sudo -u caddy test -r` — точная проверка, но требует нового правила `sudoers` для `deploy`. Отклонено: расширяет права деплоя.
- Проверять группы пользователя `caddy` (`id -Gn caddy`) и сравнивать с группой файла — точнее для случая «Caddy в группе», но этот случай запрещён (Non-goals интента: `caddy` не добавляется в `deploy`). Биты «остальные» проще и совпадают с правилом README.
- Чинить права в деплое — отклонено: fallback, и у `deploy` нет прав на `/etc/authorled`.

### D2. Права в документах

- README, настройка сервера: `chmod 751 /etc/authorled` и одна строка пояснения: проход нужен Caddy для сертификата УЦ админки, список файлов закрыт, `authorled.env` и его копии — `640`; новые файлы в каталоге, кроме сертификата, — не шире `640`.
- README «Certificate», «Renewal and loss», скилл `deploy-platform` (шаг 2 и строка о потере ключей), подсказка `admin_cert.sh`: «root, 0644; the directory /etc/authorled needs 0751, Caddy reads the file as its own user». Описание проверок перед деплоем в README (рядом с «The release stops before any change if …») называет и права.

## Risks / Trade-offs

- [ACL или другой владелец файла] Если на сервере появятся ACL или файл будет принадлежать `caddy`, проверка по битам может ошибиться. → На сервере ACL нет, владелец по документам `root`; при смене схемы прав меняется и проверка.
- [`751` у каталога] Другие пользователи сервера проходят в каталог, но не видят список файлов; файлы с секретами закрыты `640`. → Пояснение в README рядом с командой.

## Migration Plan

Слить в `main`; на сервере права уже верные, следующий релиз проходит проверку без действий владельца. Откат — релиз прошлого тега.
