# Design: участники истории и ссылка «почитать»

## Context

Мотивация — `proposal.md`. Что есть сейчас:

- Доступ к истории — только у владельца. `core/projects.py` `ProjectAccess.can_access` → `owns_project` (`owner_id`, история в корзине тоже доступна владельцу). Источник регистрирует `app/main.py:80` (и замер соавтора, `evals/coauthor/__main__.py`).
- Каждый маршрут истории сводит свой id к `project_id` и вызывает `require_project` (`app/api/body.py:79`); на отказ — `404`. Ролей в маршрутах нет. Модули ядра, кроме полки, места для оригиналов и учёта письма, владельца не фильтруют и полагаются на эту проверку.
- Полка (`core/projects.py:162` `list_projects`) фильтрует по `owner_id`. Последний открытый драфт (`draft_opens`) и учёт письма (`writing_progress`) уже ведутся по пользователю.
- Беседы соавтора хранит Agno под `user_id = sub`, его изоляция уже не показывает чужие беседы. Лимит и расход хуки соавтора берут у спрашивающего (`agents/coauthor_usage.py`).
- Предложения создаёт только соавтор (`review.create_suggestion`), автора и `decided_by` у них нет. У сообщений комментариев есть `author_kind`, `author_id`, `author_role`. Проверка якоря есть: `review._scene_of_quote`.
- Конфликт ревизии — `Conflict` → `409` с `type: about:blank`; так же отвечают замок и корзина, и экран (`useAutosave.ts`) считает конфликтом любой `409`.
- Место для оригиналов заметок считается по загрузившему (`notes.py:171`, `files.uploaded_by`) и его тарифу.
- Редактор уже умеет `readOnly` (`ScreenplayEditor.tsx`), сейчас его включает только замок драфта.
- Маршрутов без токена один — заявка в бету (`PUBLIC_ROUTES`, точные пути). Caddy на `app.soavtor.app` проксирует весь `/os/*` в API.
- Голова миграций ядра — `0018_sources`.

## Goals / Non-Goals

**Goals:**
- Одна точка проверки роли для всех маршрутов и инструментов соавтора; маршрут без проверки роли не должен пройти тесты.
- Ни одной потери текста при одновременной правке без живого редактора.
- Ссылка «почитать» не раскрывает ничего, кроме текста одного драфта.

**Non-Goals:**
- Свой журнал безопасности и ограничение частоты запросов к ссылке.
- Перенос рецензирования из текста в отдельный слой (метки остаются в тексте).

## Decisions

### 1. Владелец остаётся в `projects.owner_id`, участники — в `project_members`

Роль считает одна функция ядра `role_of(user, project)`: владелец → `owner`; иначе строка `project_members`; история в корзине → роль есть только у владельца. `ProjectAccess.can_access` = «роль не пустая». Интерфейс модуля `auth` не меняется по форме, меняется смысл «разрешено» (любая роль).

Альтернатива: перенести владельца в `project_members` с ролью `owner`. Отвергнута: `owner_id` используют полка, место, импорт и удаление; перенос без пользы для этого change.

### 2. `require_role(principal, project_id, need)` вместо `require_project`

`need` — одно из `read`, `review`, `edit`, `owner`. Нет роли → `404` (как сейчас, без признака существования); роли не хватает → `403` с `detail` «Рецензент не может менять текст сценария.». Каждый маршрут истории объявляет свой `need`:

| `need` | Маршруты |
| --- | --- |
| `read` | все `GET` историй, драфтов, документов, текста, заметок, файлов, снимков, точек, поиска, письма, оценок; `POST /drafts/{id}/open` (своя строка `draft_opens`); `GET /projects/{id}/members` |
| `review` | `POST /documents/{id}/comments`, `POST /comments/{id}/replies`, `PATCH`/`DELETE` своих сообщений, `POST /documents/{id}/suggestions`, `POST /projects/{id}/files` с `purpose=chat` |
| `edit` | `PATCH /projects/{id}`; всё создание, изменение, корзина и восстановление драфтов, документов, текста, заметок; замок; импорт; точки и откаты; `PATCH /comments/{id}` (решить); удаление сообщения ИИ-соавтора; `PATCH /suggestions/{id}`; `POST /projects/{id}/files` с `purpose=import`; `POST /files/{id}/note`; `POST /notes/{id}/text-from-file`; ссылка «почитать»; присутствие |
| `owner` | приглашения, роли, убрать участника; `POST /projects/{id}/trash`, `/restore`; любые `DELETE` навсегда (`/projects`, `/drafts`, `/documents`, `/notes`, `/notes/{id}/file`) и `POST /drafts/{id}/trash/empty` |

Исключения: `DELETE /projects/{id}/members/{свой id}` — `read` (выход); `DELETE /files/{id}` — `edit` или загрузивший файл чата.

Тест-матрица: таблица «маршрут → минимальная роль» в pytest проходит каждую роль по каждому маршруту; отдельный тест перечисляет маршруты приложения под `/api/v1` с параметром истории и падает, если маршрута нет в таблице. Так новый маршрут без объявленной роли не пройдёт тесты.

Альтернатива: декоратор с ролью на маршрутах. Отвергнута: проверка всё равно идёт после сведения id к истории, а явный вызов в теле читается так же, как сейчас `require_project`.

### 3. Приглашения принимаются в `GET /api/v1/me`

Экран вызывает `/me` до любых экранов («Аккаунт до экранов»), там же создаётся запись пользователя. Ядро в той же транзакции переводит приглашения на `users.email` вызывающего (в нижнем регистре) в `project_members` и удаляет их; приглашения в истории в корзине остаются ждать. Почта в токене подтверждена кодом из письма Authentik, поэтому совпадения почты достаточно. Белый список беты проверяет вход, приглашение его не трогает.

Альтернатива: ссылка-приглашение с ключом. Отвергнута: её можно переслать, и в историю войдёт не тот человек.

### 4. Ссылка «почитать»: ключ в теле `POST`, точный путь без токена

`draft_read_links(draft_id PK, key UNIQUE, created_by, created_at)`; ключ — `secrets.token_urlsafe(24)` (192 бита), хранится как есть, чтобы владелец мог скопировать его снова. Отключение — удаление строки. `POST /api/v1/read-links/open {key}` — один точный путь в `PUBLIC_ROUTES`, ключ не попадает в журнал адресов API. Ответ: название истории, название драфта, текст сценария, из которого ядро убирает метки `comment` и `suggestion` (под меткой предложения остаётся прежний текст, как в экспорте). `Cache-Control: no-store`. Страница `/read/:key` в `web/` вне `RequireAuth`, тот же редактор с `readOnly`, без навигатора и чата; запрос без токена. Источник `fixtures` отдаёт текст демо-драфта по ключам из своих данных и `404` на остальные.

Альтернатива: `GET /api/v1/read-links/{key}`. Отвергнута: модуль `auth` разрешает без токена только точные пути, шаблон открыл бы соседние маршруты.

### 5. Присутствие — строка в базе и опрос раз в 20 секунд

`draft_presence(draft_id, user_id, seen_at)`, `PUT /drafts/{id}/presence` обновляет свою строку и возвращает имена других со `seen_at` моложе 60 секунд. Экран шлёт отметку, пока текст сценария открыт на правку и вкладка видима. Старые строки не чистятся: их не больше, чем пар «пользователь × драфт».

Альтернатива: память процесса или SSE. Отвергнута: память пропадает при перезапуске и не переживёт вторую реплику; SSE и Redis — избыточно для подсказки, живую правку на WebSocket сделаем на этапе 2.

### 6. Конфликт: снимок отклонённого текста и `RevisionConflict`

В `texts.save` и `documents.update` проверка ревизии идёт под блокировкой строки (`FOR UPDATE`). При несовпадении ядро в отдельной транзакции пишет снимок с причиной `conflict` от вызывающего (для `PATCH` — сохранённые поля с переданными изменениями), затем бросает `RevisionConflict(Conflict)` с именем того, кто сохранил нынешнюю ревизию (`updated_by`), и признаком «это вы». `problems.py` отдаёт его как `409` с полями `saved_by`, `saved_by_me`; замок и корзина остаются обычным `Conflict` без них. Правило «снимок не чаще раза в 10 минут» снимков `conflict` не касается. Экран отличает конфликт ревизии по наличию `saved_by_me`; другой `409` показывает причину ядра.

Альтернатива: сливать правки на сервере. Отвергнута: это и есть живая правка этапа 2.

### 7. Предложения людей и якорь рецензента

`suggestions` получает `author_kind`, `author_id`, `decided_by`; старые строки — `coauthor`. `POST /documents/{id}/suggestions` проверяет цитату тем же `_scene_of_quote`, что и инструмент соавтора. Рецензент не может сохранить текст, поэтому его ветки и предложения всегда с якорем (`scene_uid` + цитата): метку в текст ставит экран владельца или соавтора тем же механизмом, что для ИИ-соавтора («Предложение по якорю», «Комментарий соавтора по якорю»). У самого рецензента экран ставит метки по якорю в открытый только для чтения текст и не сохраняет его: автосохранение при `readOnly` выключено. `scene_uid` выделения экран берёт из ближайшего заголовка сцены выше.

### 8. Соавтор: роль проверяет код инструмента, читателя останавливает хук

`_draft(run_context)` в `coauthor_tools.py` возвращает и роль. Изменяющие инструменты заметок, документов и файлов при роли ниже `coauthor` возвращают отказ с причиной; `suggest_edit` и `comment_on_screenplay` разрешены от `reviewer`. Хук до запуска (рядом с проверкой лимита) завершает запуск ошибкой, если роль спрашивающего `reader`. Контекст, который присылает экран, называет роль, чтобы модель не предлагала недоступных действий; запрет при этом — код.

### 9. Место считается по владельцу истории

`create_note_from_file` блокирует строку владельца истории и суммирует оригиналы заметок историй этого владельца; предел — `billing.storage_limit(owner_id)`. Граница биллинга не меняется: слой приложения передаёт ему id владельца вместо id вызывающего.

### 10. Роль на экране — из ответа ядра

`role` и `owner_name` приходят в `GET /api/v1/projects`; окно истории берёт роль оттуда и прячет недоступные действия. `403` от ядра всё равно показывается причиной: экран не заменяет проверку.

## Risks / Trade-offs

- [Пропущенный маршрут даст рецензенту право правки] → тест-матрица и тест полноты таблицы маршрутов (решение 2).
- [Рецензент ждёт, пока владелец или соавтор откроет текст, чтобы его метки встали в текст] → у него самого они видны сразу; у владельца появляются при открытии текста, как предложения ИИ.
- [Подтверждение действия соавтора у рецензента сначала спросит «Разрешить», а потом откажет] → модель знает роль из контекста; отказ кодом остаётся.
- [Ссылку переслали дальше] → её можно отключить; ключ 192 бита не подобрать.
- [Снимок `conflict` пишется при каждом отказе автосохранения] → экран после первого `409` перестаёт отправлять правки, поэтому снимок один на конфликт.
- [Два участника с одной почтой в `users`] → приглашение принимает первый вошедший с этой почтой; почта приходит из подтверждённого входа.
- [Имена и почты видны участникам] → только внутри общей истории; по ссылке — ни одного имени. Запись в `05-security-and-compliance.md`.

## Migration Plan

1. Миграция `0019_story_sharing`: таблицы `project_members`, `project_invitations`, `draft_read_links`, `draft_presence`; колонки `author_kind` (с `coauthor` для существующих строк), `author_id`, `decided_by` и проверки у `suggestions`; новый набор `reason` у `document_versions`. Только вперёд.
2. Выпуск обычным релизом: `agentos-migrate` до API. Откат — следующий релиз без использования новых таблиц; данных старых историй миграция не трогает.
3. Сайт (`soavtor.app`) и Caddy не меняются: `/os/*` на `app.soavtor.app` уже идёт в API.
