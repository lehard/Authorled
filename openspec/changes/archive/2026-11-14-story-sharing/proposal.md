# Proposal: участники истории и ссылка «почитать»

Источник: `business-intents/story-sharing.md` (решения владельца 2026-11-13).

## Why

Сейчас историю нельзя показать другому человеку и нельзя позвать кого-то работать над ней вместе: доступ к истории есть только у её владельца (`projects.owner_id`, источник доступа в `agno/core/projects.py`). Владелец хочет приглашать участников с ролями и давать почитать текст сценария по ссылке, как это сделано в Google Docs, WriterDuet и Arc Studio.

## What Changes

- **Участники истории с ролями.** Владелец, соавтор, рецензент, читатель. Роль действует на всю историю: на драфты, документы, заметки и файлы. Ядро проверяет роль в каждом маршруте истории: читать могут все участники, комментировать и предлагать правки — рецензент и выше, править — соавтор и владелец, действия владельца (участники, удаление истории, удаление навсегда) — только владелец.
- **Приглашение по почте без письма.** Владелец приглашает почту с ролью; история появляется на полке у того, кто вошёл под этой почтой. Владелец видит участников и ожидающие приглашения, меняет роль, убирает участника, отзывает приглашение; участник может выйти сам.
- **Чужие истории на полке.** С пометкой роли и имени владельца; действия владельца участнику не показываются.
- **Предложения правок от людей.** Рецензент и соавтор создают предложение правки в тексте сценария, как ИИ-соавтор; решает по предложению владелец или соавтор. У комментариев и предложений виден автор.
- **ИИ-соавтор по роли спрашивающего.** Беседы личные; лимит тратит спросивший; у рецензента ИИ только читает, комментирует и предлагает правки; у читателя чата нет.
- **«Сейчас правит».** Предупреждение с именем другого участника, который открыл тот же текст сценария на правку. Правку не запрещает.
- **Конфликт сохранения без потери текста.** Отказ `409` остаётся; ядро сохраняет отклонённый текст снимком с причиной «конфликт сохранения»; экран называет, кто сохранил свою версию.
- **Ссылка «почитать».** Одна на драфт, без входа, только текст сценария в нынешнем виде, отключается владельцем или соавтором. Новый маршрут без токена.
- **Учёт.** Прирост слов идёт участнику, сохранившему текст (`api/writing` уже записывает его вызывающему, требования не меняются); оригиналы заметок, загруженные участником, занимают место тарифа владельца истории.
- **Контекст-пак.** Ограничение «MVP: один автор-человек» в `openspec/context/01-product-context.md` заменяется описанием ролей.

## Capabilities

### New Capabilities

- `api/story-sharing`: участники истории и их роли, приглашения по почте, выход из истории, ссылка «почитать» на драфт и присутствие участников в тексте драфта.

### Modified Capabilities

- `api/stories`: доступ по роли вместо «только владельцу»; список историй с чужими историями, ролью и владельцем; снимок с причиной «конфликт сохранения»; место для оригиналов заметок считается по владельцу истории.
- `api/review`: предложения правок от людей (маршрут создания), автор предложения, кто решает по предложениям и комментариям.
- `api/agents`: инструменты соавтора по роли спрашивающего, лимит спросившего, справка о сервисе про участников.
- `auth`: маршрут ссылки «почитать» среди маршрутов без токена; доступ к проекту отвечает с учётом роли.
- `core/database`: таблицы участников, приглашений, ссылок и присутствия; причина снимка «конфликт сохранения»; автор предложения.
- `web/workspace`: окно «Поделиться», пометки на полке, скрытие действий не по роли, «Сейчас правит», конфликт с именем, страница чтения по ссылке, предложение правки человеком.

## Scope

- Ядро (`agno/core/`), миграция схемы `authorled`, свои маршруты (`agno/app/api/`), модуль `auth` (источник доступа и маршрут без токена), инструменты и промпт соавтора, экраны `web/`, демо-данные и `fixtures`, мастер-спеки из списка выше, `openspec/context/01-product-context.md` и `05-security-and-compliance.md`.
- Тесты ядра на PostgreSQL: каждая роль против каждого изменяющего маршрута, ссылка, приглашение, конфликт; проверка экранов в браузере.

## Non-goals

- Живая совместная правка, курсоры других людей, Yjs (бэклог этапа 2, «Живая совместная правка текста»).
- Доступ к отдельным драфтам или документам вместо всей истории; личные заметки «только мне».
- Передача владения историей; ограничение числа участников тарифом.
- Письма с приглашением и уведомления.
- Комментарии, экспорт и печать по ссылке «почитать»; ссылки с правами сверх чтения.
- Общие беседы с ИИ-соавтором; изменения биллинга.

## Impact

- База: новые таблицы в схеме `authorled`, новые значения причины снимка; миграция вперёд, одна голова.
- API: новые маршруты участников, приглашений, ссылки и присутствия; маршрут создания предложения; ответы `403` на действия не по роли; поля роли и владельца в списке историй. Клиенты — только наш `web/`.
- Модуль `auth`: один новый маршрут без токена в `PUBLIC_ROUTES`.
- Соавтор: состав разрешённых действий зависит от роли спрашивающего.
- Безопасность: ссылку «почитать» можно переслать; имена и почты участников видны только внутри общей истории.
