## MODIFIED Requirements

### Requirement: Вход
Приложение MUST пускать к экранам только после входа. Без действующей сессии приложение MUST открывать свой экран входа `/login` и после входа MUST возвращать на адрес, который открывали. Экран входа MUST следовать макету v1 (`openspec/context/_raw/design/kabinet/`, экраны `#auth/*`) и дизайн-системе:
- почта; при неверном формате — ошибка у поля;
- пароль — только если у аккаунта он задан; «Показать»; неверный пароль — ошибка у поля;
- код из письма — 6 ячеек: цифры переходят сами, вставка из буфера раскладывается по ячейкам, полный код отправляется сам; неверный код — ошибка и очищенные ячейки; «Отправить ещё раз» доступно через 60 секунд; «Другая почта» возвращает к первому шагу;
- ошибка Authentik — текст ошибки с причиной, а не пустой экран.
После последнего шага приложение MUST получить токены по OIDC без страницы Authentik. Если в Authentik уже есть сессия (вход в другой вкладке), `/login` MUST брать токены без формы. Перезагрузка страницы посреди входа MUST начинать вход с почты. Меню пользователя MUST показывать имя и почту из ответа `GET /api/v1/me`, пункт «Настройки», открывающий `/settings`, и действие «Выйти», которое завершает сессию в Authentik и возвращает на `/login`. Без входа MUST открываться только `/login`, витрина дизайн-системы и страница чтения по ссылке `/read/:key`.

#### Scenario: Вход с сохранением адреса
- GIVEN пользователь не вошёл
- WHEN он открывает `/p/water/chars` и проходит экран входа
- THEN после кода MUST открыться `/p/water/chars`

#### Scenario: Отказ во входе
- GIVEN Authentik недоступен или отвечает ошибкой
- WHEN пользователь отправляет почту на экране входа
- THEN MUST показываться причина ошибки и возможность повторить, а не пустая страница

#### Scenario: Неверный код
- GIVEN на экране кода
- WHEN пользователь вводит шесть неверных цифр
- THEN MUST показываться ошибка, ячейки MUST очиститься, и фокус MUST вернуться в первую ячейку

#### Scenario: Вставка кода
- GIVEN на экране кода
- WHEN пользователь вставляет из буфера «123456»
- THEN цифры MUST разложиться по ячейкам, и код MUST отправиться без нажатия кнопки

#### Scenario: Аккаунт без пароля
- GIVEN у аккаунта не задан пароль
- WHEN пользователь вводит почту
- THEN следующим MUST открыться экран кода

#### Scenario: Новая вкладка
- GIVEN пользователь вошёл в одной вкладке
- WHEN он открывает приложение в новой вкладке
- THEN экран MUST открыться без формы входа

#### Scenario: Перезагрузка на шаге кода
- GIVEN открыт шаг кода
- WHEN страница перезагружена
- THEN MUST показываться шаг почты без ошибки

#### Scenario: Выход
- GIVEN пользователь вошёл
- WHEN он выбирает «Выйти»
- THEN сессия в Authentik MUST завершиться, и MUST открыться `/login`

#### Scenario: Имя в меню из аккаунта
- GIVEN пользователь зарегистрировался как «Анна Петрова» и сменил имя в настройках на «Анна П.»
- WHEN он выходит и входит снова
- THEN меню пользователя MUST показывать «Анна П.»

#### Scenario: Ссылка «почитать» без входа
- GIVEN пользователь не вошёл
- WHEN он открывает `/read/<ключ>` действующей ссылки
- THEN MUST открыться текст сценария без экрана входа

### Requirement: Адреса экранов
Каждый экран MUST иметь свой адрес, и открытие адреса напрямую MUST показывать тот же экран:
- `/` — полка историй; `/trash` — корзина историй;
- `/p/:projectId/d/:draftId/:doc` — окно истории с документом драфта: `info`, `title`, `logline`, `synopsis`, `treatment`, `text`, `chars`, `char:<id>`, `locs`, `loc:<id>`, `worlds`, `world:<id>`, `notes`, `note:<id>`, `trash`;
- `/p/:projectId` и `/p/:projectId/:doc` — переход к `/p/:projectId/d/<open_draft_id>/:doc` (без `:doc` — `text`);
- `/settings` — настройки (личный кабинет);
- `/showcase` — витрина дизайн-системы;
- `/auth/callback` — возврат из Authentik;
- `/read/:key` — текст сценария драфта по ссылке «почитать».
Неизвестный адрес, история, драфт или документ MUST показывать экран «Не найдено» со ссылкой на полку.

#### Scenario: Прямая ссылка на профиль
- GIVEN пользователь вошёл
- WHEN он открывает `/p/water/char:vera`
- THEN MUST открыться окно истории «Тихая вода» с профилем Веры в последнем открытом драфте, адрес MUST содержать этот драфт, и в навигаторе Вера MUST быть текущим пунктом

#### Scenario: Нет такого документа
- GIVEN пользователь вошёл
- WHEN он открывает `/p/water/char:nobody`
- THEN MUST показываться «Не найдено» со ссылкой на полку

#### Scenario: Сравнение с самим собой
- GIVEN пользователь вошёл
- WHEN он открывает `/p/water/compare:current:current`
- THEN MUST показываться «Не найдено» со ссылкой на полку

#### Scenario: Нет такого драфта
- GIVEN пользователь вошёл
- WHEN он открывает `/p/water/d/nobody/text`
- THEN MUST показываться «Не найдено» со ссылкой на полку

#### Scenario: Документ другого драфта
- GIVEN персонаж «Нина» есть только в драфте 2
- WHEN пользователь открывает адрес «Нины» с драфтом 1
- THEN MUST показываться «Не найдено» со ссылкой на полку

#### Scenario: Адрес бывшей страницы сценария
- GIVEN пользователь вошёл
- WHEN он открывает `/p/water/sp`
- THEN MUST показываться «Не найдено» со ссылкой на полку

#### Scenario: Прямая ссылка на заметку
- GIVEN в истории «Тихая вода» есть заметка
- WHEN пользователь открывает её адрес с любым драфтом этой истории
- THEN MUST открыться заметка, и в навигаторе она MUST быть текущим пунктом

#### Scenario: Заметка в корзине по адресу
- GIVEN заметка лежит в корзине
- WHEN пользователь открывает её адрес
- THEN MUST показываться «Не найдено» со ссылкой на полку

#### Scenario: Заметка другой истории
- GIVEN заметка есть только в истории «Последний паром»
- WHEN пользователь открывает её адрес в истории «Тихая вода»
- THEN MUST показываться «Не найдено» со ссылкой на полку

### Requirement: Конфликт правок
Если ядро отказало в сохранении документа или текста из-за более новой ревизии (`409`), экран MUST показать на месте статуса сохранения «История изменилась в другой вкладке», если нынешнюю версию сохранил сам автор (`saved_by_me`), или «<Имя> сохранил(а) свою версию», если другой участник (`saved_by`), а также «Открыть свежую версию» и «Скопировать мою правку». Отказ из-за замка, корзины или роли MUST показываться своей причиной, а не конфликтом. Пока автор не выбрал, правки этого документа MUST NOT отправляться. «Открыть свежую версию» MUST загрузить сохранённую версию; несохранённая правка MUST NOT пропадать без «Скопировать мою правку».

#### Scenario: Две вкладки
- GIVEN профиль Веры открыт в двух вкладках, и в первой сохранено поле «Главный страх»
- WHEN во второй вкладке автор меняет то же поле
- THEN вторая вкладка MUST показать «История изменилась в другой вкладке», а в ядре MUST остаться правка первой

#### Scenario: Свежая версия
- GIVEN вторая вкладка показывает конфликт
- WHEN автор нажимает «Открыть свежую версию»
- THEN поле MUST показать значение, сохранённое первой вкладкой, и следующие правки MUST сохраняться

#### Scenario: Сохранил другой участник
- GIVEN Борис сохранил текст сценария драфта, пока Аня его правила
- WHEN автосохранение Ани получает `409` с `saved_by` «Борис»
- THEN на месте статуса MUST показываться «Борис сохранил(а) свою версию», «Открыть свежую версию» и «Скопировать мою правку», а в истории документа MUST быть снимок «Конфликт сохранения» с текстом Ани

### Requirement: Карточка предложения
Клик по предложению MUST открывать рядом с текстом карточку: «Предложение соавтора» или «Предложение: <имя участника>» и время, было и стало, зачем, «Обсудить в чате», «Отклонить», «Принять». «Отклонить» и «Принять» MUST показываться только владельцу и соавтору истории; «Обсудить в чате» — всем, у кого есть чат. Escape, ✕ и клик мимо карточки MUST её закрывать; чат MUST NOT закрываться.

#### Scenario: Открыть предложение
- GIVEN открыт `/p/water/text`
- WHEN автор кликает по предложению в реплике Дяди Коли «Он утонул. Всё.»
- THEN MUST открыться карточка с «Утонул. Всё.» и объяснением, зачем убрать «Он»

#### Scenario: Предложение рецензента у рецензента
- GIVEN Аня — рецензент и предложила правку
- WHEN Аня кликает по своему предложению
- THEN карточка MUST показывать «Предложение: Аня» и MUST NOT показывать «Принять» и «Отклонить»

## ADDED Requirements

### Requirement: Окно «Поделиться»
В шапке истории в навигаторе MUST быть кнопка «Поделиться», открывающая окно со списком участников (имя, почта, роль). Владельцу окно MUST давать поле почты с выбором роли («Соавтор», «Рецензент», «Читатель») и «Пригласить», смену роли и «Убрать» у участников, ожидающие приглашения с «Отозвать». Участнику окно MUST давать «Выйти из истории» с подтверждением. Отказ ядра MUST показываться у поля или в окне с причиной.

#### Scenario: Приглашение
- GIVEN владелец открыл «Поделиться»
- WHEN он вводит `anya@mail.ru`, выбирает «Рецензент» и нажимает «Пригласить»
- THEN в окне MUST появиться ожидающее приглашение `anya@mail.ru` с ролью «Рецензент» и подсказкой, что письмо не отправляется и адрес сервиса нужно сообщить самому

#### Scenario: Участник выходит
- GIVEN Аня — читатель истории и открыла «Поделиться»
- WHEN Аня нажимает «Выйти из истории» и подтверждает
- THEN MUST открыться полка, и истории на ней MUST NOT быть

### Requirement: Ссылка «почитать» в окне
Владельцу и соавтору окно «Поделиться» MUST показывать раздел «Ссылка почитать» для открытого драфта: «Создать ссылку», затем адрес с «Скопировать» и «Отключить» и подсказку, что по ссылке без входа виден только текст сценария этого драфта. Рецензенту и читателю раздел MUST NOT показываться.

#### Scenario: Создать и скопировать
- GIVEN соавтор открыл «Поделиться» в драфте 2
- WHEN он нажимает «Создать ссылку», затем «Скопировать»
- THEN в буфере MUST оказаться адрес вида `<адрес приложения>/read/<ключ>`

### Requirement: Чужая история на полке
Карточка истории, где пользователь участник, MUST показывать в мета-строке роль и имя владельца («Рецензент · история Веры»). Её меню MUST давать соавтору «Переименовать», цвет обложки и «Выйти из истории», рецензенту и читателю — только «Выйти из истории»; «Удалить в корзину» MUST NOT показываться.

#### Scenario: Карточка рецензента
- GIVEN Аня — рецензент «Маяка» Веры
- WHEN Аня открывает полку
- THEN карточка «Маяка» MUST показывать «Рецензент · история Веры», а её меню — только «Выйти из истории»

### Requirement: Экран истории по роли
У рецензента и читателя текст сценария и документы MUST открываться только для чтения, а создание, переименование, корзина, замок, точки, откат, импорт и загрузка в заметки MUST NOT показываться. Чат с соавтором у читателя MUST NOT показываться. Экран MUST брать роль из ответа ядра, а не решать её сам.

#### Scenario: Читатель открывает текст
- GIVEN Аня — читатель истории
- WHEN Аня открывает текст сценария
- THEN набор текста MUST NOT менять его, чата справа MUST NOT быть, а в навигаторе MUST NOT быть «Новый драфт» и «Создать»

### Requirement: Комментарий и предложение рецензента
Рецензенту меню выделения в тексте сценария MUST давать «Комментарий» и «Предложить правку» (новый текст и «зачем»). Выделение больше одного абзаца MUST давать подсказку выделить фрагмент в одном абзаце. Его комментарии и предложения MUST показываться у него на месте фрагмента без сохранения текста; в текст их метки MUST ставить экран владельца или соавтора по якорю.

#### Scenario: Рецензент предлагает правку
- GIVEN Аня — рецензент и выделила «Вера молчит» в сцене `s3`
- WHEN Аня выбирает «Предложить правку», вводит «Вера отворачивается» и отправляет
- THEN предложение MUST показываться у неё на месте фрагмента, а у владельца, открывшего текст, MUST появиться в тексте с карточкой «Предложение: Аня»

#### Scenario: Выделение на два абзаца
- GIVEN рецензент выделил текст из двух абзацев
- WHEN он выбирает «Комментарий»
- THEN MUST показываться подсказка выделить фрагмент в одном абзаце, и ветка MUST NOT создаваться

### Requirement: Сейчас правит
Пока у владельца или соавтора открыт на правку текст сценария драфта в видимой вкладке, экран MUST отмечаться в ядре каждые 20 секунд и MUST показывать над текстом «Сейчас правит <имя>» для других участников из ответа. Предупреждение MUST NOT запрещать правку и MUST исчезать, когда другой участник ушёл.

#### Scenario: Двое в тексте
- GIVEN Вера правит текст сценария драфта 1
- WHEN соавтор Аня открывает тот же текст
- THEN у Ани MUST в течение 20 секунд появиться «Сейчас правит Вера», и правка MUST оставаться доступной

### Requirement: Страница чтения по ссылке
`/read/:key` MUST без входа показывать название истории, название драфта и текст сценария только для чтения, без навигатора, чата, комментариев и предложений, меню пользователя и данных участников. Недействующая ссылка MUST показывать «Ссылка не работает: её отключили или она неверная» без ссылки на полку.

#### Scenario: Читатель по ссылке
- GIVEN у драфта «Маяка» есть ссылка «почитать»
- WHEN человек без аккаунта открывает её
- THEN MUST показываться «Маяк», название драфта и текст сценария, который нельзя править

#### Scenario: Отключённая ссылка
- GIVEN ссылку отключили
- WHEN человек открывает её адрес
- THEN MUST показываться «Ссылка не работает: её отключили или она неверная»
