# Proposal: экраны истории на данных ядра

Бизнес-интент: `business-intents/story-data-web.md` (согласован 2026-11-02). Первый шаг — архивный change `story-data-backend`: таблицы, маршруты `/api/v1`, загрузка, импорт и инструменты соавтора уже есть. Импорт STARC вынесен в change `starc-import` и здесь не делается.

## Why

Ядро хранит истории, но экраны работают на данных примера в памяти страницы и всё теряют при перезагрузке; источник `api` фронтенд отвергает. Ядро уже отклоняет текст без `uid` сцен, а у редактора их нет — сохранить текст через API сейчас нельзя. Предложения соавтора приходят в ядро якорем (сцена и цитата), а метку в текст никто не ставит. Импорт разбирается в браузере и знает только Fountain и FDX, вложений в чате нет, корзины обещают удаление через 30 дней, которого нет.

## What Changes

- **Источник данных `api`**: провайдер данных Refine работает с `/api/v1` (через `/os/` с токеном пользователя); ресурсы экранов (`projects`, `scripts`, `characters`, `locations`, `worlds`, `drafts`, `comments`, `suggestions`) переводятся в маршруты ядра, ревизии для `If-Match` провайдер берёт из последних ответов. `fixtures` остаётся для витрины и разработки.
- **Конфликт правок**: на `409` экран документа или текста показывает, что история изменилась в другой вкладке, даёт «Открыть свежую версию» и «Скопировать мою правку»; своя правка не теряется молча.
- **Постоянный `uid` сцены**: редактор и операции над сценами выдают `uid` каждому заголовку сцены без него и копии сцены, сохраняют его при перестановке и правке.
- **Предложения соавтора по якорю**: открытое предложение без метки в тексте ставится в текст по сцене и цитате обычной правкой с сохранением; без цитаты — в списке «Нет места в тексте» с «Отклонить». После ответа соавтора список предложений обновляется.
- **Комментарии по сообщениям**: ветки, ответы, правка и удаление — отдельными операциями, «своё» сообщение определяет ядро. **BREAKING** для формы записей фронтенда: `CommentMessage.email` заменяется на `own`.
- **Импорт через бэкенд**: «Импорт» над текстом и импорт при создании истории принимают Fountain, FDX, DOCX и TXT, загружают файл и вызывают импорт ядра. **BREAKING**: разбор Fountain и FDX в браузере удаляется; экспорт и печать остаются в браузере.
- **Файлы в чат**: скрепка, перетаскивание и вставка загружают файл к беседе; пока проверяется — отправить нельзя; отказ с причиной; соавтор получает id файлов в контексте сообщения.
- **Корзины без срока**: из корзины историй убирается «хранятся 30 дней» и «удалится через N дн.».

### Modified Capabilities
- `web/workspace`: «Источник данных» (появляется `api`), «Полка историй» (история из файла), «Корзина историй» (без срока), «Импорт, экспорт и печать на экране» (импорт через бэкенд, четыре формата); новые требования «Конфликт правок», «Предложение по якорю», «Предложения без места в тексте», «Файлы в чат», «Файлы в сообщении».
- `web/screenplay-editor`: «Импорт и экспорт» (только экспорт), «Ошибки импорта» снимается (переходит в `web/workspace`); новое требование «Постоянный uid сцены».

## Scope

- `web/src/data/`: клиент API, провайдер `api`, выбор источника; модель: `own` у сообщений, якорь у предложений, ревизии не в модели.
- `web/src/editor/`: `uid` сцены (атрибут, плагин, операции `scenes.ts`), постановка метки предложения по якорю; удаление `importers/` и `importFile`.
- `web/src/screens/`: конфликт правок, импорт через бэкенд, история из файла, вложения чата, корзины без срока, комментарии по сообщениям, список предложений без места.
- Проверки: `check:editor` без круга импорта, образцы экспорта для тестов ядра, браузер 1440 и 375 px на `api`, `./scripts/validate.sh`.

## Non-goals

- Маршруты и таблицы ядра не меняются; если экрану не хватает маршрута — правка через отдельный change бэкенда.
- STARC (`starc-import`), обложки (бэклог этапа 2), экспорт DOCX/PDF/Markdown/FB2/EPUB.
- Работа без сети, очередь несохранённых правок, совместное редактирование.
- Импорт и вложения в режиме `fixtures`: там они явно недоступны.

## Impact

- Фронтенд целиком; бэкенд не меняется. Новых зависимостей нет.
- Режим `api` требует запущенный API и ClamAV; `fixtures` работает как раньше.
- `check:editor` теряет проверку круга импорта; круг остаётся в тестах ядра на образцах, выгруженных экспортом редактора.
