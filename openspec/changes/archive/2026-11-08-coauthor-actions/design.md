# Design

## Context

Мотивация — в `proposal.md`, поведение — в дельтах спек. Ниже то, что определяет решение. Всё проверено по коду и по Agno 3.1.10.

- **Инструменты соавтора** (`agents/coauthor_tools.py`) — функции в процессе API.
  - Драфт они берут из `session_id` беседы, пользователя — из `run_principal(run_context)`, доступ проверяют через `can_access_project`.
  - Отказ возвращают модели текстом «Отказ: …» (`_answer`).
  - Сейчас инструменты только читают, кроме `suggest_edit`.
- **Операции ядра для действий уже есть:** `documents.create_documents`, `documents.update_document`, `notes.create_note`, `notes.update_note`, `review.create_thread`.
  - `update_document` и `update_note` требуют ожидаемую ревизию и при расхождении дают `Conflict`.
  - `update_document` сохраняет снимок `fields` без причины. Такой снимок пишется, только если последний снимок старый (`snapshots._due`). Поэтому прежние значения после правки соавтором сейчас сохраняются не всегда.
- **Комментарии.**
  - `comment_messages.author_id` обязателен и ссылается на `users`. Соавтор пользователем не является.
  - Id ветки — это id метки `comment`, которую клиент ставит в текст до вызова `POST …/comments`. У ветки нет `scene_uid`.
  - Предложения правки, наоборот, создаются без метки и с якорем `scene_uid` + цитата. Метку ставит браузер (`web/workspace`, «Предложение по якорю»).
- **Пауза Agno 3.1.10.**
  - Если у `Function` стоит `requires_confirmation=True`, запуск ставится на паузу (`RunStatus.paused`), и в AG-UI приходят события вызова инструмента и `RUN_FINISHED` (`os/interfaces/agui/handlers.py`, `on_run_completed`).
  - Продолжение — новый запрос AG-UI, в конце `messages` которого стоит сообщение инструмента с тем же `tool_call_id` и JSON `{"accepted": true|false, "note"?: …}` (`os/interfaces/agui/resume.py`, `_resolve_confirmation`).
  - Отказ доходит до модели ошибкой вызова: `note` или «Function call was rejected by the user».
  - Продолжение идёт под тем же `run_id`: запуск в статусе `PAUSED` продолжается на месте, без нового запуска.
  - На продолжении pre-hooks не вызываются, post-hooks вызываются в конце (`agent/_run.py`, `_acontinue_run_stream`).
  - На паузе post-hooks не вызываются.
  - `RunContext.authorization` берётся из контекстной переменной запроса (`run/base.py`), поэтому `run_principal` работает и на продолжении.
- **Инструменты по запуску.** Сам `Agent(tools=<callable>)` в Agno есть (`utils/callables.py`), но AgentOS 3.1.10 с ним не стартует: `_bind_company_tools` перебирает `tools` компонента как список и падает на функции (проверено при `/opsx:apply` 2026-11-08). Признак `requires_confirmation` у `Function` статический, решать о паузе во время запуска Agno не даёт.
- **Готовые вызовы инструментов.** Их AG-UI отдаёт событиями `TOOL_CALL_START/ARGS/END/RESULT` с текстом результата (`on_tool_call_completed`).
- **Чат** (`web/src/screens/project/chat/`) — свой интерфейс на `@copilotkit/react-core/v2` (`useAgent`, `useAgentContext`, `useCopilotKit`) над `HttpAgent` AG-UI. `CopilotChat` и хуки v1 он не использует.
  - Показываются только текстовые сообщения `user` и `assistant`. Вызовы инструментов не показываются.
  - `loadConversation` восстанавливает из сессии только текст.
  - После всей цепочки запуска чат обновляет только список предложений.
- **Подтверждение на стороне CopilotKit 1.79.1.**
  - После запуска ядро CopilotKit (`processAgentResult`) находит вызов инструмента без ответа, находит инструмент по имени (флаг `available` при поиске не проверяется) и ждёт его `handler`; у `useHumanInTheLoop` это `respond(result)` из отрисованной карточки.
  - Результат вставляется сообщением `role: "tool"` (объект через `JSON.stringify`). При `followUp` по умолчанию сразу идёт следующий запуск с этими сообщениями. Для Agno это и есть продолжение паузы.
  - `available: false` не даёт отправить инструмент в `RunAgentInput.tools`, иначе Agno завёл бы одноимённый клиентский инструмент с `external_execution`.
  - `useInterrupt` не подходит: Agno не шлёт стандартного interrupt AG-UI.
- **Данные экранов.** Списки (навигатор `GET /drafts/{id}/documents`, заметки, комментарии) после запуска соавтора сейчас не обновляются.
  - Открытые формы держат своё состояние: `EntityForm` — `useState(record)` с ключом `record.id`, `NoteDoc` — `useState(note.title/body)`. Новая запись из запроса в открытую форму не попадает.
  - Провайдер кэширует ревизии и шлёт `If-Match`. При `409` `useAutosave` уже показывает конфликт и ничего не шлёт до решения автора.
- **Метки комментариев** ставит редактор при выделении: `crypto.randomUUID()`, метка `comment` вне истории отмены (`plugins/comments.ts`), сохраняется с текстом.
  - Для предложений есть `findAnchor`/`placeAnchors` (`editor/anchors.ts`), но `placeAnchors` жёстко завязан на метку `suggestion` и запрет пересечений, а комментарии пересекаться могут.
  - У `CommentThread` нет `sceneUid`.
- **Настройки аккаунта** читает и пишет `src/account/meApi.ts` со строгим разбором (`account()`). Образец переключателя с откатом при ошибке — `ThemeRow` в `SettingsScreen.tsx`.

## Goals / Non-Goals

**Goals:**
- Пауза перед изменением задаётся кодом (`requires_confirmation`), а не просьбой в промпте; без ответа на паузу изменение не происходит ни в каком режиме.
- Не завести своего состояния подтверждений: пауза, хранение и продолжение остаются за Agno.
- Каждое изменение соавтора обратимо в пределах MVP: снимок полей, корзина для созданного, «Решено» и удаление для комментария.

**Non-Goals:**
- Восстановить карточку подтверждения после перезагрузки страницы (см. Risks).
- Своя атрибуция «изменено соавтором» в `documents.updated_by` и `notes.updated_by`: там остаётся пользователь, автор запуска.

## Decisions

1. **Статический список инструментов; каждый меняющий вызов ставит запуск на паузу, а режим решает, кто её подтверждает.** Решение владельца 2026-11-08 при `/opsx:apply`.
   - `agents/coauthor_tools.py` отдаёт `COAUTHOR_TOOLS`: читающие инструменты и `suggest_edit` как есть, меняющие как `Function.from_callable(fn)` с `requires_confirmation=True`. `Agent(tools=COAUTHOR_TOOLS)`.
   - Пауза идёт в любом режиме. В режиме `ask` её подтверждает автор карточкой, в режиме `auto` — сам чат, сразу (решение 7). Режим хранится в аккаунте и читается чатом из `/api/v1/me`.
   - Отвергнута фабрика `Agent(tools=<callable>)`, которая собирала бы инструменты с `requires_confirmation = (mode == "ask")` на каждый запуск. AgentOS 3.1.10 перебирает `tools` каждого компонента как список (`AgentOS._bind_company_tools`), и API с такой фабрикой падает на старте. Обходить отказ фреймворка нельзя (AGENTS.md), а другого способа решать о паузе во время запуска в Agno нет.
   - Отвергнуты два агента, `coauthor` и такой же без пауз: беседы и их история разошлись бы по двум компонентам.
   - Цена: в режиме `auto` на каждое действие уходит один лишний короткий запрос продолжения. Режим соблюдает клиент, но это клиент самого автора и его собственное согласие; изменить чужое он не может, доступ проверяет ядро.

2. **Меняющие инструменты** (имена — контракт с фронтендом):

   | Инструмент | Что делает |
   |---|---|
   | `create_story_note(title, body)` | новая заметка истории беседы |
   | `update_story_note(note_id, title?, body?, append?)` | `append` дописывает с новой строки в конец текста; задать `body` и `append` вместе — отказ |
   | `create_story_document(kind, name, role?, summary?, fields?)` | `kind` — `character`, `location` или `world`, как у `create_documents` |
   | `update_story_document(document_id, name?, role?, summary?, fields?)` | `fields` — частичное изменение, как PATCH (`merge_fields`) |
   | `comment_on_screenplay(scene_uid, quote, text)` | ветка с первым сообщением соавтора |

   Читающие новые: `list_story_notes()` и `read_story_note(note_id)`.

   - Ревизию инструменты не принимают: читают текущую под `for_update` и передают её в операцию ядра. Так соавтор не получает `Conflict` из-за своей устаревшей ревизии.
   - Успех возвращается JSON-строкой `{"done": "<что сделано по-русски>", "target": {"type": "note"|"document"|"comment", "id": "…", "kind"?: "…"}}`. Модель читает `done`, клиент по `target` строит ссылку.
   - Отказ, как и раньше, — строка «Отказ: …».

3. **Изменение документа соавтором — отдельная операция ядра** `documents.update_document_by_coauthor` (или параметр причины в `update_document`).
   - Она всегда пишет снимок `fields` с причиной `coauthor` и в остальном повторяет проверки `update_document`.
   - Позицию соавтор не меняет: поле `position` инструмент не принимает.
   - Альтернатива — снимок вне ядра. Отвергнута: правило хранения версий принадлежит ядру.

4. **Комментарий соавтора.**
   - Миграция `0010_coauthor_actions`:
     - `comment_messages.author_kind` (`user`|`coauthor`, существующие — `user`);
     - `author_id` становится необязательным, с ограничением `(author_kind = 'user') = (author_id IS NOT NULL)`;
     - `comment_threads.scene_uid` (пусто или непустой текст).
   - Операция `review.create_coauthor_thread(document_id, scene_uid, quote, body)`:
     - проверяет сцену и цитату так же, как `create_suggestion` (общая проверка выносится в одну функцию);
     - создаёт ветку со своим `uuid`, `author_role` = «».
   - `_messages` читает автора через `LEFT JOIN users`. Имя «Соавтор» подставляет маршрут для `author_kind = 'coauthor'`.
   - `_own_message` для сообщения соавтора: правка — `Forbidden`, удаление разрешено любому, кто прошёл проверку доступа маршрута.
   - Альтернатива — писать от имени автора с ролью «Соавтор». Отвергнута владельцем 2026-11-08: сообщение считалось бы своим, и автор правил бы его как своё.

5. **Режим в ядре.**
   - Колонка `user_settings.coauthor_mode text NOT NULL DEFAULT 'ask'` с проверкой `IN ('ask','auto')`. Значение по умолчанию — начальный режим нового пользователя (решение интента), а не подмена отсутствующего значения.
   - `users.Account` получает `coauthor_mode`, `update_account` — параметр `coauthor_mode` (как `theme`, через `UNSET`), `GET/PATCH /api/v1/me` — поле `settings.coauthor_mode`.

6. **Промпт.** В `SKILL.md` добавляются:
   - список новых инструментов;
   - правило «действуй только по прямой просьбе автора»;
   - «после действия коротко скажи, что сделано»;
   - «если автор отклонил действие, не повторяй его без новой просьбы»;
   - «удаляет и решает только автор»;
   - про комментарий: цитата символ в символ из одного абзаца, как у `suggest_edit`.

7. **Чат: ответ на паузу — свой обработчик на `useFrontendTool` (`chat/confirmations.ts`).**
   - Для каждого меняющего инструмента регистрируется `useFrontendTool({name, available: false, handler})`. Ядро CopilotKit после запуска находит вызов без ответа, вызывает `handler`, вставляет его результат сообщением `role: "tool"` и сразу продолжает запуск (`followUp`); для Agno это продолжение паузы.
   - В режиме `auto` обработчик сразу возвращает `{accepted: true}`. В режиме `ask` он возвращает обещание, которое ждёт кнопку карточки: «Разрешить» → `{accepted: true}`, «Отклонить» → `{accepted: false, note: "Автор отклонил это действие."}`. Режим берётся из аккаунта (`useAccount`) в момент паузы; режим ещё не загружен — явная ошибка.
   - Отвергнут `useHumanInTheLoop`: его `respond` есть только у отрисованной карточки, а карточка не отрисована, когда открыта «История бесед» или чат свёрнут; автоответ в «Сам» зависел бы от того, что видно на экране (найдено при `/opsx:apply` 2026-11-08). Отвергнут и ручной разбор паузы через `@ag-ui/client`: ядро CopilotKit уже находит вызов и продолжает запуск.
   - Пока идёт ход автора (от отправки до конца ответа, включая ожидание карточки), отправка, «Новая беседа» и «История бесед» заблокированы: ожидающий ответ принадлежит этой беседе.
   - Ошибка продолжения после ответа на карточку не удаляет исходное сообщение автора: ход уже состоялся.

8. **Чат: показ вызовов инструментов (`chat/ActionLines.tsx`).**
   - Под ответом соавтора выводятся меняющие вызовы: карточка, пока вызов ждёт автора; «Разрешено: …» или «Отклонено: …» после ответа; затем строка о сделанном со ссылкой или строка отказа.
   - Строка строится из результата инструмента: JSON `done` и `target` → текст и ссылка на маршрут сущности (документ драфта, заметка, текст сценария). Текст «Отказ: …» показывается как есть.
   - Результат берётся из события `TOOL_CALL_RESULT` в подписке на запуск и хранится в чате по `toolCallId`. Из сообщений его взять нельзя: после ответа на паузу у вызова уже есть сообщение инструмента с ответом автора, и `@ag-ui/client` отбрасывает второе, с результатом Agno (проверено вживую).
   - Вызов показывается один раз, под первым сообщением, которое его несёт: Agno присылает приостановленный вызов ещё раз с продолжением. Отбор считается чисто (`firstChangingCalls`), без изменения данных во время рендера.
   - Сообщение с меняющими вызовами показывает только их: текст, который Agno ставит у паузы, — его служебный, по-английски. Сообщения без текста и без меняющих вызовов (ходы читающих инструментов) не показываются. Читающие инструменты и `suggest_edit` строк не дают.

9. **Обновление экранов.**
   - Чат подписан на `TOOL_CALL_RESULT` запуска и инвалидирует ресурсы по `target` готового вызова сразу, а не в конце всей цепочки: заметки, комментарии, документы драфта и сценарий.
   - Открытая форма (`EntityForm`, `NoteDoc`) берёт новые сохранённые значения слиянием по полям (`screens/shared/useServerChanges.ts`): поле, которое автор не менял, принимает значение с сервера, поле с вводом автора его сохраняет. Ремонт по ключу с ревизией отвергнут: он сбрасывал фокус и курсор после каждого собственного автосохранения.
   - Если сохранение автора ушло со старой ревизией, `useAutosave` показывает существующий конфликт ревизий.

10. **Метка комментария соавтора.**
    - `findAnchor` используется как есть.
    - В `anchors.ts` добавляется `placeCommentAnchors(tr, anchors)`: ставит метку `comment` с id ветки, пропускает уже стоящие id, не проверяет пересечения и вешает `addToHistory=false`.
    - `useEditorComments` вызывает её для открытых веток с `sceneUid`, которых нет среди меток текста. Это делается только в редакторе текста (не в «Карточках») и только в незапертом драфте, по образцу `useEditorSuggestions`.
    - Ненайденные остаются без метки, и список показывает «Фрагмента в тексте нет».
    - `CommentThread` получает `sceneUid`, сообщение — `kind: "user" | "coauthor"`. Имя «Соавтор» приходит с сервера.

11. **Переключатель режима** стоит в нижней строке поля ввода чата: две кнопки-сегмента «Спрашивать» и «Сам».
    - `useAccount().data.coauthorMode`, сохранение через `useSaveAccount()`, откат и ошибка — как у `ThemeRow`.
    - `meApi.account()` строго требует `settings.coauthor_mode`.

12. **Расход.** Пауза и продолжение — один `run_id`. Post-hook вызывается один раз, в конце продолжения, и видит все метрики запуска. Хуки менять не нужно. Это закрепляется тестом: post-hook записывает одну строку на запуск, который ставили на паузу. Проверку лимита на продолжении Agno не делает, это принимается: запуск уже прошёл проверку при старте.

## Risks / Trade-offs

- **Брошенная пауза.** Автор закрыл вкладку, не ответив, и запуск остался в `PAUSED`.
  - Post-hook его не запишет, а pre-hook дозаписывает только `completed`, `error` и `cancelled`. Токены до паузы (один ход модели) не попадут в журнал.
  - Смягчение: пока карточка ждёт ответа, чат не даёт отправить новое сообщение. Недоучёт одного хода в бете допустим. Запись брошенных пауз — вопрос для `payments-tochka`, если суммы станут заметны.
- **История беседы без строк о сделанном.** `loadConversation` восстанавливает только текст, а результаты меняющих вызовов чат держит только в памяти, поэтому в открытой заново беседе строк о сделанном и карточек нет. Это принимается для MVP: сделанное видно в самой истории (навигатор, заметки, комментарии).
- **Карточка после перезагрузки.** Беседа, открытая заново, показывает сообщения из сессии Agno. Ожидающая карточка не восстанавливается, а следующее сообщение начинает новый запуск. Это принимается: старое действие просто не выполнено.
- **Открытый экран и действие соавтора.**
  - Если автор редактирует ту же карточку или заметку, его автосохранение получит `409` после правки соавтора.
  - Смягчение: после каждого готового меняющего вызова чат обновляет данные затронутой сущности. Открытая форма с несохранённым вводом идёт по уже существующему пути `409` автосохранения (см. web-часть).
- **Лишние действия в режиме «Сам».**
  - Смягчение: по умолчанию режим `ask`, правило в промпте, eval-случаи «совет без действия» и «действие по просьбе».
  - Всё созданное и изменённое соавтором автор может вернуть: снимок полей, корзина, «Решено» или удаление ветки.
- **Модель повторяет отклонённое.** Отказ приходит ей ошибкой вызова с `note` «Автор отклонил это действие». Правило в промпте, eval-случай не делается (кейс редкий, проверяется вживую).
- **Evals соавтора не запускаются.** `python -m evals` запускает агента без проверенного пользователя: проверка лимита (с v0.2.0) отказывает такому запуску, а инструменты соавтора без пользователя отказывают. Поэтому «совет без действия» и «действие по просьбе» проверяются вживую в чате (решение владельца 2026-11-08); запуск evals соавтора с пользователем — отдельная задача вне change.

## Migration Plan

1. Миграция `0010_coauthor_actions` вперёд: колонки и ограничения, `author_kind` = `user` у существующих сообщений, `coauthor_mode` = `ask` у существующих строк, причина снимка `coauthor` в проверке `document_versions`.
2. Релиз бэкенда и фронтенда вместе, обычным релизом из `main`. Фронтенд без бэкенда не увидит `coauthor_mode` и откажет явной ошибкой разбора `/api/v1/me`, поэтому выкладываются вместе.
3. Отката вниз миграций нет (forward-only). Откат — следующий релиз, где `COAUTHOR_TOOLS` содержит только читающие инструменты. Колонки остаются.
