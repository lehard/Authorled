# Proposal

## Why

Админка Authentik (`https://auth.soavtor.app/if/admin/`) открыта всему интернету и защищена только паролем `akadmin` и кодом на почту, а через неё меняются вход, регистрация, пользователи и группа `admins` с административными правами в API. Владелец хочет пускать в админку только с своего компьютера по клиентскому сертификату (`business-intents/admin-mtls.md`).

## What Changes

- Новый адрес админки `admin.soavtor.app`: обратный прокси принимает на нём только TLS-соединения с клиентским сертификатом, подписанным удостоверяющим центром владельца, и ведёт их на Authentik.
- На `auth.soavtor.app` административная часть (`/if/admin/`) отвечает 404.
- **BREAKING**: суперпользователь Authentik (`akadmin`, группа `admins`) входит только через адрес админки; поток входа продукта отказывает ему на любом другом адресе.
- **BREAKING**: на публичных адресах (`auth.soavtor.app`, `app.soavtor.app`) из потоков Authentik открыты только потоки продукта (`authorled-authentication`, `authorled-enrollment`, `authorled-invalidation`) и поток согласия OIDC-провайдера; остальные потоки (в том числе потоки Authentik по умолчанию) отвечают 404, чтобы правило входа суперпользователя нельзя было обойти чужим потоком.
- Новая обязательная настройка `AUTH_ADMIN_DOMAIN` (хост админки; на локальном стенде равен `AUTH_BRAND_DOMAIN`) и бренд Authentik для этого хоста с потоком входа продукта.
- Authentik на проде доверяет заголовкам прокси только с адреса шлюза сети Docker (`/32`), через который приходит Caddy, а не всему `172.16.0.0/12`: иначе контейнер той же сети подделает `X-Forwarded-Host` и обойдёт правило входа суперпользователя. Релиз останавливается, если значение не совпадает со шлюзом сети.
- Скрипт `scripts/admin_cert.sh` выпускает на компьютере владельца удостоверяющий центр и клиентский сертификат (`.p12` для Связки ключей macOS); на сервер кладётся только публичный сертификат удостоверяющего центра `/etc/authorled/admin-client-ca.pem`, без него релиз падает.
- Проверка после деплоя: `admin.soavtor.app` без клиентского сертификата отклоняет соединение, `/if/admin/` на `auth.soavtor.app` отвечает 404, чужой поток на публичном адресе отвечает 404.
- README и скилл `deploy-platform`: новый адрес админки, выпуск сертификата, файл удостоверяющего центра, DNS.

## Scope

- `deploy/Caddyfile`: сайт `admin.soavtor.app` с проверкой клиентского сертификата; на `auth.soavtor.app` и `app.soavtor.app` закрытие `/if/admin/` и чужих потоков.
- `auth/blueprints/30-authentication-flow.yaml`: шаг отказа суперпользователю вне адреса админки, бренд `AUTH_ADMIN_DOMAIN`.
- `auth/compose.yaml`, `example.env`: `AUTH_ADMIN_DOMAIN`.
- `scripts/admin_cert.sh`.
- `deploy/deploy.sh` (проверка файла удостоверяющего центра и доверенного прокси), комментарий в `compose.prod.yaml`, новый `deploy/check_admin.sh` и шаг в `.github/workflows/deploy.yml`.
- README («Module auth», «Admin interface», настройки), `.agents/skills/deploy-platform`.
- На сервере при первом релизе: A-запись `admin.soavtor.app`, файл удостоверяющего центра, `AUTH_ADMIN_DOMAIN` в `/etc/authorled/authorled.env` (каждый шаг с подтверждения владельца).

## Non-goals

- mTLS для интерфейса AgentOS (os.agno.com) и API `/os/`.
- Клиентские сертификаты для авторов и других людей; второй сертификат.
- Списки отзыва (CRL, OCSP); отзыв — перевыпуском удостоверяющего центра.
- Ограничение доступа к админке по IP.
- Своя админка во фронтенде, второй администратор Authentik.
- Проверка клиентского сертификата на локальном стенде: локально админка остаётся на `localhost:9000` без сертификата.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `auth`: «Интерфейс Authentik» — административная часть только на адресе админки по клиентскому сертификату, на домене Authentik её нет; новое требование «Вход суперпользователя» — только через адрес админки; новое требование «Потоки на публичных адресах» — открыты только потоки продукта и поток согласия.
- `runtime`: «Обратный прокси» — сайт админки с проверкой клиентского сертификата и закрытые пути на публичных доменах; «Проверка после деплоя» — проверка адреса админки и закрытых путей.

## Impact

- Конфигурация обратного прокси и blueprints Authentik; кода приложения (`agno/`, `web/`) изменение не касается: веб-фронтенд уже показывает отказ потока (`ak-stage-access-denied`).
- Новая обязательная переменная `AUTH_ADMIN_DOMAIN`: без неё Authentik не стартует (локально и на проде).
- Новый файл на сервере `/etc/authorled/admin-client-ca.pem`, новая A-запись DNS `admin.soavtor.app`.
- После релиза `akadmin` не может войти через `auth.soavtor.app`; его открытые там сессии нужно завершить в админке.
