# Design: демо-контент для пользователей разработки

## Context

Мотивация в `proposal.md`. Что есть сейчас:

- `web/src/data/fixtures.ts` собирает примеры кодом (`plainDoc`, `marked`, `numbered`), поэтому Python его прочитать не может.
- Разовый загрузчик 2026-11-06 лежит в `tmp/demo-content/`: `fixtures.json` (выгрузка примеров) и `load.py` (дополнения и запись через ядро). Он прошёл на локальной базе, экран сценариста проверен.
- Функции ядра принимают соединение, поэтому загрузку можно вести в одной транзакции.
- `auth_subject` пользователя равен `User.uid` в Authentik (`sub_mode: hashed_user_id`): на `writer` значения совпали. Python вне `agno/app/auth/` к Authentik не обращается, а `dev.sh` уже вызывает `ak shell` в команде `auth-users`.
- Доступ к истории есть только у владельца, поэтому редактору нужна своя копия.

## Goals / Non-Goals

**Goals:**
- Один файл контента для команды и для источника `fixtures`.
- Запись только функциями ядра, без прямых вставок в таблицы.

**Non-Goals:**
- Свой формат описания контента и общий механизм «сидов» для других данных.
- Точки драфта в режиме `fixtures`.

## Decisions

1. **Контент лежит в `web/src/data/demo.json`, в форме `FIXTURES`.** `fixtures.ts` становится типами и импортом этого файла, помощники `marked`, `numbered` и `local` уходят. Загрузчик читает файл по пути от корня репозитория. Файл создаётся один раз из `tmp/demo-content/` и дальше правится руками.
   Другие варианты: держать файл в `agno/` — тогда Vite пришлось бы разрешать чтение вне `web/`; оставить две копии — они разойдутся (риск из интента).

2. **Новые поля файла.** Драфт `water-2` с `forkedFromName: "Драфт 1"` хранит полный текст и карточки, как их читает `fixtures`. Верхний ключ `points` (`draftId`, `name`) читает только загрузчик. Комментарии подписаны `editor@authorled.test`, ответ `writer@authorled.test`. У файла имена авторов «Редактор» и «Сценарист», на титульной странице автор «Сценарист» у обоих владельцев.

3. **Пакет `agno/demo/`, вход `python -m demo`, как у `agno/evals`.** `demo/load.py` содержит `load_demo(connection, accounts)` без работы с окружением, поэтому тест зовёт его на `ai_test`. `demo/__main__.py` читает пользователей из stdin, проверяет миграции, открывает транзакцию и печатает только число историй. Пакет не кладём в `agno/core`: продуктовому ядру демо-контент не нужен. Пакет добавляется в `packages.find`.

4. **Порядок загрузки одной копии.**
   - Первый драфт: `create_project` с текстом, паспорт через `update_document`, карточки через `create_documents`, в корзину те, у кого `deletedAt`, комментарии и ответы, предложения, точка.
   - Ответвлённый драфт: `create_draft` от основы, точка, затем отличия: `put_text` без `reason`, а карточки сравниваются по имени и обновляются через `update_document`. Карточка без пары в основе — ошибка загрузчика.
   - История с `deletedAt`: создание и `trash_project`.
   - Время в файле (`deletedAt`, `at`) в базу не переносится, важен только факт корзины.
   - В конце `open_draft` на первый драфт.

5. **Метки в тексте.** Метки `c1`, `c2` заменяются новыми UUID, потому что маршруты и ядро ждут UUID ветки. Метки предложений `s1`, `s2` снимаются, соседние куски текста склеиваются: метку ставит браузер, а в `fixtures` она остаётся в файле.

6. **Пользователи.** `dev.sh seed` вызывает в `authentik-worker` `ak shell`, который печатает строку с префиксом `DEMO_USERS` и JSON (`subject`, `email`, `name`). Логи Authentik идут в тот же вывод, поэтому строка ищется по префиксу. Нет строки — отказ с указанием на `auth-users`, независимо от кода выхода `ak shell`. JSON уходит в stdin `python -m demo`, а там `get_or_create_user`, как при первом входе. `check_auth_boundary.sh` не задет.

7. **Проверки до записи.** В `dev.sh`: `RUNTIME_ENV` как в `auth-users`, `uv`, `AGENTOS_DB_PASSWORD`, запущенные `agentos-db` и `authentik-worker`. Команда их не поднимает и миграции не применяет: это сделали бы `db` и `migrate`, а молчаливый подъём стенда спека не требует. В Python: ревизия базы равна голове Alembic, иначе отказ с указанием на `migrate`; затем поиск демо-названий у обоих пользователей, корзина включена, до первой записи.
   `DB_DATABASE=ai` задаёт `dev.sh`, как в команде `api`.

8. **Отказ «история уже есть» — своё исключение `DemoExists`.** `__main__` печатает его текст и выходит с кодом 1. Остальные ошибки идут трассировкой и откатывают транзакцию.

## Risks / Trade-offs

- [Тесты ядра не идут в CI] → загрузчик может устареть незаметно; `./scripts/dev.sh test` обязателен в «готово» по стандартам проекта.
- [`demo as unknown as` снимает проверку типов JSON в `fixtures.ts`] → расхождение с моделью экранов покажет только запуск в режиме `fixtures`; на это есть задача проверки экрана.
- [Демо-название занято своей историей автора] → команда откажет и назовёт её; автор переименует или очистит корзину. Перезапись запрещена интентом.
- [Вывод `ak shell` изменится с версией Authentik] → нет строки с префиксом, команда откажет явно.

## Migration Plan

Схема не меняется. На локальной базе уже есть истории разовой загрузки, поэтому первый `seed` откажет. Для полной проверки удаляются только они, «Белая дача» остаётся. Откат: убрать команду и пакет, контент в базе не мешает.
