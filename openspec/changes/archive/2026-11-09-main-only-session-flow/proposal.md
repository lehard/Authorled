# Proposal: работа только через main, одна сессия доводит изменение до архива

## Why

Работа идёт по двум линиям, которые обгоняют друг друга. Основная папка стоит на `feature/openspec`: в ней 5 коммитов, которых нет в `origin/main`, в `origin/main` 64 коммита, которых нет в ней, и 167 файлов без коммита. В `.claude/worktrees/` шесть worktree, пять из них — остатки законченных сессий. Каждое изменение расползается на две-три ветки (`X`, `X-archive`, `X-close`), а verify и archive забываются, потому что по `AGENTS.md` их запускает владелец. Подробности и решения владельца — `business-intents/main-only-session-flow.md`.

## What Changes

- Единственная длинная ветка — `main`. Основная папка стоит на `main` и только читается. Каждая сессия работает в своём worktree от `origin/main` в ветке `claude/<change>` и вливается в `main` через PR.
- Одна сессия ведёт одно изменение до конца: apply, verify, archive, PR и слияние. Отдельных веток для архива нет. Проверка на сервере после релиза идёт отдельным маленьким PR.
- **BREAKING (процесс):** verify и archive сессия запускает сама, когда все задачи `tasks.md` отмечены. При критичных замечаниях verify или упавших проверках она останавливается и ничего не архивирует и не вливает. Propose, update и начало apply по-прежнему запускает владелец.
- Сессия вливает свой PR сама после зелёного `./scripts/validate.sh`, тестов, которых требует change, и verify без критичных замечаний. Релиз по-прежнему создаёт владелец.
- Два хука Claude Code в `.claude/settings.json` со скриптами в `scripts/`:
  - при старте сессии — предупреждение, если сессия открыта в основной папке или основная папка не на `main`;
  - при остановке — одно напоминание закончить verify и archive, если у изменения этой ветки все задачи отмечены, а архива нет.
- Уборка после слияния: в приложении включается автоархивация сессии после закрытия её PR (worktree удаляется), на GitHub — удаление ветки после слияния. Это настройки, их меняет владелец или сессия с его подтверждением.
- Разовая уборка: содержимое `feature/openspec` разносится по PR в `main` по решению владельца, затем ветка удаляется. Старые worktree и слитые локальные ветки удаляются по списку с подтверждением владельца.
- `AGENTS.md` (и `CLAUDE.md`, ссылка на него): разделы «Parallel sessions» и «OpenSpec is mandatory» переписываются под этот процесс.

## Capabilities

### New Capabilities
- `dev-workflow`: процесс работы агентов-разработчиков в репозитории: ветка `main` и worktree на сессию, полный цикл изменения OpenSpec в одной сессии, хуки контроля при старте и остановке сессии.

### Modified Capabilities

## Scope

- `AGENTS.md`: «Parallel sessions», «OpenSpec is mandatory», «Verification» в части слияния.
- `.claude/settings.json`: хуки `SessionStart` и `Stop`.
- `scripts/`: два скрипта хуков.
- Настройки: приложение `auto_archive_on_pr_close`, GitHub `delete_branch_on_merge` (с подтверждением владельца).
- Разовая уборка `feature/openspec`, старых worktree и слитых веток (с подтверждением владельца).
- Спека `openspec/specs/dev-workflow`.

## Non-goals

- Свой оркестратор сессий, очередь изменений, автоматический запуск propose или apply.
- Автоматический релиз и деплой после слияния.
- Защита `main` правилами GitHub и обязательные проверки CI перед слиянием.
- Автоматическая проверка на сервере после релиза.
- Правка вендорных скиллов OpenSpec в `.agents/skills/openspec-*` и команд `.claude/commands/opsx/`: процесс задаётся в `AGENTS.md`.
- Код продукта, ядро, фронтенд, сайт, деплой.

## Impact

- Меняется работа всех будущих сессий агентов в этом репозитории; продукт и прод не затрагиваются.
- Хук при остановке выполняется в конце каждого хода сессии: он должен быть быстрым и не трогать сеть.
- Разовая уборка затрагивает файлы без коммита других сессий в основной папке и в `coauthor-mentor-checks`: только по решению владельца.
