# Design

## Context

Мотивация — proposal.md («Why»), требования — `specs/dev-workflow/spec.md`. Что важно для решения:

- `CLAUDE.md` — ссылка на `AGENTS.md`, правила процесса живут только в `AGENTS.md`.
- `.claude/settings.json` в git (исключение в `.gitignore`), `.claude/settings.local.json` и `.claude/worktrees/` — нет. Хуков сейчас нет. В `settings.local.json` уже разрешены `gh pr merge` и `gh release create`.
- Скиллы `.agents/skills/openspec-*` и команды `.claude/commands/opsx/` — вендорные файлы OpenSpec, их перезаписывает `openspec update`.
- `jq` на машине владельца нет; `python3` и `git` есть.
- История `main` — merge-коммиты PR («Merge pull request #N …»). CI (`validate.yml`) запускает `./scripts/validate.sh` на PR в `main`. Правил защиты ветки нет, на GitHub `allow_auto_merge = false`, `delete_branch_on_merge = false`.
- В приложении Claude `auto_archive_on_pr_close = false`; worktree создаются в `<repo>/.claude/worktrees`, префикс веток `claude`.
- Это изменение спланировано в основной папке на `feature/openspec`, то есть так, как процесс больше не разрешает.

## Goals / Non-Goals

**Goals:**
- Процесс задаётся текстом в `AGENTS.md`; код добавляет только два коротких хука-напоминания.
- Хуки быстрые (без сети), ничего не меняют сами и не молчат при ошибке.

**Non-Goals:**
- Хуки не заставляют выполнять процесс: они напоминают, решает сессия и владелец.
- Скрипты хуков не входят в `validate.sh` и CI: они про локальные сессии, а не про код продукта.

## Decisions

1. **Новая спека `dev-workflow`, а не раздел в `runtime`.** `runtime` описывает окружение и скрипты, которые запускает человек или CI; процесс сессий — отдельная тема, которая будет расти (например, защита `main` позже). Альтернатива — требование в `runtime`: короче, но смешивает процесс с контейнерами.

2. **Процесс — в `AGENTS.md`, вендорные скиллы не трогаем.** Правило «после последней задачи apply — verify, затем archive, проверки, PR и слияние» записывается в «OpenSpec is mandatory» вместо пункта «the user runs … `/opsx:verify` and `/opsx:archive` themselves». Сессия выполняет скиллы `openspec-verify-change` и `openspec-archive-change` по этому правилу. Это правило `AGENTS.md` и есть постоянное разрешение владельца коммитить, пушить и вливать PR в этом цикле. Альтернатива — правка скилла apply: её сотрёт `openspec update`.

3. **Слияние: merge-коммит после зелёного CI.** Перед PR сессия вливает `origin/main` в свою ветку (`git merge`, не rebase, как в истории `main`); при конфликте — остановка. Потом локально `./scripts/validate.sh` (с `env -u BASH_ENV` после активации venv), `git diff --check`, тесты изменения, push, `gh pr create`, ожидание проверок одной командой `gh pr checks <PR> --watch --fail-fast` и `gh pr merge <PR> --merge`. Альтернатива — вливать сразу после локальных проверок: быстрее, но CI ставит зависимости с нуля и ловит то, чего не видно локально. Автослияние GitHub не включаем: без правил защиты ветки оно вливает сразу.

4. **Определение основной папки.** `git rev-parse --git-dir` и `--git-common-dir` совпадают только в основной папке; в worktree — разные. Ветку основной папки хук берёт как `git -C <родитель common-dir> branch --show-current`. Имя каталога не используется.

5. **Изменения «этой ветки» для хука остановки.** База — `git merge-base HEAD origin/main`. Изменённые пути — `git diff --name-only <база> -- openspec/changes` (рабочее дерево и индекс против базы) плюс `git ls-files --others --exclude-standard -- openspec/changes`. Из путей берётся имя каталога изменения, `archive` исключается, учитываются только каталоги, которые ещё существуют. Так чужие незаархивированные изменения в `main` не дают ложных напоминаний (сценарий «Чужое изменение в main»). `origin/main` хук не обновляет: локальной ссылки достаточно, `git fetch` медленный и сетевой.

6. **Подсчёт задач — как у OpenSpec.** Строка `- [<метка>]` в `tasks.md` — задача; выполнена, только если метка после удаления пробелов равна `x` или `X`. Изменение «законченное», если задач больше нуля и неотмеченных нет. Разбор на `python3` внутри скрипта на bash (нет `jq`). Альтернатива — `openspec instructions apply --json`: точнее, но запускает Node на каждом ходе и медленнее.

7. **Формат хуков Claude Code.** Оба скрипта читают JSON из stdin.
   - `scripts/hook_session_start.sh` (событие `SessionStart`): при нарушении печатает JSON с `systemMessage` (видит владелец) и `hookSpecificOutput.additionalContext` (видит сессия); иначе ничего.
   - `scripts/hook_stop.sh` (событие `Stop`): при `stop_hook_active = true` сразу выходит с кодом 0; при законченном незаархивированном изменении печатает `{"decision": "block", "reason": "…"}` с именами изменений и шагами (verify, archive, проверки, PR).
   - Ошибка git или отсутствие `origin/main` — сообщение в stderr и код 1: Claude Code показывает его как ошибку хука, остановку не блокирует, «нет изменений» не подставляется (правило без fallback).
   Пути в `settings.json` — через `$CLAUDE_PROJECT_DIR`, таймаут 10 секунд.

8. **Уборка worktree — настройкой приложения, веток — настройкой GitHub.** `auto_archive_on_pr_close = true` архивирует сессию после слияния её PR и удаляет её worktree (worktree с файлами без коммита приложение оставляет). `delete_branch_on_merge = true` удаляет ветку на GitHub. Локальные ветки остаются; их раз в какое-то время убирает владелец или сессия по его просьбе (`git branch --merged origin/main`, по списку). Свой скрипт уборки не пишем: это та самая обвязка, которой владелец не хочет.

9. **Разовая уборка только по решению владельца.** Сессия готовит список: 5 коммитов `feature/openspec`, файлы без коммита в основной папке и в `coauthor-mentor-checks`, сгруппированные по изменениям OpenSpec и интентам; старые worktree и слитые ветки. Владелец решает по каждой группе: PR в `main`, оставить сессии-владельцу или выбросить. Удаление и переключение веток — только после его ответа в чате; `git stash`, `reset --hard`, `clean` запрещены `AGENTS.md` и здесь не используются.

## Risks / Trade-offs

- [verify — проверка моделью и может пропустить ошибку] → Слияние только после `validate.sh`, CI и тестов изменения; выход на прод остаётся за релизом владельца.
- [Хук остановки срабатывает на каждом ходе] → Только локальный git и чтение файлов; блокирует один раз за ход.
- [Локальная `origin/main` устарела] → База через `merge-base` даёт лишние, но не потерянные изменения; сессия всё равно обновляет ветку перед PR.
- [Ожидание CI занимает минуты] → Одна блокирующая команда без цикла опроса; при падении — остановка с именем проверки.
- [Файлы без коммита в основной папке — работа других сессий] → Ничего не удаляется без решения владельца; уборка — отдельная группа задач в конце.
- [Это изменение начато в основной папке на `feature/openspec`] → Первая задача переносит его в worktree от `origin/main`.

## Migration Plan

1. Перенести файлы изменения и интент в новый worktree от `origin/main` и дальше работать только там.
2. Добавить хуки и правила `AGENTS.md`; влить первым PR по новому процессу (это и есть проверка процесса).
3. Включить настройки приложения и GitHub (с подтверждением владельца).
4. Разовая уборка по решению владельца.

Откат: удалить блок `hooks` из `.claude/settings.json` и вернуть прежний текст разделов `AGENTS.md` (`git revert` PR); настройки выключить обратно.
