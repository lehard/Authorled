# Design: запуск без ответа в истории беседы

## Context

- `loadConversation` (`web/src/screens/project/chat/api.ts`) строит беседу из `GET /os/sessions/{id}/runs?type=agent`. Для каждого запуска она даёт вопрос, действия (`actionsOf`) и ответ, если `content` — непустая строка. Статус запуска не читается.
- Agno 3.1.10 хранит у запуска `status`. Запуск, оставшийся на паузе подтверждения, приходит со статусом `PAUSED` и с `content` «I have tools to execute, but I need confirmation.». Продолженный после ответа автора запуск приходит со статусом `COMPLETED`, с действиями и ответом модели. Проверено 2026-11-11 на локальном стенде при проверке `research-brief`.
- Действия без ответа (`confirmed` пуст) `actionsOf` уже пропускает.

## Goals / Non-Goals

**Goals:** у запуска на паузе не показывать служебный ответ и его кнопки; остальное не трогать.

**Non-Goals:** продолжение паузы после перезагрузки, пометка «ждал ответа», бэкенд.

## Decisions

1. **По статусу, а не по тексту.** `RunRow` получает `status`. Ответ запуска показывается, только если `status !== "PAUSED"` и `content` — непустая строка. Альтернатива — сравнивать `content` со служебной строкой. Отвергнута: строка может смениться с версией Agno, а модель может написать похожий текст.
2. **Остальное как сейчас.** Вопрос и уже отвеченные действия запуска на паузе показываются. Запуск без `status` или с другим статусом показывается как сейчас, без догадок: ни запасных путей, ни отказа открыть беседу.
3. **Оценка.** Нет ответа — нет записи в `runOf`, поэтому нет и кнопок «Полезно» и «Не то». Так уже устроено для запуска без `content`.

## Risks / Trade-offs

- **Статус в другой версии Agno.** При обновлении пина надо проверить, что запуск без ответа по-прежнему приходит со статусом `PAUSED`.
- **Вопрос без ответа.** Автор видит свой вопрос без ответа. Пометку можно добавить позже, если это будет путать.
