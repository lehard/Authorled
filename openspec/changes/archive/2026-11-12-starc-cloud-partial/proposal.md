# Proposal: импорт облачного проекта STARC с пропуском пустых записей

## Why

Файл облачного проекта STARC не импортируется: «В файле несколько сценариев, а импортировать можно ровно один». В структуре проекта перечислено десять сценариев, но содержимое в файле есть только у одного; у девяти других и у одной локации есть только запись в структуре, без документа в базе файла (облачный STARC не выгрузил их). Автор видит отказ и думает, что сломан наш импорт, хотя данных просто нет в файле (`business-intents/starc-cloud-partial.md`, решение владельца 2026-11-12).

## What Changes

- Импорт STARC считает запись структуры, у которой в файле нет своего документа (сценарий без текста, персонаж или локация без профиля), отсутствующей в файле и не переносит её.
- Правило «ровно один сценарий» относится к сценариям, текст которых есть в файле: ноль — отказ «нет сценария», два и больше — отказ «несколько сценариев», как сейчас.
- Ответы обоих путей импорта (новая история из файла, замена текста импортом) получают список пропущенного; для других форматов и для полного файла STARC он пуст.
- После импорта с пропусками экран «Текст сценария» показывает автору, что пропущено (по именам) и почему: этих данных нет в самом файле STARC, так бывает с облачными проектами; чтобы перенести их, нужно выгрузить проект из STARC целиком.
- Неизвестные элементы, типы абзацев, роли и повреждённые документы по-прежнему дают отказ целиком.

## Capabilities

### New Capabilities

(нет)

### Modified Capabilities

- `api/story-import`: «Отказ импорта STARC» — пропуск записей без документа вместо отказа, число сценариев по текстам в файле; «Новая история из файла» и «Замена текста импортом» — список пропущенного в ответе.
- `web/workspace`: «Импорт, экспорт и печать на экране» и «Полка историй» — предупреждение о пропущенном после импорта в редакторе и после создания истории из файла.

## Scope

- `agno/core/importers/starc.py`, `agno/core/imports.py` (рукопись и результат импорта с пропущенным).
- `agno/app/api/stories.py`, `agno/app/api/schemas.py` (поле `skipped` в ответах импорта).
- `web/src/data/apiProvider.ts`, `web/src/data/files.ts`, `web/src/screens/shelf/` и `web/src/screens/project/docs/TextDoc.tsx` (показ предупреждения).
- Тесты ядра и маршрутов на копии образца `project.starc` с записями без документов.
- Дельты спек `api/story-import` и `web/workspace`.

## Non-goals

- Выбор одного из нескольких сценариев, текст которых есть в файле (отказ остаётся).
- Загрузка недостающего из облака STARC.
- Пропуск чего-либо, кроме записи структуры без своего документа в файле.
- Предупреждения для FDX, Fountain, DOCX, TXT.
- Хранение предупреждения: оно показывается сразу после импорта и в ядре не сохраняется.

## Impact

- API: в ответе `POST /api/v1/projects` (из файла) и `POST /api/v1/drafts/{id}/import` появляется поле `skipped` (список `{kind, name}`); поле добавочное, существующие поля не меняются.
- Поведение: облачные файлы STARC, которые раньше отказывались, теперь импортируются с предупреждением.
- Спека `api/story-import`: снимается запрет частичного импорта STARC в узком случае — запись без документа в файле, с явным списком автору.
