# Design: импорт облачного проекта STARC с пропуском пустых записей

## Context

`agno/core/importers/starc.py` читает документ структуры (`type = 1`), берёт из него все записи вне корзины и:
- отказывает, если записей `screenplay` больше одной (`_project`);
- для единственного сценария ищет документ его текста (`type = 10104`) и отказывает, если его нет (`_paragraphs`);
- для каждой записи `character` и `location` ищет профиль (`30001`, `40001`) и отказывает, если его нет (`_cast`).

Реальный облачный файл (STARC, «Выбор. Драфт 3. Облако [1899].starc», 2026-11-12): в структуре 10 сценариев, в базе — документы только «Выбор 1» (сам сценарий `10100`, титул, синопсис, текст `10104`); у остальных девяти и у одной из 87 локаций документа нет. Если не учитывать записи без документа, «Выбор 1» разбирается целиком: 1182 абзаца, 46 сцен, 93 персонажа, 86 локаций.

Результат разбора идёт дальше через `core/imports.py` (`Manuscript`, `import_into`, `create_project_from_file`) в маршруты `app/api/stories.py` (`CreatedProject`, `TextOut`) и во фронтенд (`data/apiProvider.ts` → `data/files.ts` → `screens/shelf/storyActions.ts`, `ShelfScreen.tsx` и `screens/project/docs/TextDoc.tsx`).

## Goals / Non-Goals

**Goals:** импортировать облачный STARC, в котором текст есть у одного сценария; явно сказать автору, что и почему пропущено.

**Non-Goals:** выбор сценария из нескольких с текстом; загрузка из облака STARC; предупреждения для других форматов; хранение предупреждения в ядре.

## Decisions

1. **Признак «нет в файле» — нет строки в `documents` с uuid записи.** Для сценария смотрим документ его текста (дочерняя запись `screenplay/text`): сценарий, у которого текст есть в базе, — в файле; иначе пропущен. Для персонажа и локации — профиль нужного типа по uuid. Документ, который есть, но не разбирается, по-прежнему даёт `Invalid` (422). Так пропуск возможен только при полном отсутствии данных, а не при их порче — это не запасной путь, а описание файла.
   - Альтернатива: смотреть документ самого сценария (`10100`). Отказались: импортируем мы текст, и решающий вопрос — есть ли текст.
   - Сценарий, у которого в структуре нет записи `screenplay/text` или их больше одной, остаётся отказом «должен быть ровно один текст» (повреждённая структура, а не невыгруженные данные).

2. **Порядок правил в `_project`:** записи вне корзины → сценарии делятся на «с текстом в файле» и «пропущенные» → ноль с текстом: «В файле нет сценария.»; больше одного: «В файле несколько сценариев, а импортировать можно ровно один.» → `_cast` для персонажей и локаций пропускает записи без профиля и возвращает их отдельно. Тексты отказов не меняются.

3. **Модель пропущенного.** В `starc.py` — `Skipped(kind: Literal["screenplay", "character", "location"], name: str)`; `StarcProject.skipped: list[Skipped]` в порядке структуры (сценарии и профили в том порядке, в каком они в дереве). `Manuscript.skipped` (пусто для других форматов). `import_into` и `create_project_from_file` возвращают пропущенное вместе с прежним результатом (`import_into` → `Imported(text, skipped)`, `create_project_from_file` → кортеж с четвёртым элементом). Имя — как в структуре, без смены регистра: автор узнаёт его по STARC.

4. **API.** `SkippedOut {kind, name}`. Ответ импорта в драфт — новая модель `ImportedTextOut(TextOut)` с `skipped: list[SkippedOut]`; `TextOut` остаётся у чтения и записи текста. Ответ истории из файла — `CreatedFromFile(CreatedProject)` с `skipped`; JSON-создание истории возвращает прежний `CreatedProject`. Поле добавочное, старые клиенты его не читают.

5. **Фронтенд: одно предупреждение на экране текста.**
   - `apiProvider.ts` читает `skipped` строго (список объектов с `kind` из трёх значений и строкой `name`; иначе ошибка формы ответа, как у других полей) для `import` и `createFromFile`. `files.ts`: `importInto` → `{ text, skipped }`, `createFromFile` → `NewStory & { skipped }`.
   - Новый компонент `ImportSkipped` (`screens/project/docs/`), в стиле `ActionError` (тот же плавающий блок снизу), но текстом обычного цвета, без `role="alert"` (`role="status"`), с кнопкой «Закрыть». Текст: «В файле STARC нет содержимого: сценарии «…», персонажи «…», локации «…». Их не было в самом файле — так бывает, когда облачный проект STARC выгружен не полностью. Чтобы перенести их, сохраните проект в STARC на компьютер целиком и импортируйте снова.» Пустые группы не называются.
   - Импорт в редакторе: `TextDoc` кладёт `skipped` в своё состояние после успешного импорта.
   - Новая история: `createStory` возвращает `{ id, draftId, skipped }`; `ShelfScreen` переходит сразу на `/p/:id/d/:draftId/text` с `state: { importSkipped }` (минуя редирект `OpenDraft`, который состояние не переносит). `TextDoc` читает его из `useLocation().state` при первом показе и сразу заменяет запись истории без состояния (`navigate(..., { replace: true, state: null })`), чтобы перезагрузка и «Назад» его не показывали.
   - Источник `fixtures` импорт не поддерживает, как прежде.

## Risks / Trade-offs

- [Запись без документа — порча файла, а не невыгруженное облако] → автор видит список пропущенного по именам и решает сам; текст говорит «нет в файле», не утверждая причину наверняка («так бывает»).
- [Другие версии STARC хранят облачные проекты иначе] → пример один; правило зависит только от наличия документа по uuid, неизвестные формы по-прежнему отказ.
- [Много пропущенных имён — длинный текст] → группировка по видам; блок шириной до 560 px переносит строки, а по высоте ограничен половиной окна с прокруткой.
