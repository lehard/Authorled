# Proposal

## Why

2026-11-08 соавтор перестал отвечать: на счёте DeepSeek кончились деньги. Автор увидел в чате текст исключения LiteLLM с JSON, `request_id` и словами «DeepseekException», «model group 'deepseek-fast'», «No fallback was attempted», а в конце «Попробуйте ещё раз», хотя повтор не помогал. Такой текст пугает, ничего не объясняет автору и раскрывает устройство продукта. Источник: `business-intents/coauthor-chat-errors.md`.

Причина: Agno 3.1.10 отдаёт любое исключение запуска в `RUN_ERROR` как `str(exception)`, а `CoauthorChat.tsx` вставляет этот текст в «Соавтор не смог ответить: … Попробуйте ещё раз.». Действующая спека (`web/workspace`, «Чат с соавтором», сценарий «Ошибка») требует сообщения «с причиной», и код делает ровно это. Отказы самого продукта (лимит, конец подписки, сбой проверки или записи расхода) уже приходят с понятным текстом и признаком причины; технические подробности есть только в остальных сбоях.

## What Changes

- Отказ продукта с признаком из явного списка (`usage_limit_reached`, `subscription_ended`, `usage_check_failed`, `usage_record_failed`) показывается сообщением бэкенда как есть, без «Соавтор не смог ответить». Лимит остаётся уведомлением, остальные три отказа показываются ошибкой.
- Любой другой `RUN_ERROR` (сбой модели или провайдера, исключение Agno, признак не из списка) показывается одним текстом о недоступности соавтора, без текста исключения. Полный текст события пишется в консоль браузера; на сервере его уже пишет Agno («Error in Agent run: …»).
- Сбой самого запроса к API без ответа (нет сети) показывается текстом «Нет связи с сервером…» без технической причины в скобках; причина уходит в консоль. Ответы API с кодом (401 → вход, 403, 404, 5xx) показываются, как сейчас.
- Ошибка запуска, которую клиент не может отнести ни к одному из видов выше, показывается тем же текстом о недоступности соавтора, а не своим сообщением.
- Требование «Чат с соавтором» (`web/workspace`) переписывается: вместо «сообщение об ошибке с причиной» — понятный текст без технических подробностей; добавляются сценарии сбоя модели и отказа продукта.

## Scope

- Разбор ошибки запуска соавтора на клиенте: `web/src/screens/project/chat/CoauthorChat.tsx` (`runOrThrow`), новый модуль разбора рядом и текст сетевой ошибки в `web/src/screens/project/chat/api.ts` (`osFetch`).
- Проверка разбора на образцах `RUN_ERROR` в виде Agno 3.1.10 в `web/scripts/check-chat.ts`.
- Дельта спеки `web/workspace`, требование «Чат с соавтором».
- Живая проверка на локальном стенде (сбой модели, остановленный API, лимит) и запись в `tmp/VERIFY.md`.

## Non-goals

- Запасная модель, повтор запроса или подмена провайдера при сбое DeepSeek: сбой остаётся явным (07-anti-patterns, п. 26).
- Разные тексты для видов сбоя провайдера («кончились деньги», «превышен лимит запросов»): автору это не нужно, причина есть в логе API.
- Слежение за балансом DeepSeek и оповещение владельца: бэклог этапа 2, «Предупреждение о балансе провайдера моделей».
- Изменения бэкенда: тексты отказов в `agno/agents/coauthor_usage.py`, формат `RUN_ERROR` в Agno, логирование API (Agno уже пишет исключение запуска).
- Строки отказа ядра под действием соавтора («Отказ: …», требование «Сделанное соавтором в чате»).
- Ошибки загрузки файлов в чат, истории бесед и переименования беседы: у них уже свои тексты.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `web/workspace`: в требовании «Чат с соавтором» ошибка запуска показывается автору понятным текстом без технических подробностей; отказы продукта — сообщением бэкенда; нет связи — отдельным текстом.

## Impact

- Код: `web/src/screens/project/chat/CoauthorChat.tsx`, новый `web/src/screens/project/chat/runError.ts`, `web/src/screens/project/chat/api.ts` (одна строка текста сетевой ошибки), `web/scripts/check-chat.ts`.
- Бэкенд, API, база данных, зависимости и `validate.sh` не меняются (`check:chat` уже в нём).
- Выкатка обычным релизом; после неё сбой модели на `app.soavtor.app` показывается новым текстом.
