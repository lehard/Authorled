# Spec Delta: api/stories

## ADDED Requirements

### Requirement: Поиск по драфту истории
`GET /api/v1/drafts/{id}/search?q=<запрос>` MUST искать запрос в драфте и его истории: в тексте сценария, в логлайне и синопсисе сценария, в имени, кратком описании и текстовых полях персонажей, локаций и миров вне корзины, в названии и тексте заметок истории вне корзины. Совпадение MUST искаться по подстроке без учёта регистра и разницы «ё» и «е». Поиск MUST NOT менять данные и MUST работать и в запертом драфте.

#### Scenario: Имя персонажа по всей истории
- GIVEN в драфте «Тихой воды» Вера упоминается в сценах 2 и 5, у неё есть профиль, и заметка «Финал» говорит о ней
- WHEN автор ищет «вера»
- THEN ответ MUST содержать сцены 2 и 5, профиль Веры и заметку «Финал»

#### Scenario: Ё и е
- GIVEN в логлайне написано «посёлок у озера»
- WHEN автор ищет «ПОСЕЛОК»
- THEN ответ MUST содержать логлайн с совпадением «посёлок»

#### Scenario: Корзина не ищется
- GIVEN локация «Пристань» лежит в корзине истории
- WHEN автор ищет «пристань», и больше нигде этого слова нет
- THEN группа документов MUST быть пустой

#### Scenario: Запертый драфт
- GIVEN драфт заперт
- WHEN автор ищет в нём
- THEN поиск MUST вернуть результаты, а драфт MUST остаться без изменений

### Requirement: Ответ поиска по группам
Ответ поиска MUST содержать запрос и три группы. `scenes`: `uid`, `number`, `heading` сцены. `documents`: `id`, `kind`, `name` документа (для логлайна и синопсиса — сценарий драфта) и поле `field` первого совпадения. `notes`: `id`, `title` заметки и `field` (`title` или `body`). У каждого результата MUST быть `count` совпадений и `snippet`: `before`, `match`, `after` вокруг первого совпадения, где `match` — текст как он написан. Порядок MUST совпадать с порядком в тексте и в навигаторе.

#### Scenario: Кусочек вокруг совпадения
- GIVEN в сцене 3 написано «КОЛЯ протирает ключ ветошью» и других «ключ» в сцене нет
- WHEN автор ищет «КЛЮЧ»
- THEN у сцены 3 `count` MUST быть 1, `match` MUST быть «ключ», `before` MUST заканчиваться на «протирает », а `after` MUST начинаться с « ветошью»

#### Scenario: Логлайн и синопсис отдельно
- GIVEN «посёлок» есть и в логлайне, и в синопсисе
- WHEN автор ищет «поселок»
- THEN в `documents` MUST быть два результата сценария драфта: с `field` `logline` и с `field` `synopsis`

#### Scenario: Совпадение в поле профиля
- GIVEN в подробном описании Коли есть «чинит моторы и лодки»
- WHEN автор ищет «моторы»
- THEN в `documents` MUST быть Коля с `field` этого поля

#### Scenario: Текст вне сцен
- GIVEN абзац с совпадением стоит вне сцен: до первого заголовка сцены или в строке акта
- WHEN автор ищет это слово
- THEN первым в `scenes` MUST быть один результат без `uid` с `number` 0 и пустым `heading`

#### Scenario: Ничего не нашлось
- GIVEN в истории нет слова «дирижабль»
- WHEN автор ищет «дирижабль»
- THEN ответ MUST быть `200` с тремя пустыми группами

### Requirement: Отказы поиска
Запрос без `q`, пустой после обрезки пробелов, короче 2 символов или длиннее 200 символов MUST давать `422` с причиной в `detail`, а не пустой или полный список. Чужая или несуществующая история драфта MUST давать `404`, как у остальных маршрутов драфта.

#### Scenario: Один символ
- GIVEN автор открыл свою историю
- WHEN он ищет «а»
- THEN ответ MUST быть `422` с `detail` о том, что нужно не меньше 2 символов

#### Scenario: Без запроса
- GIVEN автор открыл свою историю
- WHEN он вызывает поиск без `q`
- THEN ответ MUST быть `422` в `application/problem+json`

#### Scenario: Чужая история
- GIVEN драфт принадлежит истории другого пользователя
- WHEN автор ищет в нём
- THEN ответ MUST быть `404`, и ни один результат из той истории MUST NOT вернуться
