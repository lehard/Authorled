# Spec Delta: web/workspace

## ADDED Requirements

### Requirement: Поиск по истории в навигаторе
Под шапкой навигатора над деревом MUST быть поле «Поиск по истории». ⌘K (Ctrl+K) в окне истории MUST ставить в него курсор и выделять введённое. Пока в поле меньше 2 символов, навигатор MUST показывать дерево. С 2 символов результаты MUST показываться вместо дерева и обновляться по мере ввода; Esc в поле и крестик MUST очищать поле и возвращать дерево. На узком экране поле MUST быть в выезжающем навигаторе.

#### Scenario: Курсор по ⌘K
- GIVEN открыт профиль Веры
- WHEN автор нажимает ⌘K
- THEN курсор MUST стоять в поле «Поиск по истории»

#### Scenario: Результаты вместо дерева
- GIVEN в навигаторе видно дерево
- WHEN автор вводит «ве»
- THEN вместо дерева MUST показаться результаты, а после Esc MUST вернуться дерево с тем же раскрытием папок

#### Scenario: Esc на узком экране
- GIVEN ширина экрана 375 px, навигатор открыт, в поле «ключ»
- WHEN автор нажимает Esc в поле
- THEN поле MUST очиститься, навигатор MUST закрыться, а при следующем открытии MUST быть видно дерево

#### Scenario: Один символ
- GIVEN поле пустое
- WHEN автор вводит «в»
- THEN навигатор MUST показывать дерево без запроса к поиску

### Requirement: Результаты поиска по истории
Результаты MUST идти группами «Сцены», «Документы», «Заметки», пустая группа MUST NOT показываться. У результата MUST быть название (сцена — номер и заголовок, текст вне сцен — «Вне сцен», документ — его название в навигаторе, например «Логлайн» или имя персонажа, заметка — её название), кусочек текста с выделенным совпадением и число совпадений, если их больше одного. Без результатов MUST быть «Ничего не нашлось». Отказ поиска MUST показываться с причиной на месте результатов.

#### Scenario: Группы
- GIVEN Вера упоминается в сценах, у неё есть профиль и заметка о ней
- WHEN автор ищет «вера»
- THEN MUST быть группы «Сцены», «Документы» и «Заметки», и в каждом результате «Вера» MUST быть выделена в кусочке текста

#### Scenario: Ничего не нашлось
- GIVEN в истории нет слова «дирижабль»
- WHEN автор ищет «дирижабль»
- THEN на месте результатов MUST быть «Ничего не нашлось»

#### Scenario: Скрытая часть сценария
- GIVEN автор скрыл «Синопсис» в документе «История», а слово есть и в синопсисе, и в логлайне
- WHEN автор ищет это слово
- THEN MUST показываться только «Логлайн», результата «Синопсис» MUST NOT быть

#### Scenario: Данные примера
- GIVEN источник данных `fixtures`
- WHEN автор ищет по истории
- THEN на месте результатов MUST быть причина, что поиск по истории работает только с источником данных `api`

### Requirement: Переход к совпадению из поиска по истории
Клик по документу или заметке MUST открывать их, раскрывать раздел профиля с полем совпадения, ставить в это поле курсор и выделять первое совпадение. Клик по сцене MUST открывать «Текст сценария» на этой сцене со строкой «Найти и заменить», где уже введён запрос и текущим совпадением выбрано первое в этой сцене. После перехода результаты MUST оставаться в навигаторе, пока автор не очистит поле.

#### Scenario: Поле профиля
- GIVEN совпадение «моторы» есть в подробном описании Коли
- WHEN автор нажимает на результат «Коля»
- THEN MUST открыться профиль Коли, курсор MUST стоять в поле подробного описания, а «моторы» MUST быть выделено

#### Scenario: Сцена
- GIVEN совпадение «ключ» есть в сцене 3
- WHEN автор нажимает на результат «Сцена 3»
- THEN MUST открыться «Текст сценария», лист MUST прокрутиться к сцене 3, а строка поиска MUST показывать «ключ» и текущее совпадение в сцене 3

#### Scenario: Совпадение скрыто в тексте
- GIVEN совпадение стоит в абзаце, который сейчас скрыт в тексте (биты не показаны)
- WHEN автор нажимает на результат этой сцены
- THEN MUST открыться «Текст сценария» на этой сцене со строкой поиска и запросом, а счётчик MUST считать только видимые совпадения

## MODIFIED Requirements

### Requirement: Найти и заменить
«Найти и заменить» (кнопка, ⌘F или Ctrl+F в редакторе) MUST открывать строку поиска с полем запроса, областью поиска, счётчиком «N из M» и переходами к соседним совпадениям. Области: весь текст, заголовки сцен, описание действия, персонажи, реплики (с ремарками). Поиск MUST NOT учитывать регистр и разницу «ё» и «е» и MUST подсвечивать все совпадения и текущее отдельно. Без совпадений счётчик MUST показывать «нет». Строка поиска MUST открываться и с запросом из поиска по истории (требование «Переход к совпадению из поиска по истории»).

#### Scenario: Поиск в репликах
- GIVEN открыт `/p/water/text`
- WHEN автор ищет «мам» в области «В репликах»
- THEN счётчик MUST показать число совпадений только в репликах и ремарках, а лист MUST прокрутиться к первому

#### Scenario: Ё в тексте
- GIVEN в тексте написано «посёлок»
- WHEN автор ищет «поселок»
- THEN «посёлок» MUST быть найден и подсвечен
