# Design: сайт продукта Authorled

## Context

Мотивация — `proposal.md` («Why»). Что важно для подхода:

- Фронтенд сервиса `web/` — Vite 8 + React 19 + TypeScript 6 + Tailwind 4; токены в `web/src/design-system/tokens.css`, шрифты — `fonts.css` с путями `../../node_modules/@fontsource…`, то есть к `web/node_modules`. `tokens.css` начинается с `@import "tailwindcss"` и `@import "tw-animate-css"`, которые тоже разрешаются из `web/node_modules`.
- Локальный `web` ходит в API через прокси Vite `/os/` → `AGENTOS_URL` (с отрезанием `/os`); на сервере то же делает Caddy (`handle_path /os/*`). Значит, внутри API маршрут виден как `/api/v1/...`.
- Проверка токена — middleware Agno; `Authorization(...)` в Agno 3.1.10 принимает `excluded_route_paths` (сравнение через `fnmatch`, без учёта метода). Если список передан, он **заменяет** список по умолчанию (`/`, `/health`, `/info`, `/docs`, `/redoc`, `/openapi.json`, `/docs/oauth2-redirect`).
- Свои маршруты подключает `attach_api` (перед монтированием MCP), ошибки — `Problem` → `application/problem+json`; `body.read_object` читает тело без ограничения размера.
- Скрипт `admin` — argparse над операциями ядра; запускается `./scripts/usage.sh local|prod` в контейнере API.
- Сайт glavai.ru уже решает ту же задачу (пререндер страниц на Vite SSR: `scripts/prerender.mjs`, ~50 строк) — берём подход, не код целиком.

## Goals / Non-Goals

**Goals:**
- Сайт, который собирается в статику и выглядит как сервис, без копии дизайн-системы.
- Публичный маршрут заявки, который нельзя использовать для перебора почт и тяжело забить спамом, без новой инфраструктуры.
- Всё проверяется `validate.sh` и тестами ядра.

**Non-Goals:**
- Общий пакет дизайн-системы или npm workspaces: это перестройка `web/`, вне задачи.
- Капча, внешние антиспам-сервисы, хранение IP.
- Роутер на сайте и клиентская навигация: две страницы и 404.

## Decisions

### D1. Стек сайта: Vite + React + TS + Tailwind 4, пререндер через Vite SSR
Те же версии, что в `web/package.json` (React 19.3.1, Vite 8.3.5, Tailwind 4.3.3, TS 6.0.3, ESLint, Prettier), точные пины, свой `package-lock.json`. Сборка: `vite build` (клиент) → `vite build --ssr src/entry-server.tsx` → `scripts/prerender.mjs` рендерит каждую страницу `renderToString` в шаблон `index.html` с метками `<!--app-head-->`/`<!--app-html-->`, пишет `index.html`, `privacy/index.html`, `404.html`, `sitemap.xml`, `robots.txt`. На клиенте `hydrateRoot` нужен только ради формы заявки; остальное — статический HTML.
Таблица страниц (`src/site.ts`: путь, файл, title, description, индексировать ли; компонент страницы — в `src/App.tsx`) — единый источник для пререндера и `sitemap.xml`.
*Альтернативы:* Astro (меньше JS, но второй стек рядом с `web/`), чистый HTML (не переиспользуем токены через Tailwind, вёрстка формы вручную). React + Vite выбран как уже известный проекту стек.

### D2. Дизайн-система без копирования: импорт из `web/` и зависимость от `web/node_modules`
`site/src/styles.css` делает `@import "../../web/src/design-system/tokens.css"` (вместе с ним приходят `fonts.css` и `typography.css`) и задаёт `@source` только на `site/src`. Пути шрифтов и `@import "tailwindcss"` внутри `tokens.css` разрешаются из `web/node_modules`, поэтому **сборка сайта требует установленных зависимостей `web/`**: `site/vite.config.ts` проверяет наличие `web/node_modules` и падает с командой `npm ci --prefix web`. Версии Tailwind в обоих `package.json` совпадают (одна и та же строка пина), это проверяется в `validate.sh` (сравнение версии из обоих файлов). Компоненты shadcn из `web/src/components/ui` сайт не берёт: кнопки и поля сайта — свои небольшие компоненты на тех же токенах.
Тема фиксирована: `<html lang="ru" data-theme="light">` («Утро»), переключателя тем нет.
*Альтернативы:* копия токенов (расходится), npm workspaces (меняет установку `web/` и CI), вынос дизайн-системы в пакет (большая перестройка). Выбрана самая узкая связь с явной ошибкой при её нарушении.

### D3. Настройки сборки — из корневого `.env`, без умолчаний
`site/vite.config.ts` читает `.env` корня (`loadEnv(mode, REPO_ROOT, "")`) и берёт только `SITE_ORIGIN`, `SITE_APP_URL` (обе обязательны, абсолютный `http(s)`), а для `dev` ещё `AGENTOS_URL` (прокси `/os/`). Значения попадают в код через `define` под своими именами; остальные переменные в сборку не идут. В `example.env` — `SITE_ORIGIN=http://localhost:5174`, `SITE_APP_URL=http://localhost:5173`. В CI `validate.yml` задаёт `SITE_ORIGIN=https://site.invalid` и `SITE_APP_URL=https://app.invalid` (нейтральные адреса, только чтобы сборка прошла).
Порт сайта — `5174` (`strictPort`, `127.0.0.1`), у `web` — `5173`.

### D4. Форма: отправка на свой адрес `/os/api/v1/beta-requests`
Сайт отправляет заявку на свой же origin, чтобы не открывать CORS у API. Локально это прокси Vite `/os/` → `AGENTOS_URL`, как у `web`. На будущем домене то же сделает Caddy сайта (`handle_path /os/api/v1/beta-requests` → API) — это часть интента переезда, здесь только записываем как требование к нему.
Проверки в браузере (обязательные поля, вид почты, согласие) — удобство; решает сервер (D5).
*Альтернатива:* CORS для домена сайта в AgentOS (`cors_allowed_origins`) — затрагивает настройку всего API ради одного маршрута.

### D5. Маршрут заявки и хранение
- Новый `agno/app/api/beta.py` (`POST /api/v1/beta-requests`), подключается в `attach_api`. Тело читается новой функцией `body.read_small_object(request, limit)`: отказ `413` по `Content-Length` и по фактически прочитанным байтам (`request.stream()` с подсчётом), потом JSON-объект как в `read_object`.
- Проверка полей — в маршруте (как в остальных маршрутах: ошибки FastAPI идут через обработчик Agno), ответ `202 {"status": "accepted"}`. При реализации вид почты и длина имени проверяются в ядре (`core/beta_requests.py`, отказ `Invalid` с полем → `422`), маршрут проверяет состав и типы полей: так ядро не примет плохие данные ни с какого входа.
- `agno/core/beta_requests.py`: `submit(connection, email, name, role, consent_at) -> Outcome` и `list_requests(connection)`. `submit` в одной транзакции: `pg_advisory_xact_lock` на константу заявок → `count(*)` за последние 60 с → при 20 и больше исключение `TooManyRequests(retry_after)` → `INSERT … ON CONFLICT (email) DO NOTHING`. Блокировка делает подсчёт и вставку атомарными без памяти процесса (подходит и для нескольких реплик).
- Почта нормализуется (`strip().lower()`), проверка вида — простая (одна `@`, точка в домене, без пробелов): писем по заявке не шлём, точнее проверять незачем.
- Ловушка `website`: непустая — ответ `202`, в базу ничего, в лог — только «ловушка сработала» без данных.
- Логи: обработчик пишет идентификатор новой заявки или «повтор», без почты и имени.
- Миграция `0011_beta_requests`: таблица по спеке, `CHECK (role IN (...))`, `UNIQUE (email)`, `CHECK (email = lower(email))`, индекс по `created_at` для окна частоты.
*Альтернативы:* ограничение по IP (ПДн и прокси Caddy скрывает адрес без доп. настройки), лимит в памяти (ломается при рестарте и репликах), Redis (нет в стеке на одну реплику).

### D6. Маршрут без токена — в модуле `auth`
`build_authorization` передаёт `excluded_route_paths=[*_AGNO_DEFAULT_EXCLUDED, "/api/v1/beta-requests"]`, где `_AGNO_DEFAULT_EXCLUDED` — явный список по умолчанию Agno 3.1.10 (копия, с комментарием и тестом, что он совпадает с `JWTMiddleware._get_default_excluded_routes()` пина: при обновлении Agno расхождение упадёт тестом, а не тихо откроет или закроет маршруты). Шаблонов с `*` нет. Метод не учитывается: `GET` по тому же пути получит `405` от FastAPI, данных там нет. `scripts/check_auth_boundary.sh` не меняется: JWT по-прежнему читает только `agno/app/auth/`.

### D7. Команда `admin beta-requests`
Подкоманда в `agno/admin/__main__.py`, печать таблицей как `report`: время UTC, почта, имя, кто (по-русски), «уже пользователь» (`users` с этой почтой и `deleted_at IS NULL`). `scripts/usage.sh` проверяет подкоманды по жёсткому списку (`report`, `set-plan`) — добавить `beta-requests` без аргументов и обновить строку `usage`.

### D8. Содержание и скриншоты
Тексты пишутся по скиллам `landing-page-design`, `copywriting`, `unslop` (копируются в `.agents/skills/` с лицензиями и авторством; при реализации заметки «В проекте ГлавAI» со ссылками на файлы glavai заменены заметками про этот проект). Факты — только из `tmp/glavai-case/README.md` и кода. Скриншоты из `tmp/glavai-case/shots/` (1440×900, тема «Утро») переводятся в WebP (ширины 720 и 1440) и кладутся в `site/public/shots/`; `og:image` — кадр рабочего места 1200×630.

### D9. Проверки
`validate.sh`: блок `site/` по образцу `web/` — нет `site/node_modules` → ошибка с `npm ci --prefix site`; `format:check`, `lint`, `typecheck`, `build`; сравнение пина Tailwind (D2). `check_web_tokens.sh` получает второй каталог `site/src` (тот же шаблон сырых цветов). `format.sh` форматирует и `site/`. CI: `npm ci --prefix site` и env из D3. Тесты ядра (`agno/tests/test_beta_requests.py`): нормализация и дубль, окно частоты (20 → 21-я `429`), ловушка, отказы полей и `413`, маршрут без токена отвечает, `GET /api/v1/me` без токена — `401`, совпадение списка исключений с Agno, колонки таблицы, `admin beta-requests`.

## Risks / Trade-offs

- [Публичный маршрут на сервере в Финляндии с первым релизом] → почта и имя заявителей — новые ПДн вне РФ, пока сервер не перенесён. Сайт до домена не выкладывается, ссылок на маршрут нет; владелец до выкладки сайта расширяет принятый риск в `05-security-and-compliance.md` (это правка контекста, не кода).
- [Спам с разными почтами забивает таблицу] → окно 20 заявок/мин ограничивает рост до ~29 тыс. в сутки в худшем случае; ловушка отсекает простых ботов. Если станет проблемой — капча отдельным решением.
- [Глобальный лимит наказывает людей при атаке] → при атаке живой человек получит `429` с понятным текстом и временем ожидания; на бете трафик мал.
- [Связка `site/` → `web/node_modules`] → явная ошибка сборки и проверка совпадения пина Tailwind; правка токенов меняет оба модуля, сборка обоих в `validate.sh` это ловит.
- [Копия списка исключений Agno] → тест на совпадение с пином.
- [Ответ `202` на повтор скрывает от человека, что заявка уже была] → это осознанно: иначе маршрут раскрывает, кто подавал заявку.

## Migration Plan

- Миграция `0011_beta_requests` — вперёд, применяется шагом `agentos-migrate`; откат не нужен (новая пустая таблица).
- Выкладка API с маршрутом — обычным релизом; сайт не выкладывается.
- Локально: `npm ci --prefix site`, добавить `SITE_*` в `.env`, `npm run dev --prefix site`.
