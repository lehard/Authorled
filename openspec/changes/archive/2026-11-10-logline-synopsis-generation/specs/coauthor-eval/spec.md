## MODIFIED Requirements

### Requirement: Наборы замера
У замера MUST быть два набора. `wide` — выборка id из рабочей части широкого набора экзамена маршрутизации (`agno/evals/routing/cases/wide-work.toml`); id из отложенной части экзамена MUST NOT в неё входить. `demo` — свои случаи по демо-историям в рабочей и отложенной частях без общих id, в части проверок наставника `checks` и в части задач документов `docs`; у частей `checks` и `docs` тоже нет общих id ни с другими частями, ни между собой. В `wide` и в частях `work` и `holdout` набора `demo` MUST быть случаи всех 12 доменов широкого состава и всех разделов; к частям `checks` и `docs` это правило не относится.

#### Scenario: Неизвестный id
- GIVEN в файле выборки есть id, которого нет в `wide-work.toml`
- WHEN запускается замер
- THEN замер MUST завершиться ошибкой, называющей id, до первого вызова модели

#### Scenario: Домен без случаев
- GIVEN в выборке нет ни одного случая, ожидающего домен `wide-help`
- WHEN запускается замер
- THEN замер MUST завершиться ошибкой, называющей домен, до первого вызова модели

#### Scenario: Отложенная часть без домена
- GIVEN в отложенной части `demo` нет ни одного случая домена `wide-research`
- WHEN запускается замер набора `demo` (любой части)
- THEN замер MUST завершиться ошибкой, называющей часть и домен, до первого вызова модели

#### Scenario: Часть проверок без всех доменов
- GIVEN в части `checks` все случаи ожидают только домен `wide-review`
- WHEN запускается замер `--set demo --part checks`
- THEN замер MUST идти без ошибки покрытия

#### Scenario: Часть задач документов без всех доменов
- GIVEN в части `docs` все случаи ожидают только домен `wide-structure`
- WHEN запускается замер `--set demo --part docs`
- THEN замер MUST идти без ошибки покрытия

### Requirement: Прогон замера
Команда `python -m evals.coauthor` MUST загружать `.env`, обращаться к моделям только через LiteLLM-прокси и требовать явного выбора набора (`--set wide|demo`, для `demo` — часть `--part work|holdout|checks|docs`) и объёма: все случаи (`--all`) или первые N (`--sample N`). Замер тратит вызовы модели и MUST NOT запускаться из `validate.sh` или CI.

#### Scenario: Без цены модели
- GIVEN у `claude-sonnet` или `deepseek-fast` нет цены в `model_prices.toml`
- WHEN запускается замер
- THEN команда MUST завершиться ошибкой, называющей псевдоним, до первого вызова модели

### Requirement: Повторная оценка судьёй
Команда `python -m evals.coauthor rejudge <отчёт> --domain <домен>` MUST заново оценивать судьёй случаи отчёта, ожидающие этот домен, по сохранённым ответам и вызовам, без запусков соавтора. Ожидание случая MUST читаться из отчёта целиком, вместе с открытой сценой, открытым документом и задачей, чтобы судья получил те же строки ожидания, что в исходном прогоне; отчёт без этих полей MUST вызывать ошибку, называющую поле. Остальные случаи MUST переноситься без изменений. Результат MUST сохраняться новым отчётом с пометкой, из какого отчёта и по какому домену он сделан; исходный отчёт MUST NOT меняться.

#### Scenario: Неизвестный домен
- GIVEN домен `wide-poetry`, которого нет в широком составе
- WHEN запускается `rejudge`
- THEN команда MUST завершиться ошибкой, называющей домен, до первого вызова модели

#### Scenario: Только случаи домена
- GIVEN отчёт рабочей части `demo` и домен `wide-help`
- WHEN `rejudge` заканчивается
- THEN в новом отчёте у случаев `wide-help` MUST быть новые оценки судьи, а у остальных — прежние

#### Scenario: Задача документа при повторной оценке
- GIVEN отчёт части `docs` со случаем `task = "synopsis-viewer"`
- WHEN `rejudge` по домену `wide-structure` собирает критерии судьи
- THEN среди строк ожидания MUST быть строка задачи «Для зрителя: без финала»

#### Scenario: Отчёт без поля ожидания
- GIVEN в отчёте у ожидания случая нет поля `task`
- WHEN запускается `rejudge`
- THEN команда MUST завершиться ошибкой, называющей поле, до первого вызова модели

## ADDED Requirements

### Requirement: Случай с открытым документом
Случай набора `demo` MAY открывать документ «Логлайн» или «Синопсис» драфта своей истории (`open = { doc = "logline" }` или `{ doc = "synopsis" }`). У случая MUST быть открыта либо сцена, либо документ, не оба. Контекст чата такого случая MUST быть тем, что прикладывает чат при открытом документе: его название и текст из драфта, который открывает история случая.

#### Scenario: Контекст логлайна
- GIVEN случай `open = { doc = "logline" }` в «Тихой воде»
- WHEN соавтор получает сообщение случая
- THEN контекст MUST содержать «Открыт документ: Логлайн.» и текст логлайна первого драфта «Тихой воды»

#### Scenario: Неизвестный документ
- GIVEN случай `open = { doc = "treatment" }`
- WHEN запускается замер
- THEN замер MUST завершиться ошибкой, называющей случай и документ, до первого вызова модели

### Requirement: Задача документа в случае
Случай части `docs` MUST называть задачу кнопки «Соавтор» (`task`), и открытый документ случая MUST быть документом этой задачи. Сообщение случая MUST совпадать с текстом просьбы задачи, а у «Под заявку» — начинаться с него.

#### Scenario: Задача без совпадения текста
- GIVEN случай с `task = "logline-variants"`, а его сообщение отличается от текста этой задачи
- WHEN запускается замер
- THEN замер MUST завершиться ошибкой, называющей случай и задачу, до первого вызова модели

#### Scenario: Требования заявки в сообщении
- GIVEN случай с `task = "synopsis-application"` и сообщением «Напиши синопсис под заявку. Требования: до 800 знаков»
- WHEN запускается замер
- THEN случай MUST загрузиться без ошибки

### Requirement: Ожидание задачи документа для судьи
Судья MUST получать строку ожидания задачи случая: три варианта логлайна с героем, целью и препятствием; синопсис на страницу с финалом; краткий абзац; для зрителя — без финала и главного поворота; под заявку — по требованиям, без них — вопрос; проверка — что не так и вопрос автору. Каждая строка MUST говорить, что сюжет берётся только из истории, а записывается только с согласия автора.

#### Scenario: Строка ожидания для зрителя
- GIVEN случай с `task = "synopsis-viewer"` в «Тихой воде»
- WHEN собираются критерии судьи
- THEN среди строк ожидания MUST быть строка, что хороший ответ не раскрывает финал и главный поворот и не записывает ничего без согласия автора
