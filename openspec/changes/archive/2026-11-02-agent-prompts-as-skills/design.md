# Design

## Context

Мотивация — `proposal.md`, «Why». Требования — дельты спек `api/agents`, `architecture`, `runtime`.

Что сейчас:
- `agno/agents/coauthor.py` создаёт агента при импорте модуля, промпт — константа `INSTRUCTIONS`.
- Корень репозитория — константа `REPO_ROOT` в `agno/app/paths.py`.
- Образ API копирует весь контекст сборки (`COPY . /app`), `.dockerignore` не исключает `agno/`.
- В разработке `uvicorn --reload` следит только за `agno/agents`, `agno/app`, `agno/db`, `agno/evals` и только за `*.py`.

Поведение `agno.skills.LocalSkills` в Agno 3.1.10 (`agno/skills/loaders/local.py`), от которого зависит подход:
- путь не существует — `FileNotFoundError`;
- в папке есть `SKILL.md` — проверка по стандарту: `name` и `description` обязательны, имя папки должно совпадать с `name`, лишние поля заголовка запрещены; ошибка проверки — `SkillValidationError` со списком причин;
- в папке нет `SKILL.md` — папка считается каталогом навыков: загружаются вложенные папки, а при их отсутствии возвращается **пустой список без ошибки**;
- ошибка чтения или разбора файла после проверки **глотается**: предупреждение в лог и навык пропускается.

## Goals / Non-Goals

**Goals:**
- Один способ получить промпт агента из `agno/skills/<agent_id>/SKILL.md`, переиспользуемый следующими агентами.
- Любая проблема с файлом навыка ломает старт API с понятной причиной.

**Non-Goals:**
- Подключение навыков к агенту через `Agent(skills=...)` (каталог навыков и загрузка по запросу модели).
- Горячая перезагрузка промпта без перезапуска API.

## Decisions

### 1. Промпт — тело `SKILL.md`, переданное в `instructions`
Тело навыка передаётся в `Agent(instructions=...)`, так что системное сообщение остаётся таким же, как сейчас.

Отвергнуто: `Agent(skills=Skills(loaders=[LocalSkills(...)]))`. Тогда в системное сообщение попадает только каталог (имя и описание), а инструкцию модель должна загрузить сама инструментом `get_skill_instructions`. Это лишний вызов на каждом ходу, модель может ответить без инструкции, и у соавтора появились бы инструменты, что запрещает спека «Соавтор».

### 2. Чтение — встроенный `LocalSkills`, своя только проверка результата
Небольшая общая функция в `agno/agents/` (например, `agent_prompt(agent_id) -> str`):
- строит путь `REPO_ROOT / "agno" / "skills" / agent_id`;
- вызывает `LocalSkills(path, validate=True).load()`;
- требует ровно один навык с `name == agent_id` и непустым телом, иначе поднимает ошибку с путём и причиной;
- возвращает тело.

Почему так: Agno сам разбирает заголовок и проверяет стандарт, своего парсера YAML нет (анти-паттерн 27). Проверка «ровно один навык с этим именем» закрывает два тихих случая `LocalSkills`: пустой список при отсутствии `SKILL.md` и навык, пропущенный из-за ошибки чтения. Это не обход фреймворка, а отказ принимать пустой результат (анти-паттерн 26).

Отвергнуто: читать `SKILL.md` своим кодом (`yaml` + regex). Это дублирует Agno и расходится со стандартом при обновлении пина. Отвергнуто и `Skill`-объекты без проверки (`validate=False`): неверный заголовок прошёл бы молча.

### 3. Загрузка при импорте модуля агента
Промпт читается там же, где сейчас создаётся агент, — при импорте `agents/coauthor.py`. Ошибка навыка всплывает при импорте `app.main`, то есть API не стартует, а evals и `mcp_check` падают с той же причиной.

Отвергнуто: ленивое чтение на первом запросе — ошибка конфигурации проявилась бы у автора в чате, а не при старте.

### 4. Расположение `agno/skills/`
Навыки агентов лежат рядом с кодом бэкенда: они часть релиза API и попадают в образ без изменений `Dockerfile`. Не в `.agents/skills/`: там навыки агентов-разработчиков (Claude Code, Codex), а не промпты продуктовых агентов. Папка без `__init__.py` и не конфликтует с пакетом `agno.skills` из виртуального окружения: `agno/` в `PYTHONPATH` — это каталог с `app`, `agents`, `db`, а не пакет `agno`.

### 5. Текст переносится без изменений
Тело `SKILL.md` — тот же текст, что `INSTRUCTIONS`. Поведение соавтора проверяется smoke-евалами до и после; изменение формулировок — отдельной задачей.

## Risks / Trade-offs

- [Правка `SKILL.md` в разработке не перезапускает API: `--reload` следит только за `*.py` в четырёх папках] → после правки промпта перезапускать `agentos-api`; написать об этом в `create-agent` и `AGENTS.md`. Расширение `--reload` меняет спеку «Контейнеры разработки» и вне scope.
- [`description` в `SKILL.md` и в манифесте `config.yaml` расходятся] → открытый вопрос интента; в этом change манифест не трогаем.
- [Будущий пин Agno изменит правила проверки навыков] → проверка выполняется при старте, расхождение проявится сразу ошибкой старта.
- [Отдельная ошибка чтения `SKILL.md` попадает в лог предупреждением Agno, а наша ошибка говорит только «навык не загружен»] → в тексте нашей ошибки указать путь к файлу и предложить смотреть предупреждение Agno в логе.

## Migration Plan

1. Создать `agno/skills/coauthor/SKILL.md` с текстом из `INSTRUCTIONS`, переключить `coauthor.py` на загрузку.
2. Деплой — обычная пересборка образа, данные и миграции не затрагиваются.
3. Откат — вернуть предыдущий коммит; сохранённых состояний нет.
