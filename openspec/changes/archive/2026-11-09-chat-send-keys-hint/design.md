# Design

## Context

Поле чата — `GrowingTextarea` в `web/src/screens/project/chat/CoauthorChat.tsx`; Enter отправляет, Shift+Enter переводит строку (`onKeyDown`). Высоту пустого поля задаёт текст placeholder (копия в сетке), поэтому длинный placeholder делает пустое поле выше одной строки. Ширина поля при окне 1100 px (колонка чата 320 px) — 208 px; шрифт Golos 16 px. Замеры холстом: «⇧↵: новая строка» ≈ 150 px, «Shift+Enter: новая строка» 200 px, «Shift+Enter — новая строка» 211 px (не помещается).

Кнопки редактора уже показывают подсказку с клавишами через `Tooltip` из `web/src/components/ui/tooltip.tsx` (`Tool` в `ScreenplayEditor.tsx`: название и клавиша приглушённым цветом). Реактивная проверка media query есть в `web/src/screens/shared/useMediaQuery.ts`.

## Goals / Non-Goals

**Goals:**
- Одна общая точка, которая решает «macOS или нет» и «есть ли мышь», для чата и будущих подсказок.

**Non-Goals:**
- Перевод подсказок редактора (⌘Z, ⌘F) на эту точку — отдельная задача.

## Decisions

### 1. macOS — по `navigator.platform`

Новый модуль `web/src/screens/shared/keys.ts`: `isMac = navigator.platform.startsWith("Mac")`, вычисляется один раз при загрузке модуля, и подписи клавиш `newLineKey` (`⇧↵` / `Shift+Enter`) и `sendKey` (`↵` / `Enter`).

Почему так: `navigator.platform` устарел, но есть во всех браузерах и в Safari; `navigator.userAgentData` в Safari нет, и выбор между ними был бы запасным путём. iPad тоже даёт `MacIntel`, но на нём подсказок нет по правилу сенсорного ввода (решение 2).

Отвергнуто: разбор `navigator.userAgent` — тот же результат сложнее.

### 2. Есть ли мышь — media query `(any-pointer: fine)`

Подсказки клавиш показываются, только когда `useMediaQuery("(any-pointer: fine)")` истинно. Телефон и планшет без мыши его не проходят; ноутбук с сенсорным экраном проходит (у него есть тачпад).

Отвергнуто: `(hover: hover)` — смотрит только на основной указатель; `ontouchstart` — ноутбуки с сенсорным экраном теряли бы подсказку.

### 3. Текст поля и подсказка кнопки

- placeholder поля: `${newLineKey}: новая строка` при мыши, иначе «Напишите соавтору». `aria-label` поля не меняется («Сообщение соавтору»).
- Кнопка «Отправить» оборачивается в `Tooltip` с текстом «Отправить» и клавишей `sendKey` приглушённым цветом, как в `Tool` редактора; без мыши — без `Tooltip`. Для неактивной кнопки подсказка тоже показывается: обёртка-триггер вокруг кнопки, потому что неактивная кнопка не получает событий указателя.
- Вид подсказки поля: `placeholderClassName="placeholder:text-xs placeholder:leading-6 placeholder:text-muted-foreground/45"` (12 px, 45% приглушённого цвета). `leading-6` держит строку 24 px, и подсказка стоит по центру поля. Высоту пустого поля задаёт невидимая копия текста шрифтом поля (16 px), поэтому поле остаётся в одну строку. `GrowingTextarea` не меняется: свойство `placeholderClassName` в нём уже есть. Почему так: при 16 px подсказка «бросалась в глаза»; владелец посмотрел наброски 13 px/60% и 12 px/45% и выбрал второй (2026-11-09).

## Risks / Trade-offs

- [Запас по ширине на Windows 8 px] → Если поле станет уже (другие отступы, шрифт системы не загрузился), подсказка уйдёт на вторую строку. Задача проверки меряет высоту пустого поля при окне 1100 px в эмуляции Windows.
- [Автор не узнает, что Enter отправляет, если не наведёт на кнопку] → Решение владельца: отправка по Enter ожидаема в чатах; поле говорит о менее очевидной клавише.
- [Эмуляция платформы в Chrome не меняет `navigator.platform`] → Проверка Windows — подменой `navigator.platform` в тестовой странице или на настоящем Windows; способ записывается в `tmp/VERIFY.md`.
