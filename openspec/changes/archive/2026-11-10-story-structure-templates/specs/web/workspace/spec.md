# Spec Delta

## MODIFIED Requirements

### Requirement: Полка историй
Полка MUST показывать истории обложками с названием и действия: создать, переименовать, удалить в корзину. У истории MUST быть одна карточка; при нескольких драфтах на ней MUST быть их число, драфты отдельными карточками MUST NOT показываться. Создание MUST спрашивать название и MAY принимать файл рукописи (Fountain, FDX, STARC, DOCX, TXT): с файлом история создаётся из него импортом ядра. Без файла создание MAY принимать каркас истории (требование «Выбор каркаса»). Пустое название MUST давать ошибку у поля; отказ импорта MUST показываться с причиной, и история MUST NOT создаваться. Новая история MUST быть полнометражным сценарием и MUST открываться сразу на тексте сценария. На полке MUST NOT быть приветствия, поиска, режима фокуса и статуса сохранения.

#### Scenario: Новая история
- GIVEN открыта полка
- WHEN пользователь создаёт историю «Маяк»
- THEN MUST открыться текст «Драфт 1» новой истории с одним пустым заголовком сцены

#### Scenario: Три драфта на полке
- GIVEN в истории «Тихая вода» три драфта
- WHEN открыта полка
- THEN у истории MUST быть одна карточка с подписью «3 драфта»

#### Scenario: Пустое название
- GIVEN открыт диалог новой истории
- WHEN пользователь нажимает «Создать» с пустым названием
- THEN MUST показываться ошибка у поля, и история MUST NOT создаваться

#### Scenario: История из файла
- GIVEN источник `api` и открыт диалог новой истории
- WHEN пользователь вводит «Паром», выбирает `паром.fountain` и нажимает «Создать»
- THEN MUST открыться текст новой истории со сценами из файла, а в навигаторе MUST быть персонажи из реплик

#### Scenario: Битый файл при создании
- GIVEN источник `api` и открыт диалог новой истории
- WHEN пользователь создаёт историю из битого `.fdx`
- THEN под полем файла MUST показываться причина, диалог MUST остаться открытым, и история MUST NOT появиться на полке

### Requirement: Источник данных
Экраны MUST получать и менять данные только через провайдер данных приложения. `VITE_DATA_SOURCE` MUST быть `api` или `fixtures`. Источник `api` MUST работать с маршрутами ядра `/api/v1` (спеки `api/stories`, `api/review`, `api/files`, `api/story-import`) по адресу `/os/` фронтенда с токеном пользователя. Источник `fixtures` — данные примера макета v2 («Тихая вода», «Последний паром»), которые живут в памяти страницы и сбрасываются при перезагрузке; в этом режиме приложение MUST показывать метку «Данные примера» в меню пользователя, а импорт, файлы в чат и каркасы историй MUST отвечать, что недоступны с данными примера.

#### Scenario: Неизвестный источник
- GIVEN `VITE_DATA_SOURCE=cloud`
- WHEN приложение открыто
- THEN MUST показываться ошибка, что источник `cloud` не поддерживается, с перечнем допустимых значений

#### Scenario: Данные примера
- GIVEN `VITE_DATA_SOURCE=fixtures` и пользователь вошёл
- WHEN открыт корневой адрес
- THEN полка MUST показывать «Тихая вода» и «Последний паром»

#### Scenario: Данные ядра переживают перезагрузку
- GIVEN `VITE_DATA_SOURCE=api` и автор создал историю «Маяк» с персонажем «Вера»
- WHEN он перезагружает страницу
- THEN «Маяк» MUST быть на полке, а «Вера» — в навигаторе истории

#### Scenario: Ошибка ядра
- GIVEN `VITE_DATA_SOURCE=api` и API не отвечает
- WHEN открыта полка
- THEN MUST показываться причина и «Повторить», а не данные примера и не пустая полка

#### Scenario: Каркасы с данными примера
- GIVEN `VITE_DATA_SOURCE=fixtures` и открыт диалог новой истории
- WHEN пользователь смотрит на выбор каркаса
- THEN выбор MUST быть недоступен с пометкой, что каркасы недоступны с данными примера, а создание истории без каркаса MUST работать

## ADDED Requirements

### Requirement: Выбор каркаса
Диалог новой истории MUST предлагать «Без каркаса» (выбран по умолчанию) и каркасы ядра по названию с описанием выбранного. С выбранным файлом рукописи выбор каркаса MUST быть недоступен. История с каркасом MUST открываться на тексте сценария с актами, группами и сценами каркаса. Если список каркасов не загрузился, диалог MUST показывать причину у выбора и MUST позволять создать историю без каркаса.

#### Scenario: История по трём актам
- GIVEN источник `api` и открыт диалог новой истории
- WHEN пользователь вводит «Маяк», выбирает «Три акта» и нажимает «Создать»
- THEN MUST открыться текст новой истории, а навигатор MUST показывать акты и группы каркаса «Три акта»

#### Scenario: Каркас и файл
- GIVEN открыт диалог новой истории и выбран каркас «Три акта»
- WHEN пользователь выбирает файл рукописи
- THEN выбор каркаса MUST стать недоступным, и история MUST создаваться из файла без каркаса

#### Scenario: Список не загрузился
- GIVEN источник `api` и `GET /api/v1/story-templates` ответил ошибкой
- WHEN открыт диалог новой истории
- THEN у выбора каркаса MUST показываться причина, а «Создать» без каркаса MUST создавать историю
