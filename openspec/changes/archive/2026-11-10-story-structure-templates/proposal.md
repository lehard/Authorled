# Proposal: каркасы структуры при создании истории

Источник решений: `business-intents/story-structure-templates.md` (владелец, 2026-11-09): делаем шаблоны структуры, шаблоны формата откладываем; соавтор раскладывает готовую историю по каркасу в заметку.

Решения, принятые при создании change (агент, 2026-11-09; владелец может поправить через `/opsx:update`):
- «Пустая история» — не каркас ядра, а отсутствие каркаса: клиент не передаёт поле, и ядро создаёт историю, как сейчас (design, D3).
- Источник `fixtures` не строит каркасы: выбор каркаса в нём недоступен с той же пометкой, что импорт и файлы в чат. В интенте было «работает так же, как в `api`»; так пришлось бы держать второй экземпляр каркасов во фронтенде (design, D6).
- Подсказка точки — бит в пустой сцене каркаса; она видна на карточке сцены в поэпизоднике и по «Показать биты» (design, D4).

## Why

Шаблоны проекта есть у 14 из 19 разобранных продуктов (ST-07, `openspec/context/_raw/research/Конкуренты/Фичи.csv`), это базовый минимум. Сейчас новая история всегда начинается с одного пустого заголовка сцены. Каркас из актов и ключевых точек помогает начать с пустого листа, а иерархия «акт → группа → сцена → бит» в тексте сценария для него уже есть.

## What Changes

- **Каркасы в ядре.** Четыре каркаса как данные ядра, файл рядом с кодом:
  - «Три акта»;
  - «Путешествие героя» (12 этапов);
  - «15 опорных точек»;
  - «Эпизод сериала».

  У каркаса есть `id`, название, описание и акты с точками. У каждой точки есть название и подсказка. Описания пишем сами, по-русски. Повреждённый файл не даёт API стартовать.
- **`GET /api/v1/story-templates`** — список каркасов с актами и точками для любого вошедшего пользователя.
- **`POST /api/v1/projects` принимает `template`.** Ядро строит текст сценария:
  - каждый акт — абзац `act`;
  - каждая точка — группа `sequence` с её названием, а в ней пустой заголовок сцены с новым `uid` и бит с подсказкой.

  Неизвестный `template` даёт `422`. Без `template` всё как сейчас. Создание из файла `template` не принимает: его multipart уже отказывает неизвестным полям.
- **Диалог «Новая история»** получает выбор каркаса: «Без каркаса» (по умолчанию) и каркасы из ядра с описанием. При выбранном файле рукописи выбор каркаса недоступен. В источнике `fixtures` выбор недоступен с пометкой «недоступно с данными примера».
- **Соавтор читает каркасы.** Новый читающий инструмент даёт список каркасов с точками из того же файла ядра. По просьбе «разложи по трём актам» соавтор создаёт заметку истории: какие сцены попадают в какую точку и каких точек не хватает. Текст сценария он не меняет. Промпт получает правило раскладки, а раздел «О сервисе «Соавтор»» — строку о выборе каркаса.
- **Замер действий соавтора** получает просьбы раскладки: ожидаемое действие — `create_story_note`.

### Modified Capabilities
- `api/stories`:
  - «Создание истории» принимает `template`;
  - новое требование «Каркасы историй» описывает данные каркасов, маршрут списка и текст из каркаса.
- `api/agents`:
  - «Инструменты соавтора» получают читающий инструмент каркасов;
  - новое требование «Раскладка по каркасу».
- `web/workspace`:
  - «Полка историй» получает выбор каркаса при создании;
  - «Источник данных» — каркасы в `fixtures` недоступны;
  - новое требование «Выбор каркаса».

Требования замера действий (`coauthor-actions-eval`) не меняются: просьбы раскладки — новые строки его набора, ожидаемый инструмент `create_story_note` уже есть.

## Scope

- `agno/core/`:
  - файл каркасов `story_templates.toml` и модуль `story_templates.py` (загрузка с проверкой, текст из каркаса);
  - `projects.create_project` принимает каркас;
  - тесты в `agno/tests/`.
- `agno/app/api/`: `stories.py` (поле `template`, маршрут списка) и регистрация маршрута; загрузка каркасов при старте в `agno/app/main.py`.
- `agno/agents/coauthor_tools.py` и `agno/skills/coauthor/SKILL.md`: инструмент, правило раскладки, строка в «О сервисе».
- `agno/evals/coauthor/actions.toml`: просьбы раскладки.
- `web/src/screens/shelf/` (`ShelfScreen.tsx`, `storyActions.ts`) и диалог создания; `web/src/data/` (`apiProvider.ts`, `fixturesProvider.ts`, модель каркаса).
- Мастер-спеки `api/stories`, `api/agents`, `web/workspace` через дельты.
- `business-intents/story-structure-templates.md`: статус и решение о `fixtures`; `openspec/context/_raw/research/Конкуренты/authorled.csv` и `Сводка.md`: статус ST-07.

## Non-goals

- Шаблоны формата: сериал, короткий метр, пьеса, радио, русский стандарт страницы. Формат истории остаётся `feature`, а «Эпизод сериала» — только каркас текста.
- Шаблоны по жанру и анкеты персонажей.
- Свои каркасы автора и правка каркасов в интерфейсе.
- Вставка каркаса в уже написанную историю: соавтор не вставляет абзацы, результат раскладки — заметка.
- Скрытие битов-подсказок при печати и экспорте: биты печатаются, как сейчас.
- Методология Д1–Д22 и выбор формата на Д12.

## Impact

- **API:** новый маршрут `GET /api/v1/story-templates` и новое необязательное поле в `POST /api/v1/projects`. Старые клиенты не ломаются.
- **Ядро:** новый файл данных, который проверяется при старте; таблиц и миграций нет: каркас живёт только в тексте созданной истории.
- **Соавтор:** на один читающий инструмент больше; раскладка тратит лимит, как любой ответ.
- **Фронтенд:** диалог создания истории получает выбор каркаса и один запрос списка.
- **Контент:** названия и подсказки точек — текст продукта; их правит владелец до выпуска.
