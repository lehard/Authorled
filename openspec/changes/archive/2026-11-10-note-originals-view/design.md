# Design: оригинал и текст материала в заметке

## Context

Мотивация — `proposal.md`, требования — дельты в `specs/`.

Что есть и на что опирается решение:
- `core/files.py`: `extract_text(format, data)` по расширению; `_text_of_pdf` склеивает страницы `page.extract_text()` через пустую строку, строки страницы не трогает. `files.text_content` хранит текст, извлечённый при загрузке; байты — в `file_contents`.
- `core/notes.py`: заметка ссылается на оригинал `notes.file_id`; `delete_notes` удаляет заметки, затем их файлы (ссылка `NO ACTION` не даёт удалить файл под заметкой). `update_note` — образец правки с ревизией: блокировка строки, `ensure_project_open`, корзина → `Conflict`, ревизия → `Conflict`.
- Место для оригиналов считается суммой `size_bytes` файлов `note` пользователя: удаление строки `files` освобождает место без отдельного учёта.
- `GET /api/v1/files/{id}/content` отдаёт байты с типом файла и `Content-Disposition: attachment`; фронтенд берёт их `apiBlob` с токеном (`files.content`), поэтому фрейм не может грузить адрес API напрямую.
- `NoteDoc.tsx`: `DocHead` с заголовком `h1`, `FieldCard` с полем «Название» и строкой `Original`, лист `.sheet.sheet-prose` с `GrowingTextarea` или режимом чтения длиннее 50 000 знаков; `useFindInDoc` выделяет найденное в поле ввода по `?find=`.
- В `web/package.json` есть `radix-ui` (в нём есть Tabs) и `react-markdown`; `dompurify` уже стоит в дереве зависимостей транзитивно. CSP у приложения нет (`deploy/Caddyfile`), фрейм с `blob:` не запрещён.

## Goals / Non-Goals

**Goals:**
- Автор видит то, что загрузил, без своего просмотрщика и без серверного рендера.
- Новые действия — обычные правки заметки с ревизией, тем же путём, что `PATCH`.
- Ни один байт файла не исполняется на нашем адресе.

**Non-Goals:**
- Кэш оригиналов в браузере между открытиями заметки.
- Переизвлечение `files.text_content` у старых файлов.

## Decisions

1. **Удаление оригинала — операция ядра `remove_note_file(connection, note_id, expected_revision, user_id)`.**
   Блокирует заметку, проверяет историю, корзину, ревизию и наличие `file_id` (нет → `Conflict`), ставит `file_id = NULL`, ревизию +1, `updated_by`, `updated_at`, затем удаляет строку `files` (содержимое уходит каскадом). Всё в одной транзакции маршрута. Маршрут `DELETE /api/v1/notes/{id}/file` читает `If-Match` как `PATCH` и ставит `ETag`.
   Альтернатива — разрешить `DELETE /api/v1/files/{id}` для оригинала: отвергнута, потому что тогда меняется заметка без её ревизии, и другие вкладки не видят изменения.

2. **Текст из оригинала — операция ядра `note_text_from_file(connection, note_id, expected_revision, user_id)`.**
   Те же проверки; формат берётся `file_format(name, "note", data)`, текст — `extract_text` из байтов `file_contents`, а не из `files.text_content`, чтобы старые заметки получили новые правила PDF (сценарий «Старая заметка получает новые правила»). Длина сверх 500 000 знаков → `Invalid`. Новый текст пишется в `body` через тот же путь, что `update_note`, чтобы правила ревизии были одни. `files.text_content` не меняется: он описывает файл как загружен и нужен только копированию файла беседы.
   Альтернатива — брать `files.text_content`: проще, но не чинит уже загруженные PDF, ради которых действие и нужно.

3. **Склейка строк PDF — чистая функция над текстом страницы в `core/files.py`.**
   Правило из спеки: дефис в конце строки + строчная буква в начале следующей → склеить без дефиса; следующая строка со строчной буквы или текущая кончается запятой → склеить через пробел; иначе перевод строки сохраняется. «Строчная» — `str.islower()` первого символа, так работает и кириллица. Правило консервативное: строки реквизитов, заголовки и таблицы, где следующая строка начинается с прописной или цифры, не склеиваются.
   Альтернатива — склеивать всё, что не кончается точкой: отвергнута, она сливает таблицы и реквизиты в одну строку (пример со счётом владельца).

4. **Показ оригинала целиком в браузере, по формату.**
   - PDF: байты из `files.content` → `Blob` с типом `application/pdf` → `URL.createObjectURL` → `<iframe>` на всю ширину листа и высоту окна; «Открыть в новой вкладке» — `window.open` того же адреса. Адрес отзывается при закрытии заметки. Просмотрщик браузера сам даёт страницы, масштаб и поиск. Альтернатива — pdf.js: сотни КБ кода и своя вёрстка ради того, что браузер уже умеет.
   - DOCX: `mammoth.convertToHtml` в браузере, модуль подгружается динамическим `import()` только для DOCX. Результат проходит `DOMPurify.sanitize` с запретом всех `src` и `href`, кроме `data:` у картинок и якорей; ссылки открываются с `rel="noopener noreferrer"`. Вставка в лист с классом прозы (`.sheet-prose` + стили заголовков, списков и таблиц из токенов). Альтернатива — `docx-preview` (вёрстка страницами Word): тяжелее и вносит чужие шрифты и цвета, а цель — прочитать материал.
   - MD: байты декодируются `TextDecoder("utf-8", { fatal: true })` и отдаются `react-markdown` без `rehype-raw`: сырой HTML не исполняется, внешние картинки не грузятся (компонент `img` заменяется подписью со ссылкой).
   - Ошибка получения или разбора показывается в вкладке с причиной и «Скачать»; запасного показа текста вместо оригинала нет.

5. **Вкладки — shadcn `tabs` через CLI на `radix-ui`.** Новых зависимостей нет. Выбранная вкладка — состояние компонента, «Оригинал» при каждом открытии; `?find=` выбирает «Текст для соавтора» в том же рендере, что и сейчас открывает поле правки, чтобы `useFindInDoc` нашёл поле.

6. **Заголовок-поле только у заметки.** `DocHead` получает необязательный режим правки названия (`input` со стилем `text-heading-1`); остальные документы его не включают. Пустое название не сохраняется; на `blur` пустое поле возвращает последнее сохранённое значение. `useServerChanges` продолжает подтягивать название, изменённое соавтором.

7. **Значки по виду файла.** Вид определяется по расширению `file.name` в одном месте (`noteFileKind`), значки lucide: PDF, DOCX, текст, сценарий — четыре разных, заметка без оригинала — прежний `StickyNote`. Навигатор и список заметок берут значок оттуда же.

8. **Данные фронтенда.** В `useNoteActions` две операции: `removeFile(id)` и `textFromFile(id)`, обе с текущей ревизией заметки, обновляют заметку в `ProjectContext` ответом сервера (конфликт ревизий — как у автосохранения). `fixturesProvider` отвечает на них отказом с причиной, как на загрузку файлов.

9. **Зависимости.** `mammoth` и `dompurify` — точные версии, вышедшие не позже чем за две недели до установки; `dompurify` — та же мажорная версия, что уже в дереве, чтобы не тянуть вторую копию.

## Risks / Trade-offs

- [PDF во фрейме на телефоне показывает только первую страницу или не показывается] → «Открыть в новой вкладке» и «Скачать» рядом; на телефоне сервис не основной.
- [Склейка строк ошибается на стихах и списках с продолжением со строчной буквы] → правило консервативное; автор правит текст на вкладке «Текст для соавтора».
- [Большой DOCX с картинками даёт тяжёлый HTML с `data:`] → предел файла 20 МБ; разбор идёт только при открытии вкладки «Оригинал».
- [HTML из DOCX — вход злоумышленника] → только очищенный HTML, без скриптов, обработчиков и внешних адресов; сценарий «Ссылка на картинку в DOCX» проверяется.
- [Заголовок-поле у заметки, но не у других документов, — разнобой] → осознанно (Non-goals); перенос на другие документы — отдельное решение.
- [«Вернуть текст» по новым правилам даёт текст, отличный от первоначального] → подтверждение говорит, что правки пропадут; так и задумано.

## Migration Plan

Миграций базы нет. Выкатывается обычным релизом из `main`; откат — предыдущий релиз: новые маршруты исчезают, данные заметок совместимы в обе стороны (у заметки после удаления оригинала просто `file_id` `NULL`).
