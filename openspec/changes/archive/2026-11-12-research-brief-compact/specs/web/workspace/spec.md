## MODIFIED Requirements

### Requirement: Чат с соавтором
Колонка чата окна истории MUST быть чатом с агентом `coauthor` через AG-UI: заголовок «Соавтор», строка «Видит: <открытый документ>», сообщения автора и ответы соавтора, поле ввода (Enter — отправить, Shift+Enter — новая строка). Ответ MUST появляться по мере генерации; Markdown в ответе MUST отображаться оформленным текстом; у ответа MUST быть «Скопировать», кроме ответа с блоком задания на исследование (копирование — в самом блоке); когда этот ряд виден — требование «Оценка ответа соавтора». Пустая беседа MUST показывать «О чём эта история?» и проверки наставника (требование «Проверки наставника»), которые отправляются по клику, и «Исследовать тему», которое кладёт в поле ввода начало просьбы о задании на исследование и не отправляет его. Если запуск не удался, текст автора MUST остаться в поле, а чат MUST показать сообщение для автора без технических подробностей (текста исключения, JSON, идентификаторов запроса, названий моделей, провайдеров и компонентов сервера):
- отказ продукта (причина `usage_limit_reached`, `subscription_ended`, `usage_check_failed` или `usage_record_failed` в данных `RUN_ERROR`) — сообщение бэкенда как есть, без «Соавтор не смог ответить»; отказ по лимиту — уведомлением, а не ошибкой;
- любой другой сбой запуска, в том числе сбой модели, — «Соавтор сейчас недоступен. Попробуйте позже.»;
- запрос не дошёл до сервера — «Нет связи с сервером. Проверьте интернет и попробуйте ещё раз.»
Полный текст сбоя MUST оставаться в консоли браузера.

#### Scenario: Вопрос и ответ
- GIVEN открыт текст сценария «Тихой воды»
- WHEN автор отправляет «О чём эта история?»
- THEN в чате MUST появиться его сообщение и ответ соавтора, который нарастает по мере генерации

#### Scenario: Пустая беседа
- GIVEN автор начал новую беседу
- WHEN чат показывает пустую беседу
- THEN в ней MUST быть «О чём эта история?», восемь проверок наставника и «Исследовать тему», и MUST NOT быть других подсказок

#### Scenario: Ошибка
- GIVEN API недоступен
- WHEN автор отправляет сообщение
- THEN в чате MUST появиться «Нет связи с сервером. Проверьте интернет и попробуйте ещё раз.» без причины сбоя в скобках, а текст автора MUST остаться в поле, чтобы отправить его снова

#### Scenario: Сбой модели
- GIVEN провайдер модели отклоняет запрос соавтора (например, на счёте провайдера нет денег), и `RUN_ERROR` содержит текст исключения LiteLLM
- WHEN автор отправляет сообщение
- THEN в чате MUST появиться «Соавтор сейчас недоступен. Попробуйте позже.» и MUST NOT быть текста исключения, JSON, идентификатора запроса и названий LiteLLM, DeepSeek и модели, а текст автора MUST остаться в поле

#### Scenario: Лимит исчерпан
- GIVEN лимит соавтора автора на этот период исчерпан и обновится 7 декабря
- WHEN автор пишет соавтору
- THEN в чате MUST появиться «Лимит соавтора на этот период исчерпан. Он обновится 7 декабря.» без «Соавтор не смог ответить», а текст автора MUST остаться в поле

#### Scenario: Отказ продукта
- GIVEN проверка лимита не удалась, и `RUN_ERROR` содержит причину `usage_check_failed` и сообщение «Не удалось проверить лимит соавтора. Напишите в поддержку.»
- WHEN автор пишет соавтору
- THEN в чате MUST появиться ошибка «Не удалось проверить лимит соавтора. Напишите в поддержку.» без «Соавтор не смог ответить», а текст автора MUST остаться в поле

#### Scenario: Неизвестная причина
- GIVEN `RUN_ERROR` содержит в данных причину, которой нет в списке отказов продукта
- WHEN автор пишет соавтору
- THEN в чате MUST появиться «Соавтор сейчас недоступен. Попробуйте позже.», а не сообщение из события

#### Scenario: Исследовать тему
- GIVEN автор начал новую беседу, поле ввода пусто
- WHEN он нажимает «Исследовать тему»
- THEN поле ввода MUST содержать начало просьбы о задании на исследование с курсором в конце
- AND сообщение MUST NOT отправиться, пока автор сам его не отправит

### Requirement: Оценка ответа соавтора
У законченного ответа соавтора MUST быть «Полезно» и «Не то» в одном ряду с «Скопировать». Под последним законченным ответом ряд MUST быть виден всегда; под остальными — при наведении на ответ или фокусе клавиатурой внутри него, на сенсорном экране — после нажатия на ответ; появление ряда MUST NOT сдвигать текст. Выбранная оценка MUST быть видна значком и без наведения. Клик MUST ставить оценку, клик по выбранной — снимать, клик по другой — менять. Выбранная оценка MUST быть видна и после перезагрузки страницы и при возврате к беседе. Пока ответ пишется, кнопок MUST NOT быть. Если сохранить оценку не удалось, кнопки MUST вернуться к прежнему состоянию, а чат MUST показать причину без технических подробностей.

#### Scenario: Оценка остаётся
- GIVEN соавтор закончил ответ
- WHEN автор нажимает «Не то» и перезагружает страницу
- THEN у этого ответа MUST быть выбрано «Не то»

#### Scenario: Снять оценку
- GIVEN у ответа выбрано «Полезно»
- WHEN автор нажимает «Полезно» ещё раз
- THEN ни одна оценка MUST NOT быть выбрана

#### Scenario: Сбой сохранения
- GIVEN API недоступен
- WHEN автор нажимает «Полезно»
- THEN выбор MUST вернуться к прежнему, а чат MUST показать «Нет связи с сервером. Проверьте интернет и попробуйте ещё раз.»

#### Scenario: Ряд по наведению
- GIVEN в беседе три законченных ответа соавтора без оценок
- WHEN автор смотрит на беседу, не наводя курсор
- THEN ряд «Скопировать / Полезно / Не то» MUST быть виден только под последним ответом
- AND при наведении на первый ответ ряд MUST появиться под ним

#### Scenario: Выбранная оценка видна
- GIVEN у первого из трёх ответов выбрано «Полезно»
- WHEN курсор не наведён на него
- THEN под ним MUST быть виден значок «Полезно»

### Requirement: Блок задания в чате
Блок кода с меткой `research-brief` в ответе соавтора чат MUST показывать одной карточкой: в шапке тема (первая строка блока без `#`) и значки «Скопировать» и «В заметки» с подписью и подсказкой; ниже превью из 3–4 строк мелким приглушённым моноширинным текстом; внизу «Развернуть» («Свернуть»). Под карточкой MUST быть одна строка «Вставьте промпт в Claude или ChatGPT и используйте Deep Research», где «Claude» и «ChatGPT» — ссылки на сайты сервисов (новая вкладка, без текста задания в адресе); других кнопок и подсказок у блока MUST NOT быть. Блоки кода без этой метки MUST показываться как обычно.

#### Scenario: Скопировать задание
- GIVEN соавтор написал блок задания
- WHEN автор нажимает «Скопировать» в его шапке
- THEN буфер обмена MUST содержать текст задания целиком, без ответа вокруг

#### Scenario: Развернуть
- GIVEN блок задания длиннее видимой части
- WHEN автор нажимает «Развернуть»
- THEN MUST быть виден весь текст задания, а кнопка MUST смениться на «Свернуть»

#### Scenario: Открыть сервис
- WHEN автор нажимает «ChatGPT» в строке под карточкой
- THEN в новой вкладке MUST открыться сайт ChatGPT, и адрес MUST NOT содержать текста задания

#### Scenario: После перезагрузки
- GIVEN в беседе есть блок задания
- WHEN автор перезагружает страницу и открывает беседу из истории или меняет ширину окна
- THEN блок MUST быть на месте с теми же кнопками

### Requirement: Задание в заметки
В шапке блока задания MUST быть значок «В заметки». Нажатие MUST создавать заметку истории «Исследование: <тема>» с текстом задания тем же маршрутом, что «Добавить заметку»; после сохранения значок MUST показывать, что задание сохранено, и вести к заметке. Без нажатия автора заметка MUST NOT появляться. Отказ (история в корзине) MUST показываться с причиной.

#### Scenario: Сохранить
- GIVEN соавтор написал задание о паромщиках
- WHEN автор нажимает «В заметки» в шапке блока
- THEN в «Заметках» MUST появиться «Исследование: …» с текстом задания, а значок MUST вести к ней

#### Scenario: Без нажатия
- GIVEN соавтор написал задание
- WHEN автор не нажимает «В заметки»
- THEN заметок в истории MUST NOT прибавиться
