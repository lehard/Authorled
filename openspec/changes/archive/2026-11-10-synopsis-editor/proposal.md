# Proposal

## Why

Синопсис сейчас — простое текстовое поле на листе (`ProseDoc.tsx`, `GrowingTextarea`), в базе — строка без разметки: автор не видит, сколько страниц написал, не может разбить расширенный синопсис заголовками, у него нет панели с отменой и нечего отдать продюсеру или в фонд. Сценаристы меряют синопсис страницами («синопсис на страницу», лимиты фондов), а у нас длины нет совсем. Решение владельца 2026-11-10 — вариант «Б» из сравнения с STARC, Final Draft, Google Docs, Scrivener, Highland и NolanAI (`business-intents/synopsis-editor.md`).

## What Changes

- Синопсис открывается в редакторе ProseMirror со своей небольшой схемой: абзац, «Заголовок 1», «Заголовок 2», жирный, курсив, перевод строки внутри абзаца. Лист остаётся сплошным, шрифт и поля листа прозы прежние.
- Над листом синопсиса — липкая панель в одну строку: «Отменить», «Повторить», стиль абзаца, «Жирный», «Курсив», счёт длины «≈ N стр.» (по клику — слова, знаки, страницы). Сочетания ⌘Z, ⇧⌘Z, ⌘B, ⌘I.
- На правом поле листа — метки «стр. 2», «стр. 3» там, где начнётся страница при печати; абзац меткой не разрывается.
- Страница считается по одной вёрстке для счёта, меток и печати: A4, шрифт Tinos (метрически совпадает с Times New Roman, приходит из сборки) 12 pt, одинарный интервал, поля 2,5 см.
- «Печать» в шапке синопсиса: листы A4 с названием истории и «Синопсис» сверху первой страницы и номерами страниц; доступна и в запертом драфте.
- Синопсис хранится Markdown в том же поле `synopsis` (`#`, `##`, `**…**`, `*…*`, абзацы через пустую строку); схема базы и форма API прежние. Ядро отказывает (`422`) синопсису с заголовками глубже второго уровня. **BREAKING** для внешних писателей поля: такой текст больше не принимается (пользователей нет, демо-синопсисы без `###`).
- Поиск по истории ищет и показывает синопсис без знаков разметки.
- Соавтор пишет синопсис драфта в Markdown: заголовки — только в расширенном синопсисе или по просьбе автора, без списков и таблиц; версии в заметках остаются простым текстом.
- Логлайн, заметки, «Титульная страница» и поэпизодник не меняются.

Scope: экран «Синопсис» (`web/src/screens/project/docs/ProseDoc.tsx` и новый модуль прозы в `web/src/editor/prose/`), печать синопсиса, поиск ядра по синопсису, проверка поля `synopsis` в ядре, промпт соавтора и демо-случай качества.

Non-goals: страницы A4 с разрывами прямо в редакторе (вариант «В»); логлайн, заметки, титульная страница, поэпизодник; комментарии и предложения правки внутри синопсиса; списки, таблицы, шрифты, заголовки глубже второго уровня; экспорт синопсиса в DOCX и общий Markdown истории; несколько версий синопсиса; «Найти и заменить» внутри синопсиса.

## Capabilities

### New Capabilities
- `web/prose-editor`: редактор прозы документа истории — схема и Markdown-хранение, панель, счёт длины и метки страниц по вёрстке печати, печать A4. Сейчас его использует только синопсис.

### Modified Capabilities
- `web/workspace`: «Документы истории» — синопсис открывается в редакторе прозы (ссылка на `web/prose-editor`).
- `web/design-system`: «Многострочные поля растут с текстом» — сценарий «Поле без предела» говорит о заметке: синопсис больше не многострочное поле.
- `api/stories`: новые требования «Разметка синопсиса» (`422` на заголовки глубже второго уровня) и «Синопсис в поиске без разметки».
- `api/agents`: новое требование «Разметка синопсиса у соавтора» — синопсис драфта в Markdown, версии в заметках простым текстом.

## Impact

- `web/src/editor/prose/` (новое): схема, разбор и запись Markdown, клавиши, вёрстка страниц, печать; `web/src/screens/project/docs/ProseDoc.tsx` (синопсис — новый редактор, логлайн — прежнее поле), `useFindInDoc.ts` (переход в поле ProseMirror).
- Зависимости `web/`: `prosemirror-markdown` 1.13.9 и `markdown-it` 14.1.0, `@fontsource/tinos` 5.3.0; `prosemirror-history`, `-keymap`, `-commands` уже есть.
- `agno/core/prose.py` (новое): простой текст синопсиса и проверка заголовков на `markdown-it-py` 4.2.0 (уже стоит транзитивно, объявляется явно той же версией); `agno/core/fields.py` (проверка `synopsis`), `agno/core/search.py`; общий файл случаев разметки `web/src/editor/prose/markdown.cases.json` для `check:editor` и pytest.
- `agno/skills/coauthor/SKILL.md`, демо-случай `agno/evals/coauthor/`.
- Маршруты и миграции не меняются.
