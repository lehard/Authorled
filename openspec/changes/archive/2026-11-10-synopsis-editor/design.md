# Design

## Context

- Синопсис — `ProseDoc` (`web/src/screens/project/docs/ProseDoc.tsx`): `GrowingTextarea` над строкой `script.synopsis`, автосохранение `useAutosave("scripts")`, `useServerChanges` (поле без ввода автора берёт новое значение, поле с вводом — держит ввод), `useFindInDoc` (ищет `[data-field]` как `textarea` и ставит выделение `setSelectionRange`), `SaveHistory` (снимок `fields`), `DocTasksButton`/`DocSheetTasks`. Логлайн — тот же компонент.
- Редактор сценария (`web/src/editor/`) — форк `@plotwell/editor` на ProseMirror 1.x: своя схема типов STARC, разметка страниц US Letter (`plugins/pagination.ts`, только целые абзацы), печать через своё окно с раскладкой по страницам (`exporters/print.ts`, шрифт Cousine из сборки, `PrintError`), панель в `ScreenplayEditor.tsx`.
- Ядро: `script.fields.synopsis` — `str | None` в `core/fields.py` (`ScriptFields`), поиск `core/search.py` идёт по строке как есть. Соавтор пишет поле через `update_story_document` и читает через `read_story_document`.
- Выделение для чата берёт `document.getSelection().toString()` внутри `[data-chat-source]` (`useSelectionIn.ts`) — работает и для `contenteditable`.
- Демо-синопсисы (`web/src/data/demo.json`) — простой текст без `* _ # \`, абзацы через переводы строк.
- `markdown-it-py` 4.2.0 уже стоит в `agno/requirements.txt` транзитивно.

## Goals / Non-Goals

**Goals:**
- Один источник страницы: счёт, метки и печать считаются одной функцией вёрстки, поэтому совпадают.
- Одна грамматика Markdown для браузера и ядра, проверяемая общими случаями.
- Синопсис сохраняет всё прежнее поведение документа (`web/prose-editor`, «Синопсис с прежним поведением документа»).

**Non-Goals:**
- Общий редактор для логлайна, заметок и поэпизодника; переделка редактора сценария под прозу.
- Точное совпадение с печатью Word или Google Docs: страница — наша вёрстка A4.

## Decisions

1. **Отдельный модуль `web/src/editor/prose/`, не схема сценария.** Своя схема (`doc`, `paragraph`, `heading` с `level` 1–2, `hard_break`, `text`; метки `strong`, `em`), свои клавиши (`baseKeymap`, `history`, ⌘B/⌘I, ⌘⌥1/⌘⌥2/⌘⌥0 для стилей), свой компонент `ProseEditor` и панель `ProseToolbar`. Из редактора сценария переиспользуются только пакеты ProseMirror, приёмы (`scrollMargin` под липкую панель, подсказки дизайн-системы) и `PrintError`. Альтернатива — добавить типы прозы в схему сценария: тянет uid сцен, US Letter, карточки и предложения, отклонено.

2. **Markdown через `prosemirror-markdown` 1.13.9 и `markdown-it` 14.1.0 (закрепить).** Парсер — `markdown-it` в пресете `zero` с включёнными только `paragraph`, `heading`, `emphasis`, `escape`, `newline` ; одиночный перевод строки (токен `softbreak`, опция `breaks` меняет только HTML) и `hardbreak` разбираются в `hard_break`, как в нынешних демо-текстах. Всё прочее (списки, цитаты, код, ссылки, HTML, сущности) грамматикой не распознаётся и остаётся текстом — это определение грамматики, а не запасной путь. Заголовок уровня 3–6 — исключение с причиной «заголовок третьего уровня не поддерживается», экран показывает ошибку (Constraint: без тихой подмены). Сериализатор свой поверх `MarkdownSerializer`: `hard_break` — `\n`; экранирует только то, что грамматика распознаёт: `\`, `*`, `_`, `#` в начале строки. Ведущие пробелы строк `markdown-it` убирает — нынешний простой текст их не содержит. Альтернатива — свой разборщик: дешевле по зависимостям, но вторая реализация CommonMark-эмфазиса без проверенной основы; отклонено.

3. **Ядро понимает ту же грамматику через `markdown-it-py` 4.2.0** (объявить в `agno/pyproject.toml` той же версией, что уже стоит, без обновления). Новый `core/prose.py`: `check_synopsis(text)` — заголовок `###`+ даёт `Invalid` с полем `fields.synopsis` (по токенам, так что `\###` проходит); `plain_text(text)` — текст без разметки: абзацы через `\n\n`, `hard_break` — `\n`. `fields.py` вызывает проверку валидатором `ScriptFields.synopsis`, поэтому маршрут и инструмент соавтора отказывают одинаково. `search.py` ищет и режет `snippet` синопсиса по `plain_text`. Альтернатива — регулярные выражения: расходятся с CommonMark на `5 * 2` и `мать_и_мачеха`, отклонено.

4. **Общие случаи `web/src/editor/prose/markdown.cases.json`**: Markdown, ожидаемый простой текст, слова, знаки, «отказ» для `###`, и для сериализуемых — Markdown после круга «разбор → запись». Их читают `npm run check:editor` (разбор, запись, счёт) и `agno/tests/test_prose.py` (проверка и простой текст), как `wordCount.cases.json`.

5. **Вёрстка страницы — `prose/layout.ts`, в основном окне, невидимым блоком.** Константы A4 (210 мм, поля 25 мм: ширина текста 160 мм, высота 247 мм), Tinos 12 pt, `line-height: 1.15`, отступ после абзаца 6 pt, заголовки 16/14 pt полужирные с отступом 12 pt до — один набор CSS, который вставляют и блок замера, и окно печати. Блок замера стоит вне экрана (`position: fixed; left: -10000px`), рисует блоки тем же HTML, что печать (`prose/html.ts`), и раскладывает строки: для каждого блока `Range.getClientRects()` по символам текста даёт строки; страница наполняется строками до 247 мм; абзац может разорваться по границе строки; заголовок, который стал бы последней строкой страницы, переносится вместе со следующей строкой. Первая страница короче на блок «название истории / Синопсис», каждая — на строку номера внизу. Результат — список начал страниц `{block, offset}` и счёт слов и знаков. Ширина экрана в вёрстку не входит, поэтому меняется только положение меток. Альтернатива — считать страницы по знакам (≈ 3000 на страницу): не совпадёт с печатью на заголовках и коротких абзацах, отклонено.

6. **Шрифт Tinos из сборки (`@fontsource/tinos` 5.3.0, latin и cyrillic, 400/400i/700/700i)** под отдельным именем `"Prose Print"`, через `FontFace` только для блока замера и окна печати; интерфейс его не использует. Вёрстка ждёт `document.fonts.load('12pt "Prose Print"')`; отказ загрузки — ошибка на экране, без замены другим шрифтом. Шрифты устройства в вёрстку не входят (Constraint спеки).

7. **Метки — накладка вне `contenteditable`.** Функция `prose/pageMarks.ts` (её зовёт эффект `ProseEditor` после вёрстки) переводит каждое начало страницы `{block, offset}` в позицию документа, берёт `view.coordsAtPos` и рисует метку «стр. N» абсолютным блоком в правом поле листа (родитель — лист, не `view.dom`), с `aria-hidden` и `user-select: none`. Поэтому метка не попадает в выделение, копирование и `getSelection()` для чата. Пересчёт: изменение документа (через 150 мс после последней правки, таймером: вёрстке не нужен экран, а у скрытой вкладки нет кадров), `document.fonts.ready`, `ResizeObserver` листа (только положение меток).

8. **Печать — `prose/print.ts`, раскладка уже готова.** Окно печати получает страницы, собранные по результату вёрстки: блок, разорванный между страницами, режется на два фрагмента по `offset` (второй без отступа до). В окне повторной раскладки нет, поэтому печать равна счёту. `@page { size: A4; margin: 25mm }`, номер внизу по центру, сверху первой страницы — название истории и «Синопсис». Цвета — токены `--print-*`, как у сценария. Заблокированное окно — `PrintError` с той же причиной.

9. **`ProseDoc` разделяется.** Логлайн остаётся `GrowingTextarea`. Синопсис — `SynopsisDoc`: `ProseEditor` получает строку Markdown и `onChange(markdown)`; состояние формы — строка, поэтому `useAutosave` и `useServerChanges` не меняются. Когда строка приходит извне (соавтор, возврат из истории) и отличается от последней записанной редактором, редактор заменяет документ одной транзакцией в истории правок — «Отменить» возвращает прежний текст. Запертый драфт — `editable: () => false`, кнопки правки недоступны, счёт и «Печать» работают. Плейсхолдер «Начните синопсис» — декорация пустого документа; `DocSheetTasks` под листом — как сейчас. `data-field="synopsis"` стоит на `view.dom`.

10. **Переход из поиска.** `useFindInDoc` делится: чтение и очистка `?find&field` остаются общими, выделение найденного делает поле. Для `textarea` — как сейчас; синопсис передаёт свою функцию: по простому тексту документа (сложенному `foldText`) ищет первое совпадение, ставит `TextSelection` и прокручивает. Не нашлось — каретка в начало, как сейчас.

11. **Счёт длины на панели.** «≈ N стр.» — число страниц вёрстки; кнопка открывает поповер дизайн-системы с «Слов», «Знаков с пробелами», «Страниц», та же сводка в подсказке при наведении. Слова — правило `count_words` (кусок между пробелами с буквой или цифрой), знаки — длина простого текста без переводов строк между абзацами. На панели уже 375 px — только «N стр.» (container query, как у панели текста).

12. **Соавтор.** Промпт (`agno/skills/coauthor/SKILL.md`, «Логлайн и синопсис»): синопсис драфта — Markdown по требованию `api/agents`; раздел «О сервисе «Соавтор»» — панель, счёт страниц и печать синопсиса. Инструменты не меняются: отказ ядра на `###` соавтор видит как ошибку инструмента. Демо-случай `agno/evals/coauthor/` проверяет кодом, что синопсис на страницу без строк с `#`, а версия для зрителя в заметке без `* _ #`.

## Risks / Trade-offs

- [Печать в Safari и Firefox раскладывает строки иначе, чем замер в том же окне Chromium] → замер и печать идут в одном браузере пользователя одним шрифтом и CSS; приёмка — Chromium, WebKit 18 проверяется отдельно и записывается в `tmp/VERIFY.md`.
- [Замер на каждый символ дорог на 15 страницах] → замер через 150 мс после паузы в наборе, `getClientRects` по строкам, двоичный поиск внутри блока только на разрывах страниц; бюджет — до 100 мс на 15 страниц в Chromium (решение владельца 2026-11-10 вместо одного кадра 16 мс: замер 10 страниц — 40–85 мс, из них 23–67 мс — пересчёт вёрстки браузером при раскладке текста шрифтом, его не сократить без потери совпадения с печатью).
- [Замена документа при правке соавтора сбрасывает каретку] → каретка ставится в начало заменённого текста; ввод автора по правилу `useServerChanges` не теряется.
- [Соавтор ставит `###`] → отказ ядра с понятной причиной, правило промпта и демо-случай.
- [`markdown-it` 14 в браузере и `markdown-it-py` 4.2 расходятся в мелочах] → общие случаи `markdown.cases.json` прогоняются обеими сторонами.
- [Новые зависимости увеличат сборку] → `prosemirror-markdown` и `markdown-it` грузятся с чанком документа синопсиса; `check-bundle.mjs` проверяет размер.

## Migration Plan

Миграций базы нет. Демо-синопсисы — простой текст без знаков разметки, читаются как есть. Откат — релиз без change: поле останется Markdown-текстом и покажется в прежнем `textarea` со знаками разметки, данные не теряются.
