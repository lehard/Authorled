## Как пользоваться замером действий

Замер действий (`agno/evals/coauthor/`, README, раздел «Замер действий») отвечает на вопрос, который не видит замер качества: доходит ли действие соавтора до ядра после «Разрешить» и легли ли сведения туда, где их ждёт автор. Судьи нет, всё проверяется кодом.

- **Когда запускать.** После правки описаний или типов меняющих инструментов (`agno/agents/coauthor_tools.py`), проверок ядра, на которые они опираются (`core/fields.py`, `core/documents.py`, `core/notes.py`, `core/review.py`), и раздела «Действия в истории» промпта соавтора.
- **Цена и время.** `--all` (64 просьбы) — около 12 ₽ на `deepseek-fast` (0,17–0,19 ₽ на просьбу), около 5 минут. `--sample 5` — около 1 ₽, для проверки цены перед полным прогоном.
- **Запуск** из `agno/` с `DB_*` от `./scripts/dev.sh api` (в `.env` их нет): один раз `python -m evals.coauthor actions-setup`, затем `python -m evals.coauthor actions-run --all`. Отчёт называет коммит и есть ли незакоммиченные правки в `agno/`.
- **Сравнение «до» и «после».** Каждый вариант — в своём git worktree на фиксированном коммите (`git worktree add --detach <путь> <коммит>`), туда копируется один и тот же код замера, `.env` — симлинком на основной; venv и `DB_*` — из основной папки, `cd <worktree>/agno` перед `python -m`. Так в сравнение не попадают чужие незакоммиченные правки общей папки (например, промпт `SKILL.md`, который в это время правила другая сессия). Прогоны — по очереди, не параллельно: у них один пользователь и общие заметки историй.
- **Заметки.** Заметки принадлежат истории, а копия драфта их не отделяет. С задачи 5.2 замер сам возвращает их к демо-состоянию до первой просьбы и перед каждой (`evals/coauthor/demo_notes.py`); ручное восстановление больше не нужно. Если заметку нельзя сопоставить с демо, замер останавливается до вызова модели: значит, кто-то менял данные пользователя замера руками.
- **Как читать отчёт.** Главное — отказы по причинам (неверный тип значения, поле не этого вида, роль, цитата) и «поля заполнены». Провалы читать глазами: часть из них — спорное размещение сведений («вид с холма» в `landmark`, а не `sight`), а не ошибка контракта.
- **Шум.** Каждый вариант прогонялся один раз. Повторы одной просьбы («Василий», 5 раз) расходятся по числу попыток (4 из 5 с первой). Разница в несколько просьб между прогонами — в пределах шума; 47% → 92% — нет.
- **Набор.** `actions.toml` проверяется по `core/fields.py` и `web/src/data/demo.json` до вызова модели (на этом пойманы `income` у мира и неизвестные цели). Новая просьба об изменении заметки или карточки должна называть цель так, как она названа в `demo.json`.
