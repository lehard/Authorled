## MODIFIED Requirements

### Requirement: Чат с соавтором
Колонка чата окна истории MUST быть чатом с агентом `coauthor` через AG-UI: заголовок «Соавтор», строка «Видит: <открытый документ>», сообщения автора и ответы соавтора, поле ввода (Enter — отправить, Shift+Enter — новая строка). Ответ MUST появляться по мере генерации; Markdown в ответе MUST отображаться оформленным текстом; у ответа MUST быть «Скопировать». Пустая беседа MUST показывать «О чём эта история?» и проверки наставника (требование «Проверки наставника»), которые отправляются по клику, и «Исследовать тему», которое кладёт в поле ввода начало просьбы о задании на исследование и не отправляет его. Если запуск не удался, текст автора MUST остаться в поле, а чат MUST показать сообщение для автора без технических подробностей (текста исключения, JSON, идентификаторов запроса, названий моделей, провайдеров и компонентов сервера):
- отказ продукта (причина `usage_limit_reached`, `subscription_ended`, `usage_check_failed` или `usage_record_failed` в данных `RUN_ERROR`) — сообщение бэкенда как есть, без «Соавтор не смог ответить»; отказ по лимиту — уведомлением, а не ошибкой;
- любой другой сбой запуска, в том числе сбой модели, — «Соавтор сейчас недоступен. Попробуйте позже.»;
- запрос не дошёл до сервера — «Нет связи с сервером. Проверьте интернет и попробуйте ещё раз.»
Полный текст сбоя MUST оставаться в консоли браузера.

#### Scenario: Вопрос и ответ
- GIVEN открыт текст сценария «Тихой воды»
- WHEN автор отправляет «О чём эта история?»
- THEN в чате MUST появиться его сообщение и ответ соавтора, который нарастает по мере генерации

#### Scenario: Пустая беседа
- GIVEN автор начал новую беседу
- WHEN чат показывает пустую беседу
- THEN в ней MUST быть «О чём эта история?», восемь проверок наставника и «Исследовать тему», и MUST NOT быть других подсказок

#### Scenario: Ошибка
- GIVEN API недоступен
- WHEN автор отправляет сообщение
- THEN в чате MUST появиться «Нет связи с сервером. Проверьте интернет и попробуйте ещё раз.» без причины сбоя в скобках, а текст автора MUST остаться в поле, чтобы отправить его снова

#### Scenario: Сбой модели
- GIVEN провайдер модели отклоняет запрос соавтора (например, на счёте провайдера нет денег), и `RUN_ERROR` содержит текст исключения LiteLLM
- WHEN автор отправляет сообщение
- THEN в чате MUST появиться «Соавтор сейчас недоступен. Попробуйте позже.» и MUST NOT быть текста исключения, JSON, идентификатора запроса и названий LiteLLM, DeepSeek и модели, а текст автора MUST остаться в поле

#### Scenario: Лимит исчерпан
- GIVEN лимит соавтора автора на этот период исчерпан и обновится 7 декабря
- WHEN автор пишет соавтору
- THEN в чате MUST появиться «Лимит соавтора на этот период исчерпан. Он обновится 7 декабря.» без «Соавтор не смог ответить», а текст автора MUST остаться в поле

#### Scenario: Отказ продукта
- GIVEN проверка лимита не удалась, и `RUN_ERROR` содержит причину `usage_check_failed` и сообщение «Не удалось проверить лимит соавтора. Напишите в поддержку.»
- WHEN автор пишет соавтору
- THEN в чате MUST появиться ошибка «Не удалось проверить лимит соавтора. Напишите в поддержку.» без «Соавтор не смог ответить», а текст автора MUST остаться в поле

#### Scenario: Неизвестная причина
- GIVEN `RUN_ERROR` содержит в данных причину, которой нет в списке отказов продукта
- WHEN автор пишет соавтору
- THEN в чате MUST появиться «Соавтор сейчас недоступен. Попробуйте позже.», а не сообщение из события

#### Scenario: Исследовать тему
- GIVEN автор начал новую беседу, поле ввода пусто
- WHEN он нажимает «Исследовать тему»
- THEN поле ввода MUST содержать начало просьбы о задании на исследование с курсором в конце
- AND сообщение MUST NOT отправиться, пока автор сам его не отправит

### Requirement: Сделанное соавтором в чате
После каждого выполненного действия соавтора чат MUST показывать в ответе строку о сделанном («Создан персонаж «Пётр»», «Изменено: «Вера»») со ссылкой на созданную или изменённую сущность. Отказ ядра MUST показываться строкой с причиной без ссылки, причина — обычным текстом. Результат, который нельзя прочитать ни как сделанное, ни как отказ, MUST показываться строкой «Не удалось прочитать результат действия», без сырого результата. Когда беседа открывается из истории (в том числе после перезагрузки страницы), чат MUST показывать под каждым ответом те же строки о сделанном, отказы, «Отклонено: …» и карточки задания на исследование, что были под ним до перезагрузки, по данным запусков этой беседы. Действие, на которое автор не ответил, MUST NOT показываться ни карточкой подтверждения, ни строкой.

#### Scenario: Ссылка на персонажа
- GIVEN режим «Сам», и соавтор создал персонажа «Пётр»
- WHEN автор нажимает ссылку в строке «Создан персонаж «Пётр»»
- THEN MUST открыться карточка персонажа «Пётр»

#### Scenario: Отказ
- GIVEN драфт заперт, и соавтор попытался создать заметку
- WHEN запуск закончился
- THEN в ответе MUST быть строка с причиной отказа и MUST NOT быть ссылки

#### Scenario: Причина отказа читается
- GIVEN соавтор пытается создать персонажа с ролью, которой нет, и ядро отвечает «Отказ: Поле «role» должно быть одним из: main, secondary, episodic.»
- WHEN в чате появляется строка отказа
- THEN строка MUST показать «Отказ: Поле «role» должно быть одним из: main, secondary, episodic.» и MUST NOT содержать кавычек вокруг текста или последовательностей `\u`

#### Scenario: Нечитаемый результат
- GIVEN результат действия соавтора пришёл в виде, который не является ни сделанным, ни отказом (например, число или объект без описания сделанного)
- WHEN в чате появляется строка под действием
- THEN строка MUST показать «Не удалось прочитать результат действия» и MUST NOT показывать сырой результат

#### Scenario: Строка после перезагрузки
- GIVEN режим «Сам», и соавтор создал персонажа «Пётр»
- WHEN автор перезагружает страницу и открывает эту беседу из истории
- THEN под ответом MUST быть строка «Создан персонаж «Пётр»», и её ссылка MUST открывать карточку «Пётр»

#### Scenario: Отклонено после перезагрузки
- GIVEN режим «Спрашивать», и автор отклонил создание заметки «Финал»
- WHEN автор перезагружает страницу и открывает эту беседу из истории
- THEN под ответом MUST быть строка «Отклонено: Создать заметку «Финал»»

#### Scenario: Действие без ответа
- GIVEN режим «Спрашивать», карточка подтверждения ждёт ответа, и автор перезагружает страницу, не ответив
- WHEN он открывает эту беседу из истории
- THEN под ответом MUST NOT быть ни карточки подтверждения, ни строки об этом действии

## ADDED Requirements

### Requirement: Карточка задания на исследование
После выполненного задания на исследование чат MUST показывать вместо строки о сделанном карточку: название заметки задания ссылкой на неё, «Скопировать задание», «Открыть Claude» и «Открыть ChatGPT» с одной строкой подсказки, где включается Deep Research, вложения, одну строку о том, что задание и вложения уходят во внешний сервис, и одну строку о том, что отчёт загружают в заметки. Карточка MUST оставаться после перезагрузки беседы.

#### Scenario: Скопировать задание
- GIVEN соавтор создал задание «Исследование: паромщики на Волге»
- WHEN автор нажимает «Скопировать задание»
- THEN буфер обмена MUST содержать только текст задания, без ответа соавтора вокруг

#### Scenario: Открыть сервис
- GIVEN в чате карточка задания
- WHEN автор нажимает «Открыть ChatGPT»
- THEN в новой вкладке MUST открыться сайт ChatGPT, и адрес MUST NOT содержать текста задания и темы

#### Scenario: Подтверждение задания
- GIVEN режим «Спрашивать»
- WHEN соавтор хочет создать задание по теме «паромщики на Волге»
- THEN карточка подтверждения MUST называться «Создать задание на исследование «паромщики на Волге»» и показывать начало текста задания

#### Scenario: После перезагрузки
- GIVEN в беседе есть выполненное задание
- WHEN автор перезагружает страницу и открывает эту беседу
- THEN карточка задания MUST быть на прежнем месте с теми же кнопками

### Requirement: Вложения задания на исследование
Карточка задания MUST перечислять вложения из вызова соавтора под «Приложите к запросу»: у заметки с оригиналом — имя файла и «Скачать» с исходным именем и байтами; у сценария — «Открыть сценарий» и путь «⋯ → Экспорт → Fountain». Вложение, которого уже нет (заметка в корзине или без оригинала), MUST показываться строкой «Вложения нет», без кнопки. Без вложений этой части MUST NOT быть.

#### Scenario: Оригинал заметки
- GIVEN задание с вложением «Эпоха» из `Эпоха.pdf`
- WHEN автор нажимает «Скачать» у вложения
- THEN MUST скачаться `Эпоха.pdf` с теми же байтами

#### Scenario: Сценарий
- GIVEN задание с вложением сценария
- WHEN автор нажимает «Открыть сценарий»
- THEN MUST открыться текст сценария драфта беседы, а карточка MUST показывать путь «⋯ → Экспорт → Fountain»

#### Scenario: Без вложений
- GIVEN задание без вложений
- WHEN автор смотрит на карточку
- THEN «Приложите к запросу» MUST NOT быть

### Requirement: Исследование в заметках
В меню раздела «Заметки» и на странице списка заметок MUST быть «Исследование». Оно MUST открывать чат (на узком экране — шторку) и класть в поле ввода то же начало просьбы, что «Исследовать тему» в пустой беседе, не отправляя его; набранный автором текст MUST остаться в поле после этого начала.

#### Scenario: Из списка заметок
- GIVEN чат свёрнут, открыт список заметок
- WHEN автор нажимает «Исследование»
- THEN чат MUST открыться, и поле ввода MUST содержать начало просьбы о задании, а сообщение MUST NOT отправиться

#### Scenario: Узкий экран
- GIVEN ширина окна 375 px
- WHEN автор выбирает «Исследование» в меню раздела «Заметки»
- THEN MUST открыться шторка чата с этим началом просьбы в поле ввода
