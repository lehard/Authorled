# Design

## Context

Мотивация в `proposal.md`. Что важно для решения:

- История владеет `title` и `description`, драфт владеет документом сценария с полями `tagline`, `logline`, `show`, `title_page`, `synopsis` (`agno/core/fields.py`). `ScriptFields` и `ScriptParts` строгие: лишнее поле и неполный `show` дают `422`.
- `documents.name` обязателен. У сценария он копируется из названия истории в `create_project` и дальше не обновляется. Его читают навигатор, `docTitle`, имя файла экспорта и инструменты соавтора `list_story_documents` и `read_story_document`.
- Снимки части `fields` и точки драфта хранят поля целиком, а `restore_fields` и `_restore_document` пишут их без проверки. Старое состояние вернёт `tagline` в документ, и следующий `merge_fields` даст `422`.
- На странице сейчас один `useAutosave` и один статус в `DocHead`. Новая страница пишет в две сущности: `projects` и `scripts`.
- Инварианты и ADR: фронтенд без продуктовой логики, данные произведения в ядре, Alembic только для схемы `authorled` и только вперёд. Логлайн остаётся структурированной частью сценария (ADR-006); свои маршруты не нужны (ADR-002).

## Goals / Non-Goals

**Goals:**
- Одно место для названия истории и никакого второго, устаревающего названия ни на экране, ни у соавтора.
- Старые снимки и точки остаются рабочими.

**Non-Goals:**
- Менять модель драфтов и снимков или добавлять проверку в откат.
- Убирать запасной `ALL_PARTS` из `apiProvider` (см. Risks).

## Decisions

1. **Имя сценария постоянное в ядре.** `create_project` пишет «Сценарий», `update_document` отказывает в правке `name` у `script`, миграция выравнивает старые записи. Соавтор и API сразу получают верное имя без правок инструментов.
   Альтернативы: подменять имя в инструментах соавтора (остаётся устаревшее значение в API и снимках); обновлять имя при переименовании истории (лишние ревизии и конфликты во всех драфтах).

2. **Тэглайн живёт в `projects.description`.** Экран меняет подпись, API и столбец остаются. Полка показывает одну карточку на историю, поэтому значение не может зависеть от драфта.
   Альтернатива: оставить `tagline` у сценария и показывать на полке значение последнего открытого драфта: полка менялась бы от действий в драфте.

3. **Одна миграция данных `0007`, чистая функция внутри неё.** `_script_state(state)` принимает `{name, fields}`, отбрасывает `tagline`, ставит имя и дополняет `show`. Миграция проходит три места: документы вида `script`, строки `document_versions` с `part = 'fields'` этих документов и элементы `kind = 'script'` в `draft_points.content.documents`. Функция не импортируется из `core`, чтобы миграция не менялась вместе с кодом. Ревизии и `updated_at` не трогаются: содержимое для автора то же.
   Альтернативы: очистить истории, как `0006` (потеря локальной работы, в базе есть «Белая дача»); проверять и приводить состояние при откате (постоянный код ради разовой правки).

4. **Общий статус двух сохранений.** Страница держит два `useAutosave`, а `combineStatus(a, b)` рядом с хуком выбирает более важный: конфликт, ошибка, «сохраняется», иначе «сохранено». Конфликт любого из двух показывается обычным `SaveStatus`; `openFresh` открывает страницу заново для обеих сущностей.
   Альтернатива: два статуса на экране: автору не нужно знать, что данные лежат в двух местах.

5. **Папка как строка без адреса.** `Row.to` становится необязательным. Строка без адреса рисуется кнопкой с классом `tree-item` и переключает раскрытие; у папки нет `menu`. Адрес `sp` просто исчезает из `parseDoc`, остальное делает существующий «Не найдено».

6. **Выделение шапки.** Ссылка шапки получает `aria-current="page"`, когда открыт `info`; в `workspace.css` рядом с `.tree-item[aria-current]` правило для шапки на тех же токенах.

7. **Логлайн и синопсис — один компонент.** `SynopsisDoc` становится `ProseDoc` с полем, заголовком и подсказкой, потому что документы отличаются только этим. Значок части `Quote`. Часть добавляется в `SCRIPT_PARTS` перед `synopsis`, порядок дерева и галочек берётся оттуда. Скрытая часть уже даёт «Не найдено» в `ProjectScreen`.

8. **Страница истории собирается из `InfoDoc`.** `ScriptDoc.tsx` удаляется. Поля истории редактируются всегда, `fieldset disabled={draft.locked}` закрывает только галочки. Кнопки истории сохранений на странице нет: логлайн, синопсис и титульная страница держат её у себя.

9. **Экспорт и контекст соавтора.** `TextDoc` берёт имя файла из `project.title`, запасное «Сценарий» уходит, потому что название истории не бывает пустым. `documentText`: у `info` подпись «Тэглайн», случай `sp` уходит, у части `logline` текст логлайна.

10. **Демо-контент.** В `demo.json` у сценариев убираются `tagline` и `name`, `show` дополняется `logline: true`, а `desc` историй заменяется их тэглайном; `_passport` не читает `tagline`.

## Risks / Trade-offs

- [Старые снимки и точки ломают сохранение после отката] → миграция приводит их к новой форме; тест миграции и сценарий «Откат к старому снимку».
- [Существующий запасной вариант `show === undefined ? ALL_PARTS` в `apiProvider.toScript` скрывает незаданный `show`] → его поведение не меняется, только добавляется ключ `logline`, которого требует тип. Вопрос вынесен владельцу отдельно: правильнее задавать `show` в ядре при создании истории.
- [Правка `name` сценария теперь `422`] → единственный клиент `web/` перестаёт её отправлять.
- [Смешанная страница: история и открытый драфт] → принято владельцем для MVP; поведение под замком описано в спеке.
- [Истории в локальной базе сохраняют длинные описания под подписью «Тэглайн»] → это только демо; перезагрузка контента описана в Migration Plan.

## Migration Plan

1. Выкатить вместе: миграция `0007`, ядро, фронтенд. Отдельной совместимости старого клиента нет, других клиентов нет.
2. Локально: `./scripts/dev.sh migrate`.
3. По желанию обновить демо-контент: удалить демо-истории у `writer` и `editor`, запустить `./scripts/dev.sh seed`; «Белую дачу» не трогать.

Откат только новой миграцией вперёд: значения `tagline` восстановить нельзя, в демо-контенте они есть в истории git.
