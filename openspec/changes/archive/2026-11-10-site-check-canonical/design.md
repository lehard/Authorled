# Design

## Context

- `site/src/pages/LegalDocument.tsx` переписывает ссылку документа на `https://soavtor.app/<путь>` (`DOCUMENT_ORIGIN`) в относительную `<путь>` (D6 change `no-training-in-app`). Константа не зависит от `SITE_ORIGIN`: в тексте документов адрес продукта полный при любой сборке.
- `site/scripts/check-build.mjs` для каждой страницы документа проверяет D6 шаблоном `/href="(https:\/\/soavtor\.app[^"]*)"/g` по всему HTML. В той же функции уже есть правило «ссылка на путь, которого нет среди страниц», и оно смотрит только на `<a[^>]+href="…"`.
- `canonical` (`<link rel="canonical" href="${origin}${url}" />`) и `og:url` проверяются тем же скриптом на точное значение отдельными правилами.
- `validate.yml` задаёт `SITE_ORIGIN=https://site.invalid` и `SITE_APP_URL=https://app.invalid`; задание `validate` в `deploy.yml` вызывает этот же файл (`workflow_call`), а шаг «Build the site» деплоя собирает сайт с `vars.SITE_ORIGIN` и `vars.SITE_APP_URL` окружения `production`.

## Goals / Non-Goals

**Goals:**
- Сборка с `SITE_ORIGIN=https://soavtor.app` проходит проверку, а ссылка текста документа, оставшаяся абсолютной, по-прежнему её валит.
- Пулл-реквест ловит то, что сейчас ловит только выкладка.

**Non-Goals:**
- Разбор HTML парсером вместо регулярных выражений.
- Вторая сборка сайта в CI.

## Decisions

### D1. Правило D6 смотрит на `href` тегов `<a>`

Шаблон правила становится `/<a[^>]+href="(https:\/\/soavtor\.app[^"]*)"/g`, как у соседнего правила о путях. Сообщение прежнее: `${file}: a link to ${адрес} was not made local`.

- Ссылки на `https://app.soavtor.app` и почту по-прежнему не совпадают: перед `soavtor.app` стоит `https://`.
- Ссылка ровно на `https://soavtor.app` (без пути) по-прежнему ловится: отрисовка её не переписывает (`localHref` берёт только `https://soavtor.app/…`), и это остаётся ошибкой.
- Альтернатива — исключить из старого шаблона `rel="canonical"`. Отклонена: правило осталось бы завязано на список служебных тегов (`canonical`, `alternate`, будущие), а смысл D6 — ссылки текста, то есть `<a>`.
- Альтернатива — сравнивать с `origin` из `og:url` вместо литерала `soavtor.app`. Отклонена: отрисовка переписывает именно `DOCUMENT_ORIGIN`, а не адрес сборки; при нейтральном адресе такая проверка перестала бы видеть настоящую ошибку.

### D2. CI собирает сайт с адресами продукта

`validate.yml` задаёт `SITE_ORIGIN=https://soavtor.app` и `SITE_APP_URL=https://app.soavtor.app`, комментарий над ними говорит, что это адреса выкладки (спека `web/site`, «Локальный запуск и выкладка»). Значения — литералы в файле, а не `vars`: пулл-реквест не имеет доступа к окружению `production`, а адреса продукта зафиксированы спекой.

- Альтернатива — две сборки в CI (нейтральная и продуктовая). Отклонена: сейчас от адреса сборки зависят только `canonical`, Open Graph, `sitemap.xml` и `robots.txt`; правил, которые видны только с нейтральным адресом, нет (интент, Risks). Вторая сборка удлиняет CI без пойманных ошибок.
- Сборка в CI ничего не выкладывает: собранные файлы остаются на раннере, на сервер они попадают только в шаге деплоя.

## Risks / Trade-offs

- [Расхождение `vars` и литералов] Если владелец поменяет `SITE_ORIGIN` в окружении `production`, CI продолжит собирать со старым адресом. → Адрес продукта задан спекой `web/site`; его смена — отдельный change, который правит и спеку, и `validate.yml`.
- [Ошибка, видная только с нейтральным адресом] CI перестанет её ловить. → Таких правил сейчас нет; локальная сборка разработчика идёт со своими адресами из `.env`, и проверка в задачах прогоняется с обоими.
- [Регулярное выражение по HTML] `<a … href>` с другим порядком кавычек не совпадёт. → Пререндер React пишет атрибуты в двойных кавычках; так же устроено соседнее правило.

## Migration Plan

Слить в `main`, после чего владелец публикует релиз `v0.3.13`. Откат — релиз предыдущего тега; данные и сервер change не меняет.
