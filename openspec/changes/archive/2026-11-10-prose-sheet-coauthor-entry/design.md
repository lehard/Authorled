# Design

## Context

- `ProseDoc.tsx` рисует `<div class="sheet sheet-prose">` с `GrowingTextarea variant="bare"` внутри. Стили `.sheet`, `.sheet-prose`, `.sheet-title` лежат в `@layer components` файла `web/src/screens/workspace.css`, который импортирует `ProjectScreen.tsx`; в сборке они попадают в ленивый чанк `document-*.css`.
- Что уже проверено (2026-11-10): правило `.sheet-prose{width:min(100%,760px);padding:64px 72px 80px;…}` есть в CSS на `app.soavtor.app`; в Chrome на собранном вручную листе вычисленные стили правильные (760 px, поля 64/72/80, отступ по центру). Другие правила с классом `sheet` в CSS прода не найдены. Поломку видит владелец: прод, Safari 18.6 (macOS 13), страницы «Логлайн» и «Синопсис». На его скриншоте высота белого листа примерно равна минимальной высоте поля (11 строк), то есть полей нет, а лист шире 760 px и не по центру: похоже, что `.sheet-prose` не действует целиком, а `.sheet` (бумага, тень, скругление) действует. Причина пока не известна.
- Кнопка «Соавтор»: `DocTasksButton` в `chat/DocTasksMenu.tsx`, `Button variant="ghost"`. Задачи и тексты просьб — `DOC_TASKS` в `chat/docTasks.ts`; `agno/evals/coauthor/doc_tasks.py` повторяет просьбы слово в слово.

## Goals / Non-Goals

**Goals:**
- Лист прозы одинаков в Safari и Chrome; причина поломки названа в `tmp/VERIFY.md`.
- Один источник задач и один обработчик выбора задачи для меню и листа.

**Non-Goals:**
- Переписывать раскладку рабочей области (`DocView`, `--doc-pad-x`), если причина не в ней.
- Менять `GrowingTextarea` для всех полей, если причина не в нём.

## Decisions

1. **Сначала диагноз в Safari, потом правка.** Открыть «Логлайн» на проде в Safari 18.6 с Web Inspector: какие правила совпали у `div.sheet.sheet-prose`, какие зачёркнуты, вычисленные `width`, `padding`, `margin`; загружен ли чанк `document-*.css` и в каком порядке относительно `index-*.css`. Затем воспроизвести локально: `npm run dev --prefix web` и сборка `npm run build && npm run preview --prefix web` в Safari. Проверяемые гипотезы по порядку: (а) правило `.sheet-prose` отброшено парсером Safari из-за соседней конструкции в том же блоке сборки; (б) порядок слоёв при поздней вставке ленивого CSS; (в) правило перекрыто другим, совпадающим с тем же элементом. Причину и доказательство записать в `tmp/VERIFY.md`. Альтернатива «добавить те же поля утилитами Tailwind прямо на элемент» отклонена: она маскирует причину (правило без запасных путей из `CLAUDE.md`) и оставит сломанной «Титульную страницу», если причина общая. Если найденная причина требует правок вне Scope proposal, остановиться и попросить `/opsx:update`.

2. **Признак задачи для листа в данных, а не по id.** В `DocTask` добавить поле `onSheet: boolean`: `true` у задач, которые пишут текст (логлайн — `logline-variants`; синопсис — `synopsis-page`, `synopsis-short`, `synopsis-viewer`, `synopsis-application`), `false` у проверок. Поле `writes` не подходит: «Коротко: абзац» и другие версии в заметку пишут текст, но не в документ. Тексты просьб не меняются.

3. **Общий обработчик выбора задачи.** Логику выбора из `DocTasksButton` (отправка через `askCoauthor(request, "send")` и отложенная вставка `"fill"` после закрытия меню) разделить: функция `runDocTask(task)` для листа вызывает `askCoauthor` сразу (меню нет, фокус никто не возвращает), а меню сохраняет нынешний путь через `onCloseAutoFocus`. Фильтр запертого драфта и `coauthorBusy` — общие.

4. **Кнопки поверх пустого поля, а не под ним.** Поле пустого листа занимает 11 строк; кнопки под ним ушли бы за нижний край первого экрана. Блок кнопок стоит абсолютно внутри `.sheet` (у него уже `position: relative`), под строкой подсказки (сдвиг сверху — верхнее поле листа плюс полторы строки), слева по полю листа. Сам блок `pointer-events: none`, кнопки — `auto`: клик в пустое место листа попадает в поле. Ряд начинается подписью «Попросить соавтора:» со значком `Sparkles`, как у кнопки «Соавтор» в шапке: без неё автор не понимает, что кнопки обращаются к соавтору (владелец, 2026-11-10). Кнопки — `Button variant="outline" size="sm"` с `rounded-full`, переносятся по строкам (`flex-wrap`), чтобы на 375 px не было прокрутки. Показ: `text === "" && !draft.locked`; `text` — локальное состояние `ProseDoc`, поэтому кнопки уходят с первым символом и при записи соавтора через `useServerChanges`.

5. **Залитая кнопка в шапке.** `DocTasksButton`: `variant="default"` (`bg-primary text-primary-foreground`) и `rounded-full` вместо `ghost`. Своих цветов нет — только токены дизайн-системы, контраст проверяет `validate.sh`.

6. **Справка соавтора.** В строку о кнопке «Соавтор» раздела «О сервисе «Соавтор»» `agno/skills/coauthor/SKILL.md` добавить: на пустом логлайне и синопсисе те же задачи стоят прямо на листе.

**Итог решения 1 (2026-11-10).** Причина найдена в Safari 18.6: прод подключает `document-*.css` раньше `index-*.css`, первое объявление `@layer components` ставит его ниже `base`, и сброс preflight снимает поля и `margin: 0 auto`. Это поведение каскадных слоёв, не баг Safari. Правку внёс PR lehard/Authorled#62 (порядок слоёв в `web/index.html`); этот change её не дублирует.

## Risks / Trade-offs

- [Поломка не воспроизводится локально в Safari] → проверять на проде в Safari владельца после релиза и до закрытия change; без доказанной причины не закрывать задачу 1.
- [Кнопки поверх поля мешают выделению или набору] → блок пропускает клики, исчезает с первым символом; проверить вживую в Safari и Chrome.
- [Залитая кнопка спорит с акцентом на «Сохранить» в других экранах] → в шапке логлайна и синопсиса нет другой залитой кнопки; проверить скриншотом обе темы.
