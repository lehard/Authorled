# Design

## Context

Мотивация — в proposal.md. Что есть сейчас:

- Текст сценария — документ ProseMirror; абзацы 14 типов содержат только текстовые узлы с метками (`web/src/editor/schema/index.ts`). Ядро проверяет тот же состав (`agno/core/texts.py`, `validate_text`): внутри абзаца допустим только узел `text` с непустой строкой, и `\n` в строке уже проходит проверку.
- Лист редактора и печать уже показывают `\n` как новую строку: `white-space: pre-wrap` у `.ProseMirror` (`styles.css`) и у абзацев печати (`exporters/print.ts`).
- Клавиши: `keymaps/index.ts` (`step` для Enter и Tab по таблице `elements.ts`); `Shift-Enter` не привязан и `baseKeymap` его не обрабатывает. Ввод «ИНТ. » и переходов — `plugins/inputRules.ts`.
- Скобки ремарки рисует CSS (`.pm-parenthetical::before/::after`), в тексте их нет; импорт FDX снимает скобки (`_without_brackets`).
- Экспорт Fountain (`exporters/fountain.ts`) уже считает абзац с `\n` «не простым» и пишет его однострочной пометкой `[[@тег текст]]`, а импорт ядра (`core/importers/fountain.py`) читает файл построчно: такая пометка на нескольких строках не разбирается, и круг теряет текст. Реплики подряд экспорт пишет строками одного блока, импорт делает из каждой строки отдельную реплику.
- Экспорт FDX пишет текст узла в `<Text>` как есть; импорт собирает `itertext()` — `\n` сохраняется.
- Подсчёт слов (`core/writing.py`, `str.split()`, и счётчик редактора по `wordCount.cases.json`), поиск (`core/search.py` превращает переводы строк в пробелы), привязка предложений (`anchors.ts`, поиск цитаты в `textContent`) и инструменты соавтора читают `\n` как пробельный символ.
- TXT импортируется как Fountain; DOCX превращается в строки Fountain с пустой строкой между абзацами (`importers/plain.py`), кроме строк после персонажа и ремарки.

## Goals / Non-Goals

**Goals:**
- Перенос строки без изменения формата документа и без изменений проверки текста в ядре.
- Круг Fountain и FDX без потерь для текста с переносами строк.
- «(» и Tab по требованиям спеки `web/screenplay-editor`, одним шагом отмены.

**Non-Goals:**
- Узел `hardBreak` в схеме.
- Изменения разбора STARC, DOCX-специфики и маршрутов ядра.

## Decisions

### 1. Перенос строки — символ `\n` в текстовом узле

Shift+Enter вставляет `\n` командой `insertText` (заменяя выделение). В «Заголовке сцены», «Переходе» и «Персонаже» команда возвращает `true` и ничего не делает, чтобы браузер не вставил свой `<br>` или `<div>`.

Альтернатива — узел `hardBreak` (как в схеме ProseMirror по умолчанию). Отклонена: ядро пришлось бы учить новому узлу в `validate_text`, `block_text`, `filter_marks`, подсчёте слов, поиске, снимках и инструментах соавтора, а экспорт и привязку предложений — склеивать текст через узлы. `\n` уже проходит везде, кроме разбора Fountain.

### 2. Абзацы — `whitespace: "pre"`, перенос строки не теряется при наборе и вставке

Типы абзацев получают `whitespace: "pre"` (`schema/index.ts`). Когда автор печатает, ProseMirror заново читает текст абзаца со страницы и сохраняет переводы строк только в абзацах с `whitespace: "pre"`, в остальных заменяет их пробелами (`prosemirror-view`, `readDOMChange`). Без этой настройки перенос строки исчезает после первой же буквы рядом с ним; в браузере это подтвердилось. Правило разбора своих абзацев `p[data-type=…]` получает `preserveWhitespace: "full"`, чтобы перевод строки сохранялся при копировании и вставке внутри редактора.

При вставке HTML из других программ ProseMirror всё равно схлопывает пробелы и переводы строк (`parseSlice` с `preserveWhitespace: false`): лишние переносы из Word не появятся. Вставка простого текста не меняется.

Альтернатива — только `preserveWhitespace` у правила разбора, без `whitespace: "pre"`. Отклонена: так перенос строки сохраняется при вставке, но пропадает при наборе.

### 3. «(» и «)» — плагин `handleTextInput`

Новый плагин в `plugins/` перехватывает ввод одного символа «(» или «)» при пустом выделении:

| Где курсор | «(» | «)» |
|---|---|---|
| пустая «Реплика» | абзац становится «Ремарка» | обычный ввод |
| конец непустой «Реплика» | новый пустой абзац «Ремарка» после неё | обычный ввод |
| середина «Реплика» | разбиение реплика / ремарка / реплика (решение 4) | обычный ввод |
| «Ремарка», начало текста | не вставляется | обычный ввод |
| «Ремарка», конец текста | обычный ввод | не вставляется |
| другие типы, выделение | обычный ввод | обычный ввод |

`handleTextInput` срабатывает на введённый символ, а не на клавишу, поэтому не зависит от раскладки (в русской «(» тоже Shift+9). Плагин стоит перед `screenplayInputRules`. Ввод через IME и вставка текста идут мимо него: скобки во вставленном тексте остаются текстом.

Альтернатива — клавиша `(` в `keymap`. Отклонена: привязка по `event.key` хуже переносится между раскладками и не видит ввод с экранной клавиатуры.

### 4. Разбиение реплики ремаркой — одна транзакция

Tab в середине «Реплики» (ветка «Inside the text» в `step`) и «(» там же вызывают одну команду: удалить пробелы вокруг курсора, `split` на «Реплику» и «Ремарку», затем `split` пустой ремарки на «Ремарку» и «Реплику», курсор — в пустую ремарку. Это одна транзакция, поэтому отмена — один шаг. Метки сохраняются, потому что `split` их не трогает. Tab в середине абзацев других типов по-прежнему ничего не делает.

### 5. Fountain: перенос строки — строками блока, остальное — многострочной пометкой

Экспорт (`exporters/fountain.ts`):
- «Реплика» с `\n` внутри блока персонажа пишется строками подряд, если ни одна строка не похожа на ремарку, лирику или пометку (`(…)`, `~`, `[[`); пустая строка внутри — строкой из двух пробелов (правило Fountain). Иначе — пометкой.
- «Описание действия» с `\n` пишется строками подряд, если ни одна строка не начинается спецсимволом, не похожа на заголовок сцены, переход или персонажа; пустая строка — двумя пробелами. Иначе — пометкой.
- Другие типы с `\n` — пометкой `[[@тег …]]` на нескольких строках, пустая строка внутри — двумя пробелами.
- Реплика сразу после реплики в одном блоке пишется пометкой `[[@dialogue …]]`, чтобы импорт не склеил их в одну.

Импорт (`core/importers/fountain.py`):
- В блоке персонажа строки реплики подряд (и строки из двух пробелов между ними) собираются в одну реплику через `\n`; ремарка, лирика и пометка заканчивают реплику.
- Строки после строки действия до пустой строки собираются в то же действие через `\n` (строка из двух пробелов — пустая строка внутри).
- Строка, которая начинается с `[[` и не заканчивается `]]`, продолжается до строки, которая заканчивается `]]`; строки соединяются `\n`.

Альтернатива — оставить `\n` только в пометках. Отклонена: другие программы показали бы реплику с переносом как заметку, а не как реплику.

Следствие (BREAKING, proposal): чужой Fountain или TXT с несколькими строками реплики или действия подряд теперь импортируется одним абзацем с переносами. DOCX не меняется: `plain.py` ставит пустую строку между абзацами, кроме строк после персонажа и ремарки, а реплика за репликой в DOCX разделена пустой строкой.

### 6. FDX — `\n` внутри `<Text>`

Экспорт пишет `\n` как есть внутри `<Text>`, импорт сохраняет его через `itertext()`; код менять не нужно, нужны только образец и тест. Как Final Draft пишет мягкий перенос в своих файлах, не проверено: требование — круг через наш экспорт.

### 7. Проверки

- `check:editor` (`web/scripts/check-editor.ts`): Shift+Enter по типам, «(» и «)» по таблице решения 3, Tab в середине реплики и отмена одним шагом, круг документа с переносами через экспорт; образцы экспорта, на которых ядро проверяет импорт, дополняются абзацами с переносами.
- `agno/tests/test_import.py`: сценарии `api/story-import` — реплика и действие в несколько строк, многострочная пометка, перенос из FDX, круг образцов.
- `wordCount.cases.json`: пример с `\n` и пустой строкой внутри абзаца; ядро и редактор считают его одинаково.

- `check:editor` работает без браузера и не может проверить, как текст читается со страницы. Поэтому он проверяет `whitespace: "pre"` и правило разбора у каждого типа, а набор текста рядом с переносом проверяется в браузере.

## Risks / Trade-offs

- [Строка действия из заглавных букв под другой строкой действия] → экспорт пишет такое действие пометкой (решение 5), импорт не примет её за персонажа.
- [Чужой Fountain с действием по строкам теперь даёт один абзац] → это чтение Fountain по его правилам; пользователей пока нет, сохранённые тексты не меняются.
- [Final Draft может записывать мягкий перенос иначе] → требование покрывает круг через наш экспорт; файлы Final Draft с мягким переносом проверим, когда появится образец.
- [Лишние переносы при вставке из Word] → при вставке чужого HTML ProseMirror схлопывает пробелы; это проверяется в браузере.
- [Браузер вставит свой перенос на Shift+Enter в заголовке] → команда возвращает `true` и в этих типах; `check:editor` проверяет, что документ не меняется.
- [Скобка из IME или со вставкой попадёт в ремарку] → оформление покажет двойные скобки; это осознанно: плагин меняет только набор с клавиатуры.

## Migration Plan

Миграций данных нет: формат документа прежний. Откат — откат релиза; тексты с `\n`, созданные новой версией, старая версия покажет так же (`pre-wrap`), а экспорт Fountain старой версии запишет их однострочной пометкой.
