# Design

## Context

Причины и объём — в `proposal.md`, требования — в `specs/`. Решения об устройстве: ADR-001 (монорепозиторий, фронтенд в `web/`, тонкий клиент), ADR-004 (Refine, CopilotKit, `@plotwell/editor`, shadcn/ui на Tailwind, один набор CSS-переменных для всех трёх), ADR-005 (потоки по образцу STARC). Рекомендации по визуальному языку — `openspec/context/_raw/research/Дизайн писательских инструментов с ИИ/Отчёт.md`, раздел «Что взять в дизайн-систему Authorled».

Что есть сейчас:
- Каталога `web/` нет. В репозитории нет ни одного файла Node.js.
- `scripts/validate.sh` проверяет только Python (ruff, mypy) и границу модуля `auth`. CI вызывает только его.
- `.gitignore` не знает про `node_modules/` и `web/dist/` (в нём есть общие `dist/` и `build/` из шаблона Python).
- На машине разработчика Node.js 24.16 и npm 11.13; pnpm не установлен.
- Актуальные версии на 2026-10-27 (`npm view`): vite 8.3.5, react 19.3.1, typescript 7.0.2, tailwindcss и `@tailwindcss/vite` 4.3.3, shadcn 4.22.2, lucide-react 1.62.0, eslint 10.13.0, prettier 3.9.10, culori 4.0.2. Шрифты Fontsource 5.3.0 (`@fontsource-variable/literata`, `@fontsource-variable/golos-text`, `@fontsource/cousine`) под OFL-1.1, во всех трёх есть кириллические файлы.

## Goals / Non-Goals

**Goals:**
- Один источник стилей для будущих экранов, CopilotKit и редактора сценария.
- Правила дизайн-системы проверяются автоматически (сырые цвета, контраст), а не только описаны.
- Минимальный каркас, на который следующие changes добавят Refine, CopilotKit и редактор, ничего не переделывая.

**Non-Goals:**
- Маршрутизация, вход, работа с API: появятся с Refine.
- Конкретная привязка токенов к переменным CopilotKit (`[data-copilotkit]`) и редактора (`--pw-*`): делается в их changes, токены слоя 3 для этого уже есть.
- Логотип и фирменный стиль сверх акцентного цвета: логотипа нет, акцент — чернильно-синий (решение владельца, см. ниже).

## Decisions

**D1. Vite SPA, а не Next.js.** Фронтенд — тонкий клиент без своего сервера (ADR-001), SSR не нужен, а Next.js добавляет серверный слой и собственную телеметрию (анти-паттерн 17). Refine и CopilotKit работают в Vite-приложении. *Альтернатива:* Next.js — отвергнут по этим причинам.

**D2. npm и `package-lock.json`.** npm уже установлен вместе с Node.js, отдельный менеджер пакетов не нужен. Версии в `package.json` точные (без `^`), lock-файл в репозитории, установка в CI — `npm ci`. Node.js — актуальная LTS-ветка 24, в `web/.nvmrc` и `engines`. *Альтернатива:* pnpm или bun — лишний инструмент без выигрыша на одном пакете.

**D3. Структура `web/`.**
```
web/
  index.html                 lang="ru", скрипт начальной темы
  package.json, package-lock.json, .nvmrc
  vite.config.ts, tsconfig*.json, eslint.config.js, .prettierrc, components.json
  scripts/check-contrast.ts  проверка контраста пар токенов
  src/
    main.tsx, App.tsx        App показывает витрину
    design-system/
      tokens.css             слои 1–3 и темы
      fonts.css              подключение Fontsource
      typography.css         шкала текста, бумага, пометки редактора
      statuses.ts            таблица статусов: иконка, подпись, токен
      components/            StatusBadge, AiLabel, ThemeSwitcher, Paper
      index.ts               публичный вход дизайн-системы
    components/ui/           компоненты shadcn (генерирует CLI)
    showcase/                страница-витрина
```
`components.json` направляет CLI shadcn в `src/components/ui`, а глобальный CSS — в `src/design-system/tokens.css`. Стиль `radix-nova` текущего CLI использует для склейки классов пакет `cn` вместо файла `lib/utils.ts`, поэтому своего `lib/utils.ts` нет. Компоненты shadcn не правим вручную без нужды, чтобы их можно было обновлять CLI.

**D4. Токены: три слоя в одном CSS-файле.** Tailwind v4 читает токены через `@theme inline`, shadcn — по своим стандартным именам.
- Слой 1 — примитивы `--color-<шкала>-<1..12>` в OKLCH по ролям ступеней Radix (1–2 фон, 3–5 подложки, 6–8 границы, 9–10 заливки, 11–12 текст). Шкалы: тёплый нейтральный, акцент (чернильно-синий), ИИ (фиолетовый), зелёно-бирюзовый, янтарный, малиново-красный. В Tailwind утилиты слоя 1 не выводятся, поэтому `bg-neutral-5` написать нельзя.
- Слой 2 — все переменные shadcn (`--background` … `--sidebar-*`, `--radius`), значения ссылаются на слой 1.
- Слой 3 — `--paper`, `--paper-foreground`, `--paper-measure`; `--status-<s>` (цвет текста и иконки), `--status-<s>-subtle`, `--status-<s>-border` для семи статусов; `--deco-insert`, `--deco-delete`, `--deco-comment` (и `--deco-comment-subtle` для фона), `--deco-ai`, `--deco-conflict`, `--deco-mention`, `--deco-stale`; `--ai`, `--ai-subtle`, `--ai-border`; `--font-ui`, `--font-prose`, `--font-script`. В Tailwind выводятся как `bg-status-approved-subtle`, `text-ai` и т. п.
- Оттенки фона пометок задаются отдельным `-subtle` токеном под каждую тему, а не прозрачностью поверх фона: так контраст проверяем.

*Альтернатива:* токены в TypeScript с генерацией CSS — лишний шаг сборки; shadcn и Tailwind ждут CSS.

**D5. Цвета статусов и ИИ.** `not_started` и `draft` — нейтральные (пустой пунктирный круг / пунктирная обводка); `in_progress` и `ready` — акцентный синий (полукруг / круг с точкой); `approved` — зелёно-бирюзовый с галочкой (отличим от красного при дейтеранопии); `stale` — янтарный с часами; `conflict` — малиново-красный с треугольником. ИИ — фиолетовый, не совпадает ни с одним статусом. Иконки — lucide-react. Таблица статусов — данные в `statuses.ts`; это визуальная семантика, а не правила процесса: какой статус у документа, решает бэкенд (анти-паттерн 10).

**D6. Темы.** `data-theme="light" | "sepia" | "dark"` на `<html>`. Сепия — тёплая «бумажная» тема для долгого чтения, включается только выбором пользователя. Встроенный скрипт в `index.html` до загрузки бандла читает сохранённый выбор из `localStorage` (ключ `authorled.theme`); если выбора нет, ставит тему по `prefers-color-scheme` и следит за её изменением. Значение вне `light | sepia | dark` в хранилище — ошибка в консоли и исключение, а не тихая замена. `ThemeSwitcher` пишет выбор и атрибут. Выбор темы — удобство конкретного браузера, а не данные произведения, поэтому хранится на клиенте.

**D7. Шрифты.** Fontsource-пакеты подключаются только с подмножествами `cyrillic`, `cyrillic-ext` и `latin`: Golos Text (переменный) для интерфейса, Literata (переменный, ось `opsz`) для текста документов и прозы, Cousine 400/700 с курсивами для сценария. Cousine метрически совместим с Courier New, это сохраняет правило «страница ≈ минута» и для американского, и для русского шаблона (ADR-004 уже называет Cousine кандидатом). Файлы шрифтов попадают в сборку, CDN не используется (требование `web/app`).

**D8. Шкала текста и бумага.** Именованные размеры (`display`, `heading-1..3`, `body`, `body-prose`, `caption`, `code`) — токены `--text-*` для Tailwind v4, так в коде пишут `text-body-prose`, а не `text-lg`. Класс `.paper` (и компонент `Paper`): `max-width: var(--paper-measure)` (65ch), `line-height: 1.65`, выключка влево, `hyphens: auto`, шрифт `--font-prose`, фон и текст `--paper*`. Переносов на JavaScript нет: если браузер не знает русских переносов, текст идёт без них (это поведение браузера, а не наша подмена).

**D9. Пометки редактора — CSS-классы.** `.deco-insert` (подчёркивание), `.deco-delete` (зачёркивание), `.deco-comment` (фон `-subtle` и маркер на полях), `.deco-ai` (полоса на полях), `.deco-conflict` (волнистое подчёркивание), `.deco-mention` (пунктирное подчёркивание), `.deco-stale` (янтарная полоса на полях). Плагины `@plotwell/editor` позже вешают эти классы на декорации ProseMirror, в витрине они показаны на обычном тексте.

**D10. `AiLabel`.** Строится на `Popover` из shadcn (Radix): клавиатура, фокус и Escape — из Radix. Пропсы: `action` (что сделал ИИ), `sources` (документы-основания: код Д и название), `acceptedAt`, `acceptedBy` — необязательные, пока предложение не принято. Компонент только показывает данные, ничего не запрашивает.

**D11. Проверки.**
- `scripts/check_web_tokens.sh` (по образцу `check_auth_boundary.sh`): `grep` по `web/src` вне `tokens.css` на hex-цвета, `rgb(`, `hsl(`, `oklch(` и классы палитры Tailwind (`bg-red-500`, `text-white` и т. п.), а вне `tokens.css` и `src/showcase/` — ещё и ссылки на примитивы слоя 1 (`var(--blue-9)`); имена шкал берутся из самого `tokens.css`. Находка — ошибка с файлом и строкой.
- `web/scripts/check-contrast.ts` запускается Node.js без сборки: разбирает `tokens.css` (postcss), раскрывает цепочки `var()` для каждой темы и считает контраст WCAG (culori) для списка пар; порог 4,5:1 для текста, 3:1 для маркеров и границ. Список пар — в самом скрипте.
- `validate.sh` проверяет наличие `web/node_modules` и падает с подсказкой; затем `prettier --check`, `eslint`, `tsc -b`, `vite build`, `check-contrast`, `check_web_tokens.sh`. `format.sh` добавляет `prettier --write`.
- CI: `actions/setup-node` с `node-version-file: web/.nvmrc` и кэшем npm, `npm ci --prefix web` перед `validate.sh`.

**D12. Витрина в приложении, без Storybook.** Витрина — единственное место вне `tokens.css`, где разрешены примитивы слоя 1 (решение владельца 2026-10-27): она документирует палитру. Пока компонентов меньше десятка, страница в самом приложении проще и не тянет ещё одну сборку. Разделы: цвета по слоям, темы, шрифты, шкала текста, бумага, статусы (в том числе в оттенках серого), метка ИИ, пометки. Когда появятся продуктовые экраны, витрина переедет на отдельный маршрут.

## Risks / Trade-offs

- [TypeScript 7 вышел недавно; typescript-eslint или Vite могут его ещё не поддерживать] → при установке проверить совместимость; если её нет, закрепить последнюю совместимую мажорную версию TypeScript и записать причину в `tmp/VERIFY.md`.
- [`validate.sh` теперь требует Node.js и `npm ci`] → понятная ошибка с командой; README и AGENTS.md описывают установку.
- [`localStorage` недоступен, например в Safari с запретом хранения сайтов] → по правилу «без fallback» ошибка не глушится, приложение покажет её. Если нужно другое поведение (например, тема только по системе), это решение владельца.
- [Палитра подбирается без фирменного стиля] → значения слоя 1 меняются без правки компонентов. Проверка контраста не даст сломать читаемость при замене.
- [Русские переносы зависят от браузера] → в `tmp/VERIFY.md` записать, переносит ли текст Chrome, Firefox и Safari.

## Migration Plan

Новый каталог, бэкенд не меняется. Откат — удалить `web/` и вернуть `validate.sh`, `format.sh`, CI, `.gitignore`, `AGENTS.md`, `README.md`.

## Решения владельца (2026-10-27)

1. **Сепия** — да: три темы `light`, `sepia`, `dark`; ADR-004 дополнен.
2. **Шаблон сценария по умолчанию** — «американка», как в ADR-004. В этом change влияет только на выбор Cousine (метрика Courier New подходит обоим шаблонам); сам шаблон — change редактора.
3. **Статусы документа** — семь статусов из спеки подтверждены.
4. **Фирменный стиль** — чернильно-синий акцент на тёплой нейтральной основе; логотипа пока нет.
