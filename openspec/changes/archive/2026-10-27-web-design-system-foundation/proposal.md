# Proposal

## Why

Интерфейс писателя будет жить в этом репозитории, в каталоге `web/` (монорепозиторий, решение владельца 2026-10-27, ADR-001). Стек выбран в ADR-004: Refine, CopilotKit, `@plotwell/editor`, shadcn/ui на Tailwind CSS. Каталога `web/` и единого набора стилей пока нет. Без общей дизайн-системы каждый экран (карта Д1–Д22, редактор, чат, очередь пересмотра) придумает свои цвета, статусы и пометки ИИ. Исследования (`openspec/context/_raw/research/`) дают готовые правила для писательского интерфейса: спокойная «бумага», кириллические шрифты, статус не только цветом, явная пометка ИИ. Основу нужно заложить до первых продуктовых экранов.

## What Changes

- Новый каталог `web/`: React + TypeScript на Vite, Tailwind CSS v4, shadcn/ui (CLI и `components.json`), закреплённые версии зависимостей в `package-lock.json`. Пока это одностраничное приложение с витриной дизайн-системы, без продуктовых экранов.
- Дизайн-система в `web/src/design-system/`:
  - токены в три слоя: примитивы OKLCH, семантика shadcn без переименований, продуктовые токены (бумага редактора, статусы документов, пометки в тексте, ИИ);
  - темы светлая, сепия и тёмная через `data-theme` на `<html>`; без выбора пользователя — светлая или тёмная по настройке системы;
  - шрифты из пакетов Fontsource, без CDN: Golos Text для интерфейса, Literata для текста документов и прозы, Cousine (метрика Courier New) для сценария;
  - именованная шкала текста и стиль «бумаги»: колонка около 65 знаков, `lang="ru"`, `hyphens: auto`;
  - базовые компоненты: `StatusBadge` (цвет, иконка и подпись), `AiLabel` (метка ИИ с поповером происхождения), `ThemeSwitcher`, `Paper`, CSS-классы пометок редактора (вставка, удаление, комментарий, текст ИИ, противоречие, упоминание, устаревший фрагмент).
- Витрина: страница, где показаны все токены, темы, шрифты, статусы, метки и пометки.
- Проверки фронтенда входят в `scripts/validate.sh` и CI: ESLint, Prettier, проверка типов, сборка, запрет сырых цветов вне файла токенов, проверка контраста пар токенов во всех темах.
- Документация: `AGENTS.md` (раздел «Where changes belong», команды фронтенда), `README.md`, мастер-спека `overview` (абзац о том, что фронтенда нет).

## Scope

- `web/` целиком: каркас, конфигурация сборки, линтеров и shadcn, дизайн-система, витрина.
- `scripts/validate.sh`, `scripts/format.sh`, `.github/workflows/validate.yml`, `.gitignore`.
- Новый скрипт `scripts/check_web_tokens.sh` (сырые цвета вне токенов).
- `AGENTS.md`, `README.md`.
- Дельты мастер-спек: новые `web/app` и `web/design-system`; изменения `architecture` и `runtime`.
- Проверки и их ограничения в `tmp/VERIFY.md`.

## Non-goals

- Продуктовые экраны: карта методологии, дерево документов, панель этапа, очередь пересмотра, импорт.
- Подключение Refine, CopilotKit и `@plotwell/editor`: каждому нужны контракты бэкенда (вход OIDC, AG-UI, маршруты фрагментов), которых ещё нет. Это отдельные changes. Здесь готовятся только токены, на которые они сядут.
- Вход через Authentik во фронтенде, обращения к API бэкенда, свой код хранения данных.
- Контейнер, сборка образа и деплой фронтенда; сервис в `compose.yaml`.
- Типограф для русского текста (кавычки, неразрывные пробелы): нужен в редакторе и на бэкенде, отдельный change.
- Storybook или Ladle: витрины внутри приложения хватает, пока компонентов мало.
- Изменения бэкенда, Agno, LiteLLM, Authentik и их зависимостей.
- Правка `openspec/changes/archive/**`.

## Capabilities

### New Capabilities
- `web/app`: каркас фронтенда в `web/` — стек и версии, структура каталогов, отсутствие телеметрии и внешних запросов, команды разработки и проверки.
- `web/design-system`: слои токенов, темы, шрифты, шкала текста, «бумага», семантика статусов документов и пометок редактора, метка ИИ, правила использования цветов и контраста, витрина.

### Modified Capabilities
- `architecture`: «Слои приложения» — добавляется `web/` (фронтенд) и `web/src/design-system/`.
- `runtime`: «Проверки кода» — `scripts/validate.sh` и CI проверяют и фронтенд.

## Impact

- Код: новый каталог `web/`; правка `scripts/validate.sh`, `scripts/format.sh`, CI.
- Зависимости: появляется Node.js (LTS, закрепляется в `web/.nvmrc` и `engines`) и npm-зависимости фронтенда. Python-зависимости не меняются.
- CI: шаг установки Node.js и `npm ci` перед `validate.sh`; время проверки растёт на сборку фронтенда.
- Разработчики: для `./scripts/validate.sh` нужен `npm ci --prefix web`; без установленных зависимостей скрипт падает с понятным сообщением.
- Контекст-пак: ADR-004 дополнен темой сепия (решение владельца 2026-10-27).
