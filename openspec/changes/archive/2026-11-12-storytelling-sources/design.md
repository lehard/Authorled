# Design: библиотека первоисточников по сторителлингу

## Context

Зачем нужна библиотека — в proposal.md (Why); что она должна делать — в спеках `sources/library`, `core/database`, `api/agents`.

Что есть (сверка 2026-11-12):
- **Эмбеддинги.** `app.settings.embedder()` — `OpenAIEmbedder` на прокси с псевдонимом `EMBEDDINGS_MODEL`, 1024 измерения. `_CheckedEmbedder` проверяет размерность у одиночного вызова и у асинхронного пакета; синхронного пакета у Agno нет.
- **pgvector.** Расширение `vector` создаёт `agno/db/init.sql` в схеме `public`. Python-пакет `pgvector==0.5.1` стоит транзитивно через `agno[pgvector]`.
- **Поиск Agno.** `PgVector.search`, `vector_search`, `keyword_search` и `hybrid_search` в Agno 3.1.10 ловят любое исключение и возвращают `[]`. Полнотекстовая часть берёт один `content_language` на всю таблицу. Поэтому выбран вариант А: своя таблица в ядре (решение владельца 2026-11-12).
- **Ядро не зависит от Agno** (`agno/core/`). В нём уже есть `core/files._text_of_pdf` (pypdf, абзацы из строк, отказ на PDF без текста), `core/clamav.scan` (INSTREAM, `CLAMAV_HOST`/`CLAMAV_PORT` обязательны) и `markdown-it-py` (`core/prose.py`).
- **Миграции.** Последняя миграция ядра — `0015_note_files`. Тесты сверяют `core/tables.py` с базой (`test_migrations.py`).
- **Команды.** Есть два образца: `python -m demo` — на хосте через `dev.sh seed` с базой checkout'а, `python -m admin` — в контейнере через `scripts/usage.sh local|prod`.
- **Инструменты соавтора** — статический список `READING_TOOLS` и `CHANGING_TOOLS` в `agents/coauthor_tools.py`. Отказ возвращается текстом «Отказ: …» через `_answer`.
- **Первые книги** (папка владельца на Google Drive): EPUB «Поэтики» и четыре английские книги, уже в Markdown, без шапки.

## Goals / Non-Goals

**Goals:**
- канон проверяется до загрузки;
- загрузка атомарна по книге;
- поиск честно падает при сбое;
- поиск по словам идёт на языке книги;
- цитата проверяется кодом;
- полный текст не виден снаружи;
- одна и та же команда загрузки локально и на сервере.

**Non-Goals:**
- очередь Agno для загрузки: это редкая команда владельца, а не запрос;
- кеш векторов между базами (владелец, 2026-11-11);
- переранжирование моделью;
- поиск по нескольким библиотекам.

## Decisions

### 1. Слои: ядро без модели, векторы считает команда или инструмент

`core/sources.py` разбирает канон, режет на куски, пишет и удаляет книгу, ищет по готовому вектору запроса и проверяет цитату. Векторы ядру передают готовыми. Модель зовут `sources/` (команды) и `agents/coauthor_tools.py` (вектор запроса) через `app.settings.embedder()`.

Так ядро остаётся независимым от Agno, а тесты ядра работают на реальном PostgreSQL с векторами, составленными в тесте, без модели.

*Альтернатива:* ядро само зовёт эмбеддер. Отвергнута: это зависимость ядра от Agno и модель в тестах.

### 2. Таблицы

`authorled.source_books`:
- `id` uuid;
- `slug` text unique — имя файла без `.md`;
- `title`;
- `authors` text[] с check `cardinality > 0`;
- `language` с check `in ('ru','en')`;
- `original_year`, `edition_year`, `translation_year` — int null;
- `translator`, `original_title` — text null;
- `embedding_model` text;
- `loaded_at`.

`authorled.source_fragments`:
- `id`;
- `book_id` → `source_books` on delete cascade;
- `position` int, unique (`book_id`, `position`);
- `path` text[];
- `content` text не пустой;
- `ts_config regconfig not null` — `russian` или `english` из языка книги;
- `tsv tsvector generated always as (to_tsvector(ts_config, content)) stored` с индексом GIN;
- `embedding vector(1024) not null` с индексом HNSW `vector_cosine_ops`.

Тип `vector` живёт в схеме `public`, где его создаёт `agno/db/init.sql`; миграция и запросы находят его по пути поиска схем по умолчанию, а таблицы ядра называются со схемой явно (`core/database`, «Схема данных продукта»). `ts_config` хранится в куске, чтобы генерируемая колонка не ссылалась на другую таблицу.

*Альтернатива:* одна таблица с повтором метаданных в каждом куске. Отвергнута: метаданные книги меняются целиком при перезагрузке, а ссылка под цитатой строится из одной строки.

### 3. Канон: шапка YAML и тело по markdown-it

Шапка — YAML между `---`. Ключи:
- `title`, `authors`, `language` — обязательны;
- `original_year`, `edition_year`, `translator`, `translation_year`, `original_title` — по желанию.

Неизвестный ключ — ошибка: она ловит опечатки вроде `translater`.

Тело разбирается `markdown-it-py`:
- заголовки `#`–`####` задают путь;
- блок ` ```mermaid ` — неделимая единица;
- абзац, список или цитата — единица текста;
- `![…](…)` и пустое `[Иллюстрация: ]` — ошибка с разделом;
- Markdown-разметка внутри текста (жирный, курсив) снимается до простого текста, а блок Mermaid хранится как есть, с ограждением.

`pyyaml` объявляется в `pyproject.toml` явно (сейчас он транзитивный, 6.0.3).

### 4. Нарезка

В пределах самого мелкого раздела единицы копятся в кусок, пока он не длиннее 1 200 знаков (`SOURCE_CHUNK_CHARS`, как `CHUNK_SIZE` знаний под предел 512 токенов `gigachat-embeddings`). Единица длиннее предела — абзац без пустых строк — режется по границам предложений, а предложение длиннее предела — по пробелам. Блок Mermaid длиннее предела — ошибка проверки (спека, «Длинная схема»). Раздел без текста кусков не даёт.

Номер куска сквозной по книге. Он нужен, чтобы при надобности прочитать соседний кусок.

### 5. Загрузка и модель эмбеддингов

`sources load <dir>` сначала проверяет все книги папки и только потом считает векторы. Сломанный канон останавливает загрузку до трат на модель, ошибка называет файл.

Дальше книги загружаются по одной:
- векторы считаются пакетами по 64 куска новым методом `_CheckedEmbedder.embed_batch`: один запрос на пакет, проверка числа векторов и размерности, любой сбой — исключение. Пакетные методы Agno 3.1.10 для этого не годятся: синхронного нет, а асинхронный при ошибке переходит на поштучные вызовы и дополняет неудачные (выяснено при реализации 2026-11-12);
- запись идёт одной транзакцией: удалить книгу по `slug` (куски уходят каскадом) и вставить заново с `embedding_model = embeddings_model()`.

Сбой модели до транзакции оставляет прежнюю книгу.

Книги, которых больше нет в папке, `load` не трогает: удаление — только явное `remove`.

Поиск сверяет `embedding_model` всех книг с текущим `EMBEDDINGS_MODEL`. Расхождение — ошибка с именами книг: векторы разных моделей несравнимы, а молча искать по части библиотеки нельзя.

### 6. Поиск: векторы и слова, свод по рангам

`search(connection, query, query_vector, limit=5)` делает два запроса:
- **(а)** 20 ближайших кусков по `embedding <=> query_vector`;
- **(б)** 20 лучших по `ts_rank_cd(tsv, websearch_to_tsquery(ts_config, query))` среди кусков, где `tsv @@ websearch_to_tsquery(ts_config, query)` — запрос разбирается на языке каждого куска.

Свод — Reciprocal Rank Fusion с k = 60, отдаются первые `limit` кусков с метаданными книги.

Пустой запрос — `Invalid`. Ошибки базы не ловятся: инструмент превращает их в отказ «поиск по библиотеке не удался», а не в «ничего не нашлось».

*Альтернатива:* только векторы. Отвергнута: точные термины («перипетия», «status») по словам находятся надёжнее.

### 7. Проверка цитаты

`cite(connection, fragment_id, quote)` работает так:
1. Сжимает пробельные последовательности до одного пробела в цитате и в куске и обрезает края.
2. Пустая цитата или длиннее 300 знаков после сжатия — отказ с пределом.
3. Кусок не найден — отказ.
4. Цитата не подстрока куска — отказ «цитаты нет в источнике».

Кавычки, тире и регистр не нормализуются: «дословно» значит дословно.

Ответ:
- цитата;
- ссылка `Автор, «Название»` + `, пер. <переводчик>`, если он известен, + `, <год издания>`, если известен, + путь через `, ` (например `ч. 2, гл. 5` берётся из заголовков как есть).

### 8. Инструменты соавтора

Оба инструмента читающие, в `READING_TOOLS`, без паузы.

- **`search_sources(query)`.** Пустой запрос — отказ. Вектор запроса считается через `embedder().get_embedding`. Возвращает до 5 кусков с `fragment_id`, ссылкой, языком и текстом. В конце строка: «Цитируй только через cite_source, не больше 300 знаков».
- **`cite_source(fragment_id, quote)`.** Возвращает готовый блок Markdown: `> «цитата»` и строку ссылки, — или отказ.

Доступ к истории не проверяется: библиотека общая и не содержит данных автора. Но инструменты, как и остальные, требуют беседу драфта (`_draft`), чтобы соавтор не работал вне истории.

Исключения модели и базы в `search_sources` превращаются в отказ с причиной, и ошибка пишется в лог без текста запроса.

### 9. Промпт

Новый раздел «Опора на первоисточники» в `SKILL.md`:
- когда искать: вопросы о драматургии, структуре, приёмах, обоснование совета;
- цитата только из `cite_source`, блок вставляется как есть;
- куски длиннее цитаты не пересказываются близко к тексту;
- если ничего не нашлось, на книги не ссылаться;
- английская цитата даётся в оригинале, перевод рядом с пометкой «перевод соавтора».

Справка о сервисе получает строку о том, что соавтор опирается на книги о драматургии и показывает из них короткие цитаты.

### 10. Подготовка черновика (`sources convert <file> <canon-dir>`)

Выполняется на хосте. Сначала `core.clamav.scan(bytes)`: угроза или недоступный clamd — ошибка.

Дальше по расширению:

| Формат | Чем | Как |
|---|---|---|
| `.epub .fb2 .docx .rtf .odt .html .htm .txt .md` | pandoc | `pandoc <file> -t gfm --wrap=none` |
| `.mobi .azw3` | calibre | `ebook-convert` во временный EPUB, дальше pandoc |
| `.pdf` | `core.files` | функция текста PDF; делается публичной `pdf_text` без изменения поведения |
| `.djvu` | djvulibre | `djvutxt`; пустой текст — ошибка «в файле нет текста» |

Метаданные pandoc для шапки берутся `pandoc --template` с `$title$`/`$author$`/`$lang$`. У PDF и DjVu шапка пустая. Картинки (`![…](…)` в выводе pandoc) заменяются заготовкой `[Иллюстрация: ]`. HTML-комментарии удаляются: pandoc оставляет их даже при `gfm-raw_html`, а в книгах из OCR это метки страниц и сканов (`<!-- p. N -->`), которых в каноне быть не должно (выяснено на книгах владельца 2026-11-12). Язык берётся из `lang` или `language` метаданных: EPUB pandoc кладёт во второе.

Черновик пишется в `<canon-dir>/drafts/<slug>.md`, а `slug` — транслит имени файла в kebab-case. Существующий черновик не перезаписывается без `--force`.

Нет программы — ошибка с именем программы и командой `brew install pandoc` / `brew install --cask calibre` / `brew install djvulibre`.

Доводка черновика до канона (шапка, главы, Mermaid, описания иллюстраций) идёт вручную и моделью в сессии разработки, затем `sources check` и перенос файла на верхний уровень папки.

### 11. Где запускаются команды

- **Локально.** `./scripts/dev.sh sources <convert|check|load|remove|list> …` на хосте через `uv run`, с `DB_*` базы checkout'а (`ai` или `ai_dev_<worktree>`), `LITELLM_URL` из `.env` и `CLAMAV_HOST=127.0.0.1` с портом стенда, как у `dev.sh api`. Работает только с локальным стендом, как `seed`.
- **На сервере.** `./scripts/sources.sh <load|remove|list> …` выполняет `python -m sources … /sources` в работающем `agentos-api`. `compose.prod.yaml` монтирует `/srv/authorled/sources` в `/sources` только для чтения. `convert` на сервере не запускается.
- **Канон на сервер** копируется `rsync` под пользователем `deploy` в `/srv/authorled/sources/`: каталог создаётся вне `app` и входит в резервные копии. Шаги — в README («Библиотека источников»). На сервере они выполняются только с подтверждения владельца.

### 12. Закрытость

- Библиотека не входит в `knowledge=[…]` AgentOS и в `registry`.
- Своих маршрутов у неё нет.
- Тексты кусков и запросов не пишутся в логи, а журнал запусков пишет спаны без аргументов и результатов инструментов (`agent-tracing`).

## Risks / Trade-offs

- **[Модель пересказывает кусок длиннее цитаты в свободном тексте]** → правило промпта и строка в выдаче поиска; проверка глазами на стенде. Код ответа не проверяет: проверку после хода отложили, пока не появится нужда (интент, Open Questions).
- **[Русский вопрос плохо находит английский текст]** → свод с векторами; на первых пяти книгах проверка глазами. Плохой результат — отдельное решение (другая модель эмбеддингов).
- **[Перезагрузка всей библиотеки в новую базу worktree считает векторы заново]** → около 8 млн токенов на 50 книг, единицы рублей; кеш отвергнут владельцем.
- **[ClamAV не принимает большие файлы]** (у clamd предел потока по умолчанию 25 МБ) → ошибка называет файл. Большие PDF стоит ужать или проверить отдельно; предел clamd меняется только решением владельца.
- **[pandoc теряет главы у плохо размеченных EPUB или FB2]** → черновик проверяет человек, а `check` требует хотя бы один заголовок.
- **[Авторское право]** → риск принят владельцем 2026-11-11; записывается в `05-security-and-compliance.md` как принятый риск.

## Migration Plan

1. Миграция `0016_sources` создаёт пустые таблицы; данные историй не трогаются. Отката нет, как у остальных миграций ядра: только вперёд.
2. После релиза — только с подтверждения владельца:
   - создать `/srv/authorled/sources`;
   - скопировать канон;
   - выполнить `./scripts/sources.sh load`.

   До загрузки поиск соавтора ничего не находит, и соавтор не ссылается на книги.
