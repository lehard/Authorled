# Spec Delta

## MODIFIED Requirements

### Requirement: Наборы замера
У замера MUST быть два набора. `wide` — выборка id из рабочей части широкого набора экзамена маршрутизации (`agno/evals/routing/cases/wide-work.toml`); id из отложенной части экзамена MUST NOT в неё входить. `demo` — свои случаи по демо-историям в рабочей и отложенной частях без общих id и в части проверок наставника `checks`, у которой тоже нет общих id с ними. В `wide` и в частях `work` и `holdout` набора `demo` MUST быть случаи всех 12 доменов широкого состава и всех разделов; к части `checks` это правило не относится.

#### Scenario: Неизвестный id
- GIVEN в файле выборки есть id, которого нет в `wide-work.toml`
- WHEN запускается замер
- THEN замер MUST завершиться ошибкой, называющей id, до первого вызова модели

#### Scenario: Домен без случаев
- GIVEN в выборке нет ни одного случая, ожидающего домен `wide-help`
- WHEN запускается замер
- THEN замер MUST завершиться ошибкой, называющей домен, до первого вызова модели

#### Scenario: Отложенная часть без домена
- GIVEN в отложенной части `demo` нет ни одного случая домена `wide-research`
- WHEN запускается замер набора `demo` (любой части)
- THEN замер MUST завершиться ошибкой, называющей часть и домен, до первого вызова модели

#### Scenario: Часть проверок без всех доменов
- GIVEN в части `checks` все случаи ожидают только домен `wide-review`
- WHEN запускается замер `--set demo --part checks`
- THEN замер MUST идти без ошибки покрытия

### Requirement: Прогон замера
Команда `python -m evals.coauthor` MUST загружать `.env`, обращаться к моделям только через LiteLLM-прокси и требовать явного выбора набора (`--set wide|demo`, для `demo` — часть `--part work|holdout|checks`) и объёма: все случаи (`--all`) или первые N (`--sample N`). Замер тратит вызовы модели и MUST NOT запускаться из `validate.sh` или CI.

#### Scenario: Без цены модели
- GIVEN у `claude-sonnet` или `deepseek-fast` нет цены в `model_prices.toml`
- WHEN запускается замер
- THEN команда MUST завершиться ошибкой, называющей псевдоним, до первого вызова модели

## ADDED Requirements

### Requirement: Случай с открытым текстом сценария
Случай набора `demo` MAY открывать текст сценария и выделять в нём сцену по номеру (`open`). Сцена с этим номером MUST существовать в драфте, который открывает история случая (`web/src/data/demo.json`). Контекст чата такого случая MUST быть тем, что прикладывает чат при открытом тексте сценария и выделенной сцене: содержимое драфта с метками элементов и выделенный фрагмент.

#### Scenario: Сцены нет
- GIVEN случай `open = { scene = 9 }`, а в сценарии его истории 7 сцен
- WHEN запускается замер
- THEN замер MUST завершиться ошибкой, называющей случай и сцену, до первого вызова модели

#### Scenario: Контекст выделения
- GIVEN случай «Где вода?» с `open = { scene = 6 }` в «Тихой воде»
- WHEN соавтор получает сообщение случая
- THEN контекст MUST содержать «Открыт документ: Текст сценария.», а после «Автор выделил фрагмент:» — абзацы сцены 6

### Requirement: Ожидание проверки для судьи
У случая с открытым текстом сценария судья MUST получать строку ожидания: одно–три места с точной цитатой из выделенной сцены, объяснение, почему место слабое, вопрос автору и нет переписанной сцены целиком.

#### Scenario: Строка ожидания
- GIVEN случай с `open = { scene = 6 }` и `action = "none"`
- WHEN собираются критерии судьи
- THEN среди строк ожидания MUST быть строка про одно–три места с точной цитатой из выделенной сцены, объяснение, вопрос автору и запрет переписывать сцену целиком
