# Spec Delta

## Purpose

Свои маршруты продукта `/api/v1/coauthor-feedback` (тег OpenAPI: Coauthor feedback), без вызова модели. Автор ставит, снимает и читает оценку «Полезно» / «Не то» у ответов соавтора, а продукт получает сигнал качества соавтора. Оценки хранятся в ядре (`authorled.coauthor_feedback`).

## ADDED Requirements

### Requirement: Поставить оценку ответу соавтора
`PUT /api/v1/coauthor-feedback/{run_id}` с телом `{"value": "useful" | "not_useful"}` MUST сохранять оценку вызывающего этому запуску соавтора и отвечать `200` с `run_id`, `session_id`, `value` и `updated_at`. Повторный `PUT` MUST заменять значение: у пользователя одна оценка на запуск. Другие поля тела и другие значения MUST давать `422`, `detail` называет поле.

#### Scenario: Полезно
- GIVEN автор получил ответ соавтора в запуске `r1` беседы своей истории
- WHEN он отправляет `PUT /api/v1/coauthor-feedback/r1` с `{"value": "useful"}`
- THEN система MUST ответить `200` с `value` `useful` и `session_id` этой беседы

#### Scenario: Смена оценки
- GIVEN у запуска `r1` стоит оценка автора `useful`
- WHEN он отправляет `PUT` с `{"value": "not_useful"}`
- THEN ответ MUST содержать `not_useful`, и у автора MUST остаться одна оценка запуска `r1`

#### Scenario: Неизвестное значение
- WHEN автор отправляет `PUT` с `{"value": "great"}`
- THEN система MUST ответить `422`, `detail` MUST называть поле `value`, оценка MUST NOT меняться

### Requirement: Снять оценку
`DELETE /api/v1/coauthor-feedback/{run_id}` MUST снимать оценку вызывающего у этого запуска и отвечать `204`. Если оценки нет, ответ MUST быть тем же `204`.

#### Scenario: Снять поставленную
- GIVEN у запуска `r1` стоит оценка автора `useful`
- WHEN он отправляет `DELETE /api/v1/coauthor-feedback/r1`
- THEN система MUST ответить `204`, и в списке оценок беседы запуска `r1` MUST NOT быть

#### Scenario: Снять несуществующую
- GIVEN у запуска `r1` нет оценки автора
- WHEN он отправляет `DELETE /api/v1/coauthor-feedback/r1`
- THEN система MUST ответить `204`

### Requirement: Оценки беседы
`GET /api/v1/coauthor-feedback?session_id=<id>` MUST возвращать оценки вызывающего в этой беседе: список `run_id`, `value`, `updated_at`. Чужих оценок и снятых MUST NOT быть. Без `session_id` или с идентификатором не в форме беседы истории (`<история>:<драфт>:<uuid>`) ответ MUST быть `422`.

#### Scenario: Беседа после перезагрузки
- GIVEN в беседе автора два ответа соавтора, первый оценён `useful`
- WHEN фронтенд запрашивает оценки беседы
- THEN список MUST содержать одну оценку: запуск первого ответа и `useful`

#### Scenario: Нет беседы в запросе
- WHEN клиент вызывает `GET /api/v1/coauthor-feedback` без `session_id`
- THEN система MUST ответить `422`

### Requirement: Доступ к оценке
Оценить и снять оценку можно только у запуска агента `coauthor`, который записан в журнале расхода ядра на вызывающего, в беседе истории, к которой у вызывающего есть доступ. Иначе — `404` «Ответ соавтора не найден.», оценка MUST NOT меняться. Список оценок беседы истории без доступа MUST давать `404`. Отказы MUST отдаваться как `application/problem+json`.

#### Scenario: Чужой запуск
- GIVEN запуск `r2` записан в журнале на другого пользователя
- WHEN автор отправляет `PUT /api/v1/coauthor-feedback/r2`
- THEN система MUST ответить `404`, оценка MUST NOT сохраняться

#### Scenario: Неизвестный запуск
- GIVEN запуска `nope` нет в журнале расхода
- WHEN автор отправляет `PUT /api/v1/coauthor-feedback/nope` с `{"value": "useful"}`
- THEN система MUST ответить `404`

#### Scenario: Доступ к истории потерян
- GIVEN запуск `r1` автора идёт в беседе истории, к которой у него больше нет доступа
- WHEN он отправляет `PUT /api/v1/coauthor-feedback/r1`
- THEN система MUST ответить `404`

#### Scenario: Беседа чужой истории
- GIVEN беседа относится к истории, к которой у вызывающего нет доступа
- WHEN он запрашивает оценки этой беседы
- THEN система MUST ответить `404`

### Requirement: Оценка без текста в логах
Маршруты оценки MUST NOT вызывать модель. В логи API MUST попадать только идентификаторы запуска и беседы, значение оценки и код ответа, без текста ответа соавтора и произведения.

#### Scenario: Лог оценки
- WHEN автор ставит оценку `not_useful`
- THEN логи API MUST NOT содержать текст ответа соавтора и произведения
