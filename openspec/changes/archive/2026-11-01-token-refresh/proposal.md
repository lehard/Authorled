# Proposal

## Why

Владелец не смог войти 2026-11-01. Два вызова одновременно отправили в Authentik один и тот же refresh token. Authentik выдаёт новый refresh token при каждом продлении и отклоняет повторное использование старого (`invalid_grant`, событие «Revoked refresh token was used»). Приложение показало это как сбой «Не удалось проверить вход», а «Попробовать снова» отправляло тот же отклонённый токен по кругу. Основание — бизнес-интент `business-intents/token-refresh.md`: следуем устройству Authentik и `oidc-client-ts`, а не ослабляем защиту.

## What Changes

- **Одно продление на вкладку.** Продление идёт вызовом `oidc-client-ts` (`signinSilent` с refresh token), но через один общий шлюз. Одновременные запросы токена ждут одного продления и получают его результат. Таймер «скоро истечёт» библиотеки ходит через тот же шлюз, а не своим отдельным вызовом.
- **Отказ Authentik означает конец сессии.** На `invalid_grant` токены вкладки удаляются, и приложение открывает `/login?returnTo=…`. Если сессия Authentik жива, `/login` берёт токены без формы, как и сейчас.
- **Сбой — это не отказ.** Нет сети, Authentik недоступен, ответ 5xx или тайм-аут — по-прежнему экран «Не удалось проверить вход» с причиной и «Попробовать снова».
- **Запросы к API** (меню и `/settings` через `/api/v1/me`, чат) при конце сессии ведут на `/login`, а не показывают свою ошибку.
- **Настройки провайдера Authentik не меняются:** новый refresh token на каждое продление и отказ на повторное использование остаются.

## Scope

- `web/src/auth/userManager.ts`: шлюз продления, разбор ошибки продления, событие конца сессии.
- `web/src/auth/authProvider.ts` (`check`), `web/src/app/RefineRoot.tsx` (`RequireAuth`): конец сессии → `/login`, сбой → прежний экран.
- `web/src/auth/LoginScreen.tsx`, `web/src/account/meApi.ts`, `web/src/screens/project/chat/api.ts`: токен только через `activeUser()`.
- Спеки: дельты `web/workspace` и `auth`.
- Проверка в Playwright (одновременные запросы с истёкшим токеном, дублированная вкладка, отозванная сессия, выключенный Authentik) и по журналу событий Authentik; запись в `tmp/VERIFY.md`.

## Non-goals

- `refresh_token_threshold`, сроки жизни токенов и другие настройки провайдера в blueprints.
- Привязка токенов к браузеру (DPoP).
- Общие токены между вкладками (`localStorage`, синхронизация вкладок, Web Locks): каждая вкладка держит свои токены, дублированная вкладка восстанавливается через `/login`.
- Изменение экранов входа, кроме пути при конце сессии.
- Проверка в Safari автоматикой: Playwright запускает Chromium; Safari — ручная проверка владельцем (см. tasks).

### New Capabilities

### Modified Capabilities
- `web/workspace`: новые требования «Продление входа» (одно продление на вкладку), «Конец сессии» (`invalid_grant` → `/login`), «Сбой продления» (причина и «Попробовать снова»).
- `auth`: новое требование «Refresh token фронтенда» — каждый refresh token используется один раз; смена токена при продлении и отказ на повторное использование в Authentik остаются включены.

## Impact

- Только фронтенд и спеки; бэкенд, blueprints и Authentik не меняются.
- Журнал событий Authentik перестаёт получать «Revoked refresh token was used» от нормальной работы приложения; такое событие после выката означает реальную проблему.
