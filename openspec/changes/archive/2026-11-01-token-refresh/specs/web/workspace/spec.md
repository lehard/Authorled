## ADDED Requirements

### Requirement: Продление входа
Когда Access Token истёк или скоро истечёт, вкладка MUST продлевать его по refresh token одним запросом к Authentik, сколько бы частей приложения ни ждали токен одновременно; все они MUST получать результат этого продления. Приложение MUST NOT повторно отправлять refresh token, который уже ушёл в Authentik.

#### Scenario: Вкладка проснулась с истёкшим токеном
- GIVEN Access Token вкладки истёк, пока вкладка спала
- WHEN одновременно запрашивают токен проверка входа, меню пользователя, `/settings` и чат
- THEN в Authentik MUST уйти ровно один запрос продления
- AND экран MUST работать без перезагрузки и без экрана входа

#### Scenario: Скоро истечёт
- GIVEN до истечения Access Token осталось меньше минуты, и приложение в этот момент запрашивает токен
- WHEN срабатывает продление по таймеру
- THEN в Authentik MUST уйти один запрос продления, а не два

### Requirement: Конец сессии
Если Authentik отказал в продлении (`invalid_grant`: refresh token отозван, истёк или уже использован), приложение MUST удалить токены вкладки и MUST открыть `/login` с возвратом на текущий адрес. Запросы к API, ждавшие токен, MUST NOT показывать свою ошибку поверх. Если сессия Authentik жива, `/login` MUST взять токены без формы (требование «Вход»).

#### Scenario: Дублированная вкладка
- GIVEN вкладка B — копия вкладки A с теми же токенами, и A уже продлила токен
- WHEN B запрашивает токен, а сессия Authentik жива
- THEN B MUST оказаться на том же адресе с новыми токенами, без формы входа и без экрана «Не удалось проверить вход»

#### Scenario: Сессия Authentik закончилась
- GIVEN refresh token вкладки отозван, и сессии Authentik нет
- WHEN вкладка запрашивает токен на `/p/water/text`
- THEN MUST открыться `/login` с шагом почты, а после входа — `/p/water/text`

### Requirement: Сбой продления
Если продление не удалось из-за сбоя (нет сети, Authentik недоступен, ответ 5xx, тайм-аут), приложение MUST NOT удалять токены и MUST показывать «Не удалось проверить вход» с причиной и «Попробовать снова», которое повторяет продление.

#### Scenario: Authentik остановлен
- GIVEN Access Token истёк, а Authentik остановлен
- WHEN пользователь открывает приложение
- THEN MUST показываться «Не удалось проверить вход» с причиной
- AND после запуска Authentik «Попробовать снова» MUST впускать без повторного входа
