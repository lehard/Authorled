# Proposal

## Why

В Safari 18.6 после перевода строки (Shift+Enter) в поле чата соавтора на строку выше остаётся вторая каретка; она сливается с новой в одну длинную черту (скриншот владельца 2026-11-09). Автор видит в поле след и не понимает, где курсор. Ошибка в общем растущем поле, значит, она есть во всех многострочных полях интерфейса.

## What Changes

- Общее поле `GrowingTextarea` после смены значения, если оно в фокусе, заставляет браузер заново поставить и нарисовать каретку на её текущем месте, чтобы на старом месте не оставалось следа.
- В спеку `web/design-system` рядом с требованием «Многострочные поля растут с текстом» добавляется требование «Каретка без следа в растущем поле»: после изменения высоты поля в нём одна каретка.
- Вид поля, его рост, пределы и прокрутка внутри после предела не меняются.

## Capabilities

### New Capabilities

### Modified Capabilities
- `web/design-system`: новое требование «Каретка без следа в растущем поле» — когда поле меняет высоту, каретка видна только на её месте, без следа на прежней строке. Требование «Многострочные поля растут с текстом» не меняется.

## Scope

- `web/src/design-system/components/GrowingTextarea.tsx`.
- Спека `web/design-system`.

## Non-goals

- Переход на `field-sizing: content` (спека запрещает его в `web/src`) и другой способ роста поля.
- Изменения вида поля, отступов, пределов роста и поведения Enter в чате.
- Ветки кода по браузеру.

## Impact

- Все места `GrowingTextarea`: чат соавтора, поля документов, синопсис и проза, заметки, комментарии, карточки сцен.
- Без новых зависимостей, без изменений API и бэкенда.
- Ручная проверка в настоящем Safari: встроенный браузер разработки — Chromium, где ошибка не повторяется.
