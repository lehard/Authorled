# Design

## Context

Мотив: proposal.md, «Why».

Как результат действия соавтора попадает в строку итога сейчас:

- Agno 3.1.10, `on_tool_call_completed` (`agno/os/interfaces/agui/handlers.py`), шлёт `TOOL_CALL_RESULT` с `content = to_json_str(tool.result)`. `to_json_str` (`agno/os/interfaces/agui/utils.py`) возвращает валидный JSON как есть, Python-repr переводит в JSON, а обычную строку оборачивает `json.dumps` (по умолчанию `ensure_ascii=True`, отсюда `О…`). Значит, всё, что приходит в `content`, — валидный JSON.
- Инструменты соавтора (`agno/agents/coauthor_tools.py`) при успехе возвращают JSON-объект `{"done", "target"}`, при отказе — строку «Отказ: …». Ошибка инструмента, которую ловит сам Agno, тоже приходит строкой.
- `CoauthorChat.tsx` складывает `content` из подписчика `onToolCallResultEvent` в карту `outcomes`. Для вызова без записи в карте `ActionLines` берёт сообщение `tool` этого вызова, у которого нет решения автора (`decisionOf`).
- `Outcome` (`ActionLines.tsx`) вызывает `doneOf(content)`. Если это не объект «сделано», показывает `content` как есть в красной строке. Именно здесь JSON-строка отказа выходит сырой.
- Разговор из истории (`loadConversation` в `chat/api.ts`) содержит только текст сообщений, без вызовов инструментов. Строк действий там нет, поэтому второго формата результата, который нужно было бы поддерживать, нет.
- Проверки фронтенда в `validate.sh` — Node-скрипты (`web/scripts/check-*.ts`), которые Node запускает напрямую. Они импортируют модули только относительными путями с расширением `.ts`. Модуль `chat/actions.ts` импортирует `PROFILE` через алиас `@/`, поэтому из такого скрипта его загрузить нельзя.

## Goals / Non-Goals

**Goals:**
- Один разбор результата на клиенте с тремя исходами: «сделано», «отказ с текстом», «нечитаемый».
- Образцы в точном виде, в каком их отдаёт Agno 3.1.10, проверяются в `validate.sh`.

**Non-Goals:**
- Менять бэкенд, `to_json_str` или контракт инструментов (proposal.md, Non-goals).
- Общий разбор любых результатов инструментов. Строка итога есть только у меняющих действий соавтора.

## Decisions

1. **Разбор в отдельном модуле без алиасов: `web/src/screens/project/chat/outcome.ts`.** Функция `readOutcome(content: string)` возвращает `{ kind: "done", done, target }`, `{ kind: "refused", text }` или `{ kind: "unreadable" }`. Порядок: `JSON.parse`. Объект с `done: string` и `target: object` — это «сделано». Строка — это «отказ» с этим текстом. Всё остальное, включая невалидный JSON, — «нечитаемый». В модуле нет импортов времени выполнения, поэтому его загружает Node-проверка.
   - Альтернатива: оставить `doneOf` и рядом добавить `refusalOf` в `actions.ts`. Отклонена: две функции, каждая решает свою половину, проще пропустить третий случай, и Node-проверка не загрузит `actions.ts`.
   - Альтернатива: показывать сырой `content`, если `JSON.parse` упал. Отклонена: это молчаливая подмена (07-anti-patterns, п. 26). По Agno 3.1.10 невалидного JSON в `content` быть не может, и если он появится, это ошибка, которую нужно увидеть.
2. **`doneOf` и `changedResources` в `actions.ts` берут результат из `readOutcome`.** Вызывающий код не меняется, а «сделано» определяется в одном месте.
3. **Нечитаемый результат — красная строка «Не удалось прочитать результат действия» и `console.error` с сырым `content` и id вызова.** Автору сырой текст не показывается (спека). Разработчик видит в консоли, что пришло.
4. **Проверка `npm run check:chat` (`web/scripts/check-chat.ts`) в шаге фронтенда `validate.sh`.** Образцы:
   - `{"done":"Создан персонаж «Пётр»","target":{"type":"document","id":"…","kind":"character"}}` → «сделано»;
   - `json.dumps("Отказ: Поле «role» …")` в форме с `\u`-экранами, как на сервере → «отказ» с читаемым текстом;
   - `42`, `[]`, `{"accepted":true}`, `не JSON` → «нечитаемый».
   Образцы записаны строками в самом скрипте, рядом комментарий со ссылкой на `to_json_str` Agno 3.1.10.
   - Альтернатива: вписать случаи в `check-editor.ts`. Отклонена: этот скрипт про редактор, а у чата своя область.
   - Альтернатива: только живая проверка. Отклонена: ошибка и появилась потому, что строку отказа вживую не проверяли.

## Risks / Trade-offs

- [Agno при обновлении изменит `to_json_str`, например перестанет оборачивать строки] → образцы в `check-chat.ts` повторяют формат 3.1.10. При обновлении Agno их нужно сверить, комментарий в скрипте об этом напоминает.
- [Карточка «Разрешить / Отклонить» хранит ответ автора `{"accepted": …}` в сообщении `tool`] → `ActionLines` по-прежнему отбирает ответы автора через `decisionOf` до вызова `Outcome`. Если такой ответ всё же попадёт в `readOutcome`, строка станет «нечитаемой», а не покажет `{"accepted":true}`. Образец `{"accepted":true}` в проверке это фиксирует.

## Migration Plan

Меняется только клиент. Выкатка — обычным релизом, откат — релизом предыдущего тега. Данных и миграций нет.
