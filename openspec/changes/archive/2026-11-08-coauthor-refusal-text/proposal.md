# Proposal

## Why

Требование «Сделанное соавтором в чате» (`web/workspace`) уже говорит, что отказ ядра показывается строкой с причиной. На сервере (v0.3.1, 2026-11-08) эта строка вышла нечитаемой: `"Отказ: Поле «role» …"` вместо «Отказ: Поле «role» должно быть одним из: main, secondary, episodic.». Автор не видит, почему соавтор не смог выполнить действие. Источник: `business-intents/coauthor-refusal-text.md`.

Причина: Agno 3.1.10 (`to_json_str` в `agno/os/interfaces/agui/utils.py`) передаёт по AG-UI валидный JSON как есть, а обычную строку оборачивает в JSON-строку через `json.dumps`. Успех инструмента соавтора (`{"done", "target"}`) приходит объектом и показывается правильно. Отказ «Отказ: …» приходит JSON-строкой, а `Outcome` в `web/src/screens/project/chat/ActionLines.tsx` показывает её сырой.

## What Changes

- Строка итога под действием соавтора читает результат как JSON из AG-UI. Объект `{"done", "target"}` даёт строку «сделано» со ссылкой, как сейчас. JSON-строка даёт строку отказа с её текстом, без кавычек и `\u`-последовательностей.
- Результат другого вида (не JSON, число, массив, объект без `done` и `target`) — явная ошибка: строка «Не удалось прочитать результат действия» и запись в консоль с сырым результатом. Молча показывать сырой текст строка больше не будет.
- В требовании «Сделанное соавтором в чате» уточняется, что причина отказа читается как текст, и добавляется сценарий для нечитаемого результата.

## Scope

- Разбор результата действия соавтора на клиенте: `web/src/screens/project/chat/actions.ts` и `ActionLines.tsx`.
- Проверка разбора на образцах результата в виде, в каком его отдаёт Agno 3.1.10.
- Дельта спеки `web/workspace`, требование «Сделанное соавтором в чате».
- Живая проверка отказа на локальном стенде и запись в `tmp/VERIFY.md`.

## Non-goals

- Менять формат результата инструментов на бэкенде (например, отдавать отказ объектом) или их контракт.
- Обходить или менять `to_json_str` в Agno.
- Менять формулировки отказов ядра в `agno/agents/coauthor_tools.py`.
- Учить модель соавтора передавать правильные значения с первой попытки.
- Показывать строки действий в разговоре, открытом из истории чата. История загружает только текст сообщений автора и соавтора (`loadConversation` в `web/src/screens/project/chat/api.ts`), строк действий там нет ни сейчас, ни после этого change.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `web/workspace`: в требовании «Сделанное соавтором в чате» причина отказа показывается читаемым текстом, а результат, который нельзя прочитать, — явной ошибкой.

## Impact

- Код: `web/src/screens/project/chat/actions.ts` (разбор результата), `web/src/screens/project/chat/ActionLines.tsx` (`Outcome`).
- Бэкенд, API, база данных и зависимости не меняются.
- Проверка: `npm run check:*` фронтенда в `validate.sh` и живой отказ на локальном стенде.
