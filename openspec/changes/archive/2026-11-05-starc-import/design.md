# Design: импорт проектов STARC

## Context

Мотивация — `proposal.md`, требования — `specs/`. После `story-data-backend` разборщики живут в `agno/core/importers/` и выдают абзацы (`Paragraph`) для общего сборщика `screenplay.py`; загрузка (`core/files.py`) знает форматы по таблице `FORMATS`/`ALLOWED`, импорт (`core/imports.py`) — по `parse_manuscript`. Формат `.starc` описан в `openspec/context/_raw/research/Разбор STARC для интеграции/Отчёт.md` («Файл .starc»): одна база SQLite, таблица `documents` (`uuid`, `type`, `content`), дерево проекта — XML документа типа 1 (Structure), сценарий 10100 с текстом 10104, персонаж 30001, локация 40001; текст — XML с группами `scene`/`beat` и абзацами по типу, значение в `<v><![CDATA[…]]></v>`. Официальной спецификации нет; XML персонажей и локаций не сверен.

## Goals / Non-Goals

**Goals:** читать `.starc` без изменения файла и без кода STARC (ADR-005: только наблюдаемый формат); отказывать целиком при любом расхождении.

**Non-Goals:** драфты, комментарии, правки рецензирования, история изменений (`documents_changes`), запись `.starc`.

## Decisions

1. **Чтение копии только на чтение.** Байты пишутся во временный файл, `sqlite3.connect("file:…?mode=ro&immutable=1", uri=True)`; после разбора файл удаляется. Альтернатива — `sqlite3.deserialize` в памяти: удобнее, но зависит от сборки SQLite; временный файл проще и одинаков везде.
2. **Структура.** Документ типа 1 разбирается `xml.etree`; ровно один `item` сценария (10100) с дочерним текстом (10104), иначе `Invalid`. Персонажи и локации — `item` с MIME `.../character` и `.../location` (в документах типы 30001 и 40001): имя из атрибута `name`, имя целиком заглавными приводится к виду «Вера», как имена из текста; корзина проекта пропускается. Роль лежит в теге `story_role` профиля: 0 — главная, 1 — второстепенная, 2 и 3 (нет роли) — эпизодическая.
3. **Текст.** Таблица тегов STARC → типы редактора (`scene_heading`→`sceneHeading`, `scene_characters`→`sceneCharacters`, `action`, `character`, `parenthetical`, `dialogue`, `lyrics`, `shot`, `transition`, `unformatted_text`→`unformatted`, `inline_note`→`inlineNote`, `beat_heading`→`beat`, акты и последовательности); точный список сверяется с образцом. Акты и последовательности — папки `act`/`sequence` с абзацами `act_heading`/`sequence_heading`; `act_footer` и `sequence_footer` пропускаются. Параметры группы `scene` (`title`, `story_day`, `color`, `tags`) → `alt`, `day`, `color`, `tags` заголовка; цвет STARC переводится в ближайшую из четырёх меток редактора по таблице, иначе пусто. Неизвестный тег — `Invalid` с его именем.
4. **Подключение.** `.starc` добавляется в `FORMATS` (`application/x-starc`, сигнатура `SQLite format 3\0`) и в `ALLOWED` для `chat` и `import`; извлечение текста и `parse_manuscript` вызывают `parse_starc`.

## Сверка с образцом

Образец 2026-11-05 (STARC 0.8.2 dev 26) подтвердил таблицу `documents`, документ структуры, `item` с MIME-типами, текст 10104, группу `scene` с `content`, абзацы `scene_heading`, `action`, `character`, `parenthetical`, `dialogue` со значением в `<v>`, тег `story_role` со значением `3` у персонажей и локаций, HTML-экранирование внутри CDATA (`&quot;`).

Остального в образце нет. Решением владельца 2026-11-05 это ограничение «только наблюдаемый формат» снято для одного change: разбор доделан по фактам открытых исходников STARC (`text_model_*`, `character_model.h`, `location_model.h`, `text_template.cpp`), код STARC не перенесён. Так получены значения ролей, папки `act`/`sequence` с `act_heading`, бит внутри `content` сцены, параметры сцены, разметка `fms`. На файле, сохранённом в STARC, это не сверено: `openspec/context/backlog-stage-2.md`, раздел «Импорт STARC».

Неизвестный элемент отклоняет файл целиком. Известные данные, которым нет места в редакторе, пропускаются: иначе почти любой реальный проект получал бы отказ.

## Risks / Trade-offs

- [Формат STARC меняется между версиями] → тесты на образце 0.8.x и на испорченных копиях; файл новой версии с другой структурой отклоняется целиком.
- [Теги профилей не сверены] → берём только имя и роль; поля профиля из STARC не переносим в этом change.
- [Часть формата взята из исходников, а не из файла] → неизвестное отклоняется целиком; ошибочное значение роли или цвета отказа не даст, поэтому сверка на полном образце записана в бэклог.
