# Spec Delta

## Purpose

Знак продукта «Соавтор»: откуда берутся его файлы, какие значки страницы есть у приложения и сайта и где интерфейс показывает знак.

## ADDED Requirements

### Requirement: Источник знака
Файлы знака MUST браться только из `docs/brand/`. Копии в `web/public/` и `site/public/` MUST совпадать с файлами `docs/brand/` байт в байт. Если копия отличается или её нет, `./scripts/validate.sh` MUST завершаться ошибкой, которая называет файл. Подмена отсутствующего файла другим MUST NOT происходить.

#### Scenario: Копия разошлась с источником
- **GIVEN** в `web/public/favicon.svg` изменён цвет плашки, а `docs/brand/mark.svg` остался прежним
- **WHEN** выполняется `./scripts/validate.sh`
- **THEN** проверка MUST завершиться ошибкой с путём `web/public/favicon.svg`

#### Scenario: Копии нет
- **GIVEN** из `site/public/` удалён `apple-touch-icon.png`
- **WHEN** выполняется `./scripts/validate.sh`
- **THEN** проверка MUST завершиться ошибкой с путём `site/public/apple-touch-icon.png`

### Requirement: Значки страницы приложения
Каждая страница приложения MUST ссылаться на свои значки: SVG, ICO с размерами 16, 32 и 48, значок для iOS 180×180 и манифест с названием «Соавтор» и значками 192, 512 и 512 для маски. Все эти файлы MUST отдаваться с адреса самого приложения, без сторонних хостов. Цвет темы страницы MUST быть цветом плашки знака.

#### Scenario: Вкладка приложения
- **GIVEN** собранное приложение `web/dist/`
- **WHEN** читается `index.html`
- **THEN** в нём MUST быть ссылки на `/favicon.svg`, `/favicon.ico`, `/apple-touch-icon.png` и `/manifest.webmanifest`
- **AND** все четыре файла MUST лежать в `web/dist/`

#### Scenario: Значок на домашнем экране
- **GIVEN** приложение открыто в Chrome на Android
- **WHEN** пользователь добавляет его на домашний экран
- **THEN** значком MUST быть знак из манифеста, а не снимок страницы
- **AND** манифест MUST открывать приложение отдельным окном (`display: standalone`)

### Requirement: Значки страницы сайта
Каждая страница сайта, включая 404, MUST ссылаться на те же значки: SVG, ICO, значок для iOS и манифест. У манифеста сайта MUST быть `display: browser`. Проверка сборки сайта MUST завершаться ошибкой, если в сборке нет какого-то из этих файлов или ссылки на него на какой-то странице.

#### Scenario: Значки на всех страницах
- **GIVEN** собранный сайт
- **WHEN** читаются `index.html`, `pricing/index.html` и `404.html`
- **THEN** в каждом MUST быть ссылки на `/favicon.svg`, `/favicon.ico`, `/apple-touch-icon.png` и `/manifest.webmanifest`

#### Scenario: Нет значка в сборке
- **GIVEN** в `site/public/` нет `favicon.ico`
- **WHEN** собирается сайт
- **THEN** проверка сборки MUST завершиться ошибкой с именем `favicon.ico`

### Requirement: Знак в интерфейсе
Заставка приложения, экран входа, шапка полки и шапка сайта MUST показывать знак из файла знака, а рядом название «Соавтор» живым текстом в цвете темы. Знак MUST быть изображением с фиксированными цветами, одинаковыми во всех темах. Для экранных чтецов знак MUST быть скрыт: название читается из текста.

#### Scenario: Шапка полки в «Ночи»
- **GIVEN** у пользователя тема `dark`
- **WHEN** открыта полка
- **THEN** слева в шапке MUST стоять знак с синей плашкой, белой «С» и курсором цвета лампы, как в светлой теме
- **AND** название «Соавтор» MUST быть цвета основного текста темы `dark`

#### Scenario: Заставка до скрипта
- **GIVEN** скрипт приложения ещё не пришёл
- **WHEN** показывается заставка
- **THEN** перед названием «Соавтор» MUST стоять знак, а не пустой квадрат

#### Scenario: Знак не читается вслух
- **GIVEN** экранный чтец на экране входа
- **WHEN** он читает блок над карточкой
- **THEN** MUST прозвучать «Соавтор» один раз
