# Design

## Context

Страница группы (`web/src/screens/project/docs/GroupDoc.tsx`) рисует `data.chars`, `data.locs` или `data.worlds` одной лентой и ставит у строки метку роли через `ROLES` (`web/src/data/profiles.ts`); неизвестная роль там уже бросает ошибку. Роль приходит из ядра и проверяется и ядром, и `apiProvider.ts`. Свёртка текста для поиска уже есть: `foldText` в `web/src/editor/fold.ts` (нижний регистр и «ё» как «е», как в поиске ядра).

## Goals / Non-Goals

**Goals:**
- Группы и поиск строятся из данных, которые экран уже получил, без новых запросов.

**Non-Goals:**
- Общий компонент «список с группами» для других экранов: потребителей, кроме этой страницы, нет.
- Поиск через ядро (`/api/v1/.../search`): он ищет по тексту истории, а здесь нужен фильтр видимого списка.

## Decisions

1. **Фильтр на клиенте.** Список уже целиком загружен для экрана; фильтр меняет только то, что показано, и ничего не решает за автора и не сохраняет, поэтому это отображение, а не логика продукта (07-anti-patterns, п. 10). Альтернатива — запрос к поиску ядра — дала бы сеть на каждый символ и другую семантику (поиск по текстам).
2. **Свёртка через `foldText`.** Одно правило с поиском в тексте и поиском ядра; своя нормализация разошлась бы с ними.
3. **Подписи групп рядом с `ROLES`.** Множественное число («Главные», «Основные», «Второстепенные», «Эпизодические») добавляется полем к каждой роли в `ROLES`, чтобы порядок групп и подписи брались из одного места. Порядок групп — порядок `ROLES`.
4. **Раскрытие — локальное состояние компонента.** Начальное значение вычисляется из того, есть ли другие группы; при поиске «Эпизодические» показываются раскрытыми независимо от состояния. Ничего не пишется в `localStorage`: спека требует не запоминать раскрытие.
5. **Поле поиска — из `web/src/components/ui/`**, как остальные поля; Esc обрабатывается на самом поле. Поле живёт только на этой странице, поэтому перехват Esc на окне, как в `StorySearch.tsx`, не нужен.
6. **Страница «Миры» рисуется как сейчас.** Ветка для `kind === "world"` остаётся лентой без поля поиска.

## Risks / Trade-offs

- [Главные герои после «Найти всех персонажей в тексте» попадают в свёрнутые «Эпизодические»] → число у заголовка и раскрытие при поиске; роли по умолчанию не меняются (Non-goals).
- [Поиск находит по описанию то, чего автор не ждал] → это задумано: строка описания видна в строке списка, совпадение понятно.
