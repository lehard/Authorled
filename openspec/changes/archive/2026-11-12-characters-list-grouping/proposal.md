# Proposal

## Why

Когда персонажей в истории много, страница «Персонажи» превращается в длинную ленту: главные герои стоят вперемешку с эпизодическими, и нужного приходится искать глазами (наблюдение владельца 2026-11-12). Роль у персонажа и локации уже есть в данных («Главный», «Второстепенный», «Эпизодический»), но список показывает её только меткой у строки и ничего по ней не упорядочивает. Самый дешёвый шаг — группировать по роли то, что уже лежит в данных, и дать поиск по имени прямо в списке (`business-intents/characters-list-grouping.md`).

## What Changes

- Страница «Персонажи» показывает персонажей группами в порядке ролей: «Главные», «Второстепенные», «Эпизодические»; у заголовка группы есть число в ней; пустая группа не показывается.
- Страница «Локации» устроена так же: «Основные», «Второстепенные», «Эпизодические».
- Группа «Эпизодические» свёрнута, если на странице есть другая группа, и раскрывается кликом по заголовку; без других групп она раскрыта. Состояние раскрытия не запоминается.
- Внутри группы порядок тот же, что сейчас в списке. Метка роли у строки убирается: роль видна по группе.
- Над списком персонажей и локаций стоит поле «Поиск по имени»: фильтр по имени и строке описания без учёта регистра и разницы «ё» и «е», по мере ввода. Пока в поле есть текст, группы без совпадений скрыты, «Эпизодические» раскрыты; Esc и крестик очищают поле; без совпадений — «Ничего не нашлось».
- Страница «Миры» не меняется: у мира нет роли.

## Scope

- Фронтенд: страница списка документов группы (`web/src/screens/project/docs/GroupDoc.tsx`) и подписи групп ролей рядом с `ROLES` (`web/src/data/profiles.ts`).
- Спека `web/workspace`: требование «Документы истории» (строка о списках) и новое требование о группах ролей и поиске в списках.

## Non-goals

- Группы по роли в дереве навигатора: дерево остаётся плоским, имя там находит «Поиск по истории».
- Свои теги, папки и группы персонажей.
- Число сцен и реплик персонажа и сортировка по нему.
- Фильтр «кто в этой сцене» и граф связей.
- Новые роли, роли по умолчанию и любые изменения ядра, API и миграций.

## Capabilities

### New Capabilities

Нет.

### Modified Capabilities

- `web/workspace`: списки персонажей и локаций показываются группами по роли со свёрнутыми эпизодическими и поиском по имени; метка роли у строки списка уходит.

## Impact

- Код: `web/src/screens/project/docs/GroupDoc.tsx`, `web/src/data/profiles.ts`; переиспользуется `foldText` из `web/src/editor/fold.ts`.
- Ядро, API, миграции, агент соавтора и источники данных `api` и `fixtures` не меняются.
- Зависимости не добавляются.
