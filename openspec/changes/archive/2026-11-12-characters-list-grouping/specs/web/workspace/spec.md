# Spec Delta

## MODIFIED Requirements

### Requirement: Документы истории
Рабочее поле MUST показывать документы:
- «История»: название и тэглайн истории, видимость частей сценария в навигаторе, число сцен и оценка длительности открытого драфта, блок «Письмо» (требование «Блок «Письмо»»); тэглайн MUST показываться на полке;
- «Титульная страница»: название, жанр или формат, автор, контакты, город и год — листом бумаги;
- «Логлайн»: текст листом бумаги;
- «Синопсис»: текст листом бумаги в редакторе прозы с панелью, счётом длины, метками страниц и печатью (спека `web/prose-editor`);
- списки персонажей и локаций с одной строкой описания, по группам ролей и с поиском по имени (требования «Группы ролей в списках персонажей и локаций» и «Поиск в списках персонажей и локаций»); список миров с одной строкой описания;
- профили персонажа, локации и мира с полями макета v2 (`PROFILE` в `data.js`), ролью и, для персонажа, возрастом и полом;
- «Заметки»: список заметок истории с названием и первой строкой текста;
- заметка: название и текст листом бумаги;
- «Корзина» истории: удалённые документы с «Восстановить», «Удалить навсегда» и «Очистить корзину».
Правка поля MUST сохраняться через провайдер данных и MUST отражаться в навигаторе без перезагрузки; статус «Сохранено» MUST показываться на экранах документов.

#### Scenario: Переименование персонажа
- GIVEN открыт профиль Веры
- WHEN пользователь меняет имя на «Вера Андреевна»
- THEN навигатор MUST показывать «Вера Андреевна», а статус MUST стать «Сохранено»

#### Scenario: Восстановление из корзины истории
- GIVEN в корзине истории лежит персонаж «Миша»
- WHEN пользователь нажимает «Восстановить»
- THEN Миша MUST вернуться в группу «Персонажи» со всеми полями профиля

#### Scenario: Тэглайн на полке
- GIVEN открыта «История» в драфте 2
- WHEN автор меняет тэглайн на «Двадцать лет никто не подходил к воде.»
- THEN статус MUST стать «Сохранено», полка MUST показывать этот тэглайн, а в драфте 1 документ «История» MUST показывать его же

#### Scenario: Логлайн в драфте
- GIVEN в истории два драфта с одним логлайном
- WHEN автор меняет «Логлайн» в драфте 2
- THEN в драфте 1 логлайн MUST остаться прежним

#### Scenario: Скрытый логлайн
- GIVEN в «Истории» снята галочка «Логлайн»
- WHEN автор смотрит навигатор и открывает адрес `logline`
- THEN части MUST NOT быть в папке «Сценарий», а адрес MUST показывать «Не найдено»

#### Scenario: Сбой одного из сохранений
- GIVEN открыта «История»
- WHEN автор меняет название и галочку части, и ядро отказывает второму сохранению из-за конфликта ревизий
- THEN экран MUST показывать конфликт, а не «Сохранено»

## ADDED Requirements

### Requirement: Группы ролей в списках персонажей и локаций
Список персонажей MUST показывать персонажей группами «Главные», «Второстепенные», «Эпизодические» в этом порядке, список локаций — группами «Основные», «Второстепенные», «Эпизодические». У заголовка группы MUST быть число документов в ней; пустая группа MUST NOT показываться. У строки списка MUST NOT быть метки роли.

#### Scenario: Группы персонажей
- GIVEN в драфте «Последнего парома» главный Павел, второстепенная Лида, эпизодический Ефим
- WHEN автор открывает «Персонажи»
- THEN MUST быть группы «Главные 1», «Второстепенные 1», «Эпизодические 1» в этом порядке, и ни у одной строки MUST NOT быть метки роли

#### Scenario: Пустая группа
- GIVEN в истории нет эпизодических локаций
- WHEN автор открывает «Локации»
- THEN группы «Эпизодические» MUST NOT быть

#### Scenario: Смена роли
- GIVEN открыт профиль Миши с ролью «Второстепенный»
- WHEN автор ставит роль «Главный» и открывает «Персонажи»
- THEN Миша MUST быть в группе «Главные» без перезагрузки страницы, а число у «Второстепенных» MUST уменьшиться на один

#### Scenario: Неизвестная роль
- GIVEN источник данных отдал персонажа с ролью, которой нет среди трёх
- WHEN автор открывает «Персонажи»
- THEN экран MUST показать ошибку с именем персонажа и ролью, а не строку в какой-либо группе

### Requirement: Порядок внутри группы ролей
Внутри группы ролей документы MUST идти в том же порядке, что и в списке без групп. Сортировка по алфавиту из меню навигатора MUST NOT менять порядок в группах.

#### Scenario: Порядок главных
- GIVEN в списке без групп главные персонажи шли в порядке Вера, Аня
- WHEN автор открывает «Персонажи»
- THEN в группе «Главные» MUST быть Вера, затем Аня

### Requirement: Свёрнутые эпизодические
Группа «Эпизодические» MUST быть свёрнута при открытии списка, если в списке есть другая группа, и раскрыта, если других групп нет. Клик по заголовку группы «Эпизодические» MUST раскрывать и сворачивать её. Состояние раскрытия MUST NOT сохраняться: при новом открытии списка правило применяется заново. Другие группы MUST быть раскрыты всегда.

#### Scenario: Раскрыть эпизодических
- GIVEN открыты «Персонажи» «Последнего парома»
- WHEN автор нажимает на заголовок «Эпизодические 1»
- THEN MUST показаться Ефим, а повторный клик MUST его скрыть

#### Scenario: Только эпизодические
- GIVEN все персонажи истории эпизодические
- WHEN автор открывает «Персонажи»
- THEN группа «Эпизодические» MUST быть раскрыта

### Requirement: Поиск в списках персонажей и локаций
Над непустым списком персонажей и над непустым списком локаций MUST быть поле «Поиск по имени». По мере ввода список MUST оставлять документы, у которых запрос есть в имени или строке описания, без учёта регистра и разницы «ё» и «е». Пока в поле есть текст, группы без совпадений MUST NOT показываться, а «Эпизодические» MUST быть раскрыты. Esc в поле и крестик MUST очищать поле и возвращать весь список. Без совпадений вместо списка MUST быть «Ничего не нашлось».

#### Scenario: Поиск по описанию
- GIVEN открыты «Персонажи» «Последнего парома»
- WHEN автор вводит «яблок»
- THEN MUST остаться только группа «Эпизодические 1» с Ефимом («Постоянный пассажир с яблоками»), раскрытая

#### Scenario: Ё и е
- GIVEN в истории есть персонаж «Фёдор»
- WHEN автор вводит «федор»
- THEN Фёдор MUST остаться в списке

#### Scenario: Ничего не нашлось
- GIVEN открыты «Персонажи»
- WHEN автор вводит «дирижабль» и затем нажимает Esc
- THEN сначала MUST быть «Ничего не нашлось», а после Esc поле MUST быть пустым и MUST вернуться весь список

#### Scenario: Без поля поиска
- GIVEN в истории нет локаций, а миры есть
- WHEN автор открывает «Локации», затем «Миры»
- THEN на «Локациях» MUST быть «Пока пусто» без поля поиска, и на «Мирах» поля поиска MUST NOT быть
