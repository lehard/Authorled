## ADDED Requirements

### Requirement: Настройки
Страница `/settings` MUST следовать раскладке экрана «Настройки» макета v1 (`openspec/context/_raw/design/kabinet/`, `#settings`) и дизайн-системе: лист на столе, «Назад», заголовок «Настройки», разделы слева; при ширине меньше 768 px — над содержимым, без горизонтальной прокрутки. Клик по разделу прокручивает к нему. Раздел «Профиль»: имя с кнопкой «Сохранить» (доступна, когда имя изменено; пустое — ошибка у поля без запроса), почта для входа только для чтения, «Выйти».

#### Scenario: Смена имени
- GIVEN пользователь на `/settings` с именем «Анна Петрова»
- WHEN он вводит «Анна П.» и нажимает «Сохранить»
- THEN меню пользователя MUST показывать «Анна П.» без перезагрузки страницы
- AND после перезагрузки поле MUST содержать «Анна П.»

#### Scenario: Пустое имя
- GIVEN пользователь на `/settings`
- WHEN он стирает имя и нажимает «Сохранить»
- THEN у поля MUST показываться ошибка «Введите имя.», а запрос MUST NOT отправляться

#### Scenario: Узкий экран
- GIVEN ширина окна 375 px
- WHEN открыта `/settings`
- THEN разделы MUST стоять над содержимым, и страница MUST NOT прокручиваться по горизонтали

### Requirement: Тема в настройках
Раздел «Внешний вид» страницы `/settings` MUST предлагать тему четырьмя плитками с превью: «Утро» (`light`), «Бумага» (`sepia`), «Вечер у лампы» (`dark`) и «Как в системе»; выбранная отмечена. Выбор MUST применяться сразу и сохраняться в аккаунте через `PATCH /api/v1/me`. Если сохранение не удалось, MUST показываться причина, и тема MUST вернуться к сохранённой.

#### Scenario: Тема на другом устройстве
- GIVEN пользователь выбрал «Бумага» в одном браузере
- WHEN он входит в другом браузере
- THEN после входа MUST применяться тема `sepia`

#### Scenario: Как в системе
- GIVEN пользователь выбрал «Как в системе», а система в тёмном режиме
- WHEN страница перезагружена
- THEN MUST применяться тема `dark`

### Requirement: Данные аккаунта из API
Страница `/settings` и меню пользователя MUST брать имя, почту и тему из `GET /api/v1/me`. Если ответ не получен, они MUST показывать причину и «Повторить», а не данные из токена и не пустую страницу.

#### Scenario: API недоступен
- GIVEN API не отвечает
- WHEN пользователь открывает `/settings`
- THEN MUST показываться причина и «Повторить», а не пустая страница

## MODIFIED Requirements

### Requirement: Вход
Приложение MUST пускать к экранам только после входа. Без действующей сессии приложение MUST открывать свой экран входа `/login` и после входа MUST возвращать на адрес, который открывали. Экран входа MUST следовать макету v1 (`openspec/context/_raw/design/kabinet/`, экраны `#auth/*`) и дизайн-системе:
- почта; при неверном формате — ошибка у поля;
- пароль — только если у аккаунта он задан; «Показать»; неверный пароль — ошибка у поля;
- код из письма — 6 ячеек: цифры переходят сами, вставка из буфера раскладывается по ячейкам, полный код отправляется сам; неверный код — ошибка и очищенные ячейки; «Отправить ещё раз» доступно через 60 секунд; «Другая почта» возвращает к первому шагу;
- ошибка Authentik — текст ошибки с причиной, а не пустой экран.
После последнего шага приложение MUST получить токены по OIDC без страницы Authentik. Если в Authentik уже есть сессия (вход в другой вкладке), `/login` MUST брать токены без формы. Перезагрузка страницы посреди входа MUST начинать вход с почты. Меню пользователя MUST показывать имя и почту из ответа `GET /api/v1/me`, пункт «Настройки», открывающий `/settings`, и действие «Выйти», которое завершает сессию в Authentik и возвращает на `/login`. Без входа MUST открываться только `/login` и витрина дизайн-системы.

#### Scenario: Вход с сохранением адреса
- GIVEN пользователь не вошёл
- WHEN он открывает `/p/water/chars` и проходит экран входа
- THEN после кода MUST открыться `/p/water/chars`

#### Scenario: Отказ во входе
- GIVEN Authentik недоступен или отвечает ошибкой
- WHEN пользователь отправляет почту на экране входа
- THEN MUST показываться причина ошибки и возможность повторить, а не пустая страница

#### Scenario: Неверный код
- GIVEN на экране кода
- WHEN пользователь вводит шесть неверных цифр
- THEN MUST показываться ошибка, ячейки MUST очиститься, и фокус MUST вернуться в первую ячейку

#### Scenario: Вставка кода
- GIVEN на экране кода
- WHEN пользователь вставляет из буфера «123456»
- THEN цифры MUST разложиться по ячейкам, и код MUST отправиться без нажатия кнопки

#### Scenario: Аккаунт без пароля
- GIVEN у аккаунта не задан пароль
- WHEN пользователь вводит почту
- THEN следующим MUST открыться экран кода

#### Scenario: Новая вкладка
- GIVEN пользователь вошёл в одной вкладке
- WHEN он открывает приложение в новой вкладке
- THEN экран MUST открыться без формы входа

#### Scenario: Перезагрузка на шаге кода
- GIVEN открыт шаг кода
- WHEN страница перезагружена
- THEN MUST показываться шаг почты без ошибки

#### Scenario: Выход
- GIVEN пользователь вошёл
- WHEN он выбирает «Выйти»
- THEN сессия в Authentik MUST завершиться, и MUST открыться `/login`

#### Scenario: Имя в меню из аккаунта
- GIVEN пользователь зарегистрировался как «Анна Петрова» и сменил имя в настройках на «Анна П.»
- WHEN он выходит и входит снова
- THEN меню пользователя MUST показывать «Анна П.»

### Requirement: Адреса экранов
Каждый экран MUST иметь свой адрес, и открытие адреса напрямую MUST показывать тот же экран:
- `/` — полка историй; `/trash` — корзина историй;
- `/p/:projectId/:doc` — окно истории с документом: `info`, `sp`, `title`, `synopsis`, `treatment`, `text`, `draft:<id>`, `compare:<a>:<b>` (`a` и `b` — `current` или id драфта, разные), `chars`, `char:<id>`, `locs`, `loc:<id>`, `worlds`, `world:<id>`, `trash`;
- `/settings` — настройки (личный кабинет);
- `/showcase` — витрина дизайн-системы;
- `/auth/callback` — возврат из Authentik.
Неизвестный адрес, история или документ MUST показывать экран «Не найдено» со ссылкой на полку.

#### Scenario: Прямая ссылка на профиль
- GIVEN пользователь вошёл
- WHEN он открывает `/p/water/char:vera`
- THEN MUST открыться окно истории «Тихая вода» с профилем Веры, и в навигаторе Вера MUST быть текущим пунктом

#### Scenario: Нет такого документа
- GIVEN пользователь вошёл
- WHEN он открывает `/p/water/char:nobody`
- THEN MUST показываться «Не найдено» со ссылкой на полку

#### Scenario: Сравнение с самим собой
- GIVEN пользователь вошёл
- WHEN он открывает `/p/water/compare:current:current`
- THEN MUST показываться «Не найдено» со ссылкой на полку
