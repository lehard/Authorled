# Proposal

## Why

У пользователя нет своего места в продукте. В меню только имя из токена, почта и «Выйти». Имя после регистрации не исправить, тема хранится только в браузере, а переключателя нет. Таблица `authorled.users` есть, но запись в ней никто не создаёт: `GET /me` отложен из `core-users-table`. Основание — бизнес-интент `business-intents/user-cabinet.md`. Решения владельца от 2026-11-01:
- кабинет — страница `/settings` по раскладке макета v1;
- этап 1 — профиль и тема;
- `GET /me` входит в этот change;
- главное имя — `users.display_name`;
- настройки — в таблице профиля с явными колонками.

## What Changes

- **Таблица профиля `authorled.user_settings`** (миграция `0002_user_settings`): одна строка на пользователя, `theme` (пусто — «как в системе», иначе `light`, `sepia`, `dark`), `updated_at`.
- **Операции ядра**:
  - «получить или создать пользователя по `sub`»: при создании — запись `users` и строка профиля; повторно — обновить почту и `last_seen_at`, имя не трогать;
  - «изменить имя и тему».
- **Первые свои маршруты** (ADR-002), без LLM, — роутер в приложении AgentOS, без параметра `base_app` (с ним Agno 3.1.10 снимает свои обработчики ошибок; решение владельца 2026-11-01):
  - `GET /api/v1/me` — пользователь и его настройки;
  - `PATCH /api/v1/me` — имя и тема.
  - Ошибки — `application/problem+json`. Мягко удалённый аккаунт получает `410` и не создаётся заново.
- **Модуль `auth`**: зависимость `current_identity` отдаёт почту и имя из claims `email` и `name` Access Token. Claims читаются только в `agno/app/auth/` и не участвуют в решениях о доступе. Токен без этих claims (например, сервисной учётной записи) на `/api/v1/me` получает `403` с названием claim.
- **Страница `/settings`** в оформлении «Кабинета»:
  - заголовок «Настройки», «Назад»;
  - разделы «Профиль» (имя с сохранением, почта для чтения, «Выйти») и «Внешний вид» (плитки «Утро», «Бумага», «Вечер у лампы», «Как в системе»).
- **Меню пользователя**: пункт «Настройки», имя и почта из `/api/v1/me`, а не из ID-токена.
- **Тема аккаунта**:
  - после входа применяется тема из `/api/v1/me`;
  - выбор на странице настроек сохраняется в аккаунте;
  - браузер хранит тему только для первой отрисовки.

## Scope

- `agno/core/`: `tables.py` (`user_settings`), модуль пользователей (операции), миграция `agno/migrations/versions/0002_user_settings.py`.
- `agno/app/`: маршруты `/api/v1/me` роутером в приложении из `agent_os.get_app()` в `app/main.py`, модели Pydantic, ошибки problem+json; `agno/app/auth/`: `current_identity`.
- `web/src/`: маршрут `/settings`, экран настроек, клиент `/api/v1/me` поверх `/os/`, `authProvider.getIdentity`, `UserMenu`, применение темы аккаунта.
- `agno/tests/`: pytest ядра (профиль, операции, маршруты).
- Документы: ADR-002, `CLAUDE.md` и `AGENTS.md` («Working rules», «Where changes belong»), `openspec/context/03-architecture.md`, `04-engineering-standards.md` — «через `base_app`» → «роутер в приложении AgentOS».
- Спеки: новая `api/me`; дельты `core/database`, `auth`, `overview`, `web/workspace`, `web/design-system`.
- Проверка: pytest, `./scripts/validate.sh`, страница в трёх темах и на 375 px, тема в двух браузерах; запись в `tmp/VERIFY.md`.

## Non-goals

- Следующие этапы кабинета: соавтор (обращение, «сколько замечать»), вход и безопасность (смена почты, пароль, устройства), данные (архив, удаление аккаунта), письмо (цели).
- Из макета v1 не берём шрифт, размер текста, ширину листа, сценарный шаблон, орфографию, язык и имя для титула. Обещание «тексты не используются для обучения» тоже не показываем.
- Запись имени в Authentik и права администратора Authentik у бэкенда.
- Изменение blueprints: claims `email` и `name` уже приходят в Access Token по scopes `email` и `profile` (проверяется в задачах).
- Хранение историй в базе: данные историй остаются в `fixtures`.
- Генерация TS-клиента из OpenAPI: клиент `/api/v1/me` пишется вручную, генерация — отдельной задачей, когда маршрутов станет больше.

## Capabilities

### New Capabilities
- `api/me`: свой маршрут `/api/v1/me`. `GET` создаёт или находит запись пользователя и возвращает её с настройками, `PATCH` меняет имя и тему; ошибки, `401`/`403`/`410`/`422`.

### Modified Capabilities
- `core/database`:
  - новое требование «Таблица профиля» (`user_settings`);
  - «Что не хранится в схеме продукта» — настройки теперь в `user_settings`;
  - новое требование «Запись пользователя по входу» — получить или создать, имя не перезаписывается.
- `auth`:
  - «Principal» — свои маршруты приложения вместо «маршрутов `base_app`»;
  - «Контракт токена» — claims `email` и `name`, только для записи пользователя;
  - новое требование «Почта и имя из токена» — `current_identity`.
- `overview`: «Отсутствие маршрутов в коде репозитория» — свои маршруты `/api/v1/*` роутером в приложении AgentOS, новое число путей и операций.
- `web/workspace`:
  - «Вход» — меню показывает имя из `/api/v1/me` и пункт «Настройки»;
  - «Адреса экранов» — `/settings`;
  - новое требование «Настройки».
- `web/design-system`: «Темы» — выбор хранится в аккаунте, браузер помнит его для первой отрисовки.

## Impact

- **Документы:** ADR-002, `CLAUDE.md`/`AGENTS.md`, `openspec/context/03-architecture.md` и `04-engineering-standards.md` говорят «через `base_app`» — уточняются: роутер в приложении AgentOS.

- **API:** первый свой маршрут `/api/v1/me` в приложении AgentOS. OpenAPI растёт на один путь и две операции.
- **БД:** таблица `authorled.user_settings`, миграция применяется контейнером `agentos-migrate`.
- **Фронтенд:** первый экран, которому нужен запущенный API вне чата. Без API меню и `/settings` показывают ошибку.
- **Зависимости:** новых нет (FastAPI, Pydantic и SQLAlchemy уже есть через Agno).
