# Design

## Context

Причины — в `proposal.md`. Что есть сейчас:

- На сервере работает Caddy `v2.11.9`; локально есть образ `caddy:2.11.9`.
- В `deploy/Caddyfile` статику отдают два блока:
  - `app.soavtor.app`: `handle { encode gzip; root …/web/current; try_files {path} /index.html; file_server }`;
  - `soavtor.app`: `handle { encode gzip; root …/site/current; file_server }`.
- Тип файла `file_server` берёт по расширению из таблицы Go. На Linux Go читает `/usr/share/mime/globs2`, если файл есть, и тогда не смотрит в `/etc/mime.types`. На сервере `globs2` есть (Ubuntu 24.04) и строки для `.webmanifest` в нём нет, хотя в `/etc/mime.types` она есть. В образе `caddy:2.11.9` файла `globs2` нет, и там тип верный без правки. Поэтому `app.soavtor.app` сейчас отвечает `text/plain; charset=utf-8` со сжатием, а `soavtor.app` — без `content-type` и без сжатия: ответ меньше порога `encode`.
- Проверки после выкладки — шаги `.github/workflows/deploy.yml`: `/os/health` и `/os/agents` прямо в шаге, `deploy/check_site.sh` и `deploy/check_admin.sh` отдельными скриптами. Каждая неудача — `::error::` и красный запуск.
- `deploy/deploy.sh` перед перезагрузкой Caddy проверяет конфигурацию (`caddy validate`). Для этого нужен файл УЦ админки `/etc/authorled/admin-client-ca.pem`.

## Goals / Non-Goals

**Goals:**

- Точный тип `application/manifest+json` у манифеста на обоих доменах, со сжатием и без.
- Проверка после выкладки, которая ловит потерю типа.

**Non-Goals:**

- Общая таблица MIME-типов для Caddy и правка других расширений.

## Decisions

**D1. Заголовок через `header` с отложенной установкой.**
В каждом статическом `handle`:
```
@manifest path *.webmanifest
header @manifest >Content-Type application/manifest+json
```
Префикс `>` откладывает установку до записи ответа. Так заголовок заменяет то, что поставили `file_server` или угадывание типа, и не зависит от порядка директив. Альтернативы:
- `header` без `>`: может проиграть `file_server`, если тот перезапишет заголовок;
- `route` с `rewrite` — сложнее;
- глобальная таблица типов: в Caddyfile её нет, нужен JSON-конфиг.

Матчер с именем повторяется в двух блоках: сниппет `(manifest_type)` ради двух строк только добавил бы косвенности. Если поведение `>` с `encode gzip` в `v2.11.9` окажется другим (задача 2.1 проверяет это до выкладки), сначала обновляется этот документ, а не обходится проверка.

**D2. Отдельный скрипт `deploy/check_manifest.sh <origin>...`.**
Манифест есть у двух доменов, а `check_site.sh` проверяет только сайт. Скрипт принимает несколько адресов. Для каждого он делает два запроса — без `Accept-Encoding` и с `Accept-Encoding: gzip` — и сравнивает код (`200`) и тип: точное совпадение без параметров `; charset=…`, регистр не важен. Ошибка пишется в формате `::error::<url> answered <code> <type|no content-type> …`, как у соседних скриптов, а скрипт выходит с кодом 1. Шаг workflow — `deploy/check_manifest.sh "$PUBLIC_URL" "$SITE_ORIGIN"` после «Check the site».

**D3. Проверка до выкладки — на локальном Caddy той же версии.**
Боевой Caddyfile локально не поднять: в нём реальные домены, TLS и файл УЦ. Поэтому:
1. `caddy validate` боевого `deploy/Caddyfile` в `caddy:2.11.9`, с пустым временным PEM, подставленным по пути УЦ. Синтаксис и провизия.
2. Тестовая конфигурация на `:8080` в том же образе, с копией серверного `/usr/share/mime/globs2` по тому же пути (иначе образ отдаёт верный тип и без правки) с тем же блоком (`encode gzip`, матчер, `header`, `file_server`) и копиями манифестов из `web/public/` и `site/public/`. На ней запускается `check_manifest.sh http://127.0.0.1:8080`. Без строк D1 тот же скрипт должен упасть: это проверка самой проверки.

Тестовая конфигурация в репозиторий не кладётся — это одноразовая проверка, её результат записывается в `tmp/VERIFY.md`.

## Risks / Trade-offs

- [`encode` решает, сжимать ли ответ, по типу, а отложенный заголовок ставится позже] → сжатие манифеста не обязательно, требование только к типу. D3 проверяет оба запроса.
- [Повтор матчера в двух блоках разойдётся при правке] → `check_manifest.sh` проверяет оба домена после каждой выкладки.

## Migration Plan

Обычный релиз: `deploy.sh` проверяет и перезагружает Caddy, затем новый шаг проверяет тип. Откат — revert и следующий релиз. Неверный тип не ломает сервис: Chrome читает манифест и так.
