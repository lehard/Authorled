# Design

## Context

Мотивация и замеры описаны в proposal.md.

Как устроено сейчас (`web/src/editor/ScreenplayEditor.tsx`, как в `main`):
- Обёртка панели прилипает к верху (`sticky top-0`), ширина `w-full max-w-[816px]`, поля `px-1.5`. В обёртке лежат строка `role="toolbar"` и строка поиска (`FindBar`).
- Строка панели: `flex min-w-0 flex-wrap items-center gap-0.5`. В ней по порядку стоят:
  - «Отменить» и «Повторить»;
  - разделитель;
  - кнопка типа абзаца: `DropdownMenu`, кнопка `shrink-0` из значка `Pilcrow`, названия типа в `span.truncate` и `ChevronDown`; подсказка «Тип абзаца», доступное название «Тип абзаца: <тип>»;
  - разделитель;
  - «Показать биты» (только в режиме `text`), «Найти и заменить», «Только текущая сцена» (компонент `Tool`, `aria-pressed`);
  - группа `ml-auto flex shrink-0`: инструменты рецензирования из пропа `tools` (счётчики ✦ и 💬 из `TextDoc`) и «⋯» (`menu`). `TextDoc` передаёт `menu` только в режиме `text`; в «Поэпизоднике» «⋯» нет.
- Меню и подсказки shadcn/ui (Radix) рисуются в портале в `body`, вне дерева панели.
- Замер 2026-11-09, 375 px: строка панели 329 px. Кнопки `Tool` по 28 px, разделитель 1 px плюс поля 2 × 2 px, промежуток 2 px. Кнопка типа с «Акт» 81 px, без названия 52 px. Счётчики по 44 px, «⋯» 28 px.

Ограничения:
- тонкий клиент (ADR-001, ADR-004);
- подсказки только компонентом дизайн-системы (`check-native-ui`);
- цвета только токенами (`check_web_tokens.sh`);
- без запасных путей и без измерения скриптом: раскладку задаёт одно правило CSS по ширине панели.

## Goals / Non-Goals

**Goals:**
- Панель в одну строку на любой ширине рабочей колонки, в обоих режимах.
- Узкая и широкая раскладки переключаются только правилом CSS по ширине панели, без JS-состояния.
- Широкая панель выглядит как сейчас.

**Non-Goals:**
- Изменение счётчиков рецензирования, строки поиска, пунктов «Импорт», «Экспорт», «Печать».
- Общий компонент «переполнения» панели для других экранов.

## Decisions

1. **Container query на обёртке панели.** Обёртка получает `@container` (Tailwind 4: `container-type: inline-size`). Узкая раскладка включается вариантами `@max-[N]:` и `@min-[N]:` с одним порогом `N`. `N` — ширина, которой хватает широкой панели с самым длинным названием типа абзаца и трёхзначными счётчиками. Его замеряют в браузере при реализации и записывают одним значением с комментарием, откуда оно взялось. Строка панели теряет `flex-wrap`. Отвергнуто:
   - `useMediaQuery` по ширине окна: колонка сужается и от развёрнутого чата;
   - ResizeObserver: измерение скриптом.

2. **Тип абзаца значком.** На узкой панели `span` с названием типа скрыт (`@max-[N]:hidden`). Значок ¶ и стрелка остаются, кнопка остаётся `DropdownMenu` со списком типов, доступное название «Тип абзаца: <тип>» не меняется. Подсказка рисуется в портале, и container query до неё не дотягивается. Поэтому текст подсказки один на любой ширине: «Тип абзаца: <тип>», как доступное название (при отсутствии типа просто «Тип абзаца»). На широкой панели подсказка так повторяет видимое название; это принято ради одного правила без JS.

3. **Виды в «⋯»: два триггера, один видимый.** Пункты в портальном меню нельзя скрыть container query, а скрывать в открытом меню `display:none`-пункты опасно: Radix пытается сфокусировать их стрелками. Поэтому в строке два триггера «⋯», каждый со своим меню в портале:
   - широкий (`@max-[N]:hidden`): меню как сейчас, пункты из `menu`. Есть, только когда `menu` передан, как сейчас;
   - узкий (`@min-[N]:hidden`): сверху пункты видов `DropdownMenuCheckboxItem` («Показать биты» только в режиме `text`, «Только текущая сцена»), затем разделитель и пункты из `menu`, если он передан. Есть в обоих режимах.

   Кнопки «Показать биты» и «Только текущая сцена» в строке получают `@max-[N]:hidden`. Скрытый `display:none` триггер выпадает из порядка табуляции и из дерева доступности, поэтому в каждой раскладке у «⋯» одна кнопка. Состояние видов одно, `snap.view`, и пункт меню вызывает тот же `editor.current?.setView(...)`, что и кнопка. Пункты меню строятся одной функцией для обоих триггеров, без дублирования разметки. Отвергнуто:
   - меню без портала внутри контейнера: Floating UI 1.8 не считает `container-type` блоком-контейнером и может сдвинуть меню;
   - одно меню с пунктами видов на любой ширине: меняет широкую панель.

4. **Строка поиска** остаётся второй строкой обёртки, как сейчас. Требование про одну строку относится к строке инструментов.

## Risks / Trade-offs

- [Порог `N` подобран под нынешний набор кнопок и названий; новая кнопка или более длинное название снова переполнят панель] → `N` записан одним значением с комментарием о том, как его получили. Сценарии «Телефон», «Узкая колонка при развёрнутом чате» и «Широкая панель» ловят это в браузере.
- [Без `flex-wrap` лишняя ширина уходит за край, а не на новую строку] → это и есть требование; проверка `scrollWidth` строки панели и страницы при самых длинных подписях и трёхзначных счётчиках (подставить в DOM).
- [Подсказка типа на широкой панели повторяет видимое название] → принятая цена одного правила без JS, отмечена в proposal.
- [`container-type: inline-size` на обёртке меняет её размер по содержимому] → у обёртки `w-full` в сетке, её ширина от содержимого не зависит; проверить, что ширина панели на 1440 px прежняя (до 816 px).
- [Пункт меню вида и кнопка вида расходятся в состоянии] → оба читают `snap.view` и пишут через `setView`; сценарий «Виды в меню на узкой панели» проверяет отметку после переключения.
