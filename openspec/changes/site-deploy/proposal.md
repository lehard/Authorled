# Proposal: выкладка сайта «Соавтора» на soavtor.app

Источник решений: `business-intents/site-deploy.md` (согласовано владельцем 2026-11-08).

## Why

Сайт продукта готов (`product-site` и `site-landing-v2` в архиве, мастер-спека `web/site`), но живёт только локально: `soavtor.app` временно переадресует на сервис, а после выхода из редактора человек попадает на экран входа, откуда к сайту дороги нет. Домен появился — причина держать сайт локально («не переезжать дважды») отпала.

## What Changes

- `soavtor.app` отдаёт собранный сайт вместо временной переадресации `302` на `app.soavtor.app`; на неизвестный адрес — страница 404 сайта с кодом `404`; статические файлы сжимаются gzip, как у фронтенда. `www.soavtor.app` по-прежнему `301` на `soavtor.app` с тем же путём.
- На домене сайта до API доходит только `POST /os/api/v1/beta-requests` (форма заявки шлёт его на свой адрес); другие пути `/os/` там не открываются.
- Деплой по релизу собирает и проверяет `site/` из того же тега с `SITE_ORIGIN` и `SITE_APP_URL` из переменных GitHub Environment `production`, отправляет файлы на сервер и переключает версию сайта вместе с фронтендом. Без переменных или файлов сайта деплой останавливается до изменений на сервере.
- Проверка после деплоя дополняется адресами сайта: главная и политика `200`, неизвестный адрес `404`, пустая заявка получает отказ API `422`.
- Экран входа сервиса получает ссылку «О продукте» на сайт; адрес сайта — новая обязательная настройка фронтенда `SITE_ORIGIN`.
- Требование «Локальный запуск до домена» в `web/site` заменяется: локальный запуск остаётся, выкладка теперь есть.
- Заявки хранятся на сервере в Финляндии в рамках принятого риска закрытого тестирования (уже записан в `openspec/context/05-security-and-compliance.md`); поведение маршрута заявки не меняется.

## Capabilities

### New Capabilities
(нет)

### Modified Capabilities
- `runtime`: «Обратный прокси» — сайт на `soavtor.app` вместо `302`, маршрут заявки на домене сайта; «Деплой по релизу» — сборка и выкладка сайта; «Проверка после деплоя» — адреса сайта; «Настройки деплоя» — `SITE_ORIGIN`, `SITE_APP_URL` обязательны.
- `web/site`: «Локальный запуск до домена» заменяется на «Локальный запуск и выкладка».
- `web/workspace`: «Обязательные настройки» — `SITE_ORIGIN`; новое требование «Ссылка на сайт с экрана входа».

## Scope

- `.github/workflows/deploy.yml`, `deploy/deploy.sh`, `deploy/Caddyfile`.
- `web/vite.config.ts`, `web/src/app/config.ts`, `web/src/auth/LoginScreen.tsx`.
- `README.md` («Deploy by release»), `.agents/skills/deploy-platform/SKILL.md`, `example.env`, `AGENTS.md` (абзац про `site/`: «Not deployed until…»).
- Разово: каталог `/srv/authorled/site/incoming` на сервере (пользователь `deploy`), переменные `SITE_ORIGIN`, `SITE_APP_URL` в GitHub Environment `production` — с подтверждения владельца.
- Мастер-спеки `runtime`, `web/site`, `web/workspace` через дельты.

## Non-goals

- Яндекс Метрика и cookie на сайте.
- Тексты, блоки, вид сайта и его сборка (`site/` не меняется).
- Перенос сервера и почты в РФ, уведомление Роскомнадзора, публикация оферты и тарифов.
- Переадресация после выхода сразу на сайт: адрес выхода остаётся на домене сервиса.
- Кэширование и CDN для сайта; капча на форме.
- Изменение маршрута заявки и ядра.

## Impact

- Публичное поведение `soavtor.app`: был `302` на сервис, станет сайт. Ссылки, которые вели на `soavtor.app/<путь сервиса>`, перестанут попадать в сервис (пользователей нет, адрес сервиса — `app.soavtor.app`).
- Деплой: ещё одна сборка (`npm ci --prefix site`, около минуты) и ещё один каталог на сервере. Откат на тег до этого change возвращает и его `Caddyfile`, то есть временную переадресацию `soavtor.app`; каталог сайта при этом не трогается.
- Фронтенд без `SITE_ORIGIN` останавливается на экране ошибки настройки, как без других обязательных настроек; локальный `.env` уже содержит `SITE_ORIGIN` для сайта.
- Персональные данные из открытой формы попадают на сервер в Финляндии — принятый риск владельца 2026-11-08.
