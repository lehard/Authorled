# Design

## Context

Мотивация в `proposal.md`, требования в дельтах спек `auth` и `web/workspace`.

Регистрация проверяется политикой `authorled-email-not-registered` в шаге ввода (`auth/blueprints/30-authentication-flow.yaml`). Шаг идёт до создания пользователя и письма, поэтому отказ на нём не оставляет следов. Фронтенд переводит тексты политики в ошибки экрана через таблицу `KNOWN` в `web/src/auth/flow/flowClient.ts`.

На закреплённом Authentik 2026.8.5 проверено локально: выражение политики читает `os.environ`, отсутствующая переменная даёт ошибку, а шаг ввода считает политику без кэша (`engine.use_cache = False`).

## Goals / Non-Goals

**Goals:**

- Список меняется настройкой, без релиза и без ручных шагов в интерфейсе Authentik.
- Реальные почты не попадают в репозиторий.

**Non-Goals:**

- Отдельная политика и экран управления списком.

## Decisions

**Проверка в существующей политике.** Она идёт сразу после проверки совпадения имени пользователя с почтой и раньше проверки занятой почты, чтобы отказ не выдавал, есть ли аккаунт. Отдельная политика добавила бы порядок между политиками, а он здесь важен.

**Чтение настройки при проверке.** Выражение читает `os.environ["AUTH_ALLOWED_EMAILS"]`. Альтернатива, `!Env` в blueprint, запекла бы значение в базу: файл blueprint не меняется, и новое значение могло бы применяться не сразу. Отсутствие настройки ловит compose на старте через `${AUTH_ALLOWED_EMAILS:?...}`, а прямой доступ по ключу не подставляет значения по умолчанию.

**Разбор значения.** Значение делится по запятым, каждая часть обрезается и приводится к нижнему регистру, пустые части отбрасываются. `*` как единственный элемент открывает регистрацию. Список только из запятых не открывает ничего: compose такое значение пропустит, но почта в него не попадёт.

**Передача в контейнеры.** Настройка добавляется в общий блок окружения Authentik рядом с другими `AUTH_*`. Применяется через `docker compose up -d authentik-server authentik-worker`, а не `restart`: `restart` не перечитывает окружение.

**Локально и в CI.** `example.env` получает `AUTH_ALLOWED_EMAILS=*`. Локальные `.env` дополняются вручную, ошибка compose назовёт настройку.

**Фронтенд.** В таблицу `KNOWN` добавляется текст отказа с полем `page`. Без этого экран показал бы «Authentik ответил: …».

## Risks / Trade-offs

- [Администратор Authentik может создать пользователя в обход] → допустимо, доступ к админке только у `admins`.
- [Человек, не попавший в список, сначала вводит имя и только потом получает отказ] → принято: отдельный шаг проверки на экране почты потребовал бы менять поток входа.
- [Удаление почты из списка не закрывает доступ] → вне scope, блокировка пользователя в Authentik.

## Migration Plan

1. Реализовать change и влить в `main` до первого релиза.
2. На сервере настройка уже есть. В локальных `.env` добавить `AUTH_ALLOWED_EMAILS=*`.
3. Перед открытым запуском поставить `*` и обновить решение в спеке, если список больше не нужен.
