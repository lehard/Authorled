## MODIFIED Requirements

### Requirement: Адреса экранов
Каждый экран MUST иметь свой адрес, и открытие адреса напрямую MUST показывать тот же экран:
- `/` — полка историй; `/trash` — корзина историй;
- `/p/:projectId/d/:draftId/:doc` — окно истории с документом драфта: `info`, `title`, `logline`, `synopsis`, `treatment`, `text`, `chars`, `char:<id>`, `locs`, `loc:<id>`, `worlds`, `world:<id>`, `notes`, `note:<id>`, `trash`;
- `/p/:projectId` и `/p/:projectId/:doc` — переход к `/p/:projectId/d/<open_draft_id>/:doc` (без `:doc` — `text`);
- `/settings` — настройки (личный кабинет);
- `/settings/billing/return` и `/settings/billing/fail` — возврат со страницы оплаты Точки;
- `/showcase` — витрина дизайн-системы;
- `/auth/callback` — возврат из Authentik.
Неизвестный адрес, история, драфт или документ MUST показывать экран «Не найдено» со ссылкой на полку.

#### Scenario: Прямая ссылка на профиль
- GIVEN пользователь вошёл
- WHEN он открывает `/p/water/char:vera`
- THEN MUST открыться окно истории «Тихая вода» с профилем Веры в последнем открытом драфте, адрес MUST содержать этот драфт, и в навигаторе Вера MUST быть текущим пунктом

#### Scenario: Нет такого документа
- GIVEN пользователь вошёл
- WHEN он открывает `/p/water/char:nobody`
- THEN MUST показываться «Не найдено» со ссылкой на полку

#### Scenario: Сравнение с самим собой
- GIVEN пользователь вошёл
- WHEN он открывает `/p/water/compare:current:current`
- THEN MUST показываться «Не найдено» со ссылкой на полку

#### Scenario: Нет такого драфта
- GIVEN пользователь вошёл
- WHEN он открывает `/p/water/d/nobody/text`
- THEN MUST показываться «Не найдено» со ссылкой на полку

#### Scenario: Документ другого драфта
- GIVEN персонаж «Нина» есть только в драфте 2
- WHEN пользователь открывает адрес «Нины» с драфтом 1
- THEN MUST показываться «Не найдено» со ссылкой на полку

#### Scenario: Адрес бывшей страницы сценария
- GIVEN пользователь вошёл
- WHEN он открывает `/p/water/sp`
- THEN MUST показываться «Не найдено» со ссылкой на полку

#### Scenario: Прямая ссылка на заметку
- GIVEN в истории «Тихая вода» есть заметка
- WHEN пользователь открывает её адрес с любым драфтом этой истории
- THEN MUST открыться заметка, и в навигаторе она MUST быть текущим пунктом

#### Scenario: Заметка в корзине по адресу
- GIVEN заметка лежит в корзине
- WHEN пользователь открывает её адрес
- THEN MUST показываться «Не найдено» со ссылкой на полку

#### Scenario: Заметка другой истории
- GIVEN заметка есть только в истории «Последний паром»
- WHEN пользователь открывает её адрес в истории «Тихая вода»
- THEN MUST показываться «Не найдено» со ссылкой на полку

#### Scenario: Возврат после оплаты
- GIVEN пользователь оплатил подписку на странице Точки
- WHEN Точка возвращает его на `/settings/billing/return`
- THEN MUST открыться страница возврата в настройках, а не «Не найдено»

## ADDED Requirements

### Requirement: Тариф в настройках
Страница `/settings` MUST содержать раздел «Тариф»: название тарифа, использованную долю лимита и дату обновления лимита, дату следующего списания (только у действующей оплаченной подписки), платные тарифы с ценой и кнопкой «Оформить», «Отменить подписку» у действующей оплаченной подписки, историю платежей (дата, сумма, период). Всё, что показывает раздел, MUST браться из `GET /api/v1/billing`.

#### Scenario: Бесплатный тариф
- GIVEN у пользователя бесплатная подписка, использовано 60 % лимита, лимит обновится 7 декабря
- WHEN он открывает раздел «Тариф»
- THEN MUST показываться название тарифа, «Использовано 60 % до 7 декабря» и платные тарифы с кнопкой «Оформить»
- AND кнопка «Отменить подписку» MUST NOT показываться

#### Scenario: Оформить
- GIVEN пользователь в разделе «Тариф»
- WHEN он нажимает «Оформить» у платного тарифа
- THEN браузер MUST перейти по ссылке на оплату из ответа `POST /api/v1/billing/checkout`

#### Scenario: Отмена с подтверждением
- GIVEN подписка оплачена до 7 декабря
- WHEN пользователь нажимает «Отменить подписку» и подтверждает
- THEN раздел MUST показывать «Подписка отменена, тариф действует до 7 декабря» без даты следующего списания

#### Scenario: Ошибка запроса
- GIVEN `POST /api/v1/billing/checkout` вернул ошибку
- WHEN пользователь нажал «Оформить»
- THEN MUST показываться причина из ответа, а переход MUST NOT происходить

### Requirement: Неудачное списание в настройках
Если состояние оформления `failed`, раздел «Тариф» MUST показывать «Оплата не прошла» и кнопку «Оплатить снова», которая работает как «Оформить» для того же тарифа.

#### Scenario: Оплатить снова
- GIVEN очередное списание не прошло, и пользователь на бесплатном тарифе
- WHEN он открывает раздел «Тариф»
- THEN MUST показываться «Оплата не прошла» и кнопка «Оплатить снова»

### Requirement: Страница возврата после оплаты
Страница `/settings/billing/return` MUST отправлять `POST /api/v1/billing/check`, пока состояние не станет `active`, но не дольше двух минут. После подтверждения она MUST показывать оплаченный тариф и ссылку на настройки. Если за две минуты оплата не подтвердилась, MUST показываться «Оплата ещё не подтверждена» и кнопка «Проверить ещё раз». Страница `/settings/billing/fail` MUST показывать «Оплата не прошла» и «Оплатить снова».

#### Scenario: Подтверждение
- GIVEN пользователь оплатил, и Точка подтверждает операцию через 10 секунд
- WHEN он вернулся на `/settings/billing/return`
- THEN в течение двух минут MUST показываться оплаченный тариф

#### Scenario: Не подтвердилось
- GIVEN Точка не подтверждает операцию две минуты
- WHEN пользователь ждёт на странице возврата
- THEN MUST показываться «Оплата ещё не подтверждена» и кнопка «Проверить ещё раз»
