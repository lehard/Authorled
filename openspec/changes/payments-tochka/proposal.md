# Proposal: платная подписка через интернет-эквайринг Точки

Бизнес-интент: `business-intents/payments-tochka.md`. Строится поверх change `usage-limits` (`business-intents/usage-limits.md`): тарифы, подписки, периоды и лимит расхода уже есть там.

## Why

Когда продукт начнут продавать, нужен приём оплаты с чеками по 54-ФЗ. Счёт владельца (ИП) открыт в Точке, а её интернет-эквайринг умеет подписки с регулярным списанием и чеки через партнёра Точки, поэтому своя онлайн-касса не нужна. Модель подписок из `usage-limits` уже готова принять второй источник — оплату.

## What Changes

- В файле тарифов появляются платные тарифы (цена больше 0, «можно купить»). Устройство файла, подписок и проверки лимита не меняется. Какие это тарифы и сколько они стоят, решает владелец (Open Questions в `design.md`).
- Второй источник подписки — «Точка». Пользователь нажимает «Оформить», ядро создаёт в Точке подписку с чеком и отдаёт ссылку на оплату. Пользователь платит на странице Точки и возвращается на сайт.
- Подтверждение оплаты: Точка присылает уведомление на маршрут ядра. Ядро проверяет подпись уведомления, а затем всё равно запрашивает статус операции у API Точки. Только ответ «оплачено» переводит подписку на платный тариф или продлевает её на следующий период. Повтор того же уведомления ничего не меняет.
- Отмена: ядро отключает автосписание в Точке, тариф действует до конца оплаченного периода, затем пользователь переходит на бесплатный тариф.
- Неудачное списание: подписка не продлевается и в конце периода переходит на бесплатный тариф; страница «Тариф» показывает, что оплата не прошла, и даёт кнопку «Оплатить снова».
- История платежей в ядре: пользователь, операция Точки, сумма, статус, оплаченный период. Данные карты на наш сервер не попадают.
- Страница «Тариф» в настройках: тариф, доля использованного лимита, дата следующего списания, «Оформить», «Отменить подписку», «Оплатить снова»; страница возврата после оплаты ждёт подтверждения.
- Отчёт администратора из `usage-limits` показывает источник подписки и дату окончания оплаты.
- Настройки Точки (адрес API, JWT-ключ, код клиента, торговая точка, реквизиты чека) — обязательные переменные окружения; без них API не стартует.

## Capabilities

### New Capabilities
- `api/billing`: оплата подписки — оформление, подтверждение по уведомлению и запросу к Точке, отмена, неудачное списание, конец оплаченного периода, история платежей, маршруты `/api/v1/billing/...` и маршрут уведомлений Точки.

### Modified Capabilities
- `core/database`: новая таблица платежей; новый источник подписки в таблице подписок из `usage-limits`.
- `integrations`: новые «Интернет-эквайринг Точки», «Обязательные настройки Точки», «Подпись уведомлений Точки», «Ответы API Точки проверяются».
- `web/workspace`: «Адреса экранов» (страницы возврата после оплаты); новые «Тариф в настройках», «Неудачное списание в настройках», «Страница возврата после оплаты».

Конец оплаченного периода и переход на бесплатный тариф описаны в `api/billing`. Если `usage-limits` закрепит продление подписок в своей спеке, в фазе 2 дельта переносится туда через `/opsx:update`.

## Scope

- `agno/core/`: клиент API Точки (`tochka.py`), таблица платежей, платные тарифы в файле тарифов, источник подписки «Точка», операции «оформить», «подтвердить», «отменить», «конец оплаченного периода»; миграция поверх головы `usage-limits`.
- `agno/app/api/`: маршруты оформления, отмены, состояния тарифа (токен пользователя) и маршрут уведомлений Точки (без токена пользователя, с проверкой подписи и подтверждением через API Точки).
- `agno/app/main.py`: проверка настроек Точки при старте.
- `web/`: раздел «Тариф» в `/settings`, страница возврата после оплаты, данные через `apiProvider` и `fixturesProvider`.
- `example.env`, `scripts/dev.sh`, README: имена переменных Точки и значения тестовой среды для разработки.
- Мастер-спеки: `api/billing`, `core/database`, `integrations`, `web/workspace`; контекст `05-security-and-compliance.md` (данные о платежах), `AGENTS.md` (новые файлы и маршруты).
- Тесты: pytest клиента на подменённом HTTP; pytest ядра и маршрутов на базе с подменённым клиентом Точки (оплата, повторное уведомление, поддельное уведомление, неоплаченная операция, отмена, конец периода, неудачное списание); запись в `tmp/VERIFY.md`.

## Non-goals

- Разовые покупки и пакеты сверх лимита; промокоды, скидки, пробный период.
- Возвраты из интерфейса: их делает владелец в интернет-банке Точки.
- Юрлица и оплата по счёту; смена платного тарифа на другой платный посреди периода.
- Свои письма о списании: чек присылает Точка.
- Заявка на эквайринг, выбор партнёра по чекам, тексты оферты и политики ПДн — делает владелец.
- Проверка на настоящей Точке до подключения эквайринга: только тестовая среда и подменённый HTTP.

## Impact

- API: новые маршруты `/api/v1/billing/*` и маршрут уведомлений Точки; существующие маршруты не меняются.
- База: новая таблица платежей; миграция после головы `usage-limits`.
- Настройки: новые обязательные переменные окружения Точки на сервере (`/etc/authorled/authorled.env`) и в `.env` разработки. Без них API не стартует, поэтому выкладка требует заполнить их заранее.
- ПДн: почта пользователя уходит в Точку и её партнёру для чека — это нужно добавить в политику ПДн (владелец).
