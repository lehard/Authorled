# Design: импорт проектов STARC

## Context

Мотивация — `proposal.md`, требования — `specs/`. После `story-data-backend` разборщики живут в `agno/core/importers/` и выдают абзацы (`Paragraph`) для общего сборщика `screenplay.py`; загрузка (`core/files.py`) знает форматы по таблице `FORMATS`/`ALLOWED`, импорт (`core/imports.py`) — по `parse_manuscript`. Формат `.starc` описан в `openspec/context/_raw/research/Разбор STARC для интеграции/Отчёт.md` («Файл .starc»): одна база SQLite, таблица `documents` (`uuid`, `type`, `content`), дерево проекта — XML документа типа 1 (Structure), сценарий 10100 с текстом 10104, персонаж 30001, локация 40001; текст — XML с группами `scene`/`beat` и абзацами по типу, значение в `<v><![CDATA[…]]></v>`. Официальной спецификации нет; XML персонажей и локаций не сверен.

## Goals / Non-Goals

**Goals:** читать `.starc` без изменения файла и без кода STARC (ADR-005: только наблюдаемый формат); отказывать целиком при любом расхождении.

**Non-Goals:** драфты, комментарии, правки рецензирования, история изменений (`documents_changes`), запись `.starc`.

## Decisions

1. **Чтение копии только на чтение.** Байты пишутся во временный файл, `sqlite3.connect("file:…?mode=ro&immutable=1", uri=True)`; после разбора файл удаляется. Альтернатива — `sqlite3.deserialize` в памяти: удобнее, но зависит от сборки SQLite; временный файл проще и одинаков везде.
2. **Структура.** Документ типа 1 разбирается `xml.etree`; ровно один `item` сценария (10100) с дочерним текстом (10104), иначе `Invalid`. Персонажи и локации — `item` с MIME `.../character` и `.../location` (в документах типы 30001 и 40001): имя из атрибута `name`, имя целиком заглавными приводится к виду «Вера», как имена из текста; корзина проекта пропускается. Роль лежит в теге `story_role` профиля; значения не сверены (см. «Сверка с образцом»), поэтому пока «эпизодическая».
3. **Текст.** Таблица тегов STARC → типы редактора (`scene_heading`→`sceneHeading`, `scene_characters`→`sceneCharacters`, `action`, `character`, `parenthetical`, `dialogue`, `lyrics`, `shot`, `transition`, `unformatted_text`→`unformatted`, `inline_note`→`inlineNote`, `beat_heading`→`beat`, акты и последовательности); точный список сверяется с образцом. Форма актов и последовательностей не сверена: заметки исследования описывают папки `act`/`sequence` с абзацами `act_heading`/`act_footer` и `sequence_heading`/`sequence_footer`, и верное покажет образец. Параметры группы `scene` (`title`, `story_day`, `color`, `tags`) → `alt`, `day`, `color`, `tags` заголовка; цвет STARC переводится в ближайшую из четырёх меток редактора по таблице, иначе пусто. Неизвестный тег — `Invalid` с его именем.
4. **Подключение.** `.starc` добавляется в `FORMATS` (`application/x-starc`, сигнатура `SQLite format 3\0`) и в `ALLOWED` для `chat` и `import`; извлечение текста и `parse_manuscript` вызывают `parse_starc`.

## Сверка с образцом

Образец 2026-11-05 (STARC 0.8.2 dev 26) подтвердил таблицу `documents`, документ структуры, `item` с MIME-типами, текст 10104, группу `scene` с `content` и абзацы `scene_heading`, `action`, `character`, `parenthetical`, `dialogue` со значением в `<v>`, тег `story_role` со значением `3` у персонажей и локаций. Остального в образце нет, поэтому по решению владельца разбор читает только подтверждённое, всё прочее отклоняет целиком (решения 2 и 3 выполнены частично), а роли ставит «эпизодическая». Что осталось — группа 4 в `tasks.md`.

## Risks / Trade-offs

- [Формат STARC меняется между версиями] → тесты на образце 0.8.x и на испорченных копиях; файл новой версии с другой структурой отклоняется целиком.
- [Теги профилей не сверены] → берём только имя и роль; поля профиля из STARC не переносим в этом change.
