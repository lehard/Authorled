# Proposal

## Why

Вход сейчас идёт через страницы Authentik в его шаблоне («Welcome to authentik!»), а владелец требует вход в стиле продукта, как в макете v1 (`openspec/context/_raw/design/kabinet/`, экраны `#auth/*`; решение 2026-10-30: код из письма при каждом входе, пароль по желанию). Решение 2026-10-31: свои экраны на React, Authentik работает за ними как движок (вариант «Б»).

Попутно при проверке `web-app-shell` найдено:
- локально наш поток входа не включается: бренд `AUTH_BRAND_DOMAIN=localhost` не совпадает с заголовком `Host: localhost:9000`, Authentik отдаёт свой поток по умолчанию без второго фактора;
- войти для разработки нечем: тестовых пользователей нет, есть только первый администратор и сервисная учётная запись `sa-dev` для скриптов;
- почта Authentik не настроена, а код на почту без неё не работает.

## What Changes

- Экраны входа во фронтенде по v1: почта → пароль (только если у аккаунта он задан) → код из письма в 6 ячейках; ошибки неверного пароля и кода; повторная отправка кода через 60 секунд; «Другая почта». Шаги проходят через API шагов входа Authentik (`/api/v3/flows/executor/…`), после успешного входа фронтенд получает токены по OIDC, как сейчас.
- Поток входа Authentik: почта → пароль по политике «у пользователя есть пароль» → второй фактор кодом на почту (Email Authenticator; устройство настраивается при первом входе) → вход. **BREAKING**: второй фактор TOTP заменяется кодом на почту; пользователи с TOTP при входе получат настройку почтового кода.
- Почта Authentik: SMTP из `.env` (`AUTHENTIK_EMAIL__*`), обязательные. Для разработки — Mailpit в compose: письма видны на `http://localhost:8025`, в проде Mailpit не запускается.
- Брендинг Authentik исправлен для адреса с портом (`AUTH_BRAND_DOMAIN=localhost:9000` в разработке), чтобы страницы Authentik (восстановление, профиль, админка) тоже шли нашим потоком.
- Для разработки:
  - команда `./scripts/dev.sh auth-users` создаёт пользователей «Сценарист» (`writer@authorled.test`, группа `screenwriters`) и «Редактор» (`editor@authorled.test`, группа `editors`) с паролем из `AUTH_DEV_USER_PASSWORD`; в проде команды нет;
  - на экране входа в режиме разработки — «Войти как Сценарист» и «Войти как Редактор»: экран сам проходит шаги, код берёт из Mailpit. Поток тот же, что в проде, без обходов. В production-сборку этот код не попадает.
- Фронтенд обращается к шагам входа на своём адресе: в разработке — прокси Vite на Authentik; для прода — тот же путь на обратном прокси и общий домен cookie Authentik (`AUTHENTIK_COOKIE_DOMAIN`).

## Scope

- `web/src/auth/` — экраны входа, клиент шагов входа, быстрый вход для разработки; `web/src/app/` — маршрут `/login`, `RequireAuth` ведёт на него.
- `web/vite.config.ts` — прокси `/api/v3/flows/executor/` на Authentik и `/mailpit/` на Mailpit (только сервер разработки).
- `auth/blueprints/30-authentication-flow.yaml` — поток входа; `auth/blueprints-dev/` — пользователи для разработки (не подключаются автоматически); `auth/compose.yaml` — Mailpit, `AUTHENTIK_EMAIL__*`, `AUTHENTIK_COOKIE_DOMAIN`; `compose.prod.yaml` — Mailpit не запускается.
- `scripts/dev.sh` — команда `auth-users`; `scripts/auth_check.sh` — без изменений проверок токенов.
- `example.env`, README (модуль `auth`, фронтенд).
- Спеки: дельты `auth` и `web/workspace`.
- Проверки — в `tmp/VERIFY.md`.

## Non-goals

- Регистрация (новый адрес → код → имя → пароль по желанию) и «Забыли пароль?» — следующий change по тому же движку.
- Настройки «Вход и безопасность» (смена почты, пароля, список сеансов).
- Вход через внешних провайдеров, WebAuthn.
- Деплой фронтенда и настройка обратного прокси на сервере — описываются требованием и README, сам деплой — отдельный change.
- Перекраска страниц Authentik (вариант «А»): они остаются для админки, профиля и восстановления.

## Capabilities

### New Capabilities
- нет

### Modified Capabilities
- `auth`: второй фактор — код на почту; почта Authentik обязательна; бренд работает с портом в адресе; вход фронтенда идёт через свои экраны и API шагов входа; пользователи для разработки.
- `web/workspace`: «Вход» — свои экраны по v1 вместо перехода на страницу Authentik; быстрый вход для разработки.

## Impact

- Все пользователи с TOTP переходят на код из письма при следующем входе; локальная база пересоздаётся без потерь (эксплуатации нет).
- В `.env` новые обязательные переменные: `AUTHENTIK_EMAIL__HOST`, `__PORT`, `__USERNAME`, `__PASSWORD`, `__USE_TLS`, `__USE_SSL`, `__FROM`, `AUTHENTIK_COOKIE_DOMAIN`; для разработки — `AUTH_DEV_USER_PASSWORD`.
- Новый сервис Mailpit в разработке.
- `web-app-shell` нужно архивировать раньше: эта дельта меняет его требование «Вход».
