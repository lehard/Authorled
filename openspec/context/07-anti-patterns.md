# Anti-patterns
## Продукт: авторство и процесс
1. Код, в котором **продуктовый агент** сам заполняет или утверждает документ за автора. Агент только предлагает: вопросы, варианты, черновик или дифф. (Речь о поведении продукта, не о работе агента-разработчика.)
2. Инструмент утверждения у агента или любой путь сменить статус на «утверждён» без клика автора.
3. Изменение утверждённой версии на месте. Любая правка — новая версия.
4. Автоматическое переписывание зависимых документов при пересмотре. Только флаги, план пересмотра и решение автора.
5. Правила процесса только в промпте или SKILL.md. Блокировка этапов, лимиты и формальные пункты чек-листа проверяет код ядра: модель можно уговорить, код — нет.
6. Методология, зашитая в Python (список документов, чек-листы, лимиты, граф связей). Это данные пакета методологии; код их только читает.

## Архитектура и данные
7. Продуктовые действия через запуск агента (сохранение правки, утверждение, карта проекта). Это детерминированные маршруты API без LLM.
8. Данные произведения в таблицах, Session State или памяти Agno.
9. Векторный индекс как источник истины или запись в индекс в обход ядра. Индекс только строится из канона.
10. Логика продукта на фронтенде. Фронтенд показывает и отправляет, решает бэкенд.
11. Свой маршрут без проверки доступа к проекту. `user_isolation` Agno данные ядра не защищает.
12. Весь проект в контексте модели. Агент получает утверждённые входы этапа и нужные фрагменты.
13. Долгая работа в обработчике запроса (разбор файла, пересчёт индекса, пересмотр) — только через очередь Agno.
14. Отдельный воркер на Valkey (Celery, RQ и т.п.). Фоновые задачи — очередь Agno.
15. Миграции при старте сервиса, правка применённых миграций, смешивание схем ядра и Agno.

## Модели, внешние сервисы, безопасность агента
16. Обращение к моделям в обход LiteLLM, захардкоженные модели (Claude, OpenAI); внешние сервисы, которые увозят тексты за рубеж (модерация OpenAI, VirusTotal, зарубежные эмбеддинги).
17. Включённая телеметрия Agno, CopilotKit или Next.js; подключение Control Plane.
18. Инструменты shell, выполнения кода или свободного доступа к файловой системе у продуктового агента.
19. Текст произведения или персональные данные в логах — только идентификаторы.
20. Печать или коммит секретов; ключи в исходниках вместо env/Lockbox.

## Тесты
21. Проверка ответов LLM в pytest — для этого evals.
22. Моки базы в тестах ядра — только реальный PostgreSQL.
23. Bundled regression suite, кастомные scorers/изоляция/cleanup в evals.

## Платформа Agno (из шаблона)
24. Пересоздание OS Manager / Company Manager / очередей / lifecycle sandbox в приложении — зона Agno.
25. Вторая БД или аргументы в `get_postgres_db()`.
26. Fallback-и: дефолты, маскирующие отсутствующий env, `except: pass`, тихий откат sandbox на сервер или Valkey на in-process.
27. Обход отказа фреймворка или compatibility-адаптер под другую версию Agno.
28. Обновление Agno или других закреплённых зависимостей «заодно», внутри другой задачи.
29. PATCH метаданных Product частичным словарём — на текущем пине PATCH заменяет словарь целиком.

## На чём спотыкаются
- Документация шаблона требует `OPENAI_API_KEY` для OS Manager; после перехода на Claude нужен `ANTHROPIC_API_KEY`.
- `claude-engineer` и `codex-engineer` хардкодят модели мимо `app/settings.py` (см. `openspec/TODO.md`) — нарушает п.16.
- `python -m app.main` слушает `127.0.0.1`, контейнер — `0.0.0.0`.
- Даже `python -m evals --help` требует PostgreSQL; smoke-евалы тратят вызовы модели.
- Удаление декларации не удаляет сохранённые записи; декларации не перезаписывают правки в БД.
- Старт API не доказывает работу инженеров, HTTP-исполнения, делегирования и приёмки Task.
- Product / Project / Task в CompanyOS — сущности Agno, не проект книги.
