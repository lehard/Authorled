# Product Context
## Что за продукт
Authorled — веб-сервис для писателей и сценаристов: проводит автора через методологию создания книги или сценария от замысла до готового произведения. ИИ задаёт вопросы, предлагает варианты, проверяет связность и отслеживает последствия изменений; каждый документ утверждает автор.
Зачем: обычные ИИ-инструменты пишут историю за автора. Здесь история остаётся авторской и не разваливается на длинной дистанции.
Платформа: AgentOS на Agno (этот репозиторий) — runtime агентов продукта.

## Пользователи и роли
- **MVP: один автор** — единственный пользователь проекта, утверждает все документы. Совместную работу в MVP не проектировать.
- После MVP: у автора могут быть соавторы, редактор, продюсер; администратор платформы.

## Ключевые сценарии
Этапы Д1–Д22 — см. `02-domain-glossary.md`.
1. **Пройти документ этапа** (основной цикл ×22): ИИ подтягивает утверждённые документы-входы → вопросы и 3–5 вариантов → черновик по шаблону → формальные пункты чек-листа проверяются автоматически, субъективные отмечает автор → автор утверждает → открывается следующий этап.
2. **Изменить старое решение**: автор меняет утверждённый документ → по графу связей находятся задетые документы → ИИ с цитатами оценивает, что устарело, а что противоречит → автор утверждает план пересмотра → проходит затронутые документы по одному.
3. **Проверить целостность**: на Д18 и Д21 ИИ сверяет сцены, реплики и арки с профилями, темой и правилами мира и показывает расхождения с цитатами; что править и куда вернуться — решает автор.
4. **Начать с рукописи**: загрузка DOCX/PDF, сценария в Fountain или FDX, или проекта STARC (`.starc`, ADR-005) → ИИ извлекает сцены, персонажей, локации → черновики Д14–Д16 → автор проверяет и идёт дальше по методологии.
5. **Собрать финальный текст**: из утверждённых документов в формате Д12 (сценарий, пьеса, проза) → автор утверждает → экспорт: DOCX, PDF, Markdown; сценарий — Fountain, FDX; книга — FB2 и EPUB (FB2 принимают Author.Today, Литнет и ЛитРес: Самиздат).
6. **Писать регулярно**: автор ставит дневную цель по словам и цель проекта с дедлайном → счётчик за день и график прогресса по дням показывают, идёт ли он к цели.

## Что нельзя ломать
- «ИИ помогает пройти документ. Документ закрывает автор»: ИИ никогда не утверждает документ и не переписывает утверждённое без согласия автора.
- Следующий этап не открывается, пока не закрыт чек-лист текущего.
- Изменение утверждённого документа всегда проходит через анализ графа связей и план пересмотра, утверждённый автором.
- Оценки ИИ (устаревание, противоречия, расхождения) — всегда с цитатами из документов.
- Финальный текст (Д22) собирается только из утверждённых документов, без новых фактов.

## Known limitations
- Язык: только русский (интерфейс, вопросы ИИ, документы).
- MVP: один автор, без совместной работы.
- Ветка формата полностью описана только для полного метра.
