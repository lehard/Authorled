# Architecture
Целевая архитектура Authorled. Текущий код — шаблон AgentOS; мастер-спека `openspec/specs/` описывает его как есть и обновляется через changes.

## Сервисы
Проект — монорепозиторий: модульный монолит бэкенда плюс фронтенд в каталоге `web/`. Модули бэкенда живут в одном релизе и общаются через явные контракты; внутренности модуля другие модули не читают.
| Часть | Где в репозитории | Роль |
|---|---|---|
| Фронтенд | `web/` | Интерфейс писателя и админка (тонкий клиент) |
| Бэкенд (Agno) | корень (`app/`, `agents/`, `db/`…) | Продуктовая логика, агент, данные, API |
| Модуль `auth` | `modules/auth/`, `app/auth/` | Полный Authentik: пользователи, вход, роли, токены; адаптер в коде Agno |
Фронтенд и бэкенд живут в одном репозитории (решение 2026-10-27), но собираются и деплоятся отдельно. Модуль `auth` — часть бэкенда: Authentik работает отдельными процессами (сервер, worker), но его конфигурация и релиз в этом репозитории. Связь только через контракты: OIDC/JWT (фронтенд и плагины ↔ Authentik, бэкенд проверяет токены), REST + SSE + AG-UI (web ↔ backend). См. ADR-001.

## Модуль `auth`
- Деплой-часть `modules/auth/`: compose-фрагмент с закреплённой версией Authentik, blueprints (группы, OIDC, потоки входа, сервисные учётные записи), бренд, инициализация БД.
- Кодовая часть `app/auth/`: проверка JWT в AgentOS, сопоставление групп и scopes, `Principal`, зависимость `current_principal` для маршрутов `base_app`, интерфейс `can_access_project`.
- Другие модули знают только `Principal` и интерфейс доступа к проекту; JWT, claims и Authentik вне `app/auth/` не читаются.
- Данные Authentik — схема `authentik` в общей PostgreSQL с отдельной ролью; Agno — схема `ai` под несуперпользовательской ролью `agentos` без доступа к `authentik`.
- Контракт с бэкендом — claims и группы токена (спека `auth`, «Контракт токена»); при выносе Authentik уходит `modules/auth/` и схема `authentik`, `app/auth/` остаётся в бэкенде.

## Слои бэкенда
1. **Ядро** — своя доменная логика: документы Д1–Д22, версии и статусы, чек-листы, граф связей, утверждения автора, журнал решений. Агенту доступно как MCP-инструменты, нашим маршрутам — как обычный код.
2. **Агент и методология** — агент Agno с навыками этапов; Workflows для фиксированных процедур (пересмотр, импорт, проверка документа).
3. **Свои маршруты API** (через `base_app` AgentOS) — продуктовые действия без LLM: проекты, документы, правки автора, утверждение, файлы, поиск. См. ADR-002.

## Инварианты
1. Вся продуктовая логика — в бэкенде; отдельного бэкенда между фронтом и AgentOS нет. AgentOS — единый шлюз для всех клиентов, источник истины — бэкенд.
2. Агент меняет произведение только через ядро. Действия «утвердить документ» у агента нет: утверждает только автор, через наш маршрут.
3. Предложения агента не меняют текст автора напрямую — автор принимает или отклоняет. Предложения правок и комментарии к фрагментам агент создаёт только MCP-инструментами ядра; принятие и отклонение — маршрут автора.
4. Данные Agno и данные произведения в PostgreSQL разделены. Изоляция Agno (`user_isolation`) защищает только его данные; доступ к произведению и роли в проекте бэкенд проверяет сам, изоляция — по проекту.
5. Хранение произведения: текст по фрагментам (сцена, раздел документа); правка автора = новая версия, история не теряется; утверждение и его последствия для связанных документов — атомарно; векторный и полнотекстовый поиск — индекс поверх канона, пересобирается из него.
6. Агно-уровень (из шаблона): Agno владеет OS Manager, Company Manager, durable execution, lifecycle sandbox — не пересоздавать; общая БД через `get_postgres_db()` без аргументов; одна инстанция API; `RUNTIME_ENV=dev` не деплоится; невалидный sandbox падает, а не откатывается на сервер.

## Обязательные и запрещённые паттерны
- Поведение фреймворка сверять с пином Agno в `pyproject.toml`; отказы не обходить, compatibility-адаптеры не писать.
- Content-адаптеры знаний — с уникальными ID; второй адаптер с ID OS запрещён.
- Фронтенд не хранит своих данных и не содержит продуктовой логики.

## Ключевые интеграции
- Authentik (модуль `auth`): JWT с проверкой подписи по ключам Authentik; в AgentOS `authorization=True`, `user_isolation=True`. Приложение берёт ключи только из файла `JWT_JWKS_FILE` (выгружается модулем `auth`); загрузки по URL в Agno 3.1.10 нет.
- Фронтенд: Refine (каркас, роутинг, проекты, файлы, админка), CopilotKit (чат через AG-UI-интеграцию Agno), `@plotwell/editor` (редактор сценария; правки уходят на бэкенд по фрагментам с задержкой; комментарии и предложения агента — плагины-декорации, хранятся на бэкенде); дизайн-система — shadcn/ui на Tailwind CSS — ADR-004.
- Модели: только через LiteLLM; зарубежные LLM разрешены. Эмбеддинги, модерация, антивирус — в РФ или свои.
- Модели — DeepSeek (`deepseek-fast`, `deepseek-thinking`), эмбеддинги — один из псевдонимов, выбранный `EMBEDDINGS_MODEL` (GigaChat `Embeddings-2` или модели шлюза Sber500, все 1024 измерения); всё через LiteLLM-прокси по псевдонимам — ADR-003.
- ClamAV — проверка загрузок до обработки.

## Очереди и события
- **Фоновые задачи и Workflows** — только durable-очередь Agno (`QueueConfig(durable=True)`): задачи и состояние в PostgreSQL, выполняет сам процесс AgentOS. Отдельного воркера (Celery, RQ и т.п.) нет. Сюда же наши задачи: пересчёт поискового индекса после правки, антивирус и разбор загрузок, импорт рукописи, пересмотр.
- **Redis — координация и события, не задачи и не истина** («Redis is optional coordination, never truth»):
  1. стримы и отмена ходов агента между репликами (`QueueConfig(redis=…)`): `/resume` и отмена на любой реплике;
  2. рассылка продуктовых событий фронтенду (pub/sub → SSE: документ утверждён, флаг «требует пересмотра», импорт завершён) на все вкладки и устройства автора — пишем сами.
- На старте (одна инстанция API) Redis не нужен: стрим в памяти, рассылка внутри процесса. При ≥2 репликах Redis обязателен. Закладываем сразу; включение — только конфигурацией, без переделки кода.
- Если Redis включён конфигурацией и недоступен — явная ошибка, без тихого отката на in-process.

## Где что лежит (шаблон)
`app/main.py` — регистрация AgentOS; `app/interfaces.py` — MCP; `app/company.py`, `app/config.yaml`; `app/registry.py`; `app/settings.py` — модели; `app/sandbox.py`; `agents/`, `teams/`, `db/`, `evals/`, `scripts/`. Детали — `openspec/specs/architecture/spec.md`.

## Ключевые решения
- Фронтенд и модульный монолит бэкенда (авторизация — модуль `auth`), связь только через стандартные контракты — ADR-001.
- Свои продуктовые маршруты через `base_app`, утверждение только маршрутом — ADR-002.
- Модели DeepSeek и эмбеддинги (GigaChat или шлюз Sber500, выбор `EMBEDDINGS_MODEL`) через LiteLLM-прокси — ADR-003.
- Фронтенд: Refine, CopilotKit, `@plotwell/editor` на shadcn/ui — ADR-004.
- Писательские потоки по образцу STARC; партнёрство или своё — ADR-005.
