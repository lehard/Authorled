# Security & Compliance
## Классификация данных
- **Произведения и документы автора** — объекты авторского права автора; принадлежат автору, изолируются по проекту.
- **Персональные данные (MVP)** — только email и имя. Других ПДн (платёжных и т.п.) в MVP не собирать.
- **152-ФЗ применяется**: ПДн хранятся и обрабатываются в РФ (Authentik и бэкенд).
- **Внешние LLM** (DeepSeek, ADR-003): текст произведений отправлять можно, но только через LiteLLM; прямые вызовы провайдеров и захардкоженные модели запрещены.
- **Вспомогательные сервисы** (модерация, антивирус, эмбеддинги) — только в РФ или свои: тексты за рубеж через них не уходят (не OpenAI moderation, не VirusTotal, не зарубежные эмбеддинги).
> TODO: ПДн (email, имя) во внешние LLM не передавать (трансграничная передача по 152-ФЗ) — подтвердить у ИБ.
- **Эмбеддинги** — GigaChat `Embeddings-2` через LiteLLM-прокси (ADR-003). Принятый риск: LiteLLM получает OAuth-токен GigaChat без проверки TLS.

## Аутентификация и авторизация
- Пользователи, вход, роли и токены — только Authentik (модуль `auth` этого репозитория, ADR-001). Бэкенд проверяет подпись JWT по ключам Authentik, своих паролей не хранит.
- AgentOS: `authorization=True`, `user_isolation=True`; в проде без ключа проверки JWT не стартовать.
- Доступ к проекту и роли в проекте (автор, соавтор, редактор) проверяет бэкенд; данные произведения изолируются по проекту — изоляция Agno их не покрывает.
- Данные Authentik — схема `authentik` в общей БД с отдельной ролью без доступа к схеме `ai` (обратная изоляция не обеспечивается: загрузочный пользователь БД — суперпользователь). Админка Authentik доступна только группе `admins`.
- Сервисные аккаунты для плагинов (Stark, IDE) — учётные записи Authentik с жёстко ограниченными scopes; проектируются в change `auth-module` (срок жизни и выдача токенов — открытый вопрос интента).

## Инструменты разработки и продуктовый агент
- **Инструменты разработки** (`claude-engineer`, `codex-engineer`): работают с кодом репозитория; shell и правка файлов разрешены (`acceptEdits` / `workspace-write`). Не часть продукта и не обслуживают авторов.
- **Продуктовый агент** — единственный, к кому относятся запреты ниже: без shell, без выполнения кода, без свободного доступа к ФС.

## Защита продуктового агента
- Guardrails Agno на входе и выходе.
- Белый список инструментов; продуктовый агент не выполняет код и не имеет shell и свободной ФС.
- У агента нет действия «утвердить документ»; произведение он меняет только через ядро.

## Требования к интеграциям
- Загруженные файлы (DOCX, PDF) проверяются ClamAV до любой обработки.

## Запреты
- Секреты — только переменные окружения и Lockbox; не в коде, не в логах, не в коммитах.
- В логи не писать текст произведений и персональные данные — только идентификаторы.
- Свой маршрут без проверки доступа к проекту не проходит ревью.

## Зоны без автономии агента
Только явным действием автора (у агента нет таких инструментов или они требуют подтверждения автора):
- утверждение документов и применение плана пересмотра;
- удаление документов, версий или проекта;
- экспорт;
- запуск импорта рукописи;
- отправка чего-либо наружу (вне сервиса);
- административные действия.
