# Security & Compliance
## Классификация данных
- **Произведения и документы автора** — объекты авторского права автора; принадлежат автору, изолируются по проекту.
- **Персональные данные (MVP)** — только email и имя. Других ПДн в MVP не собирать.
- **Платежи (`payments-tochka`)** — ядро хранит только историю платежей: пользователь, идентификаторы операции и списания Точки, сумма, время оплаты, оплаченный период. Данные карты (номер, маска, токен, платёжная система) на сервер не попадают, в таблицы и логи не пишутся. Почта пользователя уходит в Точку и её партнёру по чекам, чтобы прислать чек по 54-ФЗ; это нужно указать в политике обработки ПДн (готовит владелец).
- **152-ФЗ применяется**: ПДн хранятся и обрабатываются в РФ (Authentik и бэкенд).
- **Внешние LLM** (DeepSeek, ADR-003): текст произведений отправлять можно, но только через LiteLLM; прямые вызовы провайдеров и захардкоженные модели запрещены.
- **Вспомогательные сервисы** (модерация, антивирус, эмбеддинги) — только в РФ или свои: тексты за рубеж через них не уходят (не OpenAI moderation, не VirusTotal, не зарубежные эмбеддинги).
> TODO: ПДн (email, имя) во внешние LLM не передавать (трансграничная передача по 152-ФЗ) — подтвердить у ИБ.
- **Эмбеддинги** — один из псевдонимов LiteLLM-прокси, выбранный `EMBEDDINGS_MODEL` (ADR-003): GigaChat `Embeddings-2` или модели общего шлюза Sber500 (`giga-embeddings-instruct-480m`, `bge-m3`, `qwen3-embedding-0.6b`). Принятый риск GigaChat: LiteLLM получает OAuth-токен без проверки TLS. Принятый риск шлюза Sber500 (владелец согласился 2026-10-29): размещение хоста не подтверждено (по IP похоже на РФ), ключ общий и без гарантий после программы; `bge-m3` и `qwen3` — зарубежные разработки, запущенные на шлюзе. Согласование с ИБ — не получено.

## Аутентификация и авторизация
- Пользователи, вход, роли и токены — только Authentik (модуль `auth` этого репозитория, ADR-001). Бэкенд проверяет подпись JWT по ключам Authentik, своих паролей не хранит.
- AgentOS: `authorization=True`, `user_isolation=True`; в проде без ключа проверки JWT не стартовать.
- Доступ к проекту и роли в проекте (автор, соавтор, редактор) проверяет бэкенд; данные произведения изолируются по проекту — изоляция Agno их не покрывает.
- Данные Authentik — схема `authentik` в общей БД с отдельной ролью без доступа к схеме `ai`; API подключается ролью `agentos` без прав суперпользователя и без доступа к схеме `authentik`, загрузочный суперпользователь — только для инициализации и администрирования. Админка Authentik доступна только группе `admins`.
- Сервисные аккаунты для плагинов (Stark, IDE) — учётные записи Authentik с жёстко ограниченными scopes; проектируются в change `auth-module` (срок жизни и выдача токенов — открытый вопрос интента).

## Инструменты разработки и продуктовый агент
- **Инструмент разработки** (`claude-engineer`): работает с кодом репозитория; shell и правка файлов разрешены (`acceptEdits`). Не часть продукта и не обслуживает авторов.
- **Продуктовый агент** — единственный, к кому относятся запреты ниже: без shell, без выполнения кода, без свободного доступа к ФС.

## Защита продуктового агента
- Guardrails Agno на входе и выходе.
- Белый список инструментов; продуктовый агент не выполняет код и не имеет shell и свободной ФС.
- У агента нет действия «утвердить документ»; произведение он меняет только через ядро.

## Требования к интеграциям
- Интернет-эквайринг Точки: тариф меняет только операция, которую API Точки вернуло со статусом `APPROVED`. Уведомлению Точки (вебхук) ядро не верит на слово: проверяет подпись RS256 ключом Точки и всё равно спрашивает Точку об операции. Маршрут уведомлений — единственный свой маршрут без токена пользователя. JWT-ключ Точки — секрет env-файла сервера (`TOCHKA_JWT`), не в коде и не в логах.
- Загруженные файлы (DOCX, PDF, Fountain, FDX, `.starc`) проверяются ClamAV до любой обработки.

## Запреты
- Секреты — только переменные окружения и Lockbox; не в коде, не в логах, не в коммитах.
- В логи не писать текст произведений и персональные данные — только идентификаторы.
- Свой маршрут без проверки доступа к проекту не проходит ревью.

## Зоны без автономии агента
Только явным действием автора (у агента нет таких инструментов или они требуют подтверждения автора):
- утверждение документов и применение плана пересмотра;
- удаление документов, версий или проекта;
- экспорт;
- запуск импорта рукописи;
- отправка чего-либо наружу (вне сервиса);
- административные действия.

## Согласованные исключения и принятые риски
- На время закрытого тестирования сервер продукта стоит в Финляндии, поэтому почты и имена тестировщиков из белого списка хранятся вне РФ. Риск принял владелец 2026-11-06. Перед открытым запуском сервер переносится в РФ. Согласование с ИБ не получено.
- На время закрытого тестирования письма с кодами входа отправляет зарубежный сервис Resend (регион Токио), поэтому почты тестировщиков и коды проходят через него. Риск принял владелец 2026-11-06. Перед открытым запуском почта переходит на российский сервис. Согласование с ИБ не получено.
- В MVP нет отдельного журнала безопасности (входы, доступ к данным, действия администраторов) и мониторинга.
