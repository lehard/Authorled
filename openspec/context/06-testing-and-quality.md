# Testing & Quality
Ядро — детерминированная логика: проверяется pytest, не evals. Evals — только поведение агента; ответы LLM в pytest не проверяем.

Обязательно покрывать (pytest):
- версии документов и их неизменяемость;
- утверждение как одна транзакция (вместе с последствиями для связанных документов);
- флаги пересмотра по графу связей;
- валидаторы чек-листов;
- для каждого своего маршрута — тест доступа: чужой проект → 404 или 403.

Правила:
- Тесты на реальном PostgreSQL (контейнер), без моков БД.
- Evals (`evals/cases.py`, Agno `criteria`/`expected_tool_calls`) тратят вызовы модели; ответы и причины судьи читать глазами.
- CI валидирует SKILL.md и JSON-схемы методологии.

Запуск: `pytest`, `./scripts/validate.sh`, `python -m evals --tag smoke`. Прошло = все зелёные + миграции на чистой базе; результаты и ограничения — в `tmp/VERIFY.md`.
