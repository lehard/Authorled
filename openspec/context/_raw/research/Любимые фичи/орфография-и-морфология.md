# Орфография, пунктуация и морфология имён для русского текста

Исследование, 2026-11-09. Контекст: редактор на ProseMirror (без Tiptap, см. `web/package.json`), сервер на Python в Docker на VPS в Финляндии, тексты авторов приватны, важен 152-ФЗ. Сейчас проверка только браузерная (`spellcheck`, `lang=ru` в `web/src/editor/index.ts`).

Пометка «проверено» значит, что я сам запускал инструмент 2026-11-09 на тестовых фразах (не на текстах авторов); результаты в разделах «Пробный прогон».

### Пробный прогон на выдуманных именах (2026-11-09)

**pymorphy3, разбор в тексте.** Словарные имена разбираются верно: «Анну», «Анной», «Анны» → «анна», «Ивану» → «иван», «Петром» → «пётр». Но первая гипотеза для «Анне» — несклоняемое «анне» (оценка 0,125), нужно смотреть все гипотезы. Выдуманные имена ломаются: «Элронда» → «элронда» женского рода, «Кайлом» → «кайло», «Торвальдом» → «торвалёд», «Огнеславой» → «огнеславой» в именительном, «Ксандру» → «ксандра» женского рода.

**pymorphy3, склонение.** «Анна», «Зарина», «Велимир» склоняются верно. «Ксандр» распознан как аббревиатура и не склоняется, «Элронд» и «Кайл» — как множественное число, «Лютиэн» склоняется как мужское.

**Petrovich (Python 3.0.0), склонение по полу.** Почти всё верно: «Ксандра, Ксандру, Ксандром», «Элронда, Элронду, Элрондом», «Кайла, Кайлом», «Огнеславы, Огнеславой». «Лютиэн» (ж.) не склоняется, это правильно. «Мирель» (ж.) Python-версия не склоняет, JS-версия даёт «Мирели, Мирелью»: правила версий различаются.

**Natasha NER.** Нашла PER «Анне», «Мирель», «Гэндальф», «Элронду», «Ксандру», «Огнеславой», «Кайлом», но пропустила «Элронд» в начале фразы и «Арагорна». Нормализация одиночных имён не сработала: «Анне» → «Анне». Пакет 1.6.0 на Python 3.13 не запустился без старого `setuptools` (pymorphy2 импортирует `pkg_resources`).

Вывод: для имён персонажей надёжнее не угадывать имя по словоформе, а **порождать формы известного имени и искать их в тексте**. Персонажи и так заведены в истории как сущности.

## Рекомендации

### A. Орфография и пунктуация

**Основная: свой LanguageTool в Docker на нашем сервере, плюс свой плагин ProseMirror.**
- Это единственный вариант, где есть и орфография, и часть грамматики с пунктуацией, а текст не покидает наш сервер. Для 152-ФЗ и приватности рукописей это главное.
- Бесплатно, LGPL (используем как отдельный HTTP-сервис), без лимитов.
- Для русского n-граммы не нужны (их нет), поэтому хватит кучи Java порядка 1–2 ГБ. Это заметная доля из 8 ГБ VPS, замерить до решения.
- Пропуски по запятым в сложных предложениях придётся принять. Правила для русского почти не развиваются, на рост качества рассчитывать не стоит.
- Мешает ложная тревога на именах персонажей и авторских словах: нужен словарь истории (имена из сущностей) — передавать их в запросе или фильтровать ответы, и кнопка «добавить в словарь».

**Трудоёмкость: 5–8 дней.** Контейнер в `compose.yaml` и `compose.prod.yaml`, маршрут-прокси `/api/v1/...` с авторизацией (браузер не должен ходить в LT напрямую), плагин ProseMirror на декорациях с отправкой изменённых абзацев (за основу — `prosemirror-languagetool`), всплывашка с исправлениями, словарь истории, отключение шумных правил. Сценарный формат (реплики, ремарки, заголовки сцен) требует, чтобы в проверку не попадали служебные блоки.

**Запасная: nspell + dictionary-ru в Web Worker в браузере.**
- Только орфография, зато полностью у автора и без сервера.
- Главный плюс перед встроенной проверкой браузера: можно добавить в словарь имена персонажей и одинаково вести себя во всех браузерах.
- Минусы: ~5 с загрузки и ~170 МБ памяти на вкладку (замер в Node), словарь старый.
- **Трудоёмкость: 3–4 дня.**

Яндекс.Спеллер не советую как основу. Он даёт только орфографию, а текст уходит третьей стороне. Ещё обязательная подпись Яндекса, и доступ могут отключить без причины. Литера5 в автономной версии — единственный кандидат на заметно лучшую пунктуацию с текстом внутри нашей сети, но цена не опубликована: запросить предложение, если пунктуация станет ключевой.

### B. Имена персонажей

**Основная: pymorphy3 + Petrovich на сервере по схеме «порождаю формы и ищу».**
1. Для каждого персонажа истории строится набор форм имени.
   - Словарные имена («Анна», «Велимир») склоняет pymorphy3 (`lexeme`/`inflect`).
   - Выдуманные — Petrovich по полу персонажа (пол уже есть или добавляется полем).
   - Автор может поправить или дописать формы вручную: для «Мирель» и «Лютиэн» правила спорны.
2. Поиск упоминаний — точное сравнение токенов текста с набором форм (без учёта регистра и ё/е). Ошибиться на «Кайлом» → «кайло» здесь нельзя: ищем известные формы, а не угадываем.
3. Переименование: каждой найденной форме сопоставлен падеж, новое имя склоняется в тот же падеж тем же способом. Изменение предлагается правкой (как предложения соавтора), а не тихой заменой.

Плюсы: MIT, локально, мало памяти (~45 МБ), без моделей. Минусы: омонимы («Вера», «Роза», «Лев» как обычные слова) и неоднозначные формы («Анне» — дательный или предложный) нужно показывать автору на подтверждение.

**Трудоёмкость: 4–6 дней.** Функция в `agno/core` (формы, поиск, план переименования) с тестами, маршрут API, экран подтверждения переименования. Распознавание незаведённых персонажей сюда не входит.

**Запасная: Морфер.ру Web Service для склонения при переименовании.** Склонение ФИО лучше rule-based Petrovich, есть пользовательский словарь исправлений, тариф «Бейсик» 2 500 ₽/мес. Минус: имена уходят стороннему сервису, но это короткие строки, а не текст рукописи. **Трудоёмкость: 2–3 дня** поверх основной схемы (заменить генератор форм).

Natasha или spaCy NER нужны только для другой задачи: найти в тексте *незаведённых* персонажей и предложить их завести. Для узнавания уже известных имён они хуже схемы «порождаю и ищу». У Natasha устаревшие зависимости, MyStem — из-за закрытой лицензии.

## Не проверено

- Реальные цены LanguageTool Premium и Proofreading API: на официальных страницах суммы не отобразились, сторонние агрегаторы противоречат друг другу.
- Цена автономной версии Литеры5 и её требования к серверу; качество её пунктуации на художественном тексте.
- Цена API Главреда (только сторонний каталог) и есть ли вообще API у ОРФО.
- Потребление памяти и задержка своего сервера LanguageTool только с русским языком (не запускал; оценка 1–2 ГБ кучи основана на README образа и сообществе).
- Качество LanguageTool на большой выборке художественного текста и сценариев; доля ложных срабатываний на именах и разговорной речи.
- Загрузка nspell в настоящем браузере и на слабых ноутбуках (мерил только в Node 24 на Mac); hunspell-asm/hunspell-wasm с русским словарём не запускал.
- Хранит ли Яндекс.Спеллер присланные тексты: в условиях об этом ничего нет.
- Работает ли Grammarly с русским в 2026 неофициально: в официальном списке русского нет.
- Отправляет ли встроенная проверка браузера (Chrome «улучшенная проверка», Edge) текст своим серверам в текущих версиях.
- Качество Морфер.ру на выдуманных именах: не вызывал API.
- Качество склонения фамилий и составных имён («Ле Гуин», «фон Штерн») всеми библиотеками.
