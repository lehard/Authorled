# Start Here — Authorled
Продукт: веб-сервис для сценаристов и писателей — редактор по образцу STARC (навигатор, сценарий, персонажи, локации, миры, драфты, рецензирование) с ИИ-соавтором в чате справа; ИИ предлагает, автор решает. MVP — полнометражный сценарий, без методологии Д1–Д22 в интерфейсе (ADR-005, ADR-006); методология — после MVP. Этот репозиторий — монорепозиторий из трёх модулей: бэкенд на Agno (AgentOS) в `agno/`, фронтенд в `web/` (каркас и основа дизайн-системы), деплой-часть авторизации в `auth/`; в ядре бэкенда (`agno/core/`) — пользователи и настройки, истории, документы, тексты, рецензирование, файлы и импорт рукописей.

## Перед началом любой задачи
1. Прочитай 01-product-context.md и 03-architecture.md.
2. Сверься с 05-security-and-compliance.md и 07-anti-patterns.md.
3. Не делай изменений вне scope задачи; не обновляй зависимости «заодно».
4. Не хватает контекста — сформулируй, какого, не угадывай.
5. Идею или решение «сделать после MVP» записывай в backlog-stage-2.md, а не в интенты и не в TODO по файлам; вопрос «будет ли это потом» сначала ищи там.

## Главные запреты
- Продуктовый агент не переписывает текст автора: он создаёт предложения, принимает их только автор. В MVP утверждения документов нет; версии текста — драфты, которые создаёт автор.
- Правила процесса (лимиты, проверки; после MVP — этапы и чек-листы) — в коде ядра, методология — в данных, не в Python и не только в промпте.
- Данные произведения — в ядре, не в таблицах/Session State/памяти Agno; каждый маршрут проверяет доступ к проекту.
- Модели только через LiteLLM; вспомогательные сервисы — в РФ или свои; без телеметрии, без shell/кода у агента.
- Без fallback: ошибка конфигурации — явный отказ.
- Если описание в _raw или мастер-спеке расходится с кодом — верь коду и подними вопрос.
