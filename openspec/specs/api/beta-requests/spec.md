# Beta Requests API Specification

## Purpose
Свой маршрут продукта `POST /api/v1/beta-requests` (тег OpenAPI: Beta): заявка в закрытую бету с сайта продукта, без токена и без вызова модели. Заявки хранятся в ядре (`authorled.beta_requests`); маршрута чтения нет, список смотрит администратор командой `beta-requests`.

## Requirements

### Requirement: Тело заявки
Маршрут `POST /api/v1/beta-requests` MUST принимать JSON-объект:
- `email` — после обрезки пробелов 3–254 символа, одна `@`, непустые части вокруг неё, точка после `@`, без пробелов;
- `name` — после обрезки пробелов 1–100 символов;
- `role` — `screenwriter`, `writer` или `other`;
- `consent` — `true`;
- `website` — необязательная строка (поле-ловушка).
Другие поля MUST приводить к отказу.

#### Scenario: Лишнее поле
- GIVEN верное тело с полем `phone`
- WHEN клиент отправляет заявку
- THEN система MUST ответить `422`, `detail` MUST называть `phone`

### Requirement: POST /api/v1/beta-requests
Система MUST принимать заявку в бету маршрутом `POST /api/v1/beta-requests` без токена и на принятую заявку отвечать `202` с телом `{"status": "accepted"}` — одинаково для новой и повторной почты.

#### Scenario: Новая заявка
- GIVEN заявок с почтой `anna@example.com` нет
- WHEN клиент отправляет `{"email": " Anna@Example.com ", "name": "Анна", "role": "screenwriter", "consent": true}` без токена
- THEN система MUST ответить `202`
- AND в ядре MUST появиться одна заявка с почтой `anna@example.com`, именем «Анна», ролью `screenwriter` и временем согласия

#### Scenario: Повторная почта
- GIVEN заявка с почтой `anna@example.com` уже есть
- WHEN клиент отправляет заявку с почтой `ANNA@example.com` и другим именем
- THEN система MUST ответить `202` с тем же телом
- AND заявка MUST остаться одна, её поля MUST NOT меняться

#### Scenario: Заполнена ловушка
- GIVEN тело верное, а `website` не пустой
- WHEN клиент отправляет заявку
- THEN система MUST ответить `202`
- AND заявка MUST NOT сохраняться

### Requirement: Отказы заявки
Отказы MUST отдаваться как `application/problem+json` (RFC 9457) с понятным по-русски `detail`:
- тело не JSON, не объект, лишнее поле, неверная почта, пустое или длинное имя, неизвестная роль, `consent` не `true` — `422`, `detail` называет поле;
- тело больше 4 КБ — `413`;
- превышена частота — `429` с заголовком `Retry-After` в секундах.
При отказе заявка MUST NOT сохраняться.

#### Scenario: Нет согласия
- GIVEN тело с `"consent": false`
- WHEN клиент отправляет заявку
- THEN система MUST ответить `422`, `detail` MUST называть согласие

#### Scenario: Большое тело
- GIVEN тело больше 4 КБ
- WHEN клиент отправляет заявку
- THEN система MUST ответить `413`

### Requirement: Частота заявок
Система MUST ограничивать общий поток новых заявок: если за последние 60 секунд сохранено 20 заявок, следующая новая заявка MUST получать `429` до истечения окна. Ограничение MUST считаться по данным ядра, а не по памяти процесса, и MUST NOT опираться на адрес клиента.

#### Scenario: Двадцать первая заявка за минуту
- GIVEN за последние 60 секунд сохранено 20 заявок
- WHEN приходит новая заявка с другой почтой
- THEN система MUST ответить `429` с `Retry-After`
- AND заявка MUST NOT сохраняться

### Requirement: Доступ и журнал заявок
Маршрут MUST работать без токена; токен, если передан, MUST NOT влиять на ответ. Почта, имя и тело заявки MUST NOT попадать в логи API; допустимы только идентификатор заявки и код ответа. Маршрута чтения заявок через API MUST NOT быть.

#### Scenario: Чтения нет
- GIVEN заявки сохранены
- WHEN клиент вызывает `GET /api/v1/beta-requests` с токеном автора
- THEN система MUST NOT отдавать заявки

### Requirement: Команда администратора beta-requests
Скрипт администратора MUST давать команду `beta-requests` с целью `local` или `prod`, выполняемую в контейнере API через операции ядра: список заявок в бету от новых к старым — время заявки (UTC), почта, имя, кто (сценарист, писатель, другое) и отметка, есть ли уже неудалённый пользователь с этой почтой. Команда MUST только читать; при отсутствии заявок MUST печатать, что заявок нет, и завершаться кодом `0`.

#### Scenario: Список заявок
- GIVEN есть заявки `anna@example.com` (вчера) и `boris@example.com` (сегодня), пользователь `anna@example.com` уже зарегистрирован
- WHEN администратор выполняет `beta-requests`
- THEN первой MUST идти строка `boris@example.com`, второй — `anna@example.com`
- AND у `anna@example.com` MUST стоять отметка, что пользователь уже есть

#### Scenario: Заявок нет
- GIVEN заявок нет
- WHEN администратор выполняет `beta-requests`
- THEN команда MUST напечатать, что заявок нет, и завершиться кодом `0`
