# api/stories Specification

## Purpose
Свои маршруты продукта `/api/v1` для историй автора: истории, их документы (персонажи, локации, миры, сценарий, драфты), текст сценария с ревизией, корзины и доступ только владельцу. Без вызова модели (ADR-002).

## Requirements

### Requirement: Доступ только владельцу истории
Каждый маршрут истории и всего, что в ней лежит, MUST проверять доступ через интерфейс доступа к проекту модуля `auth`; источник доступа MUST регистрировать ядро при старте API. Доступ MUST быть только у владельца истории — пользователя, создавшего её. На чужую или несуществующую историю, документ, заметку, комментарий, предложение или файл MUST возвращаться `404` без указания, существует ли запись.

#### Scenario: Чужая история
- WHEN пользователь Б запрашивает `GET /api/v1/projects/{id}/drafts` истории пользователя А
- THEN ответ MUST быть `404` в `application/problem+json`

#### Scenario: Без токена
- WHEN запрос к `GET /api/v1/projects` пришёл без `Authorization`
- THEN ответ MUST быть `401`

#### Scenario: Аккаунта ещё нет
- WHEN пользователь с верным токеном, у которого ещё нет записи в `users`, вызывает `GET /api/v1/projects`
- THEN ответ MUST быть `404` с причиной «Аккаунта ещё нет: сначала вызовите GET /api/v1/me»

#### Scenario: Источник доступа не зарегистрирован
- WHEN проверка доступа к проекту вызвана до регистрации источника ядром
- THEN MUST возникать ошибка конфигурации, а не ответ «доступ есть»

#### Scenario: Чужая заметка
- WHEN пользователь Б вызывает `PATCH`, `DELETE`, `trash` или `restore` для заметки пользователя А или читает и создаёт заметки его истории
- THEN ответ MUST быть `404` в `application/problem+json`, заметка MUST NOT меняться

### Requirement: Ошибки маршрутов историй
Отказы маршрутов историй MUST возвращаться в `application/problem+json` с полями `type`, `title`, `status`, `detail`; `detail` MUST быть по-русски и MUST называть поле или причину. Тело, которое не JSON или не объект, неизвестное поле и неверное значение MUST давать `422`.

#### Scenario: Неизвестное поле
- WHEN клиент отправляет `PATCH /api/v1/projects/{id}` с полем `color`
- THEN ответ MUST быть `422`, и `detail` MUST называть поле `color`

### Requirement: Список историй
`GET /api/v1/projects` MUST возвращать истории вызывающего: `id`, `title`, `description`, `format`, `word_goal`, `goal_deadline`, `cover_color`, `created_at`, `updated_at`, `deleted_at`, `drafts_count` (драфты не в корзине), `open_draft_id` (драфт, в котором история откроется у вызывающего), по убыванию `updated_at`. Без параметра или с `trash=false` MUST возвращаться истории не в корзине, с `trash=true` — только истории в корзине.

#### Scenario: Полка и корзина
- WHEN у автора истории «Маяк» и «Паром», и «Паром» удалена в корзину
- THEN `GET /api/v1/projects` MUST вернуть только «Маяк», а `GET /api/v1/projects?trash=true` — только «Паром»

#### Scenario: Число драфтов
- WHEN в истории три драфта, и один из них в корзине
- THEN `drafts_count` MUST быть 2

#### Scenario: История без цели
- WHEN автор создал историю и не задавал ей цели
- THEN в списке у неё MUST быть `word_goal` = `null` и `goal_deadline` = `null`

#### Scenario: Цвет в списке
- WHEN у автора история «Маяк» с цветом `teal`
- THEN `GET /api/v1/projects` MUST вернуть её с `cover_color` `teal`

### Requirement: Изменение истории
`PATCH /api/v1/projects/{id}` MUST менять `title`, `description`, `word_goal`, `goal_deadline` и `cover_color` истории не в корзине; пустое `title` MUST давать `422`. `word_goal` MUST быть целым от 1 до 1 000 000 или `null`, `goal_deadline` — датой `YYYY-MM-DD` или `null`, `cover_color` — цветом палитры («Цвет обложки истории»); иное MUST давать `422` с `detail`, называющим поле. Срок без цели (после изменения `goal_deadline` задан, а `word_goal` — `null`) MUST давать `422` с `detail`, называющим `goal_deadline`. Срок в прошлом MUST приниматься. Изменение MUST обновлять `updated_at`, кроме изменения одного только `cover_color`: оно `updated_at` MUST NOT менять. Ответ MUST содержать все поля истории из «Список историй», кроме `drafts_count` и `open_draft_id`.

#### Scenario: Переименование
- WHEN автор меняет название истории на «Маяк. Версия 2»
- THEN `GET /api/v1/projects` MUST показывать новое название

#### Scenario: Цель истории со сроком
- WHEN автор отправляет `PATCH /api/v1/projects/{id}` с `word_goal` = 20000 и `goal_deadline` = `2026-11-30`
- THEN ответ MUST быть `200` с этими значениями, а `title` и `description` MUST остаться прежними

#### Scenario: Срок без цели
- GIVEN у истории нет цели
- WHEN автор отправляет `PATCH /api/v1/projects/{id}` с `goal_deadline` = `2026-11-30`
- THEN ответ MUST быть `422` с `detail`, называющим `goal_deadline`, и история MUST NOT измениться

#### Scenario: Снять цель
- GIVEN у истории цель 20 000 и срок
- WHEN автор отправляет `PATCH /api/v1/projects/{id}` с `word_goal` = `null` и `goal_deadline` = `null`
- THEN ответ MUST содержать `word_goal` = `null` и `goal_deadline` = `null`

#### Scenario: Смена цвета
- GIVEN история «Маяк» с цветом `blue` и `updated_at` 2026-11-01
- WHEN автор вызывает `PATCH /api/v1/projects/{id}` с `{"cover_color": "amber"}`
- THEN ответ MUST содержать `cover_color` `amber`, а `updated_at` MUST остаться 2026-11-01

#### Scenario: Цвет вне палитры
- WHEN автор вызывает `PATCH /api/v1/projects/{id}` с `{"cover_color": "pink"}`
- THEN ответ MUST быть `422`, `detail` MUST называть поле `cover_color`, и история MUST NOT меняться

### Requirement: Цвет обложки истории
У каждой истории MUST быть цвет обложки `cover_color` — одно из значений `blue`, `teal`, `amber`, `crimson`, `plum`, `graphite`; пустого значения MUST NOT быть. Новой истории, для которой автор не передал `cover_color`, ядро MUST назначать цвет, следующий в этом порядке за цветом последней созданной истории того же автора (включая истории в корзине), после `graphite` — `blue`; у первой истории автора цвет MUST быть `blue`. Правило MUST быть одним для истории из JSON и из рукописи.

#### Scenario: Три истории подряд
- GIVEN у автора нет историй
- WHEN автор создаёт истории «Маяк», «Паром» и «Дача»
- THEN их `cover_color` MUST быть `blue`, `teal` и `amber`

#### Scenario: После последнего цвета
- GIVEN последняя созданная история автора имеет `cover_color` `graphite`
- WHEN автор создаёт новую историю
- THEN её `cover_color` MUST быть `blue`

#### Scenario: История из рукописи
- GIVEN последняя созданная история автора имеет `cover_color` `teal`
- WHEN автор создаёт историю из файла `паром.fountain`
- THEN её `cover_color` MUST быть `amber`

#### Scenario: Цвет выбран автором
- GIVEN автор сменил цвет последней созданной истории на `plum`
- WHEN автор создаёт новую историю
- THEN её `cover_color` MUST быть `graphite`

#### Scenario: Цвет при создании продолжает круг
- GIVEN автор создал историю с выбранным `cover_color` `crimson`
- WHEN автор создаёт следующую историю без `cover_color`
- THEN её `cover_color` MUST быть `plum`

#### Scenario: Истории другого автора
- GIVEN у автора А три истории, у автора Б историй нет
- WHEN автор Б создаёт историю
- THEN её `cover_color` MUST быть `blue`

#### Scenario: Истории до появления цвета
- GIVEN истории автора созданы до появления `cover_color`
- WHEN применены миграции
- THEN у каждой истории MUST быть цвет, по кругу палитры в порядке их создания, начиная с `blue`

### Requirement: Корзина историй
`POST /api/v1/projects/{id}/trash` MUST помещать историю в корзину (заполнять `deleted_at`), `POST /api/v1/projects/{id}/restore` — возвращать её со всеми документами. Автоматической очистки корзины MUST NOT быть: история лежит в корзине, пока автор её не удалит. Изменение истории в корзине и её документов MUST давать `409`.

#### Scenario: Восстановление со всем содержимым
- WHEN автор удаляет историю с тремя персонажами в корзину и восстанавливает её
- THEN история MUST вернуться в список, и её документы MUST быть на месте

#### Scenario: Правка истории в корзине
- WHEN автор вызывает `PATCH /api/v1/documents/{id}` для документа истории, лежащей в корзине
- THEN ответ MUST быть `409`

### Requirement: Удаление истории навсегда
`DELETE /api/v1/projects/{id}` MUST удалять навсегда только историю в корзине — вместе с драфтами, документами, текстами, заметками, комментариями, предложениями, снимками, точками и файлами; ответ `204`. Для истории не в корзине MUST возвращаться `409`.

#### Scenario: Удаление не из корзины
- WHEN автор вызывает `DELETE` для истории, которой нет в корзине
- THEN ответ MUST быть `409`, история MUST остаться

#### Scenario: Удаление из корзины
- WHEN автор удаляет навсегда историю из корзины
- THEN в базе MUST NOT остаться её драфтов, документов, текстов, заметок, комментариев, предложений, снимков, точек и файлов

### Requirement: Дерево документов
`GET /api/v1/drafts/{id}/documents` MUST возвращать все документы драфта, включая лежащие в корзине истории, без текста сценария: `id`, `draft_id`, `kind`, `name`, `role`, `summary`, `position`, `revision`, `fields`, `created_at`, `updated_at`, `deleted_at`. Порядок — по виду, затем по `position`. Документы других драфтов MUST NOT возвращаться.

#### Scenario: Корзина истории в дереве
- WHEN персонаж «Миша» удалён в корзину истории
- THEN дерево его драфта MUST содержать «Мишу» с заполненным `deleted_at`

#### Scenario: Другой драфт
- WHEN персонаж «Нина» создан в драфте 2
- THEN дерево драфта 1 MUST NOT содержать «Нину»

### Requirement: Виды документов и их поля
Документ MUST иметь вид `character`, `location`, `world` или `script` и непустое `name`. `role` (`main`, `secondary`, `episodic`) MUST быть только у персонажа и локации. `fields` MUST содержать только поля своего вида: профиль макета v2 (`PROFILE`), у персонажа `age` и `gender`, у мира `overview`, у сценария `logline`, `show`, `title_page`, `synopsis`. `show` MUST задавать все части: `title`, `logline`, `synopsis`, `treatment`, `text`. Имя сценария MUST быть «Сценарий» у каждого драфта; правка `name` сценария MUST давать `422`. Неизвестное поле или неверный тип значения MUST давать `422` с именем поля.

Если в `fields` несколько ошибок, `detail` MUST называть их все одним сообщением, в порядке полей запроса:
- неизвестное поле — его имя и допустимые поля этого вида;
- неверное значение — имя поля и ожидаемое значение: «строка», «да или нет» или список допустимых значений.

Ни одно поле MUST NOT сохраняться, пока есть хотя бы одна ошибка; значения MUST NOT приводиться к нужному типу.

#### Scenario: Поле чужого вида
- WHEN автор сохраняет у локации поле `age`
- THEN ответ MUST быть `422`, и `detail` MUST называть `age` и допустимые поля локации

#### Scenario: Роль у мира
- WHEN автор создаёт мир с `role` `main`
- THEN ответ MUST быть `422`

#### Scenario: Тэглайн у сценария
- WHEN автор сохраняет у сценария поле `tagline`
- THEN ответ MUST быть `422`, и `detail` MUST называть `tagline`

#### Scenario: Часть без логлайна
- WHEN автор сохраняет `show` без `logline`
- THEN ответ MUST быть `422`, и `detail` MUST называть `show.logline`

#### Scenario: Имя сценария
- GIVEN создана история «Маяк»
- WHEN автор читает документы драфта и меняет `name` сценария
- THEN имя сценария MUST быть «Сценарий», а ответ на правку MUST быть `422`

#### Scenario: Несколько ошибок сразу
- WHEN персонажа создают с `fields` `{"speech": {"value": "Бормочет"}, "age": 55, "appearance": "Худой"}`
- THEN ответ MUST быть `422`, и `detail` MUST называть `speech` и `age` с ожидаемым значением «строка» и `appearance` с допустимыми полями персонажа
- AND персонаж MUST NOT создаться

#### Scenario: Пол вне списка
- WHEN у персонажа сохраняют `gender` `"male"`
- THEN ответ MUST быть `422`, и `detail` MUST называть `gender` и допустимые значения

### Requirement: Создание документов
`POST /api/v1/drafts/{id}/documents` MUST создавать персонажа, локацию или мир в драфте — один (объект) или несколько (массив) за один запрос, все или ни одного; новый документ встаёт в конец своей группы. Вид `script` MUST давать `422`: сценарий у драфта ровно один.

#### Scenario: Пакет персонажей из текста
- WHEN автор создаёт массивом персонажей «Нина» и «Олег», и у «Олега» пустое имя
- THEN ответ MUST быть `422`, и ни один персонаж MUST NOT создаваться

### Requirement: Изменение документа с ревизией
`GET /api/v1/documents/{id}` MUST возвращать документ с `revision`. `PATCH /api/v1/documents/{id}` MUST требовать `If-Match` с текущей ревизией; изменение MUST увеличивать ревизию на 1. Без `If-Match` MUST возвращаться `428`, при несовпадении — `409`, документ MUST NOT меняться. Поля `fields`, переданные в `PATCH`, MUST заменять только переданные ключи.

#### Scenario: Две вкладки
- WHEN две вкладки прочитали персонажа с ревизией 3, и первая сохранила изменение
- THEN `PATCH` второй с `If-Match: 3` MUST получить `409`, изменение первой MUST остаться

#### Scenario: Частичное изменение профиля
- WHEN у персонажа заполнены `fear` и `habits`, и автор сохраняет только `fear`
- THEN `habits` MUST остаться прежним

### Requirement: Порядок документов
`PATCH /api/v1/documents/{id}` с `position` MUST переставлять документ внутри его группы и сдвигать остальные; позиции в группе MUST оставаться 0…N−1 без пропусков.

#### Scenario: Сортировка по алфавиту
- WHEN клиент проставляет позиции персонажей по алфавиту
- THEN дерево MUST возвращать их в этом порядке

### Requirement: Корзина истории
`POST /api/v1/documents/{id}/trash` и `POST /api/v1/documents/{id}/restore` MUST перемещать персонажа, локацию или мир в корзину истории и обратно со всеми полями. Сценарий MUST NOT удаляться: для него MUST возвращаться `409`. `DELETE /api/v1/documents/{id}` MUST удалять навсегда только документ в корзине; `POST /api/v1/drafts/{id}/trash/empty` MUST удалять навсегда документы корзины этого драфта, драфты и заметки истории в корзине. Автоочистки MUST NOT быть.

#### Scenario: Сценарий не удаляется
- WHEN автор вызывает `POST /api/v1/documents/{id}/trash` для сценария
- THEN ответ MUST быть `409`

#### Scenario: Очистка корзины истории
- WHEN в корзине драфта два документа, и автор очищает корзину
- THEN их MUST NOT остаться, а документы вне корзины MUST остаться

#### Scenario: Очистка не трогает другой драфт
- WHEN в корзине драфта 2 лежит персонаж, и автор очищает корзину драфта 1
- THEN персонаж драфта 2 MUST остаться в его корзине

#### Scenario: Очистка удаляет заметки
- WHEN в корзине лежит заметка истории, и автор очищает корзину драфта 2
- THEN заметки MUST NOT остаться, а заметки вне корзины MUST остаться

#### Scenario: Очистка запертого драфта
- WHEN в корзине лежит заметка, и автор очищает корзину запертого драфта
- THEN ответ MUST быть `409`, заметка MUST остаться в корзине

### Requirement: Текст сценария
`GET /api/v1/documents/{id}/text` MUST возвращать текст сценария (`content`) и его `revision`. `PUT /api/v1/documents/{id}/text` MUST заменять текст целиком и требовать `If-Match` с ревизией текста: без него — `428`, при несовпадении — `409`, текст MUST NOT меняться. Для документа без текста (персонаж, локация, мир) MUST возвращаться `404`. Успешный `PUT` MUST в той же транзакции записывать вызывающему прирост слов (`api/writing`, «Прирост слов при сохранении автором»); ответ от этого MUST NOT меняться.

#### Scenario: Сохранение текста
- WHEN автор сохраняет текст с `If-Match: 7`, и ревизия текста 7
- THEN ответ MUST содержать ревизию 8, и следующий `GET` MUST вернуть новый текст

#### Scenario: Устаревшая ревизия
- WHEN автор сохраняет текст с `If-Match: 6`, а ревизия текста 7
- THEN ответ MUST быть `409`, текст MUST остаться прежним

#### Scenario: Сохранение записывает прирост
- GIVEN в сценарии 100 слов
- WHEN автор сохраняет текст со 130 словами
- THEN ответ MUST содержать новую ревизию, а за текущий отрезок у автора по этой истории MUST добавиться прирост 30

### Requirement: Проверка текста сценария
Ядро MUST принимать текст только в формате документа редактора: корень `doc`, блоки — известные типы абзацев сценария и `pageBreak`, метки — `bold`, `italic`, `underline`, `textColor`, `highlight`, `comment`, `suggestion` со своими атрибутами. У каждого заголовка сцены MUST быть непустой `uid`, уникальный в тексте. Иначе MUST возвращаться `422` с причиной; заменять или отбрасывать неизвестное MUST NOT.

#### Scenario: Сцена без uid
- WHEN автор сохраняет текст, где у второго заголовка сцены нет `uid`
- THEN ответ MUST быть `422`, и `detail` MUST называть заголовок сцены без `uid`

#### Scenario: Неизвестный тип абзаца
- WHEN текст содержит абзац типа `chorus`
- THEN ответ MUST быть `422`, и `detail` MUST называть `chorus`

### Requirement: Драфты
`GET /api/v1/projects/{id}/drafts` MUST возвращать драфты истории, включая лежащие в корзине: `id`, `project_id`, `name`, `locked`, `forked_from_id`, `forked_from_name`, `created_at`, `updated_at`, `deleted_at`. Все драфты MUST быть равны: отметки основного драфта MUST NOT быть. `PATCH /api/v1/drafts/{id}` MUST менять `name` и `locked`; пустое `name` MUST давать `422`.

#### Scenario: Драфты истории
- WHEN в истории драфты «Драфт 1» и «После читки»
- THEN `GET /api/v1/projects/{id}/drafts` MUST вернуть оба, и ни одно поле MUST NOT выделять один из них как основной

#### Scenario: Переименование драфта
- WHEN автор меняет `name` драфта на «Версия для продюсера»
- THEN следующий `GET` списка MUST показывать новое название

#### Scenario: Драфт без пометок
- WHEN в тексте драфта 1 есть комментарий, и автор создаёт драфт на его основе
- THEN текст нового драфта MUST совпадать с текстом драфта 1 без метки комментария, и веток комментариев у него MUST NOT быть

#### Scenario: Запрещённый драфт
- WHEN автор сохраняет текст драфта с `locked` `true`
- THEN ответ MUST быть `409`, текст драфта MUST NOT меняться

### Requirement: Создание драфта
`POST /api/v1/projects/{id}/drafts` с непустым `name` и `base_id` (драфт этой истории не в корзине) MUST создавать незапертый драфт с копией текста, паспорта, персонажей, локаций и миров основы вне корзины. Метки комментариев и предложений в копию MUST NOT попадать. Комментарии, предложения, беседы, снимки и точки MUST NOT копироваться. Драфт MUST запоминать `forked_from_id` и `forked_from_name`.

#### Scenario: Независимость драфтов
- WHEN драфт 2 создан из драфта 1, и в драфте 2 изменены карточка персонажа и текст
- THEN карточка и текст драфта 1 MUST остаться прежними

#### Scenario: Основа из другой истории
- WHEN `base_id` указывает на драфт другой истории
- THEN ответ MUST быть `404`, драфт MUST NOT создаваться

#### Scenario: Подпись после удаления основы
- WHEN драфт 2 создан из драфта 1, и драфт 1 удалён навсегда
- THEN `forked_from_id` драфта 2 MUST быть пустым, а `forked_from_name` MUST остаться «Драфт 1»

### Requirement: Замок драфта
Драфт с `locked` `true` MUST запрещать правку всего содержимого: документов, текста, порядка, корзины документов, импорта, отката к снимку и точке — ответ `409`, данные MUST NOT меняться. Переименовать драфт, снять замок, удалить драфт в корзину и создать драфт на его основе MUST быть можно.

#### Scenario: Запертая карточка
- WHEN автор сохраняет карточку персонажа в запертом драфте
- THEN ответ MUST быть `409`, карточка MUST NOT меняться

#### Scenario: Основа заперта
- WHEN автор создаёт драфт на основе запертого
- THEN новый драфт MUST быть создан незапертым

### Requirement: Драфт в корзине
`POST /api/v1/drafts/{id}/trash` и `POST /api/v1/drafts/{id}/restore` MUST перемещать драфт в корзину истории и обратно со всем содержимым. Последний драфт истории вне корзины MUST NOT удаляться: `409`. `DELETE /api/v1/drafts/{id}` MUST удалять навсегда только драфт в корзине со всем содержимым. Правка содержимого драфта в корзине MUST давать `409`.

#### Scenario: Последний драфт
- WHEN в истории один драфт вне корзины, и автор удаляет его в корзину
- THEN ответ MUST быть `409`, драфт MUST остаться

#### Scenario: Восстановление со всем содержимым
- WHEN автор удаляет драфт с двумя персонажами в корзину и восстанавливает его
- THEN драфт, его текст и персонажи MUST быть на месте

### Requirement: Последний открытый драфт
`POST /api/v1/drafts/{id}/open` MUST запоминать драфт как последний открытый для пары пользователь и история. `open_draft_id` MUST быть этим драфтом, а если запись пуста или драфт в корзине — драфтом вне корзины с самым поздним `updated_at`. Открыть драфт в корзине MUST NOT быть возможно: `409`.

#### Scenario: Другое устройство
- WHEN автор открыл драфт 2 и затем запросил `GET /api/v1/projects` с другого устройства
- THEN `open_draft_id` этой истории MUST быть драфтом 2

#### Scenario: Открытый драфт удалён
- WHEN последний открытый драфт удалён в корзину
- THEN `open_draft_id` MUST быть драфтом вне корзины с самым поздним `updated_at`

### Requirement: Снимки документа
При сохранении текста или полей документа ядро MUST сохранять снимок прежнего состояния этой части, если её последний снимок старше 10 минут или снимков нет. Части: `text` (текст сценария) и `fields` (`name`, `role`, `summary`, `fields`). Изменение только `position` снимка MUST NOT создавать. Сбой снимка MUST отменять сохранение.

#### Scenario: Частые сохранения
- WHEN автор сохраняет текст пять раз за минуту
- THEN снимок MUST появиться не больше одного раза

#### Scenario: Правка через 10 минут
- WHEN последний снимок текста старше 10 минут, и автор сохраняет текст
- THEN MUST появиться снимок с причиной `auto` и текстом до сохранения

#### Scenario: Части независимы
- WHEN автор сохраняет только логлайн сценария
- THEN снимок MUST быть только у части `fields`

### Requirement: История документа
`GET /api/v1/documents/{id}/versions` с `part` `text` или `fields` MUST возвращать снимки этой части, новые первыми: `id`, `part`, `reason` (`auto`, `suggestion`, `import`, `restore`), `saved_by`, `saved_by_name`, `saved_at`. `GET /api/v1/versions/{id}` MUST возвращать снимок с содержимым. Снимки чужой истории MUST давать `404`.

#### Scenario: Кто сохранил
- WHEN автор сохранил текст, и через 10 минут сохранил снова
- THEN снимок MUST показывать имя автора, время первого сохранения и причину `auto`

#### Scenario: Неверная часть
- WHEN клиент запрашивает `part=cover`
- THEN ответ MUST быть `422`, и `detail` MUST называть `part`

#### Scenario: Чужой снимок
- WHEN пользователь Б запрашивает снимок истории пользователя А
- THEN ответ MUST быть `404`

### Requirement: Откат документа
`POST /api/v1/versions/{id}/restore` с `If-Match` текущей ревизии этой части MUST сохранять нынешнее состояние снимком с причиной `restore` и возвращать содержимое снимка новой ревизией. Другие части и документы MUST NOT меняться. Метки комментариев без ветки и метки решённых предложений в возвращённом тексте MUST NOT оставаться.

#### Scenario: Откат карточки
- WHEN автор откатывает карточку персонажа к снимку
- THEN карточка MUST вернуться к снимку, а текст и другие документы драфта MUST остаться прежними

#### Scenario: Отмена отката
- WHEN автор откатил текст к снимку
- THEN в истории MUST быть снимок с причиной `restore` и текстом до отката

#### Scenario: Устаревшая ревизия отката
- WHEN `If-Match` не совпадает с ревизией части
- THEN ответ MUST быть `409`, документ MUST NOT меняться

### Requirement: Точка драфта
`POST /api/v1/drafts/{id}/points` с непустым `name` MUST сохранять точку: все документы драфта вне корзины с полями и текстом, кто и когда. `GET /api/v1/drafts/{id}/points` MUST возвращать точки драфта, новые первыми: `id`, `name`, `kind` (`manual` или `auto`), `created_by`, `created_by_name`, `created_at`. Точки другого драфта MUST NOT возвращаться.

#### Scenario: Точка без названия
- WHEN автор сохраняет точку с пустым `name`
- THEN ответ MUST быть `422`, точка MUST NOT создаваться

#### Scenario: Свои точки у драфта
- WHEN точка сохранена в драфте 1
- THEN список точек драфта 2 MUST NOT её содержать

### Requirement: Откат к точке
`POST /api/v1/points/{id}/restore` MUST в одной транзакции создать точку `auto` «Перед откатом к «<название>»» и вернуть драфт к точке: содержимое и состав документов. Документы, созданные после точки, MUST уйти в корзину истории; документы из точки MUST вернуться, даже если их удалили. Ревизии изменённых частей MUST увеличиться.

#### Scenario: Смена героини
- WHEN после точки изменены карточка Веры и текст, и автор откатывается к точке
- THEN карточка и текст MUST вернуться к состоянию точки

#### Scenario: Документ после точки
- WHEN персонаж «Нина» создан после точки
- THEN после отката «Нина» MUST лежать в корзине истории

#### Scenario: Документ удалён навсегда
- WHEN персонаж из точки удалён навсегда
- THEN после отката персонаж MUST вернуться с теми же полями

#### Scenario: Отмена отката к точке
- WHEN автор откатился к точке и затем откатился к созданной автоматически точке
- THEN драфт MUST вернуться к состоянию до первого отката

### Requirement: Заметки истории
`GET /api/v1/projects/{id}/notes` MUST возвращать заметки истории, включая лежащие в корзине, в порядке создания: `id`, `project_id`, `title`, `body`, `revision`, `created_at`, `updated_at`, `deleted_at` и `file` — оригинал заметки (`id`, `name`, `media_type`, `size_bytes`) или `null`, если оригинала нет. `POST /api/v1/projects/{id}/notes` с непустым `title` и необязательным `body` MUST создавать заметку без оригинала с ревизией 1; ответ `201`. Пустое `title`, не строка в `body` и неизвестное поле MUST давать `422`. В истории в корзине создание MUST давать `409`.

#### Scenario: Новая заметка
- WHEN автор создаёт заметку с `title` «Финал» без `body`
- THEN ответ MUST быть `201` с пустым `body`, `revision` 1 и `file` `null`, и заметка MUST быть в списке истории

#### Scenario: Порядок заметок
- WHEN автор создал заметки «Финал» и «Вера», а затем изменил «Финал»
- THEN список MUST идти в порядке «Финал», «Вера»

#### Scenario: Пустое название
- WHEN автор создаёт заметку с `title` из пробелов
- THEN ответ MUST быть `422`, и `detail` MUST называть название

#### Scenario: Заметка с оригиналом в списке
- GIVEN автор загрузил в заметки `эпоха.pdf`
- WHEN он запрашивает заметки истории
- THEN у этой заметки `file` MUST содержать имя `эпоха.pdf`, тип и размер файла

### Requirement: Изменение заметки с ревизией
`PATCH /api/v1/notes/{id}` MUST менять `title` и `body`, если `If-Match` равен текущей ревизии, MUST увеличивать ревизию на 1 и MUST возвращать новую ревизию в `ETag`. Без `If-Match` MUST быть `428`, со старой ревизией — `409`. Пустое `title`, неизвестное поле и пустое тело MUST давать `422`. Заметку в корзине и заметку истории в корзине MUST NOT менять: `409`.

#### Scenario: Правка текста
- WHEN автор меняет `body` заметки с ревизией 1, передав `If-Match: 1`
- THEN ответ MUST быть `200` с `revision` 2 и `ETag` «2»

#### Scenario: Старая ревизия
- WHEN заметка на ревизии 3, а правка пришла с `If-Match: 2`
- THEN ответ MUST быть `409`, заметка MUST NOT меняться

#### Scenario: Заметка в корзине
- WHEN автор меняет заметку из корзины
- THEN ответ MUST быть `409`

### Requirement: Корзина заметок
`POST /api/v1/notes/{id}/trash` и `POST /api/v1/notes/{id}/restore` MUST перемещать заметку в корзину и обратно с названием, текстом и оригиналом. `DELETE /api/v1/notes/{id}` MUST удалять навсегда только заметку из корзины вместе с её оригиналом; ответ `204`. Повторный перенос и удаление заметки не из корзины MUST давать `409`. В истории в корзине все три действия MUST давать `409`.

#### Scenario: Восстановление
- WHEN автор удаляет заметку в корзину и восстанавливает её
- THEN название, текст и место в списке MUST остаться прежними

#### Scenario: Удаление не из корзины
- WHEN автор вызывает `DELETE` для заметки вне корзины
- THEN ответ MUST быть `409`, заметка MUST остаться

#### Scenario: Оригинал в корзине
- GIVEN заметка с оригиналом `эпоха.pdf` лежит в корзине
- WHEN автор скачивает её оригинал
- THEN байты ответа MUST совпадать с загруженными

#### Scenario: Удаление навсегда с оригиналом
- GIVEN заметка с оригиналом лежит в корзине
- WHEN автор удаляет её навсегда
- THEN метаданные оригинала MUST отвечать `404`

### Requirement: Заметки и драфты
Заметки MUST NOT зависеть от драфтов. Создание драфта MUST NOT копировать заметки, снимки и точки MUST NOT хранить заметки, откат к снимку или точке MUST NOT менять заметки. Замок драфта, драфт в корзине и удаление драфта MUST NOT менять заметки и MUST NOT запрещать их правку.

#### Scenario: Новый драфт
- WHEN в истории две заметки, и автор создаёт драфт
- THEN заметок в истории MUST остаться две

#### Scenario: Откат к точке
- WHEN точка создана, затем изменена заметка, и автор откатывается к точке
- THEN заметка MUST остаться изменённой, и ревизия заметки MUST NOT меняться

#### Scenario: Все драфты заперты
- WHEN все драфты истории заперты, и автор меняет заметку
- THEN правка MUST пройти

### Requirement: Отказы историй не кэшируются
Отказы маршрутов историй MUST отправляться с заголовком `Cache-Control: no-store`. Статус и тело отказа MUST NOT меняться.

#### Scenario: Отказ до создания аккаунта
- WHEN пользователь с верным токеном, у которого ещё нет записи в `users`, вызывает `GET /api/v1/projects`
- THEN ответ MUST быть `404` с причиной «Аккаунта ещё нет: сначала вызовите GET /api/v1/me» и заголовком `Cache-Control: no-store`

### Requirement: Каркасы историй
Каркасы MUST быть данными ядра в файле репозитория. У каркаса MUST быть уникальный `id`, непустые название и описание и хотя бы один акт; у акта — непустое название и хотя бы одна точка; у точки — непустые название и подсказка. Файл с ошибкой или неизвестным полем MUST останавливать старт API ошибкой, называющей каркас и поле.

#### Scenario: Каркас без точек
- GIVEN в файле каркасов у акта «Развязка» каркаса `three-acts` нет точек
- WHEN стартует API
- THEN старт MUST завершиться ошибкой, называющей `three-acts` и акт «Развязка»

#### Scenario: Набор каркасов
- WHEN API стартовал с файлом каркасов репозитория
- THEN в нём MUST быть каркасы `three-acts`, `hero-journey`, `fifteen-points` и `tv-episode`

### Requirement: Список каркасов
`GET /api/v1/story-templates` MUST возвращать все каркасы в порядке файла: `id`, `name`, `description` и `acts`, у каждого акта — `name` и `points` с `name` и `hint`. Маршрут MUST требовать токен и MUST NOT требовать доступа к истории.

#### Scenario: Список для автора
- WHEN вошедший автор вызывает `GET /api/v1/story-templates`
- THEN ответ MUST быть `200` и содержать каркас `three-acts` с названием «Три акта» и его актами и точками

#### Scenario: Без токена
- WHEN `GET /api/v1/story-templates` вызван без `Authorization`
- THEN ответ MUST быть `401`

### Requirement: Текст из каркаса
С `template` текст сценария MUST идти по актам и точкам каркаса в их порядке: абзац акта с его названием, затем на каждую точку абзац группы с названием точки, пустой заголовок сцены с новым `uid` и абзац бита с подсказкой точки. Неизвестный или не строковый `template` MUST давать `422`, называющий значение; история MUST NOT создаваться.

#### Scenario: Три акта
- WHEN автор вызывает `POST /api/v1/projects` с `{"title": "Маяк", "template": "three-acts"}`
- THEN текст сценария MUST начинаться абзацем акта с названием первого акта «Три акта», за ним — группой с названием первой точки, пустым заголовком сцены и битом с её подсказкой
- AND число заголовков сцен MUST равняться числу точек каркаса, а их `uid` MUST быть разными

#### Scenario: Неизвестный каркас
- WHEN автор вызывает `POST /api/v1/projects` с `{"title": "Маяк", "template": "save-the-dog"}`
- THEN ответ MUST быть `422`, `detail` MUST называть `save-the-dog`, и история MUST NOT создаваться

#### Scenario: Каркас и рукопись
- WHEN автор создаёт историю multipart-запросом с файлом рукописи и полем `template`
- THEN ответ MUST быть `422`, называющий поле `template`, и история MUST NOT создаваться

### Requirement: Поиск по драфту истории
`GET /api/v1/drafts/{id}/search?q=<запрос>` MUST искать запрос в драфте и его истории: в тексте сценария, в логлайне и синопсисе сценария, в имени, кратком описании и текстовых полях персонажей, локаций и миров вне корзины, в названии и тексте заметок истории вне корзины. Совпадение MUST искаться по подстроке без учёта регистра и разницы «ё» и «е». Поиск MUST NOT менять данные и MUST работать и в запертом драфте.

#### Scenario: Имя персонажа по всей истории
- GIVEN в драфте «Тихой воды» Вера упоминается в сценах 2 и 5, у неё есть профиль, и заметка «Финал» говорит о ней
- WHEN автор ищет «вера»
- THEN ответ MUST содержать сцены 2 и 5, профиль Веры и заметку «Финал»

#### Scenario: Ё и е
- GIVEN в логлайне написано «посёлок у озера»
- WHEN автор ищет «ПОСЕЛОК»
- THEN ответ MUST содержать логлайн с совпадением «посёлок»

#### Scenario: Корзина не ищется
- GIVEN локация «Пристань» лежит в корзине истории
- WHEN автор ищет «пристань», и больше нигде этого слова нет
- THEN группа документов MUST быть пустой

#### Scenario: Запертый драфт
- GIVEN драфт заперт
- WHEN автор ищет в нём
- THEN поиск MUST вернуть результаты, а драфт MUST остаться без изменений

### Requirement: Ответ поиска по группам
Ответ поиска MUST содержать запрос и три группы. `scenes`: `uid`, `number`, `heading` сцены. `documents`: `id`, `kind`, `name` документа (для логлайна и синопсиса — сценарий драфта) и поле `field` первого совпадения. `notes`: `id`, `title` заметки и `field` (`title` или `body`). У каждого результата MUST быть `count` совпадений и `snippet`: `before`, `match`, `after` вокруг первого совпадения, где `match` — текст как он написан. Порядок MUST совпадать с порядком в тексте и в навигаторе.

#### Scenario: Кусочек вокруг совпадения
- GIVEN в сцене 3 написано «КОЛЯ протирает ключ ветошью» и других «ключ» в сцене нет
- WHEN автор ищет «КЛЮЧ»
- THEN у сцены 3 `count` MUST быть 1, `match` MUST быть «ключ», `before` MUST заканчиваться на «протирает », а `after` MUST начинаться с « ветошью»

#### Scenario: Логлайн и синопсис отдельно
- GIVEN «посёлок» есть и в логлайне, и в синопсисе
- WHEN автор ищет «поселок»
- THEN в `documents` MUST быть два результата сценария драфта: с `field` `logline` и с `field` `synopsis`

#### Scenario: Совпадение в поле профиля
- GIVEN в подробном описании Коли есть «чинит моторы и лодки»
- WHEN автор ищет «моторы»
- THEN в `documents` MUST быть Коля с `field` этого поля

#### Scenario: Текст вне сцен
- GIVEN абзац с совпадением стоит вне сцен: до первого заголовка сцены или в строке акта
- WHEN автор ищет это слово
- THEN первым в `scenes` MUST быть один результат без `uid` с `number` 0 и пустым `heading`

#### Scenario: Ничего не нашлось
- GIVEN в истории нет слова «дирижабль»
- WHEN автор ищет «дирижабль»
- THEN ответ MUST быть `200` с тремя пустыми группами

### Requirement: Отказы поиска
Запрос без `q`, пустой после обрезки пробелов, короче 2 символов или длиннее 200 символов MUST давать `422` с причиной в `detail`, а не пустой или полный список. Чужая или несуществующая история драфта MUST давать `404`, как у остальных маршрутов драфта.

#### Scenario: Один символ
- GIVEN автор открыл свою историю
- WHEN он ищет «а»
- THEN ответ MUST быть `422` с `detail` о том, что нужно не меньше 2 символов

#### Scenario: Без запроса
- GIVEN автор открыл свою историю
- WHEN он вызывает поиск без `q`
- THEN ответ MUST быть `422` в `application/problem+json`

#### Scenario: Чужая история
- GIVEN драфт принадлежит истории другого пользователя
- WHEN автор ищет в нём
- THEN ответ MUST быть `404`, и ни один результат из той истории MUST NOT вернуться

### Requirement: Заметка из файла
`POST /api/v1/projects/{id}/notes/files` (multipart: `file`) MUST проверять файл как файл чата (размер, тип, ClamAV, извлечение текста) и создавать заметку с оригиналом: название — имя файла без расширения, текст — извлечённый текст, ревизия 1; ответ `201` с заметкой. Текст длиннее 500 000 знаков MUST давать `422` с причиной. Любой отказ MUST NOT оставлять ни заметки, ни файла. В истории в корзине MUST быть `409`.

#### Scenario: PDF в заметки
- WHEN автор загружает `Эпоха.pdf` с текстом «Москва, 1913»
- THEN ответ MUST быть `201`, заметка MUST называться «Эпоха», её `body` MUST содержать «Москва, 1913», а `file.name` MUST быть `Эпоха.pdf`

#### Scenario: Текст правится, оригинал нет
- GIVEN заметка из `Эпоха.pdf`
- WHEN автор меняет её `body`
- THEN байты оригинала MUST остаться прежними

#### Scenario: Скан
- WHEN автор загружает PDF из одних сканов
- THEN ответ MUST быть `422` с причиной, что в файле нет текста, и заметка MUST NOT появиться

#### Scenario: Слишком длинный текст
- WHEN автор загружает TXT на 600 000 знаков
- THEN ответ MUST быть `422`, `detail` MUST называть предел 500 000 знаков, и заметка MUST NOT появиться

#### Scenario: Чужая история
- WHEN пользователь загружает файл в заметки чужой истории
- THEN ответ MUST быть `404`, и файл MUST NOT сохраниться

### Requirement: Заметка из файла беседы
`POST /api/v1/files/{id}/note` для файла беседы (`purpose` `chat`) MUST создавать заметку с копией этого файла как оригиналом и его текстом, по тем же правилам названия и длины текста, что и загрузка в заметки; ответ `201` с заметкой. Файл беседы MUST оставаться прежним. Файл импорта или оригинал другой заметки MUST давать `422`. Чужой файл MUST давать `404`.

#### Scenario: Файл из чата
- GIVEN автор приложил к беседе `Эпоха.pdf`
- WHEN он сохраняет этот файл в заметки
- THEN MUST появиться заметка «Эпоха» с текстом файла и оригиналом с теми же байтами, а файл беседы MUST остаться

#### Scenario: Файл импорта
- WHEN автор сохраняет в заметки файл с `purpose` `import`
- THEN ответ MUST быть `422`, и заметка MUST NOT появиться

### Requirement: Место для оригиналов заметок
Сумма размеров оригиналов заметок всех историй пользователя, включая заметки в корзине, MUST NOT превышать предел его тарифа. Загрузка в заметки и сохранение файла беседы, после которых сумма превысит предел, MUST давать `413` с причиной, называющей занятое место и предел в мегабайтах, и MUST NOT оставлять заметки и файла. Файлы чата и импорта в эту сумму MUST NOT входить.

#### Scenario: Место кончилось
- GIVEN предел тарифа 500 МБ, и оригиналы заметок пользователя занимают 495 МБ
- WHEN автор загружает в заметки PDF на 10 МБ
- THEN ответ MUST быть `413`, и `detail` MUST называть 495 и 500 МБ

#### Scenario: Место освобождается удалением навсегда
- GIVEN место занято до предела
- WHEN автор удаляет заметку с оригиналом из корзины навсегда и загружает файл того же размера
- THEN загрузка MUST пройти

#### Scenario: Файлы чата не считаются
- GIVEN место для оригиналов заметок занято до предела
- WHEN автор прикладывает файл к беседе
- THEN ответ MUST быть `201`

### Requirement: Создание новой истории
`POST /api/v1/projects` с непустым `title` MUST создавать историю вызывающего с `format` `feature`, драфт «Драфт 1» и его сценарий: документ вида `script` с именем, равным названию. Без `template` текст сценария MUST быть пустым текстом из одного заголовка сцены с новым `uid`; с `template` — текстом каркаса (требование «Текст из каркаса»). Ответ `201` MUST содержать историю, `id` драфта и `id` сценария. Пустое или пробельное `title` MUST давать `422`.

#### Scenario: Новая история
- WHEN автор вызывает `POST /api/v1/projects` с `{"title": "Маяк"}`
- THEN ответ MUST быть `201`, у истории MUST быть один драфт «Драфт 1», и `GET /api/v1/drafts/{id}/documents` MUST содержать ровно один документ вида `script`

#### Scenario: Пустое название
- WHEN автор вызывает `POST /api/v1/projects` с `{"title": "  "}`
- THEN ответ MUST быть `422`, история MUST NOT создаваться

#### Scenario: Без каркаса
- WHEN автор вызывает `POST /api/v1/projects` с `{"title": "Маяк"}`
- THEN текст сценария MUST состоять из одного пустого заголовка сцены

#### Scenario: Цвет в ответе создания
- WHEN автор вызывает `POST /api/v1/projects` с `{"title": "Маяк"}`
- THEN история в ответе MUST содержать `cover_color`, назначенный ядром

### Requirement: Цвет при создании
`POST /api/v1/projects` MAY принимать `cover_color` — цвет палитры («Цвет обложки истории»): в JSON полем объекта, в multipart с файлом рукописи полем формы. С ним история MUST получать этот цвет, без него — цвет по правилу «Цвет обложки истории». `cover_color` вне палитры MUST давать `422` с `detail`, называющим `cover_color`, и история MUST NOT создаваться.

#### Scenario: Цвет выбран при создании
- GIVEN последняя созданная история автора бирюзовая
- WHEN автор вызывает `POST /api/v1/projects` с `{"title": "Маяк", "cover_color": "plum"}`
- THEN ответ MUST быть `201`, и история MUST иметь `cover_color` `plum`

#### Scenario: Цвет вне палитры при создании
- WHEN автор вызывает `POST /api/v1/projects` с `{"title": "Маяк", "cover_color": "pink"}`
- THEN ответ MUST быть `422`, `detail` MUST называть поле `cover_color`, и история MUST NOT создаваться

#### Scenario: Рукопись с цветом
- WHEN автор создаёт историю multipart-запросом с `title` «Паром», файлом `паром.fountain` и `cover_color` `crimson`
- THEN ответ MUST быть `201`, и история MUST иметь `cover_color` `crimson`

### Requirement: Цвет новой истории
`GET /api/v1/projects/next-cover-color` MUST возвращать `200` с `{"cover_color": <цвет>}` — цвет, который ядро назначило бы следующей истории вызывающего, созданной без `cover_color` (требование «Цвет обложки истории»). Маршрут MUST NOT создавать и менять истории.

#### Scenario: Первая история
- GIVEN у автора нет историй
- WHEN автор вызывает `GET /api/v1/projects/next-cover-color`
- THEN ответ MUST быть `{"cover_color": "blue"}`

#### Scenario: После бирюзовой
- GIVEN последняя созданная история автора, сейчас в корзине, бирюзовая
- WHEN автор вызывает `GET /api/v1/projects/next-cover-color`
- THEN ответ MUST быть `{"cover_color": "amber"}`

#### Scenario: Совпадает с созданием
- GIVEN маршрут вернул автору `amber`
- WHEN автор создаёт историю без `cover_color`
- THEN её `cover_color` MUST быть `amber`
