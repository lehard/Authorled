# api/stories Specification

## Purpose
Свои маршруты продукта `/api/v1` для историй автора: истории, их документы (персонажи, локации, миры, сценарий, драфты), текст сценария с ревизией, корзины и доступ только владельцу. Без вызова модели (ADR-002).

## Requirements

### Requirement: Доступ только владельцу истории
Каждый маршрут истории и всего, что в ней лежит, MUST проверять доступ через интерфейс доступа к проекту модуля `auth`; источник доступа MUST регистрировать ядро при старте API. Доступ MUST быть только у владельца истории — пользователя, создавшего её. На чужую или несуществующую историю, документ, комментарий, предложение или файл MUST возвращаться `404` без указания, существует ли запись.

#### Scenario: Чужая история
- WHEN пользователь Б запрашивает `GET /api/v1/projects/{id}/documents` истории пользователя А
- THEN ответ MUST быть `404` в `application/problem+json`

#### Scenario: Без токена
- WHEN запрос к `GET /api/v1/projects` пришёл без `Authorization`
- THEN ответ MUST быть `401`

#### Scenario: Аккаунта ещё нет
- WHEN пользователь с верным токеном, у которого ещё нет записи в `users`, вызывает `GET /api/v1/projects`
- THEN ответ MUST быть `404` с причиной «Аккаунта ещё нет: сначала вызовите GET /api/v1/me»

#### Scenario: Источник доступа не зарегистрирован
- WHEN проверка доступа к проекту вызвана до регистрации источника ядром
- THEN MUST возникать ошибка конфигурации, а не ответ «доступ есть»

### Requirement: Ошибки маршрутов историй
Отказы маршрутов историй MUST возвращаться в `application/problem+json` с полями `type`, `title`, `status`, `detail`; `detail` MUST быть по-русски и MUST называть поле или причину. Тело, которое не JSON или не объект, неизвестное поле и неверное значение MUST давать `422`.

#### Scenario: Неизвестное поле
- WHEN клиент отправляет `PATCH /api/v1/projects/{id}` с полем `color`
- THEN ответ MUST быть `422`, и `detail` MUST называть поле `color`

### Requirement: Список историй
`GET /api/v1/projects` MUST возвращать истории вызывающего: `id`, `title`, `description`, `format`, `created_at`, `updated_at`, `deleted_at`, `drafts_count` (драфты не в корзине), `open_draft_id` (драфт, в котором история откроется у вызывающего), по убыванию `updated_at`. Без параметра или с `trash=false` MUST возвращаться истории не в корзине, с `trash=true` — только истории в корзине.

#### Scenario: Полка и корзина
- WHEN у автора истории «Маяк» и «Паром», и «Паром» удалена в корзину
- THEN `GET /api/v1/projects` MUST вернуть только «Маяк», а `GET /api/v1/projects?trash=true` — только «Паром»

#### Scenario: Число драфтов
- WHEN в истории три драфта, и один из них в корзине
- THEN `drafts_count` MUST быть 2

### Requirement: Создание истории
`POST /api/v1/projects` с непустым `title` MUST создавать историю вызывающего с `format` `feature`, драфт «Драфт 1» и его сценарий: документ вида `script` с именем, равным названию, и пустым текстом из одного заголовка сцены с новым `uid`. Ответ `201` MUST содержать историю, `id` драфта и `id` сценария. Пустое или пробельное `title` MUST давать `422`.

#### Scenario: Новая история
- WHEN автор вызывает `POST /api/v1/projects` с `{"title": "Маяк"}`
- THEN ответ MUST быть `201`, у истории MUST быть один драфт «Драфт 1», и `GET /api/v1/drafts/{id}/documents` MUST содержать ровно один документ вида `script`

#### Scenario: Пустое название
- WHEN автор вызывает `POST /api/v1/projects` с `{"title": "  "}`
- THEN ответ MUST быть `422`, история MUST NOT создаваться

### Requirement: Изменение истории
`PATCH /api/v1/projects/{id}` MUST менять `title` и `description` истории не в корзине; пустое `title` MUST давать `422`. Изменение MUST обновлять `updated_at`.

#### Scenario: Переименование
- WHEN автор меняет название истории на «Маяк. Версия 2»
- THEN `GET /api/v1/projects` MUST показывать новое название

### Requirement: Корзина историй
`POST /api/v1/projects/{id}/trash` MUST помещать историю в корзину (заполнять `deleted_at`), `POST /api/v1/projects/{id}/restore` — возвращать её со всеми документами. Автоматической очистки корзины MUST NOT быть: история лежит в корзине, пока автор её не удалит. Изменение истории в корзине и её документов MUST давать `409`.

#### Scenario: Восстановление со всем содержимым
- WHEN автор удаляет историю с тремя персонажами в корзину и восстанавливает её
- THEN история MUST вернуться в список, и её документы MUST быть на месте

#### Scenario: Правка истории в корзине
- WHEN автор вызывает `PATCH /api/v1/documents/{id}` для документа истории, лежащей в корзине
- THEN ответ MUST быть `409`

### Requirement: Удаление истории навсегда
`DELETE /api/v1/projects/{id}` MUST удалять навсегда только историю в корзине — вместе с драфтами, документами, текстами, комментариями, предложениями, снимками, точками и файлами; ответ `204`. Для истории не в корзине MUST возвращаться `409`.

#### Scenario: Удаление не из корзины
- WHEN автор вызывает `DELETE` для истории, которой нет в корзине
- THEN ответ MUST быть `409`, история MUST остаться

#### Scenario: Удаление из корзины
- WHEN автор удаляет навсегда историю из корзины
- THEN в базе MUST NOT остаться её драфтов, документов, текстов, комментариев, предложений, снимков, точек и файлов

### Requirement: Дерево документов
`GET /api/v1/drafts/{id}/documents` MUST возвращать все документы драфта, включая лежащие в корзине истории, без текста сценария: `id`, `draft_id`, `kind`, `name`, `role`, `summary`, `position`, `revision`, `fields`, `created_at`, `updated_at`, `deleted_at`. Порядок — по виду, затем по `position`. Документы других драфтов MUST NOT возвращаться.

#### Scenario: Корзина истории в дереве
- WHEN персонаж «Миша» удалён в корзину истории
- THEN дерево его драфта MUST содержать «Мишу» с заполненным `deleted_at`

#### Scenario: Другой драфт
- WHEN персонаж «Нина» создан в драфте 2
- THEN дерево драфта 1 MUST NOT содержать «Нину»

### Requirement: Виды документов и их поля
Документ MUST иметь вид `character`, `location`, `world` или `script` и непустое `name`. `role` (`main`, `secondary`, `episodic`) MUST быть только у персонажа и локации. `fields` MUST содержать только поля своего вида: профиль макета v2 (`PROFILE`), у персонажа `age` и `gender`, у мира `overview`, у сценария `tagline`, `logline`, `show`, `title_page`, `synopsis`. Неизвестное поле или неверный тип значения MUST давать `422` с именем поля.

#### Scenario: Поле чужого вида
- WHEN автор сохраняет у локации поле `age`
- THEN ответ MUST быть `422`, и `detail` MUST называть `age`

#### Scenario: Роль у мира
- WHEN автор создаёт мир с `role` `main`
- THEN ответ MUST быть `422`

### Requirement: Создание документов
`POST /api/v1/drafts/{id}/documents` MUST создавать персонажа, локацию или мир в драфте — один (объект) или несколько (массив) за один запрос, все или ни одного; новый документ встаёт в конец своей группы. Вид `script` MUST давать `422`: сценарий у драфта ровно один.

#### Scenario: Пакет персонажей из текста
- WHEN автор создаёт массивом персонажей «Нина» и «Олег», и у «Олега» пустое имя
- THEN ответ MUST быть `422`, и ни один персонаж MUST NOT создаваться

### Requirement: Изменение документа с ревизией
`GET /api/v1/documents/{id}` MUST возвращать документ с `revision`. `PATCH /api/v1/documents/{id}` MUST требовать `If-Match` с текущей ревизией; изменение MUST увеличивать ревизию на 1. Без `If-Match` MUST возвращаться `428`, при несовпадении — `409`, документ MUST NOT меняться. Поля `fields`, переданные в `PATCH`, MUST заменять только переданные ключи.

#### Scenario: Две вкладки
- WHEN две вкладки прочитали персонажа с ревизией 3, и первая сохранила изменение
- THEN `PATCH` второй с `If-Match: 3` MUST получить `409`, изменение первой MUST остаться

#### Scenario: Частичное изменение профиля
- WHEN у персонажа заполнены `fear` и `habits`, и автор сохраняет только `fear`
- THEN `habits` MUST остаться прежним

### Requirement: Порядок документов
`PATCH /api/v1/documents/{id}` с `position` MUST переставлять документ внутри его группы и сдвигать остальные; позиции в группе MUST оставаться 0…N−1 без пропусков.

#### Scenario: Сортировка по алфавиту
- WHEN клиент проставляет позиции персонажей по алфавиту
- THEN дерево MUST возвращать их в этом порядке

### Requirement: Корзина истории
`POST /api/v1/documents/{id}/trash` и `POST /api/v1/documents/{id}/restore` MUST перемещать персонажа, локацию или мир в корзину истории и обратно со всеми полями. Сценарий MUST NOT удаляться: для него MUST возвращаться `409`. `DELETE /api/v1/documents/{id}` MUST удалять навсегда только документ в корзине; `POST /api/v1/drafts/{id}/trash/empty` MUST удалять навсегда документы корзины этого драфта и драфты истории в корзине. Автоочистки MUST NOT быть.

#### Scenario: Сценарий не удаляется
- WHEN автор вызывает `POST /api/v1/documents/{id}/trash` для сценария
- THEN ответ MUST быть `409`

#### Scenario: Очистка корзины истории
- WHEN в корзине драфта два документа, и автор очищает корзину
- THEN их MUST NOT остаться, а документы вне корзины MUST остаться

#### Scenario: Очистка не трогает другой драфт
- WHEN в корзине драфта 2 лежит персонаж, и автор очищает корзину драфта 1
- THEN персонаж драфта 2 MUST остаться в его корзине

### Requirement: Текст сценария
`GET /api/v1/documents/{id}/text` MUST возвращать текст сценария (`content`) и его `revision`. `PUT /api/v1/documents/{id}/text` MUST заменять текст целиком и требовать `If-Match` с ревизией текста: без него — `428`, при несовпадении — `409`, текст MUST NOT меняться. Для документа без текста (персонаж, локация, мир) MUST возвращаться `404`.

#### Scenario: Сохранение текста
- WHEN автор сохраняет текст с `If-Match: 7`, и ревизия текста 7
- THEN ответ MUST содержать ревизию 8, и следующий `GET` MUST вернуть новый текст

#### Scenario: Устаревшая ревизия
- WHEN автор сохраняет текст с `If-Match: 6`, а ревизия текста 7
- THEN ответ MUST быть `409`, текст MUST остаться прежним

### Requirement: Проверка текста сценария
Ядро MUST принимать текст только в формате документа редактора: корень `doc`, блоки — известные типы абзацев сценария и `pageBreak`, метки — `bold`, `italic`, `underline`, `textColor`, `highlight`, `comment`, `suggestion` со своими атрибутами. У каждого заголовка сцены MUST быть непустой `uid`, уникальный в тексте. Иначе MUST возвращаться `422` с причиной; заменять или отбрасывать неизвестное MUST NOT.

#### Scenario: Сцена без uid
- WHEN автор сохраняет текст, где у второго заголовка сцены нет `uid`
- THEN ответ MUST быть `422`, и `detail` MUST называть заголовок сцены без `uid`

#### Scenario: Неизвестный тип абзаца
- WHEN текст содержит абзац типа `chorus`
- THEN ответ MUST быть `422`, и `detail` MUST называть `chorus`

### Requirement: Драфты
`GET /api/v1/projects/{id}/drafts` MUST возвращать драфты истории, включая лежащие в корзине: `id`, `project_id`, `name`, `locked`, `forked_from_id`, `forked_from_name`, `created_at`, `updated_at`, `deleted_at`. Все драфты MUST быть равны: отметки основного драфта MUST NOT быть. `PATCH /api/v1/drafts/{id}` MUST менять `name` и `locked`; пустое `name` MUST давать `422`.

#### Scenario: Драфты истории
- WHEN в истории драфты «Драфт 1» и «После читки»
- THEN `GET /api/v1/projects/{id}/drafts` MUST вернуть оба, и ни одно поле MUST NOT выделять один из них как основной

#### Scenario: Переименование драфта
- WHEN автор меняет `name` драфта на «Версия для продюсера»
- THEN следующий `GET` списка MUST показывать новое название

#### Scenario: Драфт без пометок
- WHEN в тексте драфта 1 есть комментарий, и автор создаёт драфт на его основе
- THEN текст нового драфта MUST совпадать с текстом драфта 1 без метки комментария, и веток комментариев у него MUST NOT быть

#### Scenario: Запрещённый драфт
- WHEN автор сохраняет текст драфта с `locked` `true`
- THEN ответ MUST быть `409`, текст драфта MUST NOT меняться

### Requirement: Создание драфта
`POST /api/v1/projects/{id}/drafts` с непустым `name` и `base_id` (драфт этой истории не в корзине) MUST создавать незапертый драфт с копией текста, паспорта, персонажей, локаций и миров основы вне корзины. Метки комментариев и предложений в копию MUST NOT попадать. Комментарии, предложения, беседы, снимки и точки MUST NOT копироваться. Драфт MUST запоминать `forked_from_id` и `forked_from_name`.

#### Scenario: Независимость драфтов
- WHEN драфт 2 создан из драфта 1, и в драфте 2 изменены карточка персонажа и текст
- THEN карточка и текст драфта 1 MUST остаться прежними

#### Scenario: Основа из другой истории
- WHEN `base_id` указывает на драфт другой истории
- THEN ответ MUST быть `404`, драфт MUST NOT создаваться

#### Scenario: Подпись после удаления основы
- WHEN драфт 2 создан из драфта 1, и драфт 1 удалён навсегда
- THEN `forked_from_id` драфта 2 MUST быть пустым, а `forked_from_name` MUST остаться «Драфт 1»

### Requirement: Замок драфта
Драфт с `locked` `true` MUST запрещать правку всего содержимого: документов, текста, порядка, корзины документов, импорта, отката к снимку и точке — ответ `409`, данные MUST NOT меняться. Переименовать драфт, снять замок, удалить драфт в корзину и создать драфт на его основе MUST быть можно.

#### Scenario: Запертая карточка
- WHEN автор сохраняет карточку персонажа в запертом драфте
- THEN ответ MUST быть `409`, карточка MUST NOT меняться

#### Scenario: Основа заперта
- WHEN автор создаёт драфт на основе запертого
- THEN новый драфт MUST быть создан незапертым

### Requirement: Драфт в корзине
`POST /api/v1/drafts/{id}/trash` и `POST /api/v1/drafts/{id}/restore` MUST перемещать драфт в корзину истории и обратно со всем содержимым. Последний драфт истории вне корзины MUST NOT удаляться: `409`. `DELETE /api/v1/drafts/{id}` MUST удалять навсегда только драфт в корзине со всем содержимым. Правка содержимого драфта в корзине MUST давать `409`.

#### Scenario: Последний драфт
- WHEN в истории один драфт вне корзины, и автор удаляет его в корзину
- THEN ответ MUST быть `409`, драфт MUST остаться

#### Scenario: Восстановление со всем содержимым
- WHEN автор удаляет драфт с двумя персонажами в корзину и восстанавливает его
- THEN драфт, его текст и персонажи MUST быть на месте

### Requirement: Последний открытый драфт
`POST /api/v1/drafts/{id}/open` MUST запоминать драфт как последний открытый для пары пользователь и история. `open_draft_id` MUST быть этим драфтом, а если запись пуста или драфт в корзине — драфтом вне корзины с самым поздним `updated_at`. Открыть драфт в корзине MUST NOT быть возможно: `409`.

#### Scenario: Другое устройство
- WHEN автор открыл драфт 2 и затем запросил `GET /api/v1/projects` с другого устройства
- THEN `open_draft_id` этой истории MUST быть драфтом 2

#### Scenario: Открытый драфт удалён
- WHEN последний открытый драфт удалён в корзину
- THEN `open_draft_id` MUST быть драфтом вне корзины с самым поздним `updated_at`

### Requirement: Снимки документа
При сохранении текста или полей документа ядро MUST сохранять снимок прежнего состояния этой части, если её последний снимок старше 10 минут или снимков нет. Части: `text` (текст сценария) и `fields` (`name`, `role`, `summary`, `fields`). Изменение только `position` снимка MUST NOT создавать. Сбой снимка MUST отменять сохранение.

#### Scenario: Частые сохранения
- WHEN автор сохраняет текст пять раз за минуту
- THEN снимок MUST появиться не больше одного раза

#### Scenario: Правка через 10 минут
- WHEN последний снимок текста старше 10 минут, и автор сохраняет текст
- THEN MUST появиться снимок с причиной `auto` и текстом до сохранения

#### Scenario: Части независимы
- WHEN автор сохраняет только логлайн сценария
- THEN снимок MUST быть только у части `fields`

### Requirement: История документа
`GET /api/v1/documents/{id}/versions` с `part` `text` или `fields` MUST возвращать снимки этой части, новые первыми: `id`, `part`, `reason` (`auto`, `suggestion`, `import`, `restore`), `saved_by`, `saved_by_name`, `saved_at`. `GET /api/v1/versions/{id}` MUST возвращать снимок с содержимым. Снимки чужой истории MUST давать `404`.

#### Scenario: Кто сохранил
- WHEN автор сохранил текст, и через 10 минут сохранил снова
- THEN снимок MUST показывать имя автора, время первого сохранения и причину `auto`

#### Scenario: Неверная часть
- WHEN клиент запрашивает `part=cover`
- THEN ответ MUST быть `422`, и `detail` MUST называть `part`

#### Scenario: Чужой снимок
- WHEN пользователь Б запрашивает снимок истории пользователя А
- THEN ответ MUST быть `404`

### Requirement: Откат документа
`POST /api/v1/versions/{id}/restore` с `If-Match` текущей ревизии этой части MUST сохранять нынешнее состояние снимком с причиной `restore` и возвращать содержимое снимка новой ревизией. Другие части и документы MUST NOT меняться. Метки комментариев без ветки и метки решённых предложений в возвращённом тексте MUST NOT оставаться.

#### Scenario: Откат карточки
- WHEN автор откатывает карточку персонажа к снимку
- THEN карточка MUST вернуться к снимку, а текст и другие документы драфта MUST остаться прежними

#### Scenario: Отмена отката
- WHEN автор откатил текст к снимку
- THEN в истории MUST быть снимок с причиной `restore` и текстом до отката

#### Scenario: Устаревшая ревизия отката
- WHEN `If-Match` не совпадает с ревизией части
- THEN ответ MUST быть `409`, документ MUST NOT меняться

### Requirement: Точка драфта
`POST /api/v1/drafts/{id}/points` с непустым `name` MUST сохранять точку: все документы драфта вне корзины с полями и текстом, кто и когда. `GET /api/v1/drafts/{id}/points` MUST возвращать точки драфта, новые первыми: `id`, `name`, `kind` (`manual` или `auto`), `created_by`, `created_by_name`, `created_at`. Точки другого драфта MUST NOT возвращаться.

#### Scenario: Точка без названия
- WHEN автор сохраняет точку с пустым `name`
- THEN ответ MUST быть `422`, точка MUST NOT создаваться

#### Scenario: Свои точки у драфта
- WHEN точка сохранена в драфте 1
- THEN список точек драфта 2 MUST NOT её содержать

### Requirement: Откат к точке
`POST /api/v1/points/{id}/restore` MUST в одной транзакции создать точку `auto` «Перед откатом к «<название>»» и вернуть драфт к точке: содержимое и состав документов. Документы, созданные после точки, MUST уйти в корзину истории; документы из точки MUST вернуться, даже если их удалили. Ревизии изменённых частей MUST увеличиться.

#### Scenario: Смена героини
- WHEN после точки изменены карточка Веры и текст, и автор откатывается к точке
- THEN карточка и текст MUST вернуться к состоянию точки

#### Scenario: Документ после точки
- WHEN персонаж «Нина» создан после точки
- THEN после отката «Нина» MUST лежать в корзине истории

#### Scenario: Документ удалён навсегда
- WHEN персонаж из точки удалён навсегда
- THEN после отката персонаж MUST вернуться с теми же полями

#### Scenario: Отмена отката к точке
- WHEN автор откатился к точке и затем откатился к созданной автоматически точке
- THEN драфт MUST вернуться к состоянию до первого отката
