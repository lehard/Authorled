# api/story-import Specification

## Purpose
Импорт рукописи в историю на бэкенде: файлы Fountain, FDX, DOCX и TXT переводятся в текст сценария, персонажей и локации — новой историей или заменой текста существующей.

## Requirements

### Requirement: Новая история из файла
`POST /api/v1/projects` в `multipart/form-data` с непустым `title` и файлом `file` MUST проверить файл как загрузку для импорта (размер, тип, ClamAV), создать историю с текстом сценария из файла, персонажами и локациями из текста и сохранить файл в ней с `purpose` `import`. Если проверка или разбор не удались, история и файл MUST NOT создаваться.

#### Scenario: История из Fountain
- WHEN автор создаёт историю «Паром» из Fountain-файла с тремя сценами
- THEN текст сценария MUST содержать три заголовка сцены с разными `uid`
- AND файл MUST быть в истории с `purpose` `import`

#### Scenario: Битый файл при создании
- WHEN автор создаёт историю из FDX с нарушенным XML
- THEN ответ MUST быть `422` с причиной, и у автора MUST NOT появиться новой истории

### Requirement: Замена текста импортом
`POST /api/v1/projects/{id}/import` с `file_id` и `If-Match` ревизии текста сценария MUST заменять текст сценария текстом из файла и добавлять недостающих персонажей и локации. Комментарии и предложения старого текста MUST оставаться в ядре, их метки в новом тексте MUST NOT появляться. Драфты MUST NOT меняться. Несовпадение ревизии — `409`, ошибка разбора — `422`; в обоих случаях история MUST NOT меняться.

#### Scenario: Битый файл
- WHEN автор импортирует FDX с нарушенным XML
- THEN ответ MUST быть `422` с причиной, текст и документы истории MUST NOT меняться

#### Scenario: Файл чата
- WHEN `file_id` указывает на файл с `purpose` `chat`
- THEN ответ MUST быть `422`

### Requirement: Абзацы сценария из файла
Импорт MUST переводить абзацы в типы сценария редактора: Fountain — по правилам Fountain и пометкам `[[@тег текст]]` нашего экспорта; FDX — по типам абзацев Final Draft; DOCX и TXT — построчно по правилам Fountain. Каждой сцене MUST выдаваться новый `uid`.

#### Scenario: Русские заголовки в TXT
- WHEN импортируется TXT со строками «ИНТ. КУХНЯ — ДЕНЬ» и «ВЕРА» над репликой
- THEN текст MUST содержать заголовок сцены, персонажа и реплику

#### Scenario: Круг через наш Fountain
- WHEN импортируется Fountain, выгруженный экспортом редактора, с абзацами «Участники сцены» и «Бит»
- THEN эти абзацы MUST вернуться своих типов

### Requirement: Персонажи и локации из импорта
Импорт MUST добавлять эпизодическими персонажей из абзацев «Персонаж» (без пометок в скобках) и локации из заголовков сцен (между «ИНТ.»/«НАТ.»/«INT.»/«EXT.» и тире), которых в истории нет без учёта регистра.

#### Scenario: Без дублей
- WHEN в истории есть персонаж «Вера», а в импортируемом тексте реплики «ВЕРА» и «ОЛЕГ»
- THEN MUST добавиться только «Олег»
