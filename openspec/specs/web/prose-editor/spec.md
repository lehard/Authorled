# web/prose-editor Specification

## Purpose
Редактор прозы документа истории: текст с заголовками и выделением на сплошном листе, панель, счёт длины и метки страниц по вёрстке печати, печать A4. Сейчас им открывается синопсис драфта.

## Requirements

### Requirement: Синопсис в редакторе прозы
Документ «Синопсис» MUST открываться в редакторе прозы на сплошном листе с прежними шрифтом и полями листа прозы. Редактор MUST поддерживать абзац, «Заголовок 1», «Заголовок 2», жирный, курсив и перевод строки внутри абзаца (Shift+Enter); Enter MUST начинать новый абзац. Других видов абзацев и выделения MUST NOT быть.

#### Scenario: Заголовок и выделение
- GIVEN открыт синопсис «Тихой воды»
- WHEN автор ставит каретку в абзац «Акт 1», выбирает стиль «Заголовок 1», выделяет слово «утонул» и нажимает ⌘B
- THEN абзац MUST показываться заголовком, слово — жирным, а статус MUST стать «Сохранено»

#### Scenario: Пустой синопсис
- GIVEN синопсис драфта пуст
- WHEN автор открывает его
- THEN лист MUST показывать «Начните синопсис» и задачи соавтора, как до перехода на редактор прозы

### Requirement: Хранение синопсиса Markdown
Редактор MUST сохранять синопсис в поле `synopsis` сценария текстом Markdown: `# ` и `## ` в начале строки — заголовки, `**…**` — жирный, `*…*` — курсив, абзацы — через пустую строку, перевод строки внутри абзаца — одним переводом строки. Знаки разметки, набранные автором как текст, MUST сохраняться экранированными и после перезагрузки MUST показываться тем же текстом. Синопсис без разметки MUST открываться абзацами, как раньше.

#### Scenario: Разметка после перезагрузки
- GIVEN автор сделал «Акт 1» заголовком первого уровня и выделил «утонул» курсивом
- WHEN страница перезагружена
- THEN заголовок и курсив MUST быть на месте, а поле `synopsis` MUST содержать `# Акт 1` и `*утонул*`

#### Scenario: Звёздочки и решётка в тексте
- GIVEN автор набирает абзац «#3 — 5*2»
- WHEN страница перезагружена
- THEN абзац MUST показываться тем же текстом «#3 — 5*2», без заголовка и курсива

#### Scenario: Прежний простой текст
- GIVEN поле `synopsis` содержит три абзаца простого текста через пустую строку и одну строку с переводом внутри абзаца
- WHEN автор открывает синопсис
- THEN MUST показываться три абзаца, перевод строки MUST остаться внутри своего абзаца

#### Scenario: Неподдерживаемая разметка
- GIVEN поле `synopsis` содержит строку `### Сцена` (записано в обход ядра)
- WHEN автор открывает синопсис
- THEN экран MUST показать ошибку с причиной «заголовок третьего уровня не поддерживается» и MUST NOT показывать текст без этой строки

### Requirement: Панель редактора прозы
Над листом синопсиса MUST быть липкая панель: «Отменить», «Повторить», стиль абзаца («Заголовок 1», «Заголовок 2», «Текст»), «Жирный», «Курсив» и счёт длины. Кнопки MUST иметь доступные названия и подсказки дизайн-системы с сочетанием клавиш. Панель MUST помещаться в одну строку на любой ширине рабочей колонки. Сочетания ⌘Z, ⇧⌘Z, ⌘B и ⌘I (Ctrl на Windows и Linux) MUST работать.

#### Scenario: Отмена кнопкой
- GIVEN автор набрал в синопсисе слово
- WHEN он нажимает «Отменить», затем «Повторить»
- THEN слово MUST исчезнуть и вернуться, а «Повторить» MUST быть недоступна, пока отменять нечего

#### Scenario: Стиль под кареткой
- GIVEN каретка стоит в заголовке второго уровня
- WHEN автор смотрит на панель
- THEN список стилей MUST показывать «Заголовок 2», а кнопки «Жирный» и «Курсив» MUST показывать, включено ли выделение под кареткой

#### Scenario: Телефон
- GIVEN окно шириной 375 px
- WHEN открыт синопсис
- THEN все кнопки панели MUST быть в одной строке, ширина страницы MUST NOT превышать ширину окна, а счёт длины MUST показывать только страницы

#### Scenario: Каретка не под панелью
- GIVEN синопсис выше окна, каретка у верха видимой части листа
- WHEN автор нажимает Enter
- THEN каретка MUST оставаться ниже липкой панели

### Requirement: Вёрстка страницы синопсиса
Страница синопсиса MUST считаться по одной вёрстке для счёта, меток и печати: лист A4, поля 2,5 см, шрифт Tinos (метрически равен Times New Roman) 12 pt из сборки приложения, одинарный интервал, абзацы с отступом после, заголовки крупнее и не остаются последней строкой страницы. Абзац MAY переходить на следующую страницу посередине. Вёрстка MUST NOT зависеть от шрифтов устройства.

#### Scenario: Страница по печати
- GIVEN синопсис из 400 слов обычных абзацев
- WHEN автор смотрит счёт длины и затем печатает
- THEN число страниц на панели MUST совпадать с числом страниц печати

#### Scenario: Заголовок не в конце страницы
- GIVEN заголовок «Акт 2» пришёлся бы последней строкой первой страницы
- WHEN синопсис свёрстан
- THEN «Акт 2» MUST начинать вторую страницу

### Requirement: Счёт длины синопсиса
Панель MUST показывать «≈ N стр.» по вёрстке страницы синопсиса; пустой синопсис — «0 стр.». По клику или наведению MUST показываться число слов, знаков с пробелами и страниц. Слова MUST считаться по правилу слов сценария (`wordCount.cases.json`), знаки — без знаков разметки. Счёт MUST обновляться при наборе, правке соавтора и смене ширины окна без перезагрузки.

#### Scenario: Подробный счёт
- GIVEN в синопсисе «**Вера** молчит.»
- WHEN автор наводит на счёт длины
- THEN MUST показываться 2 слова, 12 знаков и 1 страница

#### Scenario: Правка соавтора
- GIVEN открыт синопсис на одну страницу
- WHEN соавтор записывает синопсис на две страницы
- THEN счёт MUST показать «≈ 2 стр.» без перезагрузки

### Requirement: Метки страниц на листе
Сплошной лист синопсиса MUST показывать на правом поле метку «стр. N» на высоте строки, с которой страница N начинается в печати, для каждой страницы после первой. Метка MUST NOT разрывать абзац, сдвигать текст, попадать в выделение, копирование и контекст соавтора. Метки MUST пересчитываться при правке и смене ширины.

#### Scenario: Метка второй страницы
- GIVEN синопсис на полторы страницы
- WHEN автор смотрит лист
- THEN на правом поле MUST быть одна метка «стр. 2» напротив строки, которая в печати открывает вторую страницу, и текст абзаца MUST идти без разрыва

#### Scenario: Копирование без меток
- GIVEN синопсис на две страницы
- WHEN автор выделяет весь текст и копирует
- THEN скопированный текст MUST NOT содержать «стр. 2»

### Requirement: Печать синопсиса
Шапка синопсиса MUST давать действие «Печать»: окно печати браузера с листами A4 по вёрстке страницы синопсиса, названием истории и словом «Синопсис» над текстом первой страницы и номером на каждой странице. Шрифт печати MUST приходить из сборки приложения. «Печать» MUST работать и в запертом драфте. Если браузер не открыл окно печати, MUST показываться причина.

#### Scenario: Печать двух страниц
- GIVEN синопсис «Тихой воды» на две страницы с заголовком «Акт 1»
- WHEN автор нажимает «Печать»
- THEN окно печати MUST показать две страницы A4 с «Тихая вода» и «Синопсис» над текстом первой, заголовок — жирным крупнее текста, номера «1» и «2»

#### Scenario: Окно заблокировано
- GIVEN браузер запрещает всплывающие окна
- WHEN автор нажимает «Печать»
- THEN экран MUST показать, что окно печати не открылось, и попросить разрешить всплывающие окна

### Requirement: Синопсис с прежним поведением документа
Редактор прозы MUST сохранять поведение документа синопсиса: автосохранение со статусом «Сохранено», историю сохранений и возврат к ней, новый текст от соавтора без перезагрузки с сохранением ввода автора, путь конфликта ревизий, только чтение в запертом драфте (панель правки недоступна), выделенный фрагмент в контексте соавтора текстом без разметки, переход к совпадению из поиска по истории с выделением найденного.

#### Scenario: Переход из поиска
- GIVEN в синопсисе есть «**вещий** сон»
- WHEN автор ищет «вещий сон» в поиске по истории и открывает результат синопсиса
- THEN каретка MUST стоять в синопсисе, и «вещий сон» MUST быть выделен

#### Scenario: Выделение в чат
- GIVEN в синопсисе «Вера *молчит*.»
- WHEN автор выделяет эту строку
- THEN плашка выделения в чате MUST показывать «Вера молчит.» без звёздочек

#### Scenario: Запертый драфт
- GIVEN драфт заперт
- WHEN автор открывает синопсис
- THEN текст MUST не правиться, кнопки правки панели MUST быть недоступны, а счёт длины и «Печать» MUST работать

#### Scenario: Соавтор пишет, пока автор печатает
- GIVEN автор набирает в синопсисе и сохранение ещё не ушло
- WHEN соавтор записывает новый синопсис
- THEN ввод автора MUST остаться в редакторе, а если его сохранение ушло со старой ревизией, MUST показываться конфликт ревизий, как при правке в другой вкладке (web/workspace, «Экраны после действия соавтора»)
