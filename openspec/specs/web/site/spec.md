# Site Specification

## Purpose
Сайт продукта «Соавтор» в модуле `site/`: статические страницы (главная, политика обработки персональных данных, 404), собранные заранее в HTML, с токенами и шрифтами дизайн-системы `web/`, и форма заявки в закрытую бету, которая отправляет заявку маршруту ядра `POST /api/v1/beta-requests`. Своего сервера и данных у сайта нет.

## Requirements

### Requirement: Модуль сайта
Сайт продукта MUST быть отдельным модулем `site/` со своими зависимостями (точные версии в `package.json`, закоммиченный `package-lock.json`, Node.js той же версии, что `web/`). Сайт MUST собираться в статические файлы без своего сервера и своей базы. Сайт MUST NOT подключать код экранов сервиса (`web/src/screens`, `web/src/data`, `web/src/auth`) и MUST NOT хранить данные посетителя в браузере.

#### Scenario: Сборка в статические файлы
- GIVEN зависимости сайта установлены и настройки сборки заданы
- WHEN выполняется сборка сайта
- THEN в каталоге сборки MUST появиться готовые файлы `index.html`, `privacy/index.html`, `404.html`, `sitemap.xml`, `robots.txt` и ресурсы страниц
- AND для их отдачи MUST хватать любого статического сервера

### Requirement: Страницы в готовом HTML
Каждая страница сайта MUST собираться заранее в HTML с полным текстом страницы, своими `<title>`, `description`, `canonical` и Open Graph (`og:title`, `og:description`, `og:url`, `og:image`). `sitemap.xml` MUST перечислять главную и политику; `robots.txt` MUST ссылаться на `sitemap.xml`. Страница 404 MUST быть закрыта от индексации (`noindex`). Язык страниц MUST быть русским (`lang="ru"`).

#### Scenario: Текст виден без JavaScript
- GIVEN собранный сайт
- WHEN `index.html` читается без выполнения скриптов
- THEN в нём MUST быть заголовок главной, тексты блоков и кнопки «Войти» и «Хочу в бету»

#### Scenario: Метаданные страницы
- GIVEN собранный сайт с `SITE_ORIGIN=https://example.test`
- WHEN читается `privacy/index.html`
- THEN `canonical` и `og:url` MUST быть `https://example.test/privacy/`
- AND `title` MUST отличаться от `title` главной

### Requirement: Настройки сборки
Сборка и локальный сервер сайта MUST читать из `.env` корня репозитория:
- `SITE_ORIGIN` — адрес сайта для `canonical`, Open Graph и `sitemap.xml`;
- `SITE_APP_URL` — адрес сервиса, куда ведёт «Войти».
Если настройка не задана или не является абсолютным адресом `http(s)`, сборка и локальный сервер MUST завершаться ошибкой, называющей настройку; значение по умолчанию MUST NOT подставляться. В собранные файлы MUST NOT попадать другие переменные `.env`.

#### Scenario: Нет адреса сервиса
- GIVEN `SITE_APP_URL` не задан
- WHEN запускается сборка сайта
- THEN сборка MUST завершиться ошибкой с именем `SITE_APP_URL`

#### Scenario: Секреты не попадают в сборку
- GIVEN в `.env` есть `LITELLM_MASTER_KEY`
- WHEN сайт собран
- THEN значения этой переменной MUST NOT быть ни в одном собранном файле

### Requirement: Главная страница
Главная MUST содержать блоки в таком порядке:
1. первый экран: суть продукта, закрытая бета, «Хочу в бету», «Войти», скриншот;
2. принцип «ИИ предлагает, автор решает»;
3. возможности беты;
4. методология из 22 этапов, «скоро»;
5. вопросы и ответы;
6. форма заявки;
7. подвал: политика, «Войти».

#### Scenario: Первый экран
- GIVEN собранная главная
- WHEN читается первый экран
- THEN он MUST говорить, что это редактор сценариев с ИИ-соавтором, который предлагает, а не пишет за автора, и что идёт закрытая бета

#### Scenario: Возможности беты
- GIVEN собранная главная
- WHEN читается блок возможностей
- THEN он MUST называть редактор сценария, персонажей, локации и миры, драфты, сохранения, рецензирование, импорт Fountain, FDX, STARC, DOCX и TXT и соавтора, который предлагает правки

#### Scenario: Порядок блоков
- GIVEN собранная главная
- WHEN перечисляются её блоки сверху вниз
- THEN порядок MUST совпадать со списком требования

### Requirement: Правда на главной
На сайте MUST NOT быть цифр, отзывов, логотипов клиентов и возможностей, которых нет в бете, кроме методологии с пометкой «скоро» и фразой, что в бете её нет. Скриншоты MUST быть снимками сервиса в светлой теме на демонстрационной истории и MUST быть подписаны как экраны бета-версии.

#### Scenario: Методология помечена
- GIVEN собранная главная
- WHEN читается блок методологии
- THEN рядом с ним MUST быть пометка «скоро»
- AND текст MUST говорить, что в бете методологии нет

#### Scenario: Телефон
- GIVEN главная открыта в окне шириной 390 px
- WHEN страница прокручивается до конца
- THEN горизонтальной прокрутки MUST NOT быть
- AND кнопки «Хочу в бету» и «Войти» MUST быть видны на первом экране

### Requirement: Вход из сайта
Кнопки «Войти» MUST вести на `SITE_APP_URL` (экран входа сервиса делает сам сервис). Сайт MUST NOT показывать форму входа или регистрации.

#### Scenario: Переход ко входу
- GIVEN `SITE_APP_URL=http://localhost:5173`
- WHEN посетитель нажимает «Войти»
- THEN браузер MUST открыть `http://localhost:5173/`

### Requirement: Форма заявки в бету
Форма MUST собирать почту, имя, «кто вы» («Сценарист», «Писатель», «Другое») и согласие на обработку персональных данных со ссылкой на политику; все поля обязательны, согласие по умолчанию не отмечено. Форма MUST отправлять заявку `POST /os/api/v1/beta-requests` на адрес самого сайта; локальный сервер сайта MUST проксировать `/os/` на AgentOS (`AGENTOS_URL` из `.env`, без него сервер MUST NOT стартовать).

#### Scenario: Отправка на свой адрес
- GIVEN сайт открыт локально на `127.0.0.1:5174`
- WHEN посетитель отправляет заполненную форму
- THEN запрос MUST уйти на `http://127.0.0.1:5174/os/api/v1/beta-requests`

### Requirement: Ответы формы
Форма MUST показывать: до отправки — ошибки незаполненных полей и неверной почты, без запроса к API; после `202` — «Заявка принята», одинаково для новой и повторной почты; при отказе API — `detail` из `application/problem+json`; при сетевой ошибке или неожиданном ответе — что отправить не удалось, с кодом ответа. Во время отправки кнопка MUST быть недоступна.

#### Scenario: Без согласия
- GIVEN почта, имя и «кто вы» заполнены, согласие не отмечено
- WHEN посетитель нажимает «Отправить»
- THEN форма MUST показать ошибку у согласия
- AND запрос к API MUST NOT отправляться

#### Scenario: Заявка принята
- GIVEN поля заполнены верно и согласие отмечено
- WHEN API отвечает `202`
- THEN форма MUST показать «Заявка принята»

#### Scenario: Слишком много заявок
- GIVEN API отвечает `429` с `detail` о частоте
- WHEN посетитель отправляет форму
- THEN форма MUST показать этот `detail`

### Requirement: Политика обработки персональных данных
Страница `/privacy/` MUST описывать: какие данные собирает форма (почта, имя, кто вы), зачем (рассмотреть заявку и пригласить в бету), где хранятся (сервер продукта), сколько хранятся и как отозвать согласие (написать на почту для связи). Ссылки на политику MUST быть у согласия в форме и в подвале каждой страницы. Оператор и почта для связи в тексте MUST браться из согласованного владельцем текста; заглушек вида «[ИНН]» в собранной странице MUST NOT быть.

#### Scenario: Ссылки на политику
- GIVEN собранная главная
- WHEN перечисляются ссылки на `/privacy/`
- THEN ссылка MUST быть у согласия формы и в подвале

### Requirement: Вид сайта
Сайт MUST использовать токены, шрифты и тему «Утро» (`data-theme="light"`) из `web/src/design-system` без их копирования. Цвета в коде сайта MUST задаваться только семантическими токенами: проверка сырых цветов MUST охватывать `site/` так же, как `web/`.

#### Scenario: Сырой цвет на сайте
- GIVEN в файле `site/src` есть класс `bg-blue-500` или значение `#1a1a1a`
- WHEN выполняется `./scripts/validate.sh`
- THEN проверка MUST завершиться ошибкой с путём файла

### Requirement: Проверки сайта
`./scripts/validate.sh` MUST проверять формат, линт, типы и сборку сайта. Если зависимости сайта не установлены (`site/node_modules`), проверка MUST завершаться ошибкой с командой установки, а не пропускаться. CI MUST ставить зависимости сайта и задавать настройки сборки нейтральными адресами.

#### Scenario: Нет зависимостей сайта
- GIVEN `site/node_modules` отсутствует
- WHEN выполняется `./scripts/validate.sh`
- THEN проверка MUST завершиться ошибкой и назвать `npm ci --prefix site`

### Requirement: Локальный запуск до домена
До появления домена сайт MUST запускаться только локально: `npm run dev --prefix site` (сервер разработки) и `npm run preview --prefix site` (собранные файлы), оба слушают только loopback на своём порту, отличном от порта `web/`. Выкладки сайта на сервер в этом изменении MUST NOT быть.

#### Scenario: Локальный просмотр
- GIVEN стек compose запущен и `.env` содержит `SITE_ORIGIN`, `SITE_APP_URL`, `AGENTOS_URL`
- WHEN выполняется `npm run dev --prefix site`
- THEN сайт MUST открываться на `127.0.0.1` и отправлять заявку в локальный API
