# web/workspace Specification

## Purpose
Рабочее место автора во фронтенде (`web/`): вход, полка историй, окно истории с навигатором, документами, текстом сценария, поэпизодником, комментариями и чатом с соавтором.

## Requirements

### Requirement: Вход
Приложение MUST пускать к экранам только после входа. Без действующей сессии приложение MUST открывать свой экран входа `/login` и после входа MUST возвращать на адрес, который открывали. Экран входа MUST следовать макету v1 (`openspec/context/_raw/design/kabinet/`, экраны `#auth/*`) и дизайн-системе:
- почта; при неверном формате — ошибка у поля;
- пароль — только если у аккаунта он задан; «Показать»; неверный пароль — ошибка у поля;
- код из письма — 6 ячеек: цифры переходят сами, вставка из буфера раскладывается по ячейкам, полный код отправляется сам; неверный код — ошибка и очищенные ячейки; «Отправить ещё раз» доступно через 60 секунд; «Другая почта» возвращает к первому шагу;
- ошибка Authentik — текст ошибки с причиной, а не пустой экран.
После последнего шага приложение MUST получить токены по OIDC без страницы Authentik. Если в Authentik уже есть сессия (вход в другой вкладке), `/login` MUST брать токены без формы. Перезагрузка страницы посреди входа MUST начинать вход с почты. Меню пользователя MUST показывать имя и почту из ответа `GET /api/v1/me`, пункт «Настройки», открывающий `/settings`, и действие «Выйти», которое завершает сессию в Authentik и возвращает на `/login`. Без входа MUST открываться только `/login` и витрина дизайн-системы.

#### Scenario: Вход с сохранением адреса
- GIVEN пользователь не вошёл
- WHEN он открывает `/p/water/chars` и проходит экран входа
- THEN после кода MUST открыться `/p/water/chars`

#### Scenario: Отказ во входе
- GIVEN Authentik недоступен или отвечает ошибкой
- WHEN пользователь отправляет почту на экране входа
- THEN MUST показываться причина ошибки и возможность повторить, а не пустая страница

#### Scenario: Неверный код
- GIVEN на экране кода
- WHEN пользователь вводит шесть неверных цифр
- THEN MUST показываться ошибка, ячейки MUST очиститься, и фокус MUST вернуться в первую ячейку

#### Scenario: Вставка кода
- GIVEN на экране кода
- WHEN пользователь вставляет из буфера «123456»
- THEN цифры MUST разложиться по ячейкам, и код MUST отправиться без нажатия кнопки

#### Scenario: Аккаунт без пароля
- GIVEN у аккаунта не задан пароль
- WHEN пользователь вводит почту
- THEN следующим MUST открыться экран кода

#### Scenario: Новая вкладка
- GIVEN пользователь вошёл в одной вкладке
- WHEN он открывает приложение в новой вкладке
- THEN экран MUST открыться без формы входа

#### Scenario: Перезагрузка на шаге кода
- GIVEN открыт шаг кода
- WHEN страница перезагружена
- THEN MUST показываться шаг почты без ошибки

#### Scenario: Выход
- GIVEN пользователь вошёл
- WHEN он выбирает «Выйти»
- THEN сессия в Authentik MUST завершиться, и MUST открыться `/login`

#### Scenario: Имя в меню из аккаунта
- GIVEN пользователь зарегистрировался как «Анна Петрова» и сменил имя в настройках на «Анна П.»
- WHEN он выходит и входит снова
- THEN меню пользователя MUST показывать «Анна П.»

### Requirement: Обязательные настройки
Приложение MUST получать адрес Authentik (`AUTH_ISSUER`), клиента (`AUTH_FRONTEND_CLIENT_ID`), адрес возврата (`AUTH_FRONTEND_REDIRECT_URI`) и источник данных (`VITE_DATA_SOURCE`). Если любая настройка отсутствует или неверна, приложение MUST показать экран ошибки с именем настройки и MUST NOT подставлять значение по умолчанию. Если приложение открыто не с того адреса, что указан в `AUTH_FRONTEND_REDIRECT_URI` (схема, хост, порт), MUST показываться ошибка с правильным адресом.

#### Scenario: Нет настройки входа
- GIVEN `AUTH_ISSUER` не задан
- WHEN приложение открыто
- THEN MUST показываться ошибка, называющая `AUTH_ISSUER`

#### Scenario: Чужой адрес
- GIVEN `AUTH_FRONTEND_REDIRECT_URI` равен `http://localhost:5173/auth/callback`
- WHEN приложение открыто по адресу `http://127.0.0.1:5173/`
- THEN MUST показываться ошибка с адресом `http://localhost:5173`

### Requirement: Источник данных
Экраны MUST получать и менять данные только через провайдер данных приложения. `VITE_DATA_SOURCE` MUST быть `api` или `fixtures`. Источник `api` MUST работать с маршрутами ядра `/api/v1` (спеки `api/stories`, `api/review`, `api/files`, `api/story-import`) по адресу `/os/` фронтенда с токеном пользователя. Источник `fixtures` — данные примера макета v2 («Тихая вода», «Последний паром»), которые живут в памяти страницы и сбрасываются при перезагрузке; в этом режиме приложение MUST показывать метку «Данные примера» в меню пользователя, а импорт и файлы в чат MUST отвечать, что недоступны с данными примера.

#### Scenario: Неизвестный источник
- GIVEN `VITE_DATA_SOURCE=cloud`
- WHEN приложение открыто
- THEN MUST показываться ошибка, что источник `cloud` не поддерживается, с перечнем допустимых значений

#### Scenario: Данные примера
- GIVEN `VITE_DATA_SOURCE=fixtures` и пользователь вошёл
- WHEN открыт корневой адрес
- THEN полка MUST показывать «Тихая вода» и «Последний паром»

#### Scenario: Данные ядра переживают перезагрузку
- GIVEN `VITE_DATA_SOURCE=api` и автор создал историю «Маяк» с персонажем «Вера»
- WHEN он перезагружает страницу
- THEN «Маяк» MUST быть на полке, а «Вера» — в навигаторе истории

#### Scenario: Ошибка ядра
- GIVEN `VITE_DATA_SOURCE=api` и API не отвечает
- WHEN открыта полка
- THEN MUST показываться причина и «Повторить», а не данные примера и не пустая полка

### Requirement: Адреса экранов
Каждый экран MUST иметь свой адрес, и открытие адреса напрямую MUST показывать тот же экран:
- `/` — полка историй; `/trash` — корзина историй;
- `/p/:projectId/d/:draftId/:doc` — окно истории с документом драфта: `info`, `title`, `logline`, `synopsis`, `treatment`, `text`, `chars`, `char:<id>`, `locs`, `loc:<id>`, `worlds`, `world:<id>`, `trash`;
- `/p/:projectId` и `/p/:projectId/:doc` — переход к `/p/:projectId/d/<open_draft_id>/:doc` (без `:doc` — `text`);
- `/settings` — настройки (личный кабинет);
- `/showcase` — витрина дизайн-системы;
- `/auth/callback` — возврат из Authentik.
Неизвестный адрес, история, драфт или документ MUST показывать экран «Не найдено» со ссылкой на полку.

#### Scenario: Прямая ссылка на профиль
- GIVEN пользователь вошёл
- WHEN он открывает `/p/water/char:vera`
- THEN MUST открыться окно истории «Тихая вода» с профилем Веры в последнем открытом драфте, адрес MUST содержать этот драфт, и в навигаторе Вера MUST быть текущим пунктом

#### Scenario: Нет такого документа
- GIVEN пользователь вошёл
- WHEN он открывает `/p/water/char:nobody`
- THEN MUST показываться «Не найдено» со ссылкой на полку

#### Scenario: Сравнение с самим собой
- GIVEN пользователь вошёл
- WHEN он открывает `/p/water/compare:current:current`
- THEN MUST показываться «Не найдено» со ссылкой на полку

#### Scenario: Нет такого драфта
- GIVEN пользователь вошёл
- WHEN он открывает `/p/water/d/nobody/text`
- THEN MUST показываться «Не найдено» со ссылкой на полку

#### Scenario: Документ другого драфта
- GIVEN персонаж «Нина» есть только в драфте 2
- WHEN пользователь открывает адрес «Нины» с драфтом 1
- THEN MUST показываться «Не найдено» со ссылкой на полку

#### Scenario: Адрес бывшей страницы сценария
- GIVEN пользователь вошёл
- WHEN он открывает `/p/water/sp`
- THEN MUST показываться «Не найдено» со ссылкой на полку

### Requirement: Полка историй
Полка MUST показывать истории обложками с названием и действия: создать, переименовать, удалить в корзину. У истории MUST быть одна карточка; при нескольких драфтах на ней MUST быть их число, драфты отдельными карточками MUST NOT показываться. Создание MUST спрашивать название и MAY принимать файл рукописи (Fountain, FDX, STARC, DOCX, TXT): с файлом история создаётся из него импортом ядра. Пустое название MUST давать ошибку у поля; отказ импорта MUST показываться с причиной, и история MUST NOT создаваться. Новая история MUST быть полнометражным сценарием и MUST открываться сразу на тексте сценария. На полке MUST NOT быть приветствия, поиска, режима фокуса и статуса сохранения.

#### Scenario: Новая история
- GIVEN открыта полка
- WHEN пользователь создаёт историю «Маяк»
- THEN MUST открыться текст «Драфт 1» новой истории с одним пустым заголовком сцены

#### Scenario: Три драфта на полке
- GIVEN в истории «Тихая вода» три драфта
- WHEN открыта полка
- THEN у истории MUST быть одна карточка с подписью «3 драфта»

#### Scenario: Пустое название
- GIVEN открыт диалог новой истории
- WHEN пользователь нажимает «Создать» с пустым названием
- THEN MUST показываться ошибка у поля, и история MUST NOT создаваться

#### Scenario: История из файла
- GIVEN источник `api` и открыт диалог новой истории
- WHEN пользователь вводит «Паром», выбирает `паром.fountain` и нажимает «Создать»
- THEN MUST открыться текст новой истории со сценами из файла, а в навигаторе MUST быть персонажи из реплик

#### Scenario: Битый файл при создании
- GIVEN источник `api` и открыт диалог новой истории
- WHEN пользователь создаёт историю из битого `.fdx`
- THEN под полем файла MUST показываться причина, диалог MUST остаться открытым, и история MUST NOT появиться на полке

### Requirement: Корзина историй
Удалённая история MUST попадать в корзину историй и пропадать с полки. Корзина MUST показывать дату удаления и MUST давать «Восстановить» и «Удалить навсегда»; «Удалить навсегда» MUST требовать подтверждения. Срока хранения и автоматического удаления MUST NOT быть, и корзина MUST NOT их обещать.

#### Scenario: Удаление и восстановление
- GIVEN на полке есть «Последний паром»
- WHEN пользователь удаляет её в корзину и затем восстанавливает из `/trash`
- THEN история MUST вернуться на полку со всеми документами

#### Scenario: Без срока
- GIVEN в корзине лежит история
- WHEN открыта `/trash`
- THEN на экране MUST NOT быть срока хранения и числа дней до удаления

### Requirement: Окно истории
Окно истории MUST состоять из навигатора слева, рабочего поля посередине и колонки чата справа. Колонка чата MUST быть видна на всех экранах истории. На ширине до 900 px навигатор MUST открываться кнопкой поверх рабочего поля, а чат — листом снизу.

#### Scenario: Узкий экран
- GIVEN окно шириной 375 px
- WHEN открыт `/p/water/text`
- THEN рабочее поле MUST занимать ширину экрана без горизонтальной прокрутки, навигатор MUST открываться кнопкой, чат — листом снизу

### Requirement: Навигатор
Вверху навигатора MUST быть переключатель драфтов. Шапка навигатора с обложкой и названием истории MUST открывать документ «История»; отдельной строки истории в дереве MUST NOT быть. Навигатор MUST показывать дерево открытого драфта: «Персонажи», «Локации», «Миры» с документами; папку «Сценарий» с частями «Титульная страница», «Логлайн», «Синопсис», «Поэпизодник», «Текст сценария» (видимость частей задаётся в документе «История»); «Корзина» с числом документов. Папка «Сценарий» MUST называться так при любом названии истории и MUST только раскрываться, своего документа у неё нет. Открытый документ MUST быть выделен, документ «История» — выделением шапки.

#### Scenario: Поэпизодник в дереве
- GIVEN открыта история «Тихая вода»
- WHEN пользователь раскрывает сценарий в навигаторе
- THEN части MUST идти в порядке «Титульная страница», «Логлайн», «Синопсис», «Поэпизодник», «Текст сценария»

#### Scenario: Новый персонаж
- GIVEN открыта история «Тихая вода»
- WHEN пользователь добавляет персонажа «Нина Петровна»
- THEN персонаж MUST появиться в группе «Персонажи», и MUST открыться его профиль

#### Scenario: Удаление в корзину истории
- GIVEN в навигаторе есть локация «Пристань»
- WHEN пользователь выбирает «Удалить» в её меню
- THEN локация MUST пропасть из группы и появиться в «Корзине» истории, а счётчик корзины MUST увеличиться на 1

#### Scenario: Шапка открывает историю
- GIVEN открыт текст сценария истории «Тихая вода»
- WHEN пользователь нажимает на название в шапке навигатора
- THEN MUST открыться документ «История», шапка MUST быть выделена, а в дереве MUST NOT быть строки «Тихая вода»

#### Scenario: Папка только раскрывается
- GIVEN открыт профиль Веры и папка «Сценарий» раскрыта
- WHEN пользователь нажимает на «Сценарий»
- THEN папка MUST свернуться, а открытый документ и адрес MUST NOT измениться

#### Scenario: Папка не зависит от названия истории
- GIVEN история называется «Тихая вода»
- WHEN автор меняет название на «Маяк»
- THEN шапка MUST показывать «Маяк», а папка MUST называться «Сценарий»

### Requirement: Документы истории
Рабочее поле MUST показывать документы:
- «История»: название и тэглайн истории, видимость частей сценария в навигаторе, число сцен и оценка длительности открытого драфта; тэглайн MUST показываться на полке;
- «Титульная страница»: название, жанр или формат, автор, контакты, город и год — листом бумаги;
- «Логлайн»: текст листом бумаги;
- «Синопсис»: текст листом бумаги;
- списки персонажей, локаций и миров с ролью и одной строкой описания;
- профили персонажа, локации и мира с полями макета v2 (`PROFILE` в `data.js`), ролью и, для персонажа, возрастом и полом;
- «Корзина» истории: удалённые документы с «Восстановить», «Удалить навсегда» и «Очистить корзину».
Правка поля MUST сохраняться через провайдер данных и MUST отражаться в навигаторе без перезагрузки; статус «Сохранено» MUST показываться на экранах документов.

#### Scenario: Переименование персонажа
- GIVEN открыт профиль Веры
- WHEN пользователь меняет имя на «Вера Андреевна»
- THEN навигатор MUST показывать «Вера Андреевна», а статус MUST стать «Сохранено»

#### Scenario: Восстановление из корзины истории
- GIVEN в корзине истории лежит персонаж «Миша»
- WHEN пользователь нажимает «Восстановить»
- THEN Миша MUST вернуться в группу «Персонажи» со всеми полями профиля

#### Scenario: Тэглайн на полке
- GIVEN открыта «История» в драфте 2
- WHEN автор меняет тэглайн на «Двадцать лет никто не подходил к воде.»
- THEN статус MUST стать «Сохранено», полка MUST показывать этот тэглайн, а в драфте 1 документ «История» MUST показывать его же

#### Scenario: Логлайн в драфте
- GIVEN в истории два драфта с одним логлайном
- WHEN автор меняет «Логлайн» в драфте 2
- THEN в драфте 1 логлайн MUST остаться прежним

#### Scenario: Скрытый логлайн
- GIVEN в «Истории» снята галочка «Логлайн»
- WHEN автор смотрит навигатор и открывает адрес `logline`
- THEN части MUST NOT быть в папке «Сценарий», а адрес MUST показывать «Не найдено»

#### Scenario: Сбой одного из сохранений
- GIVEN открыта «История»
- WHEN автор меняет название и галочку части, и ядро отказывает второму сохранению из-за конфликта ревизий
- THEN экран MUST показывать конфликт, а не «Сохранено»

### Requirement: Без методологии
Интерфейс приложения MUST NOT показывать документы, этапы и статусы методологии Д1–Д22.

#### Scenario: Нет статусов
- GIVEN пользователь вошёл и открыл любую историю
- WHEN просматриваются все экраны приложения
- THEN на них MUST NOT встречаться обозначения Д1–Д22 и статусы документов методологии

### Requirement: Быстрый вход для разработки
В сервере разработки экран входа MUST показывать кнопки «Войти как Сценарист» и «Войти как Редактор». Кнопка MUST проходить тот же поток входа, что и пользователь, с почтой пользователя для разработки, паролем из `AUTH_DEV_USER_PASSWORD` и кодом из письма в Mailpit. Если Mailpit недоступен или письмо не пришло за 10 секунд, MUST показываться ошибка с причиной. В production-сборке кнопок и их кода MUST NOT быть.

#### Scenario: Вход одной кнопкой
- GIVEN локальный стенд, пользователи созданы `./scripts/dev.sh auth-users`
- WHEN разработчик нажимает «Войти как Редактор»
- THEN MUST открыться полка историй, а меню пользователя MUST показывать «Редактор»

#### Scenario: Нет в production
- GIVEN выполнен `npm run build --prefix web`
- WHEN в `web/dist/assets/*.js` ищутся строки «Войти как» и `mailpit`
- THEN совпадений MUST NOT быть

### Requirement: Чат с соавтором
Колонка чата окна истории MUST быть чатом с агентом `coauthor` через AG-UI: заголовок «Соавтор», строка «Видит: <открытый документ>», сообщения автора и ответы соавтора, поле ввода (Enter — отправить, Shift+Enter — новая строка). Ответ MUST появляться по мере генерации; Markdown в ответе MUST отображаться оформленным текстом; у ответа MUST быть «Скопировать». Пустая беседа MUST показывать подсказки-вопросы, которые отправляются по клику.

#### Scenario: Вопрос и ответ
- GIVEN открыт текст сценария «Тихой воды»
- WHEN автор отправляет «О чём эта история?»
- THEN в чате MUST появиться его сообщение и ответ соавтора, который нарастает по мере генерации

#### Scenario: Ошибка
- GIVEN API недоступен
- WHEN автор отправляет сообщение
- THEN в чате MUST появиться сообщение об ошибке с причиной, а текст автора MUST остаться в поле, чтобы отправить его снова

### Requirement: Контекст соавтора
С каждым сообщением фронтенд MUST передавать соавтору контекст AG-UI: название истории, открытый документ (название и содержимое: текст сценария, синопсис, поля профиля и т. п.) и выделенный автором фрагмент, если он есть. Выделенный фрагмент MUST показываться плашкой над полем ввода с кнопкой «Убрать». Плашка MUST помещаться в ширину чата при любой длине выделения.

#### Scenario: Выделенный фрагмент
- GIVEN в тексте сценария выделена реплика
- WHEN автор спрашивает «Как сделать короче?»
- THEN над полем MUST быть плашка с фрагментом, а запрос к AG-UI MUST содержать этот фрагмент в контексте

#### Scenario: Длинное выделение
- GIVEN в тексте сценария выделена целая сцена
- WHEN над полем ввода появляется плашка
- THEN её текст MUST обрезаться многоточием в пределах чата, кнопка «Убрать» MUST быть видна, а контекст AG-UI MUST содержать выделение целиком

### Requirement: Беседы по истории
Беседы MUST храниться сессиями Agno пользователя и MUST относиться к одному драфту истории. «Новая беседа» MUST начинать пустую беседу в открытом драфте; «История бесед» MUST показывать беседы открытого драфта (название — начало первого сообщения, дата) и открывать выбранную с её сообщениями. Беседы другого драфта и другой истории MUST NOT показываться. При переключении драфта чат MUST перейти к новой пустой беседе этого драфта.

#### Scenario: Возврат к беседе
- GIVEN в драфте истории «Тихая вода» была беседа «О чём эта история?»
- WHEN автор открывает «История бесед» и выбирает её
- THEN MUST показаться её сообщения, и новый вопрос MUST продолжить ту же беседу

#### Scenario: Смена драфта
- GIVEN в драфте 1 открыта беседа
- WHEN автор переключается на драфт 2
- THEN чат MUST показать пустую беседу, а «История бесед» MUST NOT содержать беседу драфта 1

### Requirement: Текст сценария в редакторе
Документ «Текст сценария» MUST открываться в редакторе сценария листом бумаги. Правки MUST сохраняться автоматически, со статусом сохранения в шапке документа, как в других документах. Выделение в редакторе MUST попадать в чат соавтора так же, как в других документах.

#### Scenario: Правка сохраняется
- GIVEN открыт `/p/water/text`
- WHEN автор дописывает реплику, открывает «Синопсис» и возвращается в «Текст сценария»
- THEN дописанная реплика MUST быть на месте

#### Scenario: Выделение в чат
- GIVEN открыт «Текст сценария» и чат соавтора
- WHEN автор выделяет реплику в редакторе
- THEN над полем ввода чата MUST появиться выделенный фрагмент

### Requirement: Импорт, экспорт и печать на экране
Над листом «Текста сценария» MUST быть действия «Импорт» (файл Fountain, Final Draft, STARC, DOCX или TXT с диска, разбирается ядром), «Экспорт» (Fountain, Final Draft) и «Печать» с титульной страницей из документа «Титульная страница». Импорт MUST спрашивать подтверждение перед заменой текста, загружать файл и вызывать импорт ядра с ревизией открытого текста; после импорта MUST показываться новый текст и добавленные персонажи и локации. Ошибка импорта или печати MUST показываться с причиной, и текст MUST NOT меняться.

#### Scenario: Битый файл
- GIVEN открыт «Текст сценария»
- WHEN автор импортирует файл `.fdx` без корневого элемента `FinalDraft`
- THEN MUST показаться ошибка с причиной из ядра, и текст MUST остаться прежним

#### Scenario: Импорт DOCX
- GIVEN источник `api` и открыт «Текст сценария»
- WHEN автор импортирует DOCX с заголовком «ИНТ. КУХНЯ — ДЕНЬ» и репликой Веры и подтверждает замену
- THEN текст MUST содержать эту сцену, а «Вера» MUST появиться в «Персонажах»

### Requirement: Панель инструментов текста
Над листом «Текста сценария» MUST быть панель: «Отменить», «Повторить», список типов абзаца, «Показать биты», «Найти и заменить», «Только текущая сцена» и меню «⋯» с действиями «Импорт», «Экспорт» и «Печать». Кнопки MUST иметь доступные названия и подсказки дизайн-системы. При ширине окна 375 px панель MUST помещаться в одну строку без горизонтальной прокрутки страницы.

#### Scenario: Отмена кнопкой
- GIVEN автор допечатал слово в реплике
- WHEN он нажимает «Отменить»
- THEN слово MUST исчезнуть, а «Повторить» MUST вернуть его

#### Scenario: Телефон
- GIVEN окно шириной 375 px и открыт `/p/water/text`
- WHEN экран отрисован
- THEN все кнопки панели MUST быть в одной строке, а ширина страницы MUST NOT превышать ширину окна

### Requirement: Показ битов
Абзацы типа «Бит» MUST быть скрыты, пока автор не нажмёт «Показать биты»; повторное нажатие MUST скрыть их снова. Кнопка MUST показывать состояние нажатия. Скрытие MUST NOT менять текст документа.

#### Scenario: Биты видны по кнопке
- GIVEN открыт `/p/water/text`, в тексте есть бит «Миша уходит на озеро один»
- WHEN автор нажимает «Показать биты»
- THEN бит MUST стать видимым, а после второго нажатия — скрытым

### Requirement: Найти и заменить
«Найти и заменить» (кнопка, ⌘F или Ctrl+F в редакторе) MUST открывать строку поиска с полем запроса, областью поиска, счётчиком «N из M» и переходами к соседним совпадениям. Области: весь текст, заголовки сцен, описание действия, персонажи, реплики (с ремарками). Поиск MUST NOT учитывать регистр и MUST подсвечивать все совпадения и текущее отдельно. Без совпадений счётчик MUST показывать «нет».

#### Scenario: Поиск в репликах
- GIVEN открыт `/p/water/text`
- WHEN автор ищет «мам» в области «В репликах»
- THEN счётчик MUST показать число совпадений только в репликах и ремарках, а лист MUST прокрутиться к первому

### Requirement: Замена
В строке поиска MUST быть «Заменить» (текущее совпадение) и «Заменить все» (все совпадения в области). Каждая из них MUST быть одной правкой, которую целиком отменяет «Отменить». Замена MUST менять только текст совпадения и MUST сохранять тип абзаца и метки остального текста.

#### Scenario: Заменить все и отменить
- GIVEN в тексте три совпадения «Вера»
- WHEN автор заменяет все на «Надя», а затем нажимает «Отменить» один раз
- THEN после замены совпадений MUST быть ноль, а после отмены MUST вернуться все три «Вера»

### Requirement: Только текущая сцена
«Только текущая сцена» MUST оставлять видимой сцену с курсором: от её заголовка до следующего заголовка сцены, группы или акта; остальной текст MUST скрываться без изменения документа. Повторное нажатие MUST показывать весь текст. Если курсор стоит до первой сцены, MUST показываться первая сцена.

#### Scenario: Одна сцена
- GIVEN курсор в реплике сцены «ИНТ. ДОМ ВЕРЫ, КУХНЯ — УТРО»
- WHEN автор нажимает «Только текущая сцена»
- THEN MUST быть виден только текст этой сцены, а поиск MUST находить совпадения только в ней

### Requirement: Автодополнение
В абзаце «Персонаж» редактор MUST предлагать имена персонажей истории, начинающиеся с набранного. В «Заголовке сцены» MUST предлагаться «ИНТ.», «НАТ.», «ИНТ./НАТ.», после них — локации истории, после тире — время суток. Стрелки MUST листать список, Enter и Tab — подставлять, Escape — закрывать. Без открытого списка Enter и Tab MUST работать по переходам типов.

#### Scenario: Имя персонажа
- GIVEN курсор в пустом абзаце «Персонаж» истории «Тихая вода»
- WHEN автор печатает «ВЕ» и нажимает Enter
- THEN абзац MUST содержать имя «Вера» из профиля и показываться как «ВЕРА», а курсор MUST остаться в конце абзаца

### Requirement: Сцены в навигаторе
У «Текста сценария» в навигаторе MUST быть кнопка списка сцен. Список MUST показывать акты и группы разделителями, у каждой сцены — номер, заголовок, примерную длительность и первую строку текста, и MUST выделять текущую сцену. Клик по сцене MUST открывать «Текст сценария» с курсором в её заголовке. «Назад» MUST возвращать дерево. Список MUST обновляться при правке текста.

#### Scenario: Переход к сцене
- GIVEN открыт список сцен «Тихой воды»
- WHEN автор выбирает сцену 3
- THEN MUST открыться «Текст сценария», лист MUST прокрутиться к заголовку сцены 3, а курсор MUST стоять в нём

### Requirement: Действия навигатора
У узлов навигатора MUST быть меню (правый клик и кнопка «⋮») с действиями узла: добавить документ в группу, сортировать по алфавиту, открыть, удалить в корзину, очистить корзину. Кнопка «Добавить документ» MUST создавать персонажа, локацию или мир; пустое имя MUST давать ошибку. Добавить свободный документ или папку MUST NOT быть возможно.

#### Scenario: Пустое имя
- GIVEN открыт диалог «Добавить документ»
- WHEN пользователь сохраняет персонажа без имени
- THEN MUST показаться ошибка у поля имени, и документ MUST NOT создаваться

### Requirement: Персонажи и локации из текста
В меню группы «Персонажи» MUST быть «Найти всех персонажей в тексте», в меню «Локации» — «Найти все локации в тексте». Команда MUST добавлять эпизодическими персонажей из абзацев «Персонаж» (без пометок в скобках) и места из заголовков сцен (между «ИНТ.»/«НАТ.» и тире), которых в истории ещё нет без учёта регистра, и MUST показывать список добавленного или «Новых нет».

#### Scenario: Новый персонаж из реплики
- GIVEN в тексте есть абзац «Персонаж» «ПАРОМЩИК (З.К.)», а персонажа «Паромщик» в истории нет
- WHEN автор выбирает «Найти всех персонажей в тексте»
- THEN в группе «Персонажи» MUST появиться эпизодический «Паромщик», а повторная команда MUST сообщить «Новых нет»

### Requirement: Поэпизодник
«Поэпизодник» MUST открывать тот же текст сценария в редакторе, показывая только заголовки сцен, биты, группы и акты. Tab и Enter MUST работать по таблице поэпизодника макета v2 (`TREAT`), список типов и клавиши типов MUST предлагать только эти четыре типа. Правка в поэпизоднике MUST NOT удалять или склеивать скрытый текст сцен; курсор MUST NOT попадать в скрытые абзацы.

#### Scenario: Новый бит
- GIVEN открыт «Поэпизодник», курсор в конце заголовка сцены 2
- WHEN автор нажимает Enter и печатает «Вера решает молчать»
- THEN в «Тексте сценария» бит MUST оказаться в сцене 2, а текст сцены MUST остаться прежним

#### Scenario: Скрытый текст цел
- GIVEN в «Поэпизоднике» выделены заголовки сцен 2 и 3
- WHEN автор нажимает Backspace
- THEN текст сцен 2 и 3 в «Тексте сценария» MUST остаться прежним

### Requirement: Карточки сцен
«Текст сценария» и «Поэпизодник» MUST переключаться между видами «Текст» и «Карточки»; вид MUST быть частью адреса (`?view=cards`). Карточки MUST быть сгруппированы по актам и показывать номер, название, заголовок, первую строку текста (в поэпизоднике — биты), теги, день истории, длительность и цвет сцены. «+ Сцена» и «+ Акт» MUST добавлять их в конец; двойной клик MUST открывать текст сцены.

#### Scenario: Карточки по актам
- GIVEN открыт `/p/water/text?view=cards`
- WHEN экран отрисован
- THEN MUST быть видны группы «Акт первый» и «Акт второй» с карточками сцен 1–3 и 4–7

### Requirement: Параметры сцены
Выбор карточки MUST открывать панель параметров рядом с карточками, не закрывая чат: название, заголовок, биты (строка — бит), день истории, цвет из палитры меток автора, теги, длительность, «Открыть текст сцены», «Выше», «Ниже» и «Удалить сцену». Правки MUST сохраняться в документ сценария автоматически. Удаление MUST спрашивать подтверждение и MUST удалять сцену со всем её текстом.

#### Scenario: Цвет и тег
- GIVEN выбрана карточка сцены 3
- WHEN автор выбирает цвет 2 и добавляет тег «пристань»
- THEN карточка и строка сцены 3 в навигаторе MUST получить цвет 2, а тег MUST сохраниться после перехода в «Синопсис» и обратно

### Requirement: Перестановка сцен
Сцену MUST можно переставить перетаскиванием карточки или строки списка сцен навигатора на место другой сцены, а также кнопками «Выше» и «Ниже». Сцена MUST переезжать со всем своим текстом; бросок на заголовок акта MUST ставить сцену в начало этого акта. Номера сцен MUST пересчитываться.

#### Scenario: Сцена переехала с текстом
- GIVEN открыт `/p/water/text?view=cards`
- WHEN автор перетаскивает карточку сцены 3 на место сцены 1
- THEN «Пристань посёлка» MUST стать сценой 1, а в «Тексте сценария» её реплики MUST идти сразу за её заголовком

### Requirement: Комментарий к фрагменту
В меню выделения редактора «Текста сценария» и «Поэпизодника» MUST быть «Комментировать». Команда MUST подсвечивать выделенный фрагмент и открывать рядом с ним карточку с полем комментария. Пустой комментарий MUST NOT сохраняться; «Отмена» MUST снимать подсветку. Место комментария MUST переезжать вместе с текстом, в том числе при перестановке сцен.

#### Scenario: Новый комментарий
- GIVEN в «Тексте сценария» выделено слово «Склейка»
- WHEN автор выбирает «Комментировать», пишет «Нужен ли переход?» и сохраняет
- THEN слово MUST остаться подсвеченным, а счётчик комментариев на панели MUST увеличиться на 1

### Requirement: Ветка комментария
Клик по подсвеченному фрагменту MUST открывать карточку ветки рядом с текстом, не закрывая чат: цитату фрагмента, комментарии с автором, ролью и временем, поле ответа, «Решено», «Удалить пометку». Свои комментарии MUST правиться и удаляться. Escape, ✕ и клик мимо карточки MUST её закрывать.

#### Scenario: Ответ редактору
- GIVEN открыт `/p/water/text`, в реплике Веры есть комментарий Ирины Беловой
- WHEN автор кликает по фрагменту и отвечает «Подумаю»
- THEN в ветке MUST появиться ответ автора с его именем и временем

### Requirement: Решённые комментарии
«Решено» MUST снимать подсветку фрагмента и закрывать ветку; решённый фрагмент MUST NOT открываться кликом по тексту. «Вернуть в открытые» в ветке из списка «Все» MUST возвращать подсветку.

#### Scenario: Решено
- GIVEN открыта ветка комментария к реплике
- WHEN автор нажимает «Решено»
- THEN подсветка реплики MUST исчезнуть, а счётчик открытых комментариев MUST уменьшиться на 1

### Requirement: Список комментариев
На панели редактора MUST быть кнопка комментариев с числом открытых. Она MUST открывать список с вкладками «Открытые» и «Все»: цитата фрагмента, первый комментарий, автор, время, число ответов, отметка «решено». Выбор пункта MUST прокручивать текст к фрагменту и открывать его ветку. Если фрагмента в тексте больше нет, пункт MUST показывать «Фрагмента в тексте нет».

#### Scenario: Переход из списка
- GIVEN в «Тихой воде» два открытых комментария
- WHEN автор открывает список и выбирает второй
- THEN лист MUST прокрутиться к фрагменту «Он сказал, что Миша утонул не случайно.» и открыть его ветку

### Requirement: Хранение комментариев
Место комментария MUST храниться в документе сценария меткой с идентификатором ветки; ветки (автор, роль, время, текст, ответы, «решено») MUST храниться в источнике данных отдельно от текста. Добавление и снятие метки комментария MUST NOT попадать в отмену правок текста. Экспорт в Fountain и Final Draft и печать MUST NOT содержать комментариев.

#### Scenario: Отмена не трогает комментарии
- GIVEN автор добавил комментарий и затем напечатал слово
- WHEN он нажимает «Отменить»
- THEN исчезнуть MUST только напечатанное слово, а комментарий MUST остаться

### Requirement: Предложение правки в тексте
Предложение соавтора MUST показываться в «Тексте сценария» и «Поэпизоднике» на месте фрагмента: убираемый текст зачёркнут, предлагаемый подчёркнут цветом соавтора сразу за ним. Текст сценария MUST NOT меняться, пока автор не примет предложение. Правка внутри предложения MUST NOT проходить; набор на его границах и удаление абзаца целиком MUST работать.

#### Scenario: Предложение в сцене
- GIVEN открыт `/p/water/text`
- WHEN автор доходит до сцены «ИНТ. ДОМ ВЕРЫ, КУХНЯ — НОЧЬ»
- THEN «Чашка давно чистая. Она всё равно трёт её губкой.» MUST быть зачёркнуто, а «Чашка давно чистая — Вера всё равно её трёт.» — подчёркнуто за ним

#### Scenario: Правка внутри
- GIVEN курсор внутри зачёркнутого текста предложения
- WHEN автор печатает букву
- THEN текст MUST NOT измениться

### Requirement: Карточка предложения
Клик по предложению MUST открывать рядом с текстом карточку: «Предложение соавтора» и время, было и стало, зачем, «Обсудить в чате», «Отклонить», «Принять». Escape, ✕ и клик мимо карточки MUST её закрывать; чат MUST NOT закрываться.

#### Scenario: Открыть предложение
- GIVEN открыт `/p/water/text`
- WHEN автор кликает по предложению в реплике Дяди Коли «Он утонул. Всё.»
- THEN MUST открыться карточка с «Утонул. Всё.» и объяснением, зачем убрать «Он»

### Requirement: Принять и отклонить
«Принять» MUST заменять фрагмент предложенным текстом обычной правкой, которую отменяет ⌘Z. «Отклонить» MUST оставлять текст прежним и снимать предложение без шага отмены. Решённое предложение MUST NOT показываться в тексте и в счётчике.

#### Scenario: Принять
- GIVEN открыта карточка предложения в реплике Дяди Коли
- WHEN автор нажимает «Принять»
- THEN в реплике MUST остаться «Утонул. Всё.», счётчик предложений MUST уменьшиться на 1, а ⌘Z MUST вернуть «Он утонул. Всё.»

#### Scenario: Отклонить
- GIVEN открыта карточка предложения в сцене на кухне
- WHEN автор нажимает «Отклонить»
- THEN в тексте MUST остаться «Чашка давно чистая. Она всё равно трёт её губкой.» без зачёркивания

### Requirement: Обход предложений
На панели редактора MUST быть кнопка со значком соавтора и числом открытых предложений в тексте. Нажатие MUST прокручивать лист к следующему предложению по тексту и открывать его карточку; без открытых предложений кнопка MUST быть неактивной.

#### Scenario: Следующее предложение
- GIVEN в «Тихой воде» два открытых предложения
- WHEN автор дважды нажимает кнопку предложений
- THEN MUST открыться сначала предложение в гараже, затем на кухне

### Requirement: Обсудить предложение в чате
«Обсудить в чате» MUST выделять убираемый текст предложения, чтобы он ушёл в чат как «Выделено: …», и закрывать карточку; на узком экране MUST открываться чат.

#### Scenario: Обсудить
- GIVEN открыта карточка предложения в реплике Дяди Коли
- WHEN автор нажимает «Обсудить в чате»
- THEN над полем чата MUST быть «Выделено: «Он утонул. Всё.»»

### Requirement: Хранение предложений
Место предложения MUST храниться в документе сценария меткой с идентификатором; предлагаемый текст, «зачем», время и статус MUST храниться в источнике данных отдельно от текста. Экспорт в Fountain и Final Draft и печать MUST содержать текст без предложений, каким он был до решения автора.

#### Scenario: Экспорт до решения
- GIVEN предложение в реплике Дяди Коли открыто
- WHEN автор экспортирует сценарий в Fountain
- THEN в файле MUST быть «Он утонул. Всё.» и MUST NOT быть «Утонул. Всё.» отдельной строкой

### Requirement: Создание драфта
Внизу переключателя драфтов MUST быть «Новый драфт». Диалог MUST спрашивать название (подставлен следующий номер, например «Драфт 3») и «На основе» (любой драфт истории вне корзины, выбран открытый). Пустое название MUST давать ошибку. После создания MUST открыться новый драфт на том же типе документа, без замка.

#### Scenario: Драфт после читки
- GIVEN открыта «Тихая вода»
- WHEN автор создаёт драфт «После читки» на основе открытого драфта
- THEN MUST открыться «После читки», в переключателе MUST быть подпись «от Драфта 1», а содержимое основы MUST NOT измениться

#### Scenario: Без названия
- GIVEN открыт диалог «Новый драфт»
- WHEN автор нажимает «Создать» с пустым названием
- THEN диалог MUST остаться открытым с ошибкой «Назовите драфт.»

### Requirement: Драфты в корзине
Меню драфта «Удалить в корзину» MUST убирать драфт из переключателя в корзину истории; у единственного драфта вне корзины этого действия MUST NOT быть. Если удалён открытый драфт, MUST открыться драфт из `open_draft_id`. «Восстановить» MUST возвращать драфт в переключатель, «Удалить навсегда» MUST удалять его с подтверждением. Корзина MUST показывать документы открытого драфта и драфты истории.

#### Scenario: Восстановить драфт
- GIVEN драфт «После читки» удалён в корзину
- WHEN автор нажимает «Восстановить» в корзине истории
- THEN «После читки» MUST вернуться в переключатель с тем же содержимым

#### Scenario: Единственный драфт
- GIVEN в истории один драфт
- WHEN автор открывает его меню
- THEN пункта «Удалить в корзину» MUST NOT быть

### Requirement: Регистрация на экране входа
Экран входа `/login` MUST вести регистрацию своими экранами по дизайн-системе через API шагов Authentik:
- почта без аккаунта — вместо ошибки сообщение «Аккаунта с почтой … ещё нет» с действиями «Создать аккаунт» и «Другая почта»;
- «Как вас зовут?» — имя и фамилия; пустое — ошибка у поля;
- «Подтвердите почту» — тот же ввод кода, что при входе, с «Отправить ещё раз» и «Другая почта»;
- после верного кода — токены по OIDC и возврат на открытый адрес, как после входа.

#### Scenario: Регистрация новой почты
- GIVEN аккаунта с почтой `new@authorled.test` нет
- WHEN пользователь вводит почту, выбирает «Создать аккаунт», вводит имя и код из письма
- THEN MUST открыться полка историй, а меню пользователя MUST показывать введённое имя

#### Scenario: Другая почта вместо регистрации
- GIVEN показано «Аккаунта с почтой … ещё нет»
- WHEN пользователь выбирает «Другая почта»
- THEN MUST открыться шаг почты с прежним адресом для правки, без отправки писем

#### Scenario: Пустое имя
- GIVEN открыт шаг «Как вас зовут?»
- WHEN пользователь продолжает с пустым полем
- THEN у поля MUST показываться ошибка, и письмо MUST NOT отправляться

### Requirement: Регистрация: существующая почта и повтор
Почта, у которой есть аккаунт, MUST вести во вход, а не в регистрацию. Перезагрузка посреди регистрации MUST начинать с почты без ошибки.

#### Scenario: Перезагрузка на шаге имени
- GIVEN открыт шаг «Как вас зовут?»
- WHEN страница перезагружена
- THEN MUST показываться шаг почты без ошибки

#### Scenario: Возврат после брошенной регистрации
- GIVEN регистрация брошена на шаге кода
- WHEN пользователь снова вводит ту же почту
- THEN MUST открыться шаг кода входа, и после верного кода MUST открыться приложение

### Requirement: Настройки
Страница `/settings` MUST следовать раскладке экрана «Настройки» макета v1 (`openspec/context/_raw/design/kabinet/`, `#settings`) и дизайн-системе: лист на столе, «Назад», заголовок «Настройки», разделы слева; при ширине меньше 768 px — над содержимым, без горизонтальной прокрутки. Клик по разделу прокручивает к нему. Раздел «Профиль»: имя с кнопкой «Сохранить» (доступна, когда имя изменено; пустое — ошибка у поля без запроса), почта для входа только для чтения, «Выйти».

#### Scenario: Смена имени
- GIVEN пользователь на `/settings` с именем «Анна Петрова»
- WHEN он вводит «Анна П.» и нажимает «Сохранить»
- THEN меню пользователя MUST показывать «Анна П.» без перезагрузки страницы
- AND после перезагрузки поле MUST содержать «Анна П.»

#### Scenario: Пустое имя
- GIVEN пользователь на `/settings`
- WHEN он стирает имя и нажимает «Сохранить»
- THEN у поля MUST показываться ошибка «Введите имя.», а запрос MUST NOT отправляться

#### Scenario: Узкий экран
- GIVEN ширина окна 375 px
- WHEN открыта `/settings`
- THEN разделы MUST стоять над содержимым, и страница MUST NOT прокручиваться по горизонтали

### Requirement: Тема в настройках
Раздел «Внешний вид» страницы `/settings` MUST предлагать тему четырьмя плитками с превью: «Утро» (`light`), «Бумага» (`sepia`), «Вечер у лампы» (`dark`) и «Как в системе»; выбранная отмечена. Выбор MUST применяться сразу и сохраняться в аккаунте через `PATCH /api/v1/me`. Если сохранение не удалось, MUST показываться причина, и тема MUST вернуться к сохранённой.

#### Scenario: Тема на другом устройстве
- GIVEN пользователь выбрал «Бумага» в одном браузере
- WHEN он входит в другом браузере
- THEN после входа MUST применяться тема `sepia`

#### Scenario: Как в системе
- GIVEN пользователь выбрал «Как в системе», а система в тёмном режиме
- WHEN страница перезагружена
- THEN MUST применяться тема `dark`

### Requirement: Данные аккаунта из API
Страница `/settings` и меню пользователя MUST брать имя, почту и тему из `GET /api/v1/me`. Если ответ не получен, они MUST показывать причину и «Повторить», а не данные из токена и не пустую страницу.

#### Scenario: API недоступен
- GIVEN API не отвечает
- WHEN пользователь открывает `/settings`
- THEN MUST показываться причина и «Повторить», а не пустая страница

### Requirement: Продление входа
Когда Access Token истёк или скоро истечёт, вкладка MUST продлевать его по refresh token одним запросом к Authentik, сколько бы частей приложения ни ждали токен одновременно; все они MUST получать результат этого продления. Приложение MUST NOT повторно отправлять refresh token, который уже ушёл в Authentik.

#### Scenario: Вкладка проснулась с истёкшим токеном
- GIVEN Access Token вкладки истёк, пока вкладка спала
- WHEN одновременно запрашивают токен проверка входа, меню пользователя, `/settings` и чат
- THEN в Authentik MUST уйти ровно один запрос продления
- AND экран MUST работать без перезагрузки и без экрана входа

#### Scenario: Скоро истечёт
- GIVEN до истечения Access Token осталось меньше минуты, и приложение в этот момент запрашивает токен
- WHEN срабатывает продление по таймеру
- THEN в Authentik MUST уйти один запрос продления, а не два

### Requirement: Конец сессии
Если Authentik отказал в продлении (`invalid_grant`: refresh token отозван, истёк или уже использован), приложение MUST удалить токены вкладки и MUST открыть `/login` с возвратом на текущий адрес. Запросы к API, ждавшие токен, MUST NOT показывать свою ошибку поверх. Если сессия Authentik жива, `/login` MUST взять токены без формы (требование «Вход»).

#### Scenario: Дублированная вкладка
- GIVEN вкладка B — копия вкладки A с теми же токенами, и A уже продлила токен
- WHEN B запрашивает токен, а сессия Authentik жива
- THEN B MUST оказаться на том же адресе с новыми токенами, без формы входа и без экрана «Не удалось проверить вход»

#### Scenario: Сессия Authentik закончилась
- GIVEN refresh token вкладки отозван, и сессии Authentik нет
- WHEN вкладка запрашивает токен на `/p/water/text`
- THEN MUST открыться `/login` с шагом почты, а после входа — `/p/water/text`

### Requirement: Сбой продления
Если продление не удалось из-за сбоя (нет сети, Authentik недоступен, ответ 5xx, тайм-аут), приложение MUST NOT удалять токены и MUST показывать «Не удалось проверить вход» с причиной и «Попробовать снова», которое повторяет продление.

#### Scenario: Authentik остановлен
- GIVEN Access Token истёк, а Authentik остановлен
- WHEN пользователь открывает приложение
- THEN MUST показываться «Не удалось проверить вход» с причиной
- AND после запуска Authentik «Попробовать снова» MUST впускать без повторного входа

### Requirement: Конфликт правок
Если ядро отказало в сохранении документа или текста из-за более новой ревизии (`409`), экран MUST показать на месте статуса сохранения «История изменилась в другой вкладке», «Открыть свежую версию» и «Скопировать мою правку». Пока автор не выбрал, правки этого документа MUST NOT отправляться. «Открыть свежую версию» MUST загрузить сохранённую версию; несохранённая правка MUST NOT пропадать без «Скопировать мою правку».

#### Scenario: Две вкладки
- GIVEN профиль Веры открыт в двух вкладках, и в первой сохранено поле «Главный страх»
- WHEN во второй вкладке автор меняет то же поле
- THEN вторая вкладка MUST показать «История изменилась в другой вкладке», а в ядре MUST остаться правка первой

#### Scenario: Свежая версия
- GIVEN вторая вкладка показывает конфликт
- WHEN автор нажимает «Открыть свежую версию»
- THEN поле MUST показать значение, сохранённое первой вкладкой, и следующие правки MUST сохраняться

### Requirement: Предложение по якорю
Открытое предложение соавтора без метки в тексте MUST ставиться в «Текст сценария» по якорю: в сцене с его `uid` MUST находиться первое вхождение цитаты внутри одного абзаца, и на него MUST ставиться метка предложения обычной правкой с сохранением. После ответа соавтора в чате список предложений MUST обновляться без перезагрузки. Метка MUST ставиться один раз; уже стоящая метка MUST NOT дублироваться.

#### Scenario: Предложение из чата
- GIVEN открыт «Текст сценария» со сценой `s3`, где есть «Вера молчит.»
- WHEN соавтор в чате предлагает заменить «Вера молчит» на «Вера отворачивается»
- THEN в тексте MUST появиться предложение на «Вера молчит» без перезагрузки страницы, и его карточка MUST давать «Принять» и «Отклонить»

### Requirement: Предложения без места в тексте
Открытое предложение, чей якорь не найден (нет сцены с `uid` или цитаты в ней), MUST NOT ставиться в текст и MUST показываться в списке «Нет места в тексте», который открывает кнопка предложений соавтора: цитата, предлагаемый текст, «зачем» и «Отклонить». Такие предложения MUST NOT входить в число открытых предложений в тексте.

#### Scenario: Фрагмент переписан
- GIVEN соавтор предложил правку к «Вера молчит», а автор уже переписал эту строку
- WHEN открыт «Текст сценария»
- THEN предложение MUST быть в списке «Нет места в тексте», и «Отклонить» MUST снимать его

### Requirement: Файлы в чат
Поле ввода чата MUST принимать файлы скрепкой, перетаскиванием на колонку чата и вставкой из буфера: DOCX, PDF, TXT, MD, Fountain, FDX, STARC, до 20 МБ и до 5 файлов в сообщении. Файл MUST загружаться в ядро к текущей беседе. Отказ (тип, размер, антивирус, нечитаемый файл) MUST показываться под полем с причиной, и файл MUST NOT прикрепляться.

#### Scenario: Неподходящий файл
- GIVEN открыта беседа
- WHEN автор перетаскивает `обложка.png`
- THEN под полем MUST показаться причина, и файл MUST NOT прикрепиться

### Requirement: Файлы в сообщении
Пока прикреплённый файл загружается и проверяется, отправить сообщение MUST NOT быть возможно. Отправленное сообщение MUST показывать имена файлов, а соавтор MUST получать их id в контексте сообщения. Сообщение MAY состоять из одних файлов.

#### Scenario: Заметки в чат
- GIVEN источник `api` и открыта беседа истории
- WHEN автор прикрепляет `заметки.docx` и спрашивает «Что здесь важно для Веры?»
- THEN сообщение MUST показывать «заметки.docx», и соавтор MUST ответить по тексту файла

#### Scenario: Отправка во время проверки
- GIVEN файл ещё проверяется антивирусом
- WHEN автор нажимает Enter
- THEN сообщение MUST NOT отправиться, пока файл не прикреплён или не отклонён

### Requirement: Переключатель драфтов
Переключатель MUST показывать открытый драфт и быть виден при любом числе драфтов. Список MUST содержать драфты вне корзины: название, дату создания, значок замка и подпись «от <основа>». Выбор драфта MUST открывать в нём текст сценария без потери несохранённых правок. На ширине 375 px переключатель MUST помещаться в навигатор без горизонтальной прокрутки.

#### Scenario: Переключение
- GIVEN открыт драфт 1, и автор только что напечатал слово
- WHEN автор выбирает драфт 2
- THEN правка MUST сохраниться в драфт 1, и MUST открыться текст драфта 2 с деревом драфта 2

#### Scenario: Возврат в историю
- GIVEN автор работал в драфте 2 и вернулся на полку
- WHEN он открывает историю
- THEN MUST открыться драфт 2

#### Scenario: Один драфт
- GIVEN в истории один драфт
- WHEN открыто окно истории
- THEN в навигаторе MUST быть переключатель с этим драфтом и «Новый драфт»

### Requirement: Меню драфта
У драфта MUST быть меню: «Переименовать», «Запретить правку» или «Разрешить правку», «Сохранить точку», «Точки драфта», «Удалить в корзину». Понятия «основной текст» и «текущий текст» MUST NOT показываться на экранах.

#### Scenario: Пункты меню
- GIVEN в истории два драфта
- WHEN автор открывает меню драфта
- THEN MUST быть все пункты меню, и MUST NOT быть пункта сравнения

### Requirement: Запертый драфт
В запертом драфте все документы драфта MUST открываться только для чтения: текст, паспорт, логлайн, части в навигаторе, профили. Название и тэглайн принадлежат истории и MUST оставаться доступными для правки. Действия правки, комментарии, импорт и решение по предложениям MUST быть недоступны. Экран MUST показывать, что правка запрещена, и давать «Разрешить правку».

#### Scenario: Разрешить правку
- GIVEN открыт запертый драфт «После читки»
- WHEN автор нажимает «Разрешить правку» и печатает в тексте
- THEN драфт MUST сохраниться с правкой, значок замка MUST исчезнуть, а другие драфты MUST остаться прежними

#### Scenario: Профиль в запертом драфте
- GIVEN открыт запертый драфт
- WHEN автор открывает профиль персонажа
- THEN поля MUST быть только для чтения

#### Scenario: История в запертом драфте
- GIVEN открыт запертый драфт
- WHEN автор открывает документ «История»
- THEN название и тэглайн MUST быть доступны для правки, а галочки частей MUST быть закрыты

### Requirement: История документа
У текста, частей паспорта и профилей MUST быть действие «История сохранений»: список снимков (когда, кто, почему). Выбранный снимок MUST открываться только для чтения. «Восстановить» MUST возвращать документ к снимку; после него экран MUST показать восстановленное содержимое. В запертом драфте «Восстановить» MUST быть недоступно.

#### Scenario: Откат профиля
- GIVEN у профиля Веры есть вчерашний снимок
- WHEN автор выбирает его и нажимает «Восстановить»
- THEN профиль MUST показать вчерашние поля, а текст сценария MUST NOT измениться

#### Scenario: Причина снимка
- GIVEN автор принял предложение соавтора
- WHEN он открывает «История сохранений» текста
- THEN в списке MUST быть снимок с подписью «Перед принятием предложения соавтора»

### Requirement: Точки драфта
«Сохранить точку» MUST спрашивать название; пустое название MUST давать ошибку. «Точки драфта» MUST показывать точки: название, кто, когда, и «Вернуться». Откат MUST спрашивать подтверждение и предупреждать, что откатится весь драфт; автоматическая точка перед откатом MUST быть видна в списке. После отката MUST обновиться навигатор и открытый документ.

#### Scenario: Вернуть героиню
- GIVEN сохранена точка «до смены героини», затем изменены карточка Веры и текст
- WHEN автор выбирает «Вернуться» и подтверждает
- THEN карточка и текст MUST вернуться, а в списке MUST появиться точка «Перед откатом к «до смены героини»»

#### Scenario: Отказ от отката
- GIVEN открыт диалог подтверждения
- WHEN автор выбирает «Отмена»
- THEN драфт MUST NOT измениться

### Requirement: Выход к полке
Наверху навигатора истории, над её названием, MUST быть строка «Все истории» со стрелкой назад. Клик по строке MUST открывать полку `/` без перезагрузки страницы. Строка MUST быть видна и в дереве документов, и в списке сцен.

#### Scenario: Выход из документа
- GIVEN открыт текст сценария истории «Тихая вода»
- WHEN пользователь нажимает «Все истории»
- THEN MUST открыться полка, и на ней MUST быть «Тихая вода»

#### Scenario: Выход из списка сцен
- GIVEN в навигаторе открыт список сцен «Текста сценария»
- WHEN пользователь нажимает «Все истории»
- THEN MUST открыться полка

#### Scenario: Выход на узком экране
- GIVEN окно шириной 375 px и открыт навигатор
- WHEN пользователь нажимает «Все истории»
- THEN MUST открыться полка, и навигатор MUST закрыться

#### Scenario: Правка перед выходом
- GIVEN автор только что допечатал фразу в «Тексте сценария»
- WHEN он сразу нажимает «Все истории» и снова открывает историю
- THEN фраза MUST быть в тексте
