## Requirements

### Requirement: Вход
Приложение MUST пускать к экранам только после входа. Без действующей сессии приложение MUST открывать свой экран входа `/login` и после входа MUST возвращать на адрес, который открывали. Экран входа MUST следовать макету v1 (`openspec/context/_raw/design/kabinet/`, экраны `#auth/*`) и дизайн-системе:
- почта; при неверном формате — ошибка у поля;
- пароль — только если у аккаунта он задан; «Показать»; неверный пароль — ошибка у поля;
- код из письма — 6 ячеек: цифры переходят сами, вставка из буфера раскладывается по ячейкам, полный код отправляется сам; неверный код — ошибка и очищенные ячейки; «Отправить ещё раз» доступно через 60 секунд; «Другая почта» возвращает к первому шагу;
- ошибка Authentik — текст ошибки с причиной, а не пустой экран.
После последнего шага приложение MUST получить токены по OIDC без страницы Authentik. Если в Authentik уже есть сессия (вход в другой вкладке), `/login` MUST брать токены без формы. Перезагрузка страницы посреди входа MUST начинать вход с почты. Меню пользователя MUST показывать имя из токена и действие «Выйти», которое завершает сессию в Authentik и возвращает на `/login`. Без входа MUST открываться только `/login` и витрина дизайн-системы.

#### Scenario: Вход с сохранением адреса
- GIVEN пользователь не вошёл
- WHEN он открывает `/p/water/chars` и проходит экран входа
- THEN после кода MUST открыться `/p/water/chars`

#### Scenario: Отказ во входе
- GIVEN Authentik недоступен или отвечает ошибкой
- WHEN пользователь отправляет почту на экране входа
- THEN MUST показываться причина ошибки и возможность повторить, а не пустая страница

#### Scenario: Неверный код
- GIVEN на экране кода
- WHEN пользователь вводит шесть неверных цифр
- THEN MUST показываться ошибка, ячейки MUST очиститься, и фокус MUST вернуться в первую ячейку

#### Scenario: Вставка кода
- GIVEN на экране кода
- WHEN пользователь вставляет из буфера «123456»
- THEN цифры MUST разложиться по ячейкам, и код MUST отправиться без нажатия кнопки

#### Scenario: Аккаунт без пароля
- GIVEN у аккаунта не задан пароль
- WHEN пользователь вводит почту
- THEN следующим MUST открыться экран кода

#### Scenario: Новая вкладка
- GIVEN пользователь вошёл в одной вкладке
- WHEN он открывает приложение в новой вкладке
- THEN экран MUST открыться без формы входа

#### Scenario: Перезагрузка на шаге кода
- GIVEN открыт шаг кода
- WHEN страница перезагружена
- THEN MUST показываться шаг почты без ошибки

#### Scenario: Выход
- GIVEN пользователь вошёл
- WHEN он выбирает «Выйти»
- THEN сессия в Authentik MUST завершиться, и MUST открыться `/login`

### Requirement: Обязательные настройки
Приложение MUST получать адрес Authentik (`AUTH_ISSUER`), клиента (`AUTH_FRONTEND_CLIENT_ID`), адрес возврата (`AUTH_FRONTEND_REDIRECT_URI`) и источник данных (`VITE_DATA_SOURCE`). Если любая настройка отсутствует или неверна, приложение MUST показать экран ошибки с именем настройки и MUST NOT подставлять значение по умолчанию. Если приложение открыто не с того адреса, что указан в `AUTH_FRONTEND_REDIRECT_URI` (схема, хост, порт), MUST показываться ошибка с правильным адресом.

#### Scenario: Нет настройки входа
- GIVEN `AUTH_ISSUER` не задан
- WHEN приложение открыто
- THEN MUST показываться ошибка, называющая `AUTH_ISSUER`

#### Scenario: Чужой адрес
- GIVEN `AUTH_FRONTEND_REDIRECT_URI` равен `http://localhost:5173/auth/callback`
- WHEN приложение открыто по адресу `http://127.0.0.1:5173/`
- THEN MUST показываться ошибка с адресом `http://localhost:5173`

### Requirement: Источник данных
Экраны MUST получать и менять данные только через провайдер данных приложения. Пока у бэкенда нет маршрутов историй и документов, единственным допустимым источником MUST быть `fixtures`: данные примера макета v2 («Тихая вода», «Последний паром»), которые живут в памяти страницы и сбрасываются при перезагрузке. В режиме `fixtures` приложение MUST показывать метку «Данные примера» в меню пользователя.

#### Scenario: Неизвестный источник
- GIVEN `VITE_DATA_SOURCE=api`
- WHEN приложение открыто
- THEN MUST показываться ошибка, что источник `api` не поддерживается, с перечнем допустимых значений

#### Scenario: Данные примера
- GIVEN `VITE_DATA_SOURCE=fixtures` и пользователь вошёл
- WHEN открыт корневой адрес
- THEN полка MUST показывать «Тихая вода» и «Последний паром»

### Requirement: Адреса экранов
Каждый экран MUST иметь свой адрес, и открытие адреса напрямую MUST показывать тот же экран:
- `/` — полка историй; `/trash` — корзина историй;
- `/p/:projectId/:doc` — окно истории с документом: `info`, `sp`, `title`, `synopsis`, `text`, `chars`, `char:<id>`, `locs`, `loc:<id>`, `worlds`, `world:<id>`, `trash`;
- `/showcase` — витрина дизайн-системы;
- `/auth/callback` — возврат из Authentik.
Неизвестный адрес, история или документ MUST показывать экран «Не найдено» со ссылкой на полку.

#### Scenario: Прямая ссылка на профиль
- GIVEN пользователь вошёл
- WHEN он открывает `/p/water/char:vera`
- THEN MUST открыться окно истории «Тихая вода» с профилем Веры, и в навигаторе Вера MUST быть текущим пунктом

#### Scenario: Нет такого документа
- GIVEN пользователь вошёл
- WHEN он открывает `/p/water/char:nobody`
- THEN MUST показываться «Не найдено» со ссылкой на полку

### Requirement: Полка историй
Полка MUST показывать истории обложками с названием и действия: создать, переименовать, удалить в корзину. Создание MUST спрашивать только название; пустое название MUST давать ошибку у поля; новая история MUST быть полнометражным сценарием и MUST открываться сразу на тексте сценария. На полке MUST NOT быть приветствия, поиска, режима фокуса и статуса сохранения.

#### Scenario: Новая история
- GIVEN открыта полка
- WHEN пользователь создаёт историю «Маяк»
- THEN MUST открыться `/p/<id>/text` новой истории с одним пустым заголовком сцены

#### Scenario: Пустое название
- GIVEN открыт диалог новой истории
- WHEN пользователь нажимает «Создать» с пустым названием
- THEN MUST показываться ошибка у поля, и история MUST NOT создаваться

### Requirement: Корзина историй
Удалённая история MUST попадать в корзину историй и пропадать с полки. Корзина MUST показывать дату удаления и срок хранения 30 дней и MUST давать «Восстановить» и «Удалить навсегда»; «Удалить навсегда» MUST требовать подтверждения.

#### Scenario: Удаление и восстановление
- GIVEN на полке есть «Последний паром»
- WHEN пользователь удаляет её в корзину и затем восстанавливает из `/trash`
- THEN история MUST вернуться на полку со всеми документами

### Requirement: Окно истории
Окно истории MUST состоять из навигатора слева, рабочего поля посередине и колонки чата справа. Колонка чата MUST быть видна на всех экранах истории. На ширине до 900 px навигатор MUST открываться кнопкой поверх рабочего поля, а чат — листом снизу.

#### Scenario: Узкий экран
- GIVEN окно шириной 375 px
- WHEN открыт `/p/water/text`
- THEN рабочее поле MUST занимать ширину экрана без горизонтальной прокрутки, навигатор MUST открываться кнопкой, чат — листом снизу

### Requirement: Навигатор
Навигатор MUST показывать дерево: история; «Персонажи», «Локации», «Миры» с документами; сценарий с частями «Титульная страница», «Синопсис», «Текст сценария» (видимость частей задаётся в документе «Сценарий»); «Корзина» с числом документов. Открытый документ MUST быть выделен. У узлов MUST быть меню (правый клик и кнопка «⋮») с действиями узла: добавить документ в группу, сортировать по алфавиту, открыть, удалить в корзину, очистить корзину. Кнопка «Добавить документ» MUST создавать персонажа, локацию или мир; пустое имя MUST давать ошибку. Добавить свободный документ или папку MUST NOT быть возможно.

#### Scenario: Новый персонаж
- GIVEN открыта история «Тихая вода»
- WHEN пользователь добавляет персонажа «Нина Петровна»
- THEN персонаж MUST появиться в группе «Персонажи», и MUST открыться его профиль

#### Scenario: Удаление в корзину истории
- GIVEN в навигаторе есть локация «Пристань»
- WHEN пользователь выбирает «Удалить» в её меню
- THEN локация MUST пропасть из группы и появиться в «Корзине» истории, а счётчик корзины MUST увеличиться на 1

### Requirement: Документы истории
Рабочее поле MUST показывать документы:
- «История»: название и короткое описание;
- «Сценарий»: название, тэглайн, логлайн, видимость частей в навигаторе, число сцен и оценка длительности;
- «Титульная страница»: название, жанр или формат, автор, контакты, город и год — листом бумаги;
- «Синопсис»: текст листом бумаги;
- списки персонажей, локаций и миров с ролью и одной строкой описания;
- профили персонажа, локации и мира с полями макета v2 (`PROFILE` в `data.js`), ролью и, для персонажа, возрастом и полом;
- «Корзина» истории: удалённые документы с «Восстановить», «Удалить навсегда» и «Очистить корзину».
Правка поля MUST сохраняться через провайдер данных и MUST отражаться в навигаторе без перезагрузки; статус «Сохранено» MUST показываться на экранах документов.

#### Scenario: Переименование персонажа
- GIVEN открыт профиль Веры
- WHEN пользователь меняет имя на «Вера Андреевна»
- THEN навигатор MUST показывать «Вера Андреевна», а статус MUST стать «Сохранено»

#### Scenario: Восстановление из корзины истории
- GIVEN в корзине истории лежит персонаж «Миша»
- WHEN пользователь нажимает «Восстановить»
- THEN Миша MUST вернуться в группу «Персонажи» со всеми полями профиля

### Requirement: Текст сценария для чтения
До подключения редактора документ «Текст сценария» MUST показывать текст истории листом бумаги с оформлением типов абзацев из макета v2 и MUST NOT давать его править. Экран MUST явно сообщать, что редактор подключается отдельным этапом.

#### Scenario: Текст примера
- GIVEN открыт `/p/water/text`
- WHEN экран отрисован
- THEN MUST быть видны заголовки сцен, имена персонажей и реплики «Тихой воды» с оформлением сценария, и текст MUST NOT быть редактируемым

### Requirement: Без методологии
Интерфейс приложения MUST NOT показывать документы, этапы и статусы методологии Д1–Д22.

#### Scenario: Нет статусов
- GIVEN пользователь вошёл и открыл любую историю
- WHEN просматриваются все экраны приложения
- THEN на них MUST NOT встречаться обозначения Д1–Д22 и статусы документов методологии

### Requirement: Быстрый вход для разработки
В сервере разработки экран входа MUST показывать кнопки «Войти как Сценарист» и «Войти как Редактор». Кнопка MUST проходить тот же поток входа, что и пользователь, с почтой пользователя для разработки, паролем из `AUTH_DEV_USER_PASSWORD` и кодом из письма в Mailpit. Если Mailpit недоступен или письмо не пришло за 10 секунд, MUST показываться ошибка с причиной. В production-сборке кнопок и их кода MUST NOT быть.

#### Scenario: Вход одной кнопкой
- GIVEN локальный стенд, пользователи созданы `./scripts/dev.sh auth-users`
- WHEN разработчик нажимает «Войти как Редактор»
- THEN MUST открыться полка историй, а меню пользователя MUST показывать «Редактор»

#### Scenario: Нет в production
- GIVEN выполнен `npm run build --prefix web`
- WHEN в `web/dist/assets/*.js` ищутся строки «Войти как» и `mailpit`
- THEN совпадений MUST NOT быть

### Requirement: Чат с соавтором
Колонка чата окна истории MUST быть чатом с агентом `coauthor` через AG-UI: заголовок «Соавтор», строка «Видит: <открытый документ>», сообщения автора и ответы соавтора, поле ввода (Enter — отправить, Shift+Enter — новая строка). Ответ MUST появляться по мере генерации; Markdown в ответе MUST отображаться оформленным текстом; у ответа MUST быть «Скопировать». Пустая беседа MUST показывать подсказки-вопросы, которые отправляются по клику.

#### Scenario: Вопрос и ответ
- GIVEN открыт текст сценария «Тихой воды»
- WHEN автор отправляет «О чём эта история?»
- THEN в чате MUST появиться его сообщение и ответ соавтора, который нарастает по мере генерации

#### Scenario: Ошибка
- GIVEN API недоступен
- WHEN автор отправляет сообщение
- THEN в чате MUST появиться сообщение об ошибке с причиной, а текст автора MUST остаться в поле, чтобы отправить его снова

### Requirement: Контекст соавтора
С каждым сообщением фронтенд MUST передавать соавтору контекст AG-UI: название истории, открытый документ (название и содержимое: текст сценария, синопсис, поля профиля и т. п.) и выделенный автором фрагмент, если он есть. Выделенный фрагмент MUST показываться плашкой над полем ввода с кнопкой «Убрать».

#### Scenario: Выделенный фрагмент
- GIVEN в тексте сценария выделена реплика
- WHEN автор спрашивает «Как сделать короче?»
- THEN над полем MUST быть плашка с фрагментом, а запрос к AG-UI MUST содержать этот фрагмент в контексте

### Requirement: Беседы по истории
Беседы MUST храниться сессиями Agno пользователя и MUST относиться к одной истории. «Новая беседа» MUST начинать пустую беседу; «История бесед» MUST показывать беседы этой истории (название — начало первого сообщения, дата) и открывать выбранную с её сообщениями. Беседы другой истории MUST NOT показываться.

#### Scenario: Возврат к беседе
- GIVEN в истории «Тихая вода» была беседа «О чём эта история?»
- WHEN автор открывает «История бесед» и выбирает её
- THEN MUST показаться её сообщения, и новый вопрос MUST продолжить ту же беседу
