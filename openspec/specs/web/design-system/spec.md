# Web Design System Specification

## Purpose
Дизайн-система фронтенда Authorled: токены, темы, шрифты, «бумага» редактора, семантика статусов документов, пометок в тексте и метки ИИ. Все экраны, чат и редактор берут стили только из неё.

## Requirements

### Requirement: Слои токенов
Цвета, радиусы, тени, шрифты и размеры MUST задаваться CSS-переменными в трёх слоях:
1. примитивы — шкалы цветов в OKLCH;
2. семантика shadcn/ui под стандартными именами (`--background`, `--foreground`, `--primary`, `--muted`, `--accent`, `--destructive`, `--border`, `--ring`, `--sidebar-*`, `--radius` и другие из документации shadcn), без переименований;
3. продуктовая семантика: поверхности «Кабинета» (`--desk`, `--desk-glow`, `--panel`, `--shadow-panel`, `--shadow-paper`, `--grain-opacity`, `--grain-image`, `--radius-panel`), бумага редактора (`--paper*`), статусы документов (`--status-*`), пометки в тексте (`--deco-*`), ИИ (`--ai*`).

Компоненты и экраны MUST использовать только слои 2 и 3. Слой 1 MUST использоваться только внутри определений слоёв 2 и 3. Исключение — страница-витрина дизайн-системы: она MAY показывать примитивы слоя 1, чтобы документировать палитру.

#### Scenario: Примитив в экране
- GIVEN в файле под `web/src/` вне файла токенов и витрины используется примитив слоя 1 (например, `var(--blue-9)`)
- WHEN выполняется `./scripts/validate.sh`
- THEN проверка MUST завершиться ошибкой с именем файла и строкой

#### Scenario: Сырой цвет в компоненте
- GIVEN в файле под `web/src/` вне файла токенов используется цвет напрямую (hex, `rgb()`, `oklch()` или класс палитры Tailwind вроде `bg-red-500`)
- WHEN выполняется `./scripts/validate.sh`
- THEN проверка MUST завершиться ошибкой с именем файла и строкой

### Requirement: Темы
Система MUST поддерживать темы `light`, `sepia` и `dark`, выбираемые атрибутом `data-theme` на `<html>`. Каждая тема MUST переопределять все токены слоёв 2 и 3. Пока пользователь не выбрал тему, MUST применяться `light` или `dark` по настройке системы (`prefers-color-scheme`); `sepia` включается только выбором пользователя. Выбор пользователя MUST храниться в аккаунте (`user_settings.theme`, спека `web/workspace`, «Настройки»), а браузер MUST помнить его копию и применять её до первой отрисовки, без мигания чужой темы. После ответа `GET /api/v1/me` MUST применяться тема аккаунта, и копия в браузере MUST обновляться; «Как в системе» MUST удалять копию. Переключатель витрины (`/showcase`, без входа) меняет только копию в браузере.

Темы MUST следовать образу «Кабинета» (ADR-006): лист бумаги на тёплом столе.
- `light` («Утро»): тёплый светлый стол, бумага светлее стола, чернильно-синий акцент.
- `sepia` («Бумага»): кремовые стол и бумага плотнее, чем в `light`.
- `dark` («Вечер у лампы»): тёплый уголь; нейтральные тона стола, панели и бумаги MUST иметь тёплый оттенок, а не сине-чёрный.
Во всех темах бумага MUST отличаться по светлоте от стола, а панель — лежать между ними или совпадать с одним из них, чтобы лист читался на столе.

#### Scenario: Выбор темы
- GIVEN пользователь выбрал тёмную тему в переключателе
- WHEN страница перезагружена
- THEN `<html>` MUST иметь `data-theme="dark"` до первой отрисовки содержимого

#### Scenario: Выбор сепии
- GIVEN пользователь выбрал сепию в переключателе
- WHEN страница перезагружена
- THEN `<html>` MUST иметь `data-theme="sepia"` до первой отрисовки содержимого

#### Scenario: Тема по системе
- GIVEN выбор не сохранён, а система в тёмном режиме
- WHEN страница открыта
- THEN MUST применяться тёмная тема

#### Scenario: Тёплая тёмная тема
- GIVEN открыта тёмная тема
- WHEN измеряется оттенок токенов `--desk`, `--panel` и `--paper` в OKLCH
- THEN оттенок каждого MUST лежать в тёплом диапазоне (от 40 до 100 градусов), а не в синем

#### Scenario: Тема аккаунта побеждает копию в браузере
- GIVEN в браузере сохранена копия `light`, а в аккаунте — `dark`
- WHEN пользователь входит
- THEN после ответа `GET /api/v1/me` `<html>` MUST иметь `data-theme="dark"`
- AND после перезагрузки страницы `data-theme="dark"` MUST стоять до первой отрисовки

### Requirement: Контраст
Для каждой темы основной текст на своём фоне MUST иметь контраст не ниже 4,5:1, а иконки, границы полей ввода и маркеры пометок — не ниже 3:1 (WCAG 2.2 AA). Пары токенов для проверки MUST быть перечислены в проверке контраста. Среди пар MUST быть основной и приглушённый текст на столе (`--desk`) и на панели (`--panel`), а также ИИ на панели.

#### Scenario: Недостаточный контраст
- GIVEN значение токена изменено так, что пара `--paper-foreground` / `--paper` в одной из тем даёт контраст ниже 4,5:1
- WHEN выполняется `npm run check:contrast --prefix web`
- THEN проверка MUST завершиться ошибкой с именем темы, пары и фактическим значением

#### Scenario: Приглушённый текст на столе
- GIVEN значение `--muted-foreground` или `--desk` изменено так, что их контраст в одной из тем ниже 4,5:1
- WHEN выполняется `npm run check:contrast --prefix web`
- THEN проверка MUST завершиться ошибкой с именем темы и этой пары

### Requirement: Шрифты
Система MUST использовать три гарнитуры с кириллицей, поставляемые из собственной сборки: Golos Text для интерфейса, Literata для текста документов, прозы и заголовков, Cousine для сценария (метрика Courier New). Роли MUST задаваться токенами `--font-ui`, `--font-prose`, `--font-heading`, `--font-script`. Размеры `display`, `heading-1` и `heading-2` MUST набираться шрифтом `--font-heading`.

#### Scenario: Кириллица из своей сборки
- GIVEN приложение открыто без доступа в интернет
- WHEN на витрине показан образец «Съешь же ещё этих мягких французских булок» каждой гарнитурой
- THEN текст MUST отрисовываться нужной гарнитурой без запросов к сторонним хостам

#### Scenario: Заголовок шрифтом заголовков
- GIVEN на витрине показан образец размера `heading-1`
- WHEN проверяется вычисленный `font-family` образца
- THEN он MUST совпадать со значением `--font-heading`

### Requirement: Шкала текста и бумага
Размеры текста MUST задаваться именованной шкалой (`display`, `heading-1`, `heading-2`, `heading-3`, `body`, `body-prose`, `caption`, `code`). Область текста документа («бумага») MUST иметь ширину колонки не больше `--paper-measure` (по умолчанию 65 знаков), межстрочный интервал 1,6–1,7, выключку влево и `hyphens: auto` при `lang="ru"`. Отсутствие русских переносов в браузере MUST NOT подменяться переносами на JavaScript.

#### Scenario: Ширина колонки
- GIVEN окно шире 1200 px
- WHEN на витрине открыт образец бумаги
- THEN строка текста MUST NOT превышать `--paper-measure`

### Requirement: Метка ИИ
Всё, что предложил или создал ИИ, MUST помечаться компонентом `AiLabel`. Метка MUST открывать поповер с данными, которые ей передали: что сделал ИИ, на какие документы опирался, когда и кем принято. Поповер MUST открываться мышью и клавиатурой и закрываться клавишей Escape. Цвет ИИ MUST отличаться от цветов статусов.

#### Scenario: Открытие с клавиатуры
- GIVEN фокус на метке ИИ
- WHEN нажата клавиша Enter
- THEN MUST открыться поповер происхождения, а Escape MUST его закрыть и вернуть фокус на метку

### Requirement: Пометки в тексте
Система MUST задавать стили пометок редактора: вставка, удаление, комментарий, текст ИИ, противоречие, упоминание сущности, устаревший фрагмент. Каждая пометка MUST различаться формой (подчёркивание, зачёркивание, волнистая линия, пунктир, фон или полоса на полях), а не только цветом, и MUST иметь вариант для каждой темы.

#### Scenario: Пометки во всех темах
- GIVEN на витрине открыт образец текста со всеми пометками
- WHEN переключаются темы
- THEN каждая пометка MUST оставаться различимой по форме и иметь контраст маркера не ниже 3:1

### Requirement: Витрина
Приложение MUST содержать страницу-витрину дизайн-системы по адресу `/showcase` с образцами всех токенов, тем, шрифтов, шкалы текста, бумаги, поверхностей «Кабинета» (стол со светом и зерном, панель, обе тени, радиус панели), метки ИИ и пометок. Сама витрина MUST лежать на столе «Кабинета». Витрина MUST открываться без входа и MUST содержать переключатель темы.

#### Scenario: Витрина открывается
- GIVEN запущен сервер разработки
- WHEN открыт адрес `/showcase`
- THEN MUST показываться витрина со всеми разделами выше без запроса входа

### Requirement: Поверхности «Кабинета»
Дизайн-система MUST задавать поверхности рабочего места из ADR-006 и связывать с ними семантику shadcn:
- стол (`--desk`) — фон страницы; `--background` MUST совпадать с ним;
- свет лампы (`--desk-glow`) — мягкое пятно света в верхней части стола;
- зерно (`--grain-image`, `--grain-opacity`) — едва заметная текстура стола; её непрозрачность MUST NOT превышать 0,1;
- панель (`--panel`) — боковые колонки, карточки и плавающие инструменты на столе; `--card` и `--sidebar` MUST совпадать с ней;
- бумага (`--paper`) — лист документа и всплывающие окна; `--popover` MUST совпадать с ней;
- тени: `--shadow-panel` для панелей и кнопок на столе, `--shadow-paper` для листа и всплывающих окон;
- радиусы: `--radius` для полей и кнопок, `--radius-panel` (больше `--radius`) для панелей и карточек.
Дизайн-система MUST давать готовый класс фона стола, который собирает зерно, свет и цвет стола, чтобы экраны не повторяли этот фон сами.

#### Scenario: Стол со светом и зерном
- GIVEN на витрине открыт образец стола в любой теме
- WHEN элементу назначен класс фона стола
- THEN фон MUST состоять из зерна, пятна света и цвета `--desk` текущей темы

#### Scenario: Семантика shadcn на поверхностях
- GIVEN открыта любая тема
- WHEN сравниваются вычисленные значения токенов
- THEN `--background` MUST совпадать с `--desk`, `--card` и `--sidebar` — с `--panel`, а `--popover` — с `--paper`

### Requirement: Цвет ИИ
Цвет ИИ (`--ai`, `--ai-subtle`, `--ai-border`, `--deco-ai`) MUST быть сливовым (оттенок OKLCH от 310 до 340 градусов) во всех темах и MUST отличаться по оттенку от акцента `--primary` и от всех цветов статусов не меньше чем на 40 градусов.

#### Scenario: ИИ отличается от акцента
- GIVEN открыта любая тема
- WHEN сравниваются оттенки `--ai` и `--primary` в OKLCH
- THEN `--ai` MUST лежать в диапазоне 310–340 градусов, а разница с `--primary` MUST быть не меньше 40 градусов

### Requirement: Без системного вида
Элементы, которые браузер и ОС рисуют по умолчанию, MUST выглядеть по дизайн-системе во всех темах и MUST брать цвета только из токенов:
- полосы прокрутки — тонкий скруглённый бегунок без видимой дорожки, ярче при наведении;
- выделение текста и курсор ввода;
- обводка фокуса с клавиатуры — одно кольцо цвета `--ring` у всех элементов;
- поля после автозаполнения — фон и текст как без него в любом состоянии, рамки фокуса и ошибки видны;
- многострочные поля — без уголка растягивания.

#### Scenario: Прокрутка в тёмной теме
- GIVEN открыта тёмная тема и навигатор длиннее экрана
- WHEN навигатор прокручивается
- THEN бегунок MUST быть скруглённым, цветом из токенов, без светлой системной дорожки

#### Scenario: Фокус с клавиатуры
- GIVEN открыто окно истории
- WHEN фокус переходит клавишей Tab на пункт навигатора
- THEN вокруг пункта MUST быть кольцо цвета `--ring`, а не системная обводка

#### Scenario: Автозаполнение в поле с ошибкой
- GIVEN открыта тёмная тема и браузер подставил сохранённую почту на экране входа
- WHEN поле в фокусе или показывает ошибку
- THEN фон поля MUST быть тем же, что без автозаполнения, а текст — цвета `--foreground`
- AND рамка фокуса или ошибки MUST быть видна

#### Scenario: Правило автозаполнения на месте
- GIVEN в стилях дизайн-системы нет правила для полей после автозаполнения или оно лежит в слое стилей
- WHEN выполняется `./scripts/validate.sh`
- THEN проверка `check:native-ui` MUST завершиться ошибкой, называющей правило автозаполнения

### Requirement: Без системных подсказок и полей выбора
Подсказки MUST показываться компонентом дизайн-системы, а не атрибутом `title`. Флажки, переключатели и списки выбора MUST быть компонентами дизайн-системы, а не нативными `<input type="checkbox">`, `<input type="radio">` и `<select>`. Проверка репозитория MUST находить нарушения.

#### Scenario: Подсказка абзаца
- GIVEN открыт текст сценария
- WHEN указатель наведён на абзац
- THEN тип абзаца MUST показываться подсказкой дизайн-системы, а системная подсказка MUST NOT появляться

#### Scenario: Проверка запрещённых элементов
- GIVEN в `web/src` есть HTML-элемент с атрибутом `title`, нативный флажок или `<select>`
- WHEN выполняется `npm run check:native-ui --prefix web`
- THEN проверка MUST завершиться ошибкой с файлом и строкой

### Requirement: Метки автора
Дизайн-система MUST задавать палитру меток автора для цвета текста и заливки в редакторе: не меньше четырёх цветов, у каждого — цвет текста и цвет заливки, для каждой темы. Цвета меток MUST отличаться по оттенку от цвета ИИ не меньше чем на 40°, чтобы метку автора нельзя было принять за текст ИИ. Цвет текста метки MUST иметь контраст не ниже 4,5:1 на бумаге, основной текст на заливке — не ниже 4,5:1. Витрина MUST показывать редактор сценария с метками автора.

#### Scenario: Контраст меток во всех темах
- GIVEN палитра меток автора в `tokens.css`
- WHEN выполняется `npm run check:contrast --prefix web`
- THEN проверка MUST пройти для каждого цвета текста на `--paper` и для `--paper-foreground` на каждой заливке во всех темах

#### Scenario: Метки не похожи на ИИ
- GIVEN палитра меток автора в `tokens.css`
- WHEN проверка контраста сравнивает оттенки
- THEN каждый цвет метки MUST отстоять от `--ai` не меньше чем на 40°, иначе проверка MUST упасть с названием темы и токена

#### Scenario: Витрина
- GIVEN открыта витрина
- WHEN автор выделяет текст в разделе «Редактор сценария» и выбирает цвет
- THEN текст MUST получить цвет из палитры меток в текущей теме
