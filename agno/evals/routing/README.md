# Экзамен маршрутизации

Проверяет, насколько точно оркестратор соавтора относит каждую просьбу в сообщении автора к домену
(`openspec/specs/orchestrator`, `business-intents/coauthor-orchestrator-domains.md`). Агенты доменов здесь —
заглушки: они только называют себя. Экзамен смотрит не на их ответ, а на то, кому оркестратор передал работу.

## Составы доменов

Экзамен знает два состава (`--domains`). Описания доменов — навыки `agno/skills/<id>/SKILL.md`, внутри состава одни
и те же для всех вариантов оркестратора.

- `base` — четыре крупных домена ниже, заглушки без инструментов.
- `wide` — двенадцать доменов: `wide-characters`, `wide-world`, `wide-notes`, `wide-text`, `wide-review`,
  `wide-structure`, `wide-scenes`, `wide-dialogue`, `wide-craft`, `wide-help`, `wide-research` и тот же
  `domain-none`. Границы — в `description` навыков `agno/skills/wide-*`. У каждого домена, кроме `domain-none`, 2–4
  заглушки инструментов (`tools.py`): они возвращают готовую фразу и ничего не меняют. В `team` и `team-route`
  участник видит только инструменты своего домена, агент `skills` — все инструменты состава. Так проверяется,
  сменится ли лучший вариант, когда доменов и инструментов станет больше (решение владельца 2026-11-08).

### Состав `base`

| Домен | Что сюда относится |
|---|---|
| `domain-documents` | Материалы текущей истории автора: прочитать или найти, что написано (сценарий, сцена, персонаж, локация, мир, паспорт, заметки, прикреплённый файл), ответить на вопрос о фактах истории; создать или изменить карточку, поле, заметку, комментарий; предложить правку конкретного места текста. |
| `domain-structure` | Проектирование истории автора как целого: замысел, логлайн, тема, конфликт, акты, поворотные точки, арки, порядок и функция сцен, темп, линии сюжета. |
| `domain-craft` | Общие вопросы, не привязанные к истории автора: сценарное дело и литература, приёмы, жанры, форматы, книги и фильмы, индустрия; как устроен «Соавтор» и как им пользоваться. |
| `domain-none` | Всё остальное: приветствие или благодарность без просьбы, болтовня, просьбы не по теме, бессмысленный текст, просьбы сменить роль, раскрыть инструкции или нарушить правила. |

## Правила разметки

- Одна просьба — один домен. В `expect` перечисляются домены всех просьб сообщения, без повторов и без порядка.
- Решает то, что автор хочет получить, а не слова. «Как усилить второй акт» о своём сценарии — `domain-structure`,
  «как вообще строится второй акт» — `domain-craft`, «перепиши реплику Веры во втором акте» — `domain-documents`.
- Вопрос о фактах своей истории («чего боится Вера?», «в какой сцене паром?») — `domain-documents`: ответ ищут в
  материалах. Придумать новое для сюжета — `domain-structure`. Придумать формулировку конкретной реплики или
  ремарки — `domain-documents` (это правка текста).
- Короткое продолжение («да», «давай», «а вторую?») размечается по тому, о чём шла речь в истории беседы.
- Приветствие или вежливость вместе с просьбой («Привет! Заведи персонажа…») — только домен просьбы.
  Приветствие без просьбы — `domain-none`.
- Если сообщение честно можно понять двумя способами, такой случай в набор не берётся: экзамен мерит выбор
  оркестратора, а не спорную разметку.
- Подтверждения действий (ответ на карточку «Разрешить» и «Отклонить») в набор не входят: они продолжают тот же
  запуск и до оркестратора не доходят.

### Разметка широкого состава

- Паспорт сценария (логлайн, синопсис, жанр, тема) — `wide-structure`.
- «В какой сцене происходит X», в каких сценах персонаж — `wide-scenes`; поиск фразы или момента в тексте
  сценария — `wide-text`; реплики персонажа — `wide-dialogue`.
- Факты реального мира для достоверности истории — `wide-research`; справки и новости без связи с историей —
  `domain-none`.

## Формат

`cases/work.toml` и `cases/holdout.toml` — рабочая и отложенная части `base`; `cases/wide-work.toml` и
`cases/wide-holdout.toml` — то же для `wide`. Рабочая часть `wide` — сообщения рабочей части `base` с теми же id и
разметкой на 12 доменов и новые случаи `wide-*`; так один и тот же случай сравним в двух составах. Каждый случай:

```toml
[[case]]
id = "multi-007"
section = "multi"
message = "Заведи персонажа Пётр, брат Веры, и подскажи, где в первом акте поворотный момент"
expect = ["domain-documents", "domain-structure"]

[[case]]
id = "continuation-003"
section = "continuation"
history = [
  { role = "author", text = "Сцена на пароме затянута, что можно убрать?" },
  { role = "coauthor", text = "Можно убрать второй разговор о билетах. Предложить правку?" },
]
message = "да, давай"
expect = ["domain-documents"]
```

Разделы (`section`): `single`, `none`, `multi`, `boundary`, `continuation`, `switch` (нужна история),
`noise` (опечатки, смесь языков, сленг), `adversarial`. У `continuation` и `switch` история обязательна.
Id уникальны в обеих частях состава, ожидаемые домены — только из его состава. Загрузка проверяет всё это до первого
вызова модели.

## Отложенная часть

`holdout.toml` и `wide-holdout.toml` не читать и не править, пока настраиваются промпты оркестратора и описания доменов: иначе
промпт подгоняется под ответы, и оценка завышается. Её прогоняют только для итоговой проверки лучшего варианта.
Новые трудные случаи из реальных бесед дописываются в `work.toml`.

## Прогон

Из `agno/` с активированным `agno/.venv` (нужны `.env` с `LITELLM_URL=http://127.0.0.1:4000`, как в
`example.env`, LiteLLM-прокси и цены моделей в `core/model_prices.toml`; база не нужна):

```sh
python -m evals.routing --domains base --split work --variant team --model deepseek-fast --sample 20
python -m evals.routing --domains wide --split work --variant skills --model claude-sonnet --sample 20
python -m evals.routing --domains base --split holdout --variant skills --model deepseek-fast
```

- `--domains`: `base` или `wide`, обязателен.
- `--model`: `deepseek-fast` (модель соавтора), `claude-sonnet` или `claude-opus` — эталон качества только для
  экзамена; им нужен `ANTHROPIC_EXAM_API_KEY` в `.env`, без него их случаи уходят в «ошибки запуска».

- `--variant team` — команда в режиме `coordinate`, `team-route` — в режиме `route` (один домен на сообщение,
  только для сравнения цены), `skills` — один агент с навыками доменов.
- `--sample N` — первые N случаев части, чтобы измерить цену перед полным прогоном.
- Каждый прогон тратит вызовы модели. Отчёт: `tmp/routing/<время>-<состав>-<часть>-<вариант>-<модель>.json` (всё
  по случаям, с ответами и вызванными инструментами) и `.md` (сводка). В составе `wide` сводка добавляет итоги по
  инструментам: «чужой инструмент» (домен инструмента не среди ожидаемых), «домен без действия» (ожидаемый домен
  выбран, его инструмент не вызван) и инструмент без выбора его домена. Сводка печатается в консоль, в лог идут только id случаев.

Подсчёт без LLM-судьи — отступление от запрета своих счётчиков в evals, разрешённое владельцем 2026-11-08
только для этого экзамена (`openspec/context/07-anti-patterns.md`, п. 23).
