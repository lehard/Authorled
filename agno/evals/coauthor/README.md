# Замер соавтора

Проверяет, как справляется нынешний соавтор — один агент `coauthor` с одним промптом и 14 инструментами — с просьбами
всех доменов широкого состава экзамена маршрутизации (`openspec/specs/coauthor-eval`,
`business-intents/coauthor-quality-eval.md`). В отличие от экзамена, здесь отвечает настоящий соавтор, а оценивается
его действие и ответ.

## Наборы

- **`wide`** — выборка около 150 случаев рабочей части широкого набора экзамена (`../routing/cases/wide-work.toml`)
  по списку `sample.toml`: у каждого id и история, в которой он идёт (`tihaya-voda` или `posledniy-parom`). Отложенная
  часть экзамена не используется. Широкая проверка; базовая линия 2026-11-08 — хороший ответ 65% (97/150).
- **`demo`** — свои случаи по содержимому демо-историй: `cases/demo-work.toml` (70) и `cases/demo-holdout.toml` (30),
  около 20 из них «такого нет» (намеренно про отсутствующее). Исправления соавтора подбираются на рабочей части;
  отложенная прогоняется один раз в конце, по ней в отчёте только сводка. Третья часть `cases/demo-checks.toml`
  (`--part checks`, 8) — проверки наставника из `web/src/screens/project/chat/checks.ts` над выделенной сценой 6
  «Тихой воды» (поле случая `open = { scene = 6 }`: открыт текст сценария, сцена выделена, контекст как в
  `docContext.ts`); правило «все домены и разделы» к ней не относится. Четвёртая часть `cases/demo-docs.toml`
  (`--part docs`) — задачи кнопки «Соавтор» у логлайна и синопсиса (`web/src/screens/project/chat/docTasks.ts`, в замере
  — `doc_tasks.py`) над открытым документом (`open = { doc = "logline" }` или `{ doc = "synopsis" }`); у случая есть
  `task`, его сообщение — текст просьбы задачи (у «Под заявку» — начинается с него), судья получает строку ожидания
  задачи; правило «все домены и разделы» к ней тоже не относится.

Поля случая `demo` (кроме полей экзамена `id`, `section`, `message`, `expect`, `history`):

- `place` — история случая;
- `action` — `"none"` или список изменяющих инструментов, из которых нужен хотя бы один;
- `mention` — группы основ слов, из каждой группы ответ должен содержать хотя бы одну (без учёта регистра);
- `refs` — что из истории спрашивает случай: `{ kind, name }`, `kind` — `scene` (номер), `character`, `location`,
  `world`, `document` (карточка любого вида), `note`;
- `absent` — о чём спрашивает случай, чего в истории нет;
- `open` — `{ scene = N }` (часть `checks`) или `{ doc = "logline" | "synopsis" }` (часть `docs`);
- `task` — только в части `docs` и там обязателен: id задачи из `doc_tasks.py`.

Загрузка до вызова модели проверяет ссылки по `web/src/data/demo.json` — в драфте, который история открывает
(«Тихая вода» — 7 сцен, «Последний паром» — 6; карточки и заметки из корзины не видны), что `absent` отсутствует, что
`action` — изменяющие инструменты, что id не повторяются между частями и что в каждой части есть все 12 доменов и все
разделы.

## Что делает

- Запускает копию агента `coauthor` (тот же промпт, инструменты, модель `deepseek-fast` и hooks расхода) с сессиями
  в памяти: беседы замера не попадают в сессии AgentOS. Запуск — от имени пользователя замера `coauthor-eval`, в
  беседе его демо-истории, с контекстом чата «открыт документ История», у продолжений — их история.
- Изменения не применяются: изменяющий инструмент ставит запуск на паузу, замер записывает предложенное действие,
  отвечает отказом, как автор, и продолжает запуск, чтобы соавтор дописал ответ. История пользователя замера не
  меняется, кроме журнала расхода.
- Оценивает:
  - **чужое изменение** — изменяющий инструмент, не допустимый ни для одного домена случая (таблица `ALLOWED` в
    `score.py`); чтение не ошибка;
  - в наборе `demo` ещё **действие** («лишнее действие X», «нет ожидаемого действия») и **факт** (группы `mention`) —
    кодом;
  - **ответ** — судья Agno `AgentAsJudgeEval` на `claude-sonnet`: ответил ли на каждую просьбу, опирается ли на
    материалы истории, не утверждает ли несделанного, держит ли роль, коротко ли отказывает не по теме, оговаривает
    ли, что факты мира стоит проверить, отвечает ли по-русски. В наборе `demo` судья получает ожидание случая
    строкой критериев (действие, факты, чего нет в истории). Если в промпте соавтора есть справка о сервисе (раздел
    «О сервисе «Соавтор»» в `SKILL.md`), прогон пишет её в отчёт (`meta.service_help`), а судья видит её как то, что
    соавтор знает о сервисе; без неё верные ответы по справке выглядят выдумкой.
  - **хороший случай** (`demo`) — пройдены действие, факт и судья.

## Запуск

Из `agno/` с активированным `agno/.venv`. Нужны LiteLLM-прокси (`LITELLM_URL` из `.env`), локальная база и
переменные `DB_*` — те же, что экспортирует `./scripts/dev.sh api` (в worktree база — `ai_dev_<worktree>`, а не `ai`):

```sh
export DB_DRIVER=postgresql+psycopg DB_HOST=127.0.0.1 DB_PORT=5432 DB_USER=agentos DB_DATABASE=ai
export DB_PASS=<AGENTOS_DB_PASSWORD из .env>
python -m evals.coauthor setup                                     # один раз: пользователь замера и его демо-истории
python -m evals.coauthor run --set demo --part work --sample 3     # проверить цену
python -m evals.coauthor run --set demo --part work --all --repeat 2
python -m evals.coauthor run --set wide --all
python -m evals.coauthor compare ../tmp/coauthor-eval/<до>.json ../tmp/coauthor-eval/<после>.json
python -m evals.coauthor rejudge ../tmp/coauthor-eval/<отчёт>.json --domain wide-help
```

- `setup` создаёт пользователя `coauthor-eval` (тариф `beta`) и редактора `coauthor-eval-editor` — его аккаунт нужен
  демо-загрузчику для комментариев. Повторный `setup` отказывает: истории уже есть.
- `run` требует набор (`--set`), для `demo` — часть (`--part`), и объём: `--all` или `--sample N`. `--repeat K`
  проходит каждый случай K раз; без флага — один раз. До первого вызова модели проверяет набор, пользователя и цены
  `deepseek-fast` и `claude-sonnet`. Случаи идут по два.
- Отчёт: `tmp/coauthor-eval/<время>.json` (всё по случаям и повторам), `.md` (сводка по доменам и разделам, шум,
  провалы с ответами и причинами, цена) и `<время>-review.md` — 30 случаев, по 2–3 на домен, для чтения владельцем
  (у отложенной части `demo` — без провалов и без этого файла).
- Шум — случаи, чья оценка расходится между повторами. `compare` сравнивает только отчёты одного набора и части:
  разница по доменам и разделам, ставшие хорошими и плохими случаи. Шумный случай сдвигает долю группы не больше чем
  на полслучая, поэтому разница не больше половины шумных случаев помечается «шум». Пишет
  `tmp/coauthor-eval/compare-<до>-<после>.md`. У `wide` один повтор, шум не измерен: по снимкам `demo` разброс
  одного промпта — до 5–8 пунктов.
- `rejudge` заново судит случаи домена по сохранённым в отчёте ответам, со справкой из нынешнего `SKILL.md`, и пишет
  новый отчёт (`meta.rejudged_from`); соавтор не запускается. Запускать сразу после прогона, без правок промпта между
  ними.
- Цена по замеру 2026-11-08: соавтор около 0,19 ₽ на случай, судья около 1,3 ₽ — 150 случаев `wide` около 220 ₽,
  100 случаев `demo` около 150 ₽ за повтор.

## Замер действий

Проверяет то, чего не видит замер качества: доходит ли действие соавтора до ядра после «Разрешить» и ложатся ли
сведения туда, где их ждёт автор (`openspec/specs/coauthor-actions-eval/spec.md`,
`business-intents/coauthor-tool-contracts.md`). Как сравнивать прогоны «до» и «после», результаты первых прогонов и
оставшиеся слабые места — `openspec/changes/archive/2026-11-09-coauthor-tool-contracts/verification.md`.

- **Набор** — `actions.toml`, 64 разговорные просьбы по демо-историям: создать персонажа, локацию, мир, изменить
  карточку (поле, роль, имя), создать и изменить заметку, оставить комментарий, и просьбы без действия. У просьбы
  `id`, `place`, `message`, `expect` (изменяющий инструмент или `"none"`), у создания карточки — `kind`, у изменения —
  `target` (имя карточки или название заметки), у карточек — `fields`: поля, о которых просьба говорит прямо
  (`"a|b"` — достаточно одного), у изменения карточки ещё `role` и `name`. Загрузка до вызова модели проверяет
  инструменты, поля по `core/fields.py` и цели по `web/src/data/demo.json`.
- **Запуск** — для каждой просьбы ядро копирует открытый драфт демо-истории (`create_draft`, имя
  `замер <id> <время>`), соавтор работает в беседе копии от имени пользователя `coauthor-actions-eval`, с сессиями в
  памяти. Каждую паузу замер подтверждает, как чат в режиме `auto`, и продолжает запуск до ответа, не больше 6
  продолжений. Истории идут параллельно, просьбы одной истории — по одной (заметки общие для её драфтов). Заметки
  истории копия драфта не отделяет, поэтому перед прогоном и перед каждой просьбой замер возвращает их к
  демо-состоянию (`demo_notes.py`): демо-заметки получают название, текст и корзину из `demo.json`, остальные уходят
  в корзину. Заметка, которую нельзя сопоставить с демо (переписаны и название, и начало текста, или изменилась
  корзина), останавливает замер. Драфты замера и заметки в корзине остаются в локальной базе пользователя замера.
- **Проверки кодом**, без судьи: отказы ядра «Отказ: …» в изменяющих вызовах; попытки — вызовы ожидаемого
  инструмента до первого успешного (больше двух — провал); ожидаемое действие или отсутствие изменяющих вызовов;
  заполненные ожидаемые поля, роль и имя карточки; «сведения в описании» — поле не заполнено, а `summary` длиннее
  300 знаков; изменения сверх просьбы (другие карточки, заметки, комментарии, предложения правки, любое изменение
  открытого драфта).

```sh
python -m evals.coauthor actions-setup              # один раз: пользователь замера действий и его демо-истории
python -m evals.coauthor actions-run --sample 5     # проверить цену
python -m evals.coauthor actions-run --all
```

- `actions-setup` создаёт `coauthor-actions-eval` (тариф `beta`) и редактора `coauthor-actions-eval-editor`; повтор
  отказывает с ненулевым кодом. Пользователь и истории замера качества не меняются.
- `actions-run` требует `--all` или `--sample N` (первые N просьб набора). Отчёт: `tmp/coauthor-actions/<время>.json`
  и `.md` — коммит кода (и есть ли незакоммиченные правки в `agno/`), доли без отказа, верного действия, заполненных
  полей и прошедших просьб по инструментам и видам, среднее число попыток, провалы с аргументами, ответами ядра и
  ответом соавтора, цена и время.

Свой набор, сводка и проверки действия и факта кодом — второе исключение из запрета своих счётчиков в evals,
разрешённое владельцем 2026-11-08 (`openspec/context/07-anti-patterns.md`, п. 23); судья — инструмент Agno. Замер
действий с проверками кодом входит в то же исключение (владелец, 2026-11-08, `business-intents/coauthor-tool-contracts.md`).
