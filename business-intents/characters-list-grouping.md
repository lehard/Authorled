# Бизнес-интент: персонажи и локации по ролям и поиск в их списке

Статус: решение согласовано с владельцем 2026-11-12; OpenSpec change `characters-list-grouping` создан, реализован и архивирован 2026-11-12 (`openspec/changes/archive/2026-11-12-characters-list-grouping/`). Владелец: lehard. Обновлено: 2026-11-12.
Рамки: мастер-спека `web/workspace` («Экраны документов»: списки персонажей, локаций и миров), макет v2 в духе STARC.

## Why

Когда персонажей много, их список превращается в длинную ленту: главные герои стоят вперемешку с эпизодическими, и нужного приходится искать глазами (наблюдение владельца 2026-11-12).

В других редакторах эту задачу решают так: в STARC и КИТ Сценаристе есть роль персонажа в истории, в Plottr есть категории, по которым список группируется. У нас роль уже есть у персонажа и локации («Главный», «Второстепенный», «Эпизодический»; `core/fields.py`, `web/src/data/profiles.ts`), но список её только показывает меткой и ничего по ней не упорядочивает. Самый дешёвый шаг — группировать по роли то, что уже лежит в данных, и дать поиск по имени прямо в списке.

## What Changes

- Страница «Персонажи» показывает персонажей тремя группами в порядке ролей: «Главные», «Второстепенные», «Эпизодические». У заголовка группы есть число в ней. Пустая группа не показывается.
- Так же устроена страница «Локации»: «Основные», «Второстепенные», «Эпизодические».
- Группа «Эпизодические» свёрнута, если на странице есть хотя бы одна другая группа, и раскрывается кликом по заголовку. Если других групп нет, она раскрыта. Состояние раскрытия не запоминается.
- Внутри группы порядок тот же, что сейчас в списке.
- Метка роли у строки убирается: роль видна по группе.
- Над списком стоит поле «Поиск по имени». Оно фильтрует строки по имени и по строке описания без учёта регистра и разницы «ё» и «е», сразу по мере ввода. Пока в поле есть текст, группы без совпадений скрыты, а «Эпизодические» раскрыты. Esc и крестик очищают поле. Если совпадений нет, вместо списка написано «Ничего не нашлось».
- Страница «Миры» не меняется: у мира нет роли. Поиск на ней тоже не появляется.

## Scope

- `web/src/screens/project/docs/GroupDoc.tsx`: группы по роли, сворачивание эпизодических, поле поиска.
- Подписи групп во множественном числе рядом с `ROLES` в `web/src/data/profiles.ts`.
- Спека `web/workspace`, требование о списках персонажей, локаций и миров: группы, сворачивание и поиск со сценариями.
- Проверка в браузере на демо-истории: широкий экран и 375 px, светлая, сепия и тёмная темы.

## Non-goals

- Группы по роли в дереве навигатора: дерево остаётся плоским, а имя там уже находит «Поиск по истории».
- Свои теги, папки и группы персонажей («семья», «полиция»).
- Число сцен и реплик персонажа и сортировка по нему: следующий шаг, отдельным намерением.
- Фильтр «кто в этой сцене» и граф связей.
- Новые роли и изменение данных: ядро, API и миграции не меняются.

## Constraints (из контекст-пака)

- Только структурированные сущности, без методологии в интерфейсе: группы — это роль, которая уже есть в профиле.
- Цвета только из семантических токенов дизайн-системы (`./web/scripts/check_web_tokens.sh`).
- Роль, которой нет в `ROLES`, по-прежнему даёт ошибку, а не попадает в какую-то группу молча.
- Работает одинаково для источников данных `api` и `fixtures`.

## Acceptance criteria

- На демо-истории страница «Персонажи» показывает группы в порядке «Главные», «Второстепенные», «Эпизодические» с числами; «Эпизодические» свёрнута и раскрывается кликом.
- Смена роли в профиле персонажа переносит его в другую группу без перезагрузки.
- Ввод «вер» оставляет только персонажей, у которых «вер» есть в имени или строке описания; «ё» и «е» не различаются; Esc возвращает весь список.
- Запрос без совпадений показывает «Ничего не нашлось».
- На ширине 375 px страница без горизонтальной прокрутки.
- `./scripts/validate.sh` проходит.

## Risks

- **Персонаж «пропал».** Эпизодического персонажа не видно в свёрнутой группе, и автор может решить, что его нет. Число у заголовка группы и раскрытие при поиске это смягчают.
- **Роль по умолчанию.** Персонаж, добавленный кнопкой, получает роль «Второстепенный», а найденный в тексте («Найти всех персонажей в тексте») — «Эпизодический» (`web/src/screens/project/entityActions.ts`). После поиска по тексту главные герои окажутся в свёрнутой группе, пока автор не поправит роль. Группировка честно это покажет; менять роли по умолчанию здесь не предлагается.
