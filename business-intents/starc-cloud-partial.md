# Бизнес-интент: импорт облачного проекта STARC с пропуском пустых записей

Статус: дефект найден владельцем 2026-11-12 на настоящем файле; решение согласовано 2026-11-12. Change `starc-cloud-partial` создан, выполнен и архивирован 2026-11-12 (`openspec/changes/archive/2026-11-12-starc-cloud-partial/`). Владелец: lehard. Обновлено: 2026-11-12.
Рамки: мастер-спека `api/story-import` (требования «Отказ импорта STARC», «Персонажи и локации из импорта», «Новая история из файла», «Замена текста импортом»), диалог «Новая история» и импорт в редакторе.

## Why

Файл облачного проекта STARC («Выбор. Драфт 3. Облако [1899].starc») не импортируется: «В файле несколько сценариев, а импортировать можно ровно один». В структуре проекта перечислены десять сценариев «Выбор 1…10», но в самом файле лежит содержимое только «Выбор 1» (текст, титул, синопсис). У девяти других и у одной локации («КОЛИБА ДАРЬЯНА ПОЗДНИЙ ВЕЧЕР») есть только запись в структуре, документа в базе файла нет: облачный STARC не выгрузил их в этот файл. Проба 2026-11-12: если не учитывать записи без документа, «Выбор 1» разбирается целиком — 1182 абзаца, 46 сцен, 93 персонажа, 86 локаций.

Автор видит отказ и думает, что импорт сломан, хотя в файле просто нет остальных данных.

## What Changes

- Запись структуры STARC, у которой в файле нет своего документа, импорт считает отсутствующей в файле: сценарий без текста в файле, персонаж или локация без профиля, их не переносит.
- Правило «ровно один сценарий» относится к сценариям, текст которых есть в файле. Ноль таких — отказ, как сейчас («В файле нет сценария»); два и больше — отказ, как сейчас.
- Импорт возвращает список пропущенного с причиной, и интерфейс показывает его автору после успешного импорта (в диалоге «Новая история» и при импорте в редакторе). Текст объясняет, что это данные, которых нет в самом файле STARC (например, облачный проект выгружен не полностью), а не ошибка импорта; называет пропущенное по именам: «В файле STARC нет содержимого сценариев «Выбор 2», …, «Выбор 10» и профиля локации «…». Их не было в файле — так бывает с облачными проектами STARC. Чтобы перенести их, выгрузите проект из STARC целиком». Точный текст — в design.
- Пропущенное по этой причине не молча: каждое пропущенное имя есть в ответе и на экране.

## Scope

- `agno/core/importers/starc.py`: учёт записей без документа, список пропущенного.
- Результат разбора рукописи и ответы обоих путей импорта (новая история из файла, замена текста импортом) — с полем пропущенного; для других форматов оно пустое.
- `web/`: показ пропущенного после импорта (диалог «Новая история», импорт в редакторе).
- Спека `api/story-import`: изменить требование отказа STARC («частичного импорта MUST NOT быть» — теперь допускается пропуск записей, которых нет в файле, с предупреждением); сценарий на облачный проект.
- Тест на маленьком синтетическом `.starc`: два сценария в структуре, текст у одного, локация без профиля.

## Non-goals

- Выбор одного из нескольких сценариев, текст которых есть в файле (отказ остаётся).
- Скачивание недостающего из облака STARC.
- Пропуск чего-либо другого: неизвестные элементы, типы абзацев и роли по-прежнему дают отказ целиком.
- Предупреждения для FDX, Fountain, DOCX, TXT.

## Constraints (из контекст-пака)

- Без запасных путей: пропускается только запись без документа в файле, и только с явным списком автору; всё остальное неизвестное или битое — отказ `422`, как сейчас.
- Корзина проекта по-прежнему не импортируется и в список пропущенного не попадает.
- Файл читается только на чтение.

## Acceptance criteria

- Файл «Выбор. Драфт 3. Облако [1899].starc» импортируется новой историей: текст «Выбор 1», 93 персонажа, 86 локаций; автор видит предупреждение с девятью сценариями и одной локацией и причиной.
- Тот же файл через импорт в редакторе даёт тот же текст и то же предупреждение.
- Файл, где текст есть у двух сценариев, по-прежнему отказ «несколько сценариев».
- Файл, где ни у одного сценария нет текста, — отказ «нет сценария».
- Обычный STARC без пустых записей — импорт без предупреждения, как сейчас.
- `./scripts/dev.sh test`, `./scripts/validate.sh` проходят.

## Risks

- Если запись без документа значит не «не выгружено», а повреждённый файл, автор получит неполную историю; список пропущенного это видно показывает.
- Реальный пример облачного файла один; другие версии STARC могут хранить облачные проекты иначе.
