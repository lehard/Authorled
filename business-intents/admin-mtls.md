# Бизнес-интент: админка Authentik открывается только по клиентскому сертификату с компьютера владельца

Статус: решения согласованы с владельцем 2026-11-09; OpenSpec change `admin-mtls` выполнен и архивирован 2026-11-09 (`openspec/changes/archive/2026-11-09-admin-mtls/`). Владелец: lehard. Обновлено: 2026-11-09.
Рамки: мастер-спека `auth` («Интерфейс Authentik», «Конфигурация из blueprints»), мастер-спека `runtime` («Обратный прокси»), `deploy/Caddyfile`, `auth/blueprints/`, проверка развёрнутого сервера; связанное решение: `business-intents/auth-admin-ui.md` (в его Non-goals стояли «ограничение доступа к админке по IP или отдельный домен для неё», этот интент снимает это ограничение).

## Why

Админка Authentik (`https://auth.soavtor.app/if/admin/`) открыта всему интернету. Её защищают только пароль `akadmin` и код на почту `AUTHENTIK_BOOTSTRAP_EMAIL`. Через админку меняются вход, регистрация, пользователи и группы, в том числе группа `admins` с административными правами в API AgentOS. Владелец хочет, чтобы в админку можно было попасть только с его компьютера по сертификату mTLS (владелец, 2026-11-09).

Повесить требование сертификата на путь `/if/admin/` у `auth.soavtor.app` нельзя. Сертификат запрашивается на уровне TLS-соединения, до пути, и браузеры начнут показывать окно выбора сертификата обычным авторам при входе. Поэтому для админки нужен отдельный адрес.

## What Changes

1. **Отдельный адрес админки `admin.soavtor.app`.** В `deploy/Caddyfile` появляется сайт `admin.soavtor.app`. Он принимает соединение только с клиентским сертификатом, который подписан удостоверяющим центром владельца (Caddy `client_auth`, режим `require_and_verify`). Без такого сертификата TLS-соединение отклоняется, и HTTP-ответа нет. За этим адресом находится тот же сервер Authentik (`127.0.0.1:9000`).
2. **На публичных адресах админки нет.** На `auth.soavtor.app` пути `/if/admin/` отвечают 404. Вход, регистрация, сброс пароля, профиль и выход для авторов работают как сейчас, в том числе через прокси `app.soavtor.app`.
3. **Суперпользователь входит только через `admin.soavtor.app`.** Поток входа продукта в blueprints отказывает пользователю с `is_superuser` (сейчас это `akadmin` и группа `admins`), если вход идёт не через адрес админки. Отказ даётся понятным сообщением. Без этого правила сертификат закрывал бы только экран админки, а её API (`/api/v3/…`) оставался бы доступен с публичного адреса тому, кто знает пароль и получает коды на почту. Как Authentik отличит адрес админки (отдельный бренд `admin.soavtor.app` с тем же потоком входа или метка от Caddy, которую публичные сайты срезают), решает дизайн change. Подменить признак снаружи должно быть нельзя.
4. **Свой удостоверяющий центр на компьютере владельца.** Скрипт в репозитории (рабочее имя `scripts/admin_cert.sh`) делает три вещи:
   - создаёт ключ и сертификат удостоверяющего центра;
   - выпускает клиентский сертификат сроком на 2 года;
   - упаковывает его в `.p12` для импорта в Связку ключей macOS.
   Ключи и `.p12` лежат только на Mac владельца, в `~/.config/authorled/admin-ca/`. Скрипт не перезаписывает существующий удостоверяющий центр молча. На сервер попадает только публичный сертификат удостоверяющего центра: `/etc/authorled/admin-client-ca.pem`. Caddy без этого файла не стартует, запасного режима без сертификата нет.
5. **DNS.** A-запись `admin.soavtor.app` указывает на IP сервера `authorled` (Reg.ru, зона `soavtor.app`).
6. **Проверка после релиза.** Скрипт проверки развёрнутого сервера убеждается, что `admin.soavtor.app` без клиентского сертификата отклоняет соединение, а `https://auth.soavtor.app/if/admin/` отвечает 404. Проверку с сертификатом владелец делает с Mac, порядок шагов описан в README.
7. **Памятка в README.** Раздел «Админка Authentik» получает новый адрес и шаги: как выпустить сертификат, импортировать `.p12`, положить сертификат удостоверяющего центра на сервер, перевыпустить сертификат при потере Mac или когда истекает срок.

## Scope

- `deploy/Caddyfile`: сайт `admin.soavtor.app` с `client_auth`, 404 на `/if/admin/` у `auth.soavtor.app`.
- `auth/blueprints/`: правило «суперпользователь входит только через адрес админки», а если дизайн его выберет, ещё и бренд адреса админки.
- `scripts/admin_cert.sh`: выпуск удостоверяющего центра и клиентского сертификата.
- Скрипт проверки развёрнутого сервера (`deploy/check_site.sh` или соседний) и `deploy/deploy.sh`, если для релиза нужно проверять файл удостоверяющего центра.
- README, `.agents/skills/deploy-platform` (новый файл в `/etc/authorled/`, DNS, порядок первого включения).
- Требования мастер-спек: `auth` («Интерфейс Authentik»: адрес админки, вход суперпользователя), `runtime` («Обратный прокси»: сайт админки и его сертификат).
- Локальная разработка: админка на `localhost:9000` остаётся без сертификата. Правило входа суперпользователя на локальном стенде либо отключается явной настройкой окружения, либо адрес админки локально равен адресу Authentik; выбор за дизайном. Молчаливого обхода быть не должно.

## Non-goals

- mTLS для интерфейса AgentOS (os.agno.com) и для API `/os/`: они работают через тот же API, что и продукт.
- Клиентские сертификаты для авторов или других людей. Сертификат один, для компьютера владельца.
- Списки отзыва (CRL, OCSP). Отзыв делается перевыпуском удостоверяющего центра и заменой файла на сервере.
- Ограничение доступа к админке по IP.
- Своя админка в веб-фронтенде продукта.
- Второй администратор Authentik.

## Constraints (из контекст-пака)

- Снаружи открыты только порты 22, 80 и 443. Authentik по-прежнему слушает только `127.0.0.1`.
- `/etc/caddy/Caddyfile` только импортирует `deploy/Caddyfile`. Сайт админки описывается в файле из репозитория, путь к сертификату удостоверяющего центра лежит в `/etc/authorled/`.
- Нет запасных путей: без файла удостоверяющего центра Caddy и релиз падают с ошибкой, а не открывают админку без сертификата.
- Секреты не попадают в репозиторий и в чат. Ключ удостоверяющего центра и клиентский ключ не покидают Mac владельца. Публичный сертификат удостоверяющего центра секретом не считается, но тоже хранится в `/etc/authorled/`, а не в репозитории.
- Настройки Authentik живут только в `auth/` (мастер-спека `auth`, «Граница модуля»). Поток входа привязан к бренду `AUTH_BRAND_DOMAIN` и не зависит от других blueprints.
- Изменения на сервере (файл удостоверяющего центра, DNS) делаются только с подтверждения владельца в чате. Код выкатывается только релизом из `main`.

## Acceptance criteria

- С Mac владельца с импортированным сертификатом `https://admin.soavtor.app/if/admin/` открывает вход, и `akadmin` попадает в админку после пароля и кода.
- Без клиентского сертификата, или с сертификатом, подписанным другим удостоверяющим центром, соединение с `admin.soavtor.app` отклоняется на уровне TLS.
- `https://auth.soavtor.app/if/admin/` отвечает 404.
- `akadmin`, который входит через `auth.soavtor.app` или `app.soavtor.app`, получает отказ после ввода почты или имени. Сессия не создаётся.
- Автор из `screenwriters` входит, регистрируется, сбрасывает пароль и выходит через `app.soavtor.app` как раньше. Окно выбора сертификата у него не появляется.
- Признак адреса админки нельзя подставить запросом к публичным адресам: запрос с поддельным заголовком или Host к `auth.soavtor.app` вход суперпользователю не открывает.
- Без `/etc/authorled/admin-client-ca.pem` релиз завершается ошибкой с именем файла.
- `scripts/admin_cert.sh` на чистом Mac выпускает удостоверяющий центр и `.p12`, а при существующем удостоверяющем центре отказывается его перезаписывать без явного флага.
- Скрипт проверки развёрнутого сервера проходит, `./scripts/validate.sh` и `./scripts/auth_check.sh` проходят.

## Risks

- Потеря Mac или ключа означает потерю доступа к админке до перевыпуска. Восстановление: новый удостоверяющий центр на другом компьютере, замена файла на сервере по SSH. Если потерян ещё и доступ к почте кодов, действует `ak` на сервере.
- Cookie сессии Authentik общая для `.soavtor.app` (`AUTHENTIK_COOKIE_DOMAIN`). Сессия `akadmin`, открытая через адрес админки, действует и на `auth.soavtor.app`, так что API админки доступен из того же браузера и без сертификата. Это допустимо: сессия живёт только в браузере владельца. Сократить срок сессии суперпользователя можно отдельным решением.
- Сессии `akadmin`, открытые до релиза через публичный адрес, после релиза не закрываются сами: их нужно завершить в админке.
- Срок клиентского сертификата 2 года. Если о нём забыть, админка закроется. Срок пишется в README и в вывод скрипта.
- Бренд Authentik выбирается по Host. Если для адреса админки брендов не будет, Authentik может показать поток входа по умолчанию вместо потока продукта. Дизайн change должен это закрыть.
- Safari и Chrome по-разному показывают окно выбора клиентского сертификата. На Mac владельца это проверяется вручную.

## Open Questions

- Как Authentik отличает адрес админки: отдельный бренд `admin.soavtor.app` или метка от Caddy. Решает дизайн change, выбранный вариант нельзя подделать снаружи.
- Нужен ли второй клиентский сертификат (например, для телефона). Сейчас решено: не нужен.
