# Бизнес-интент: `dev.sh` безопасно работает из worktree

Статус: решения согласованы с владельцем 2026-11-10 («главное проще, надёжнее, без реинжиниринга и костылей»); change `worktree-dev-sh` спланирован, реализован, проверен и архивирован 2026-11-10 (`openspec/changes/archive/2026-11-10-worktree-dev-sh/`, проверки — `verification.md` там; команды из основной папки на стенде не запускались); при планировании добавлена команда `./scripts/dev.sh up` — запуск стенда для API на хосте из основной папки, без `agentos-api`. Владелец: lehard. Обновлено: 2026-11-10.
Рамки: спека `runtime` («`scripts/dev.sh`»), спека `core/database` («Тесты хранения на чистой базе»), `CLAUDE.md` / `AGENTS.md` («Parallel sessions», «Local development»), `openspec/context/07-anti-patterns.md` (п. 26: fallback-и). Продукт не меняется.

## Why

Несколько сессий работают параллельно, каждая в своём worktree под `.claude/worktrees/`, и делят один локальный стенд: Docker, `agentos-db` с базами `ai` и `ai_test`, порты 8000 и 5173. Стенд запущен из основной папки, проект Compose `authorled` (по имени папки: в `compose.yaml` нет `name:`). Сейчас порядок работы с `ai_test` сессии согласуют вручную, сообщениями. Найдено 2026-11-09 и 2026-11-10:

1. **Из worktree пересоздаются общие контейнеры.** Чтобы попасть в стенд, сессии запускают compose из worktree с проектом `authorled`. Тогда `up` и `run` берут пути из worktree: `litellm`, `authentik-server` и `authentik-db-init` подключают файлы папки checkout, и при `up` compose пересоздаёт их с путями ветки. `run --rm agentos-db-init` без `--no-deps` заодно поднимает `authentik-db-init`. На 2026-11-10 `authentik-db-init` и `agentos-phoenix` числятся созданными из worktree (`usage-limits-0a1ec9`, `agent-tracing`). Без проекта `authorled` команды из worktree попадают в пустой проект по имени папки и падают или заводят свой стенд: остались тома `agent-tracing_pgdata`, `first-load-release_pgdata`, `usage-limits-0a1ec9_pgdata`.
2. **Одна `ai_test` на всех.** `dev.sh test` всегда делает `DROP DATABASE ai_test WITH (FORCE)`, а `agno/tests/conftest.py` пускает тесты только в `ai_test`. Параллельные прогоны ломают друг друга: таблицы пропадают посреди прогона, deadlock, миграции чужой ветки (`0013_story_cover_colors`). Одна сессия завела себе отдельный Postgres вне compose (`story-materials-test-db`, порт 55432).
3. **Миграции ветки попадают в общую `ai`.** `run agentos-migrate` подключает код той папки, из которой запущен (`..:/app`), и накатывает в `ai` миграции ветки. После этого основная папка и другие ветки встречают в `ai` неизвестную им ревизию.
4. **`.env` в worktree отстаёт.** Его копируют один раз; compose требует все переменные, и интерполяция падает. На 2026-11-10 в `project-search` и `story-cover-colors` нет `AUTH_ADMIN_DOMAIN`, в `payments-tochka-a9b7da` нет `ANTHROPIC_EXAM_API_KEY`; в основном `.env` есть все ключи `example.env`.

## What Changes

Одно правило: **стенд принадлежит основной папке, а worktree пользуется им, ничего в нём не перезапуская, и пишет только в свои базы.**

1. **Запускает, останавливает и сбрасывает стенд только основная папка.** `dev.sh up`, `db`, `stop` и `reset-db` из worktree завершаются кодом 1 с сообщением «запустите из основной папки <путь>».
2. **Остальные команды стенд не поднимают и не останавливают** (`test`, `migrate`, `api`, `seed`, `psql`, `auth-users`), откуда бы их ни запустили. Они обращаются к проекту Compose `authorled` явно и требуют, чтобы нужные сервисы уже работали; если сервис не запущен, команда завершается кодом 1 с сообщением, что стенд запускается из основной папки командой `./scripts/dev.sh up` (сервисы стенда для API на хосте, без `agentos-api`). Разовые шаги (`agentos-db-init`, миграции, выгрузка ключей Authentik) запускаются без подъёма зависимостей. `name:` в `compose.yaml` не добавляется (решение 2026-11-08 остаётся): ручной `docker compose up` из worktree по-прежнему падает на занятых именах контейнеров, а не пересоздаёт общие.
3. **Свои базы у worktree.** Имя берётся из имени папки worktree (приводится к допустимому имени базы):
   - `test`: `ai_test_<worktree>`, пересоздаётся перед каждым прогоном, как сейчас `ai_test`;
   - `migrate`, `api`, `seed`: `ai_dev_<worktree>`; если базы нет, `dev.sh` создаёт её и готовит тем же шагом инициализации, что и `ai`, затем накатывает миграции ветки;
   - основная папка работает как сейчас: `ai_test` и `ai`.
   `conftest.py` пускает тесты только в `ai_test` или `ai_test_<…>`. Пользователи Authentik общие (схема `authentik` в `ai`), поэтому вход и `auth-users` работают как сейчас; демо-истории в своей базе — через `dev.sh seed`.
4. **API на хосте один, на порту 8000.** `dev.sh api` больше не останавливает контейнер `agentos-api` сам: если порт 8000 занят, команда завершается кодом 1 и называет, кто его держит (контейнер `agentos-api` или процесс), — остановку решает владелец.
5. **`.env` в worktree — ссылка на `.env` основной папки.** Если в worktree `.env` обычный файл или ссылка на другой файл, `dev.sh` завершается кодом 1 и печатает готовую команду `ln -sf <основная папка>/.env .env`. Отдельной сверки ключей с `example.env` нет: недостающую переменную уже называет compose (`${VAR:?...}`); новую переменную ветки владелец добавляет в основной `.env`.
6. **Документы.** Спека `runtime` («`scripts/dev.sh`»): правило о стенде основной папки, явный проект `authorled` вместо запрета выбирать проект, базы worktree, порт 8000, ссылка `.env`. Спека `core/database`: тестовая база `ai_test` или `ai_test_<worktree>`. `AGENTS.md` / `CLAUDE.md`, «Parallel sessions» и «Local development»: те же правила одной-двумя строками.

## Scope

- `scripts/dev.sh`, `agno/tests/conftest.py`.
- Спеки `runtime` и `core/database`; `AGENTS.md` / `CLAUDE.md`.
- Проверка: из worktree `test` идёт в своей базе, пока в основной папке идёт свой `test`; `migrate` и `api` из worktree не меняют `ai`; `db`, `stop`, `reset-db` из worktree отказывают; у контейнеров стенда после этих команд не меняются время создания и рабочий каталог; на работающем стенде из основной папки команды ведут себя как раньше, кроме остановки `agentos-api`. Результаты — в `tmp/VERIFY.md`.

## Non-goals

- Несколько API на хосте одновременно, другие порты для worktree, отдельный фронтенд на worktree.
- `name:` в `compose.yaml`, свой стенд или свой Postgres на каждый worktree.
- Автоматическая уборка баз `ai_test_<…>` и `ai_dev_<…>` удалённых worktree; их удаляет владелец, когда нужно.
- Сверка `.env` с `example.env` в `dev.sh`.
- Уборка уже оставшихся контейнера `story-materials-test-db` и томов `*_pgdata` других стендов: отдельно, с согласия владельца.

## Constraints (из контекст-пака)

- Без fallback: нет стенда, занят порт, `.env` не ссылка — явная ошибка с причиной и что сделать; `dev.sh` не выбирает другую базу, проект или порт сам и не подставляет значения.
- Контейнеры стенда, `reset-db` и `docker compose down` — только с согласия владельца; новые команды их не трогают.
- Основная база `ai` меняется только командами из основной папки.
- Секреты из `.env` в вывод не попадают.

## Acceptance criteria

- Два `./scripts/dev.sh test` одновременно — из основной папки и из worktree (или из двух worktree) — проходят, каждый в своей базе, не мешая друг другу.
- `./scripts/dev.sh migrate` и `api` из worktree с новой миграцией ветки: в `ai` ревизия не меняется, миграция применена в `ai_dev_<worktree>`.
- После `test`, `migrate`, `api` из worktree у контейнеров стенда то же время создания и тот же рабочий каталог (основная папка).
- `db`, `stop`, `reset-db` из worktree завершаются кодом 1 с путём основной папки; стенд не меняется.
- Стенд не запущен: `test` из любой папки завершается кодом 1 с сообщением, как его запустить.
- Порт 8000 занят: `api` завершается кодом 1 и называет, кто его держит; контейнер `agentos-api` не останавливается.
- `.env` в worktree — обычный файл: любая команда `dev.sh` завершается кодом 1 и печатает команду `ln -sf`.

## Risks

- **Параллельная подготовка баз.** `agno/db/init.sql` при каждом запуске меняет роль `agentos` (`ALTER ROLE ... PASSWORD`), а роль общая для всех баз; две сессии одновременно могут получить «tuple concurrently updated». Смягчение решается в design.md самым простым способом, который не прячет ошибку.
- **Длинные имена worktree.** Имя базы в PostgreSQL до 63 байт; слишком длинное или недопустимое имя — явная ошибка, а не обрезка втихую, если design.md не найдёт однозначного правила.
- **Привычка владельца.** `dev.sh api` из основной папки больше не останавливает `agentos-api` сам; сообщение называет команду.
