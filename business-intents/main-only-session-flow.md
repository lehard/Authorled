Рамки: `CLAUDE.md` / `AGENTS.md` (разделы «Parallel sessions», «OpenSpec is mandatory»), README («Deploy by release»), скиллы `openspec-verify-change` и `openspec-archive-change` в `.agents/skills/`, `.claude/settings.json`. Продукт и ядро не меняются.

## Why

Работа идёт по двум конкурирующим линиям, и они то и дело обгоняют друг друга. Состояние на 2026-11-09:

1. **Основная папка не на main.** `/Users/Shared/Workspace/Authorled` стоит на `feature/openspec`: 5 коммитов, которых нет в `origin/main`; в `origin/main` 64 коммита, которых нет в этой ветке; 109 изменённых и 58 новых файлов без коммита. Локальная `main` отстаёт от `origin/main` на 34 коммита. Релизы выходят только из `main`, поэтому всё из `feature/openspec` приходится переносить отдельными PR (`claude/merge-feature-openspec`, `claude/usage-limits-0a1ec9` — «Merge feature/openspec…»).
2. **Worktree не убираются.** В `.claude/worktrees/` шесть штук: пять чистых (остатки законченных сессий), в `coauthor-mentor-checks` 46 файлов без коммита, `usage-limits-0a1ec9` в detached HEAD. Автоархивация сессий после слияния PR в приложении выключена; на GitHub `delete_branch_on_merge = false`.
3. **Одно изменение — три ветки.** Verify и archive делаются отдельными сессиями после основной работы: `domain-soavtor-app`, `-archive`, `-close`; `rename-soavtor` и `-archive`; `site-deploy` и `-archive`. Около 15 локальных веток `claude/*`.
4. **Verify и archive забываются.** По `CLAUDE.md` их запускает владелец; на деле он помнит об этом не всегда, и законченные изменения висят в `openspec/changes/`.

## What Changes

1. **Одна длинная ветка — `main`.** Основная папка всегда стоит на `main`, в ней никто не правит и не коммитит; она только для чтения и `git pull`. Каждая сессия работает в своём worktree от `origin/main` в ветке `claude/<change>` и вливается в `main` через PR. `feature/openspec` один раз разбирается (коммиты и файлы без коммита разносятся по PR в `main` или выбрасываются по решению владельца) и удаляется.
2. **Одна сессия ведёт одно изменение до конца.** Apply, verify и archive — в одной ветке и одном PR; веток `-archive` и `-close` больше нет. Исключение — проверка на сервере после релиза: она возможна только после релиза и идёт отдельным маленьким PR.
3. **Verify и archive сессия делает сама.** Когда все задачи `tasks.md` отмечены, сессия без отдельной команды владельца:
   - запускает verify (скилл `openspec-verify-change`);
   - если критичных замечаний нет — archive (скилл `openspec-archive-change`, с синхронизацией спек), `./scripts/validate.sh`, `git diff --check`, коммит своих файлов, PR и его слияние (`gh pr merge` уже разрешён в `.claude/settings.local.json`);
   - если есть критичные замечания или проверки падают — останавливается и показывает их владельцу; ничего не архивирует и не вливает.
   Propose, update и начало apply по-прежнему запускает владелец.
4. **Уборка после слияния.** В приложении включается «Auto-archive sessions when their pull request closes»: сессия архивируется после слияния PR, её worktree удаляется (worktree с файлами без коммита остаётся на диске). На GitHub включается «Automatically delete head branches». Существующие старые worktree и слитые локальные ветки убираются один раз вручную, по списку, с подтверждением владельца.
5. **Контроль — два коротких хука в `.claude/settings.json`** (скрипты по 15–20 строк в `scripts/`):
   - при старте сессии: предупреждение, если сессия открыта в основной папке, а не в worktree, или основная папка не на `main`;
   - при остановке: если в `openspec/changes/` есть изменение этой ветки, у которого все задачи отмечены, но оно не заархивировано, сессия один раз получает напоминание закончить verify и archive (повторно в том же ходе не блокирует, `stop_hook_active`).
6. **Документы процесса.** `CLAUDE.md`/`AGENTS.md`: правило «verify и archive запускает владелец» заменяется пунктом 3; в «Parallel sessions» — пункт 1 и правило «основная папка только на main». README и скиллы `setup-platform`/`deploy-platform` — только там, где упоминают рабочие ветки.

## Scope

- `CLAUDE.md`, `AGENTS.md`, README (при необходимости).
- `.claude/settings.json`: хуки SessionStart и Stop; два скрипта в `scripts/`.
- Настройка приложения `auto_archive_on_pr_close` и настройка репозитория GitHub `delete_branch_on_merge` (меняются с подтверждением владельца, не кодом).
- Разовая уборка: `feature/openspec`, старые worktree и слитые ветки.

## Non-goals

- Свой оркестратор сессий, очередь изменений, автоматический запуск propose или apply.
- Автоматический релиз и деплой после слияния: релиз по-прежнему создаёт владелец (`gh release create … --target main`).
- Защита ветки `main` правилами GitHub и обязательные проверки CI перед слиянием — можно позже, отдельно.
- Автоматическая проверка на сервере после релиза.

## Constraints

- Без fallback: хук не «чинит» состояние сам (не переключает ветки, не архивирует), а только сообщает; сессия при падении verify или `validate.sh` останавливается, а не вливает «как есть».
- Правила «Parallel sessions» остаются: чужие файлы не трогать, никаких `git stash`, `reset --hard`, `add -A`; коммит только своих файлов по путям.
- Одна сессия — одно OpenSpec-изменение.
- Слияние PR — только после зелёного `validate.sh` и verify без критичных замечаний.

## Acceptance criteria

- Основная папка на `main` без файлов без коммита; ветки `feature/openspec` нет ни локально, ни на GitHub.
- В `.claude/worktrees/` только worktree работающих сессий.
- Следующее изменение после этого проходит apply → verify → archive → PR → слияние в одной сессии без команды владельца на verify и archive; после слияния его сессия архивирована, worktree и ветка удалены.
- Хук при старте предупреждает в основной папке и молчит в worktree; хук при остановке напоминает о незаархивированном законченном изменении и молчит, когда его нет.

## Risks

- **Сессия вольёт неготовое.** verify — это проверка моделью, она может пропустить ошибку. → Слияние только после `validate.sh` и тестов, которые требует change; критичные замечания останавливают; релиз всё равно делает владелец.
- **Хук остановки мешает обычным ходам.** → Он срабатывает только при «все задачи отмечены, нет архива» и только один раз за ход.
- **Файлы без коммита в `feature/openspec` и `coauthor-mentor-checks` принадлежат другим сессиям.** → Разбор только вместе с владельцем, по списку; ничего не удалять без его решения.
- **Слияние параллельных PR в одни и те же спеки** (archive синхронизирует `openspec/specs/`). → Перед слиянием ветка обновляется от `origin/main`; конфликт — остановка и вопрос владельцу.

## Open Questions

1. **Что делать с содержимым `feature/openspec`** (5 коммитов и 167 файлов без коммита). Рекомендую: сначала список по изменениям OpenSpec, к которым они относятся, затем по PR в `main` на каждое; что не относится ни к одному — показать владельцу.
2. **Сливать PR сессия сама или оставлять владельцу кнопку.** Рекомендую сливать сама при зелёных проверках: владелец всё равно контролирует выход на прод через релиз.
3. **Проверка на сервере после релиза.** Рекомендую оставить её отдельным маленьким PR от сессии, которая делает релиз, а не возвращаться в закрытую ветку.
