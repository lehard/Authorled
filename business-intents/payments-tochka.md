# Бизнес-интент: платная подписка через интернет-эквайринг Точки

Статус: черновик 2026-11-07; часть решений согласована, остальные ждут владельца (см. Open Questions). Делается после `usage-limits`: подписка выдаёт тариф с лимитом из того интента. Владелец: lehard. Обновлено: 2026-11-07.
Рамки: ADR-002 (свои маршруты без LLM), `openspec/context/05-security-and-compliance.md` (ПДн, секреты), мастер-спеки `core/database`, `api/me`, `web/workspace`; интент `usage-limits`.

## Why

Когда продукт начнут продавать, нужен приём оплаты с чеками по 54-ФЗ. Расчётный счёт владельца открыт в Точке (владелец, 2026-11-07). У Точки есть API интернет-эквайринга: ссылки на оплату, подписки с регулярным списанием и чеки, которые оформляет партнёр Точки. Своя онлайн-касса не нужна.

## What Changes

1. **Месячная подписка.** Пользователь оформляет платный тариф, а Точка каждый месяц списывает оплату с сохранённой карты (метод «подписка с фискализацией»). Чек приходит на почту аккаунта.
2. **Платные тарифы в той же модели.** Тарифы, подписки, периоды и лимит уже есть после `usage-limits`. Этот интент добавляет в файл тарифов платные тарифы (цена больше 0, «можно купить») и второй источник подписки — оплату Точкой. Устройство тарифов, подписок и проверки лимита не меняется.
3. **Страница «Тариф» в настройках:** текущий тариф, использованная доля лимита, дата следующего списания, кнопки «Оформить» и «Отменить подписку».
4. **Оплата.** «Оформить» → ядро создаёт подписку в Точке и получает ссылку → пользователь платит на странице Точки → возвращается на сайт, где страница ждёт подтверждения.
5. **Подтверждение.** Точка присылает уведомление (вебхук `acquiringInternetPayment`) на свой маршрут ядра. Ядро не верит телу уведомления на слово: оно запрашивает статус операции у API Точки и только после ответа «оплачено» переводит подписку пользователя на оплаченный тариф или продлевает её на следующий период. Повторное уведомление подписку второй раз не продлевает.
6. **Отмена.** Пользователь отменяет подписку, ядро отключает автосписание в Точке, и тариф действует до конца оплаченного периода. Потом пользователь переходит на бесплатный тариф.
7. **Неудачное списание.** Платная подписка не продлевается и в конце оплаченного периода переходит на бесплатный тариф, на странице «Тариф» видно, что оплата не прошла, и есть кнопка «Оплатить снова».
8. **История платежей.** Ядро хранит операции: пользователь, идентификатор операции Точки, сумма, статус, оплаченный период. Данные карты на наш сервер не попадают.
9. **Отчёт администратора** из `usage-limits` показывает и тариф с датой окончания оплаты.

## Scope

- `agno/core/`: клиент API Точки, таблица платежей, платные тарифы в файле тарифов, источник подписки «Точка», операции «оформить», «подтвердить», «отменить», «окончание оплаченного периода»; миграция.
- `agno/app/api/`: маршруты оформления и отмены (с токеном пользователя) и маршрут вебхука Точки (без токена пользователя, с подтверждением через API Точки).
- `web/`: страница «Тариф» в настройках, страница возврата после оплаты.
- Настройки и секреты: ключ API Точки, код клиента и идентификатор магазина — в `/etc/authorled/authorled.env`; без них API не стартует.
- Сайт: оферта, политика обработки ПДн и реквизиты — это требования эквайринга, тексты готовит владелец.
- Мастер-спеки: `core/database`, новая спека `api/billing`, `web/workspace` (настройки), `05-security-and-compliance` (новые данные о платежах).
- Тесты: pytest ядра с подменённым API Точки (оплата, повторное уведомление, неоплаченная операция, отмена, конец периода); проверка в тестовой среде Точки, если она есть; запись в `tmp/VERIFY.md`.

## Non-goals

- Разовые покупки и пакеты сверх лимита.
- Промокоды, скидки, пробный период.
- Возвраты из интерфейса: пока их делает владелец в интернет-банке Точки.
- Юрлица и оплата по счёту.
- Письма о списании от нашего сервиса: чек присылает Точка.

## Constraints (из контекст-пака)

- Свои маршруты — только действия продукта без LLM (ADR-002); вебхук — такой маршрут.
- Секреты — только в env-файле сервера, не в коде и не в логах.
- ПДн хранятся в РФ (152-ФЗ). Почта уходит в Точку и её партнёру для чека, это нужно указать в политике ПДн. Данные карты не храним и не видим.
- Без fallback: нет настройки Точки — API не стартует; неизвестный статус операции — явная ошибка в логе, тариф не назначается.

## Acceptance criteria

- Пользователь оформляет подписку, платит на странице Точки, возвращается и видит платный тариф и новый лимит.
- В почту пришёл чек.
- Повторное уведомление Точки тариф не продлевает второй раз.
- Поддельное уведомление без настоящей оплаты в Точке тариф не меняет.
- После отмены тариф действует до конца периода, затем меняется на тариф без оплаты.
- Неудачное списание видно на странице «Тариф».
- pytest ядра и `./scripts/validate.sh` проходят.

## Risks

- **Подключение эквайринга** требует заявки руководителя и выбора партнёра по чекам; без этого работу нельзя проверить вживую.
- **Налоговый режим ИП** влияет на реквизиты чека (система налогообложения, НДС). Их нужно указать в позициях чека при подключении.
- **Документы на сайте** (оферта, политика ПДн, реквизиты) — без них банк может не подключить эквайринг.

## Open Questions

- Решено 2026-11-07: продаёт ИП владельца, счёт в Точке; схема с чеками от партнёра Точки подходит.
- Решено 2026-11-07: тарифы, подписки и лимит делаются в `usage-limits` сразу в модели подписки; этот интент только добавляет платные тарифы и оплату.
- Тарифы и цены: сколько платных тарифов, цена и лимит у каждого.
- Какой бесплатный тариф после окончания оплаты и для новых пользователей после беты. Рекомендация: бесплатный тариф с небольшим лимитом, тексты доступны всегда; `beta` закрыть, когда начнутся продажи.
- Система налогообложения ИП и НДС для реквизитов чека.
- Есть ли у Точки тестовая среда для эквайринга и как Точка подписывает вебхуки — проверить по документации в design.
- Партнёр по чекам — выбирается при подключении в интернет-банке.
