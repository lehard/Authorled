# Бизнес-интент: учёт расхода соавтора, тарифы и подписки с лимитом

Статус: решения согласованы с владельцем 2026-11-07 (кроме последнего пункта Open Questions); готов к `/opsx:propose`. Владелец: lehard. Обновлено: 2026-11-07.
Рамки: ADR-002 (свои маршруты без LLM), ADR-003 (модели только через LiteLLM), `openspec/context/07-anti-patterns.md` (п. 5–6: лимиты проверяет код ядра, сами лимиты — данные), `openspec/context/05-security-and-compliance.md`, мастер-спеки `core/database`, `api/agents` («Соавтор»), `api/me`. Следующий шаг после него — интент `payments-tochka`.

## Why

Продукт выходит к бета-тестерам, и каждый запрос к соавтору стоит денег у DeepSeek. Сейчас владелец не видит, кто сколько тратит, и ничто не мешает одному человеку израсходовать много (владелец, 2026-11-07).

Ограничение сразу устроено так, как будет при продаже: у каждого пользователя есть подписка на тариф с периодом и лимитом. Бета-тестеры получают бесплатную подписку на тариф `beta`. Оплата в интенте `payments-tochka` только добавит платные тарифы и продление подписки за деньги, а модель тарифов, подписок и лимита переделывать не придётся (владелец, 2026-11-07). Личных лимитов для отдельных пользователей нет.

Что уже есть: Agno сохраняет у каждого запуска токены и стоимость в долларах, которую считает LiteLLM (`ai.agno_runs.run_data->'metrics'`; на сервере 2026-11-07 так записан первый запуск соавтора). Дневная сводка Agno (`/metrics`, таблица `ai.agno_metrics`) даёт токены по моделям, но не рубли, не подписки и не лимиты. Запретить запуск при исчерпанном лимите Agno не умеет.

## What Changes

1. **Журнал расхода в ядре.** После каждого запуска соавтора ядро записывает в свою таблицу: пользователь, подписка, запуск, агент, модель, токены (вход, вход из кэша, выход), стоимость в рублях и стоимость от LiteLLM в долларах для сверки. Запись делает post-hook агента соавтора. Таблицы Agno ядро не читает: это внутренняя схема Agno, она меняется при обновлениях.
2. **Цены моделей — данные.** Цена каждого псевдонима модели в рублях за миллион токенов (вход, вход из кэша, выход) лежит в файле данных в репозитории. Если у модели, которую использует продуктовый агент, нет цены, API не стартует с ошибкой, где названа эта модель.
3. **Тарифы — данные.** Тариф в файле данных: код, название, цена в рублях за период, длина периода, лимит расхода в рублях за период, признак «можно купить». Сейчас один тариф: `beta`, цена 0 ₽, период — месяц, лимит 500 ₽, купить нельзя. Платные тарифы `payments-tochka` добавит в тот же файл, не меняя его устройства.
4. **Подписка.** У каждого пользователя ровно одна действующая подписка: тариф, начало и конец текущего периода, статус, источник. Источник сейчас один — «выдана» (бесплатно); оплата Точкой станет вторым. При создании аккаунта (`GET /me`) пользователь получает подписку на `beta` с периодом от даты создания. Уже созданные аккаунты получают её миграцией.
5. **Период и продление.** Расход считается за текущий период подписки, а не за календарный месяц. Когда период кончился, бесплатная подписка продлевается на следующий период сама, и расход начинается с нуля. Платную подписку продлевает только подтверждённая оплата (`payments-tochka`).
6. **Проверка перед запуском.** Pre-hook соавтора сравнивает расход за текущий период с лимитом тарифа. Если лимит исчерпан, запуск не начинается, а в чате появляется понятное сообщение, например: «Лимит соавтора на этот период исчерпан. Он обновится 7 декабря». Технической ошибки человек не видит. Если у пользователя нет действующей подписки или её тарифа нет в файле, это явная ошибка, а не запуск без лимита.
7. **Отчёт для администратора.** Скрипт на сервере выполняется в контейнере API через операции ядра:
   - `report`: по каждому пользователю почта, тариф, текущий период, число запросов, токены, расход в рублях, лимит, остаток и сумма в долларах от LiteLLM;
   - `set-plan <почта> <тариф>`: перевести пользователя на другой тариф из файла. Например, отдельный тариф для активных тестеров, если владелец его заведёт. Других ручных настроек лимита нет.

## Scope

- `agno/core/`: таблицы журнала расхода и подписок; файлы данных с ценами моделей и тарифами, их проверка при старте; операции «записать запуск», «текущий период и расход», «проверить лимит», «продлить бесплатную подписку», «сменить тариф», «отчёт»; миграция.
- `agno/agents/coauthor.py`: pre-hook проверки лимита и post-hook записи расхода. Это код приложения, вызывающий ядро, как у инструментов соавтора.
- `agno/core/users.py`: подписка на `beta` при создании аккаунта.
- `scripts/`: скрипт отчёта и смены тарифа для администратора.
- `web/`: в чате показывается сообщение об исчерпанном лимите (сейчас любой отказ показывается как общая ошибка).
- Мастер-спеки: `core/database` (новые таблицы), `api/agents` («Соавтор»: лимит), `api/me` (подписка при создании).
- Тесты: pytest ядра на чистой базе (запись расхода без дублей, сумма за период, продление бесплатной подписки на границе периода, исчерпанный лимит, смена тарифа, пользователь без подписки, тариф или модель не из файла); проверка сообщения в чате; запись в `tmp/VERIFY.md`.

## Non-goals

- Оплата, платные тарифы и страница тарифа — интент `payments-tochka`.
- Личные лимиты отдельных пользователей: меняется только тариф.
- Страница администратора в интерфейсе: пока хватит скрипта.
- Учёт платформенных агентов (OS Manager, Company Manager, `claude-engineer`) и эмбеддингов базы знаний: ими пользуется только администратор, авторам они недоступны.
- Перенос старых запусков из `ai.agno_runs`: пользователей ещё нет, на сервере один запуск.
- Точная стоимость до запуска: последний запрос может немного выйти за лимит.

## Constraints (из контекст-пака)

- Лимит проверяет код ядра, а не промпт; тарифы, лимиты и цены — данные, не Python (07-anti-patterns, п. 5–6).
- Ядро не зависит от Agno: hook вызывает операции ядра, ядро не читает схему `ai`.
- Схема `authorled`: миграции Alembic только вперёд, одна голова.
- Без fallback: модель без цены, пользователь без подписки, тариф не из файла, нет токенов в метриках запуска — явная ошибка с названием того, чего не хватает.
- В журнал и логи — только идентификаторы, без текста произведений и без почты.

## Acceptance criteria

- Новый пользователь после первого входа имеет подписку на `beta` с периодом в месяц от даты создания; у существующих после миграции тоже.
- После запроса к соавтору в журнале появляется ровно одна запись с токенами и стоимостью в рублях; повтор того же запуска дубля не создаёт.
- `report` на сервере показывает расход каждого пользователя за его текущий период, и токены совпадают с `ai.agno_runs`.
- Когда расход достиг 500 ₽, следующий запрос не уходит в модель, а в чате видно сообщение с датой обновления лимита.
- После конца периода бесплатная подписка продлевается, расход начинается с нуля, и соавтор снова отвечает.
- `set-plan` переводит пользователя на другой тариф без релиза, и лимит сразу берётся из нового тарифа.
- Если у модели нет цены или у подписки неизвестный тариф, API не стартует или запрос завершается явной ошибкой с названием модели или тарифа.
- pytest ядра и `./scripts/validate.sh` проходят.

## Risks

- **Неудачные запуски.** Если запуск упал после вызова модели, post-hook может не сработать, и токены не попадут в журнал. Нужно проверить поведение Agno 3.1.10 в design; при недоучёте записывать и неудачные запуски.
- **Цена расходится со счётом DeepSeek.** Цены задаёт владелец; сверка — колонка в долларах от LiteLLM и счёт DeepSeek.
- **Одновременные запросы** одного пользователя могут вместе выйти за лимит. Для беты допустимо.
- **Смена тарифа посреди периода.** Предложение для design: период и накопленный расход сохраняются, меняется только лимит. У платных тарифов правила смены уточнит `payments-tochka`.

## Open Questions

- Решено 2026-11-07: никаких личных лимитов; у каждого пользователя подписка на тариф, бета-тестеры — на бесплатный `beta`; оплата потом только продлевает подписку.
- Решено 2026-11-07: `beta` — 0 ₽, период месяц от даты создания аккаунта, лимит 500 ₽ за период, продлевается сама.
- Решено 2026-11-07: курс 100 ₽ за доллар, для беты без наценки (лимит защищает от расходов, а не приносит доход), цены DeepSeek по полному прайсу без временных скидок. Уточнено 2026-11-07 по официальной странице api-docs.deepseek.com/quick_start/pricing (журнал от 2026-10-17): у DeepSeek две цены, пиковая (будни 01:00–04:00 и 06:00–10:00 UTC) и вдвое ниже вне пика; полным прайсом считаем пиковую. Получается, в рублях за 1M токенов (вход / вход из кэша / выход): `deepseek-fast` (deepseek-flash) — 30 / 0,6 / 120; `deepseek-thinking` (deepseek-v4-pro) — 132 / 4,4 / 396.
- Решено 2026-11-07: расход считается по своим ценам в рублях из файла данных; стоимость в долларах от LiteLLM хранится только для сверки.
- Показывать ли пользователю, сколько осталось, например «использовано 60 % до 7 декабря» в настройках. Рекомендация: отложить до страницы тарифа в `payments-tochka`.
