# Бизнес-интент: выкладка сайта «Соавтора» на soavtor.app

Статус: решения согласованы с владельцем 2026-11-08 (повод: «лендинг не открывается, после выхода из редактора попадаю на вход»; `www` ведёт на сайт; форма заявки выкладывается, принятый риск «сервер в Финляндии» распространяется на заявки). Change ещё не создан, следующий шаг — `/opsx:propose`. Владелец: lehard. Обновлено: 2026-11-08.
Рамки: `business-intents/product-site.md` (п. 1 и 9: сайт в корне своего домена, выкладка вместе с доменом), `business-intents/site-landing-v2.md`, `business-intents/deploy-on-release.md`, мастер-спеки `web/site`, `api/beta-requests`, `runtime`; `deploy/Caddyfile`, `deploy/deploy.sh`, `.github/workflows/deploy.yml`; `openspec/context/05-security-and-compliance.md`.

## Why

Сайт продукта готов (`product-site` и `site-landing-v2` в архиве, мастер-спека `web/site`), но живёт только локально. Домен `soavtor.app` уже есть, а Caddy временно переадресует его на сервис (`302` на `app.soavtor.app`). Из-за этого лендинг не открыть никому, включая владельца: после выхода из редактора человек попадает на экран входа, и дороги к сайту нет (владелец, 2026-11-08).

В `product-site` сайт не выкладывали, чтобы не переезжать дважды: ждали своего домена. Домен появился, причина отпала.

## What Changes

1. **Адреса.** `soavtor.app` отдаёт сайт. `www.soavtor.app` постоянно (`301`) переадресует на `soavtor.app` с сохранением пути; это правило в `deploy/Caddyfile` уже есть и остаётся. Временная переадресация `soavtor.app → app.soavtor.app` убирается. Сервис и вход остаются на `app.soavtor.app` и `auth.soavtor.app`.
2. **Сборка в релизе.** Workflow деплоя собирает `site/` вместе с `web/` из того же тега, с настройками продакшена `SITE_ORIGIN=https://soavtor.app` и `SITE_APP_URL=https://app.soavtor.app` из переменных GitHub Environment `production`. Сборку проверяет `site/scripts/check-build.mjs`. Без любой из переменных деплой останавливается до выкладки.
3. **Файлы на сервере.** Сайт выкладывается так же, как фронтенд: файлы релиза приходят в `/srv/authorled/site/incoming/<tag>`, `deploy.sh` переключает ссылку `/srv/authorled/site/current` и удаляет старые версии. Если файлов сайта для тега нет, деплой останавливается.
4. **Caddy.** Блок `soavtor.app` в `deploy/Caddyfile` отдаёт статические файлы из `site/current`, на неизвестный адрес отвечает страницей 404 сайта с кодом 404. Путь `/os/api/v1/beta-requests` ведётся на API (`127.0.0.1:8000`, без префикса `/os`). Другие пути API на домене сайта не открываются.
5. **Проверка после деплоя.** Кроме нынешних проверок сервиса: `https://soavtor.app/` и страница политики отвечают `200` с HTML сайта, неизвестный адрес отвечает `404`, а `POST /os/api/v1/beta-requests` с пустым телом получает отказ проверки (`4xx` от API, не `404` и не `5xx`). Настоящую заявку проверка не создаёт.
6. **Дорога к сайту из сервиса.** На экране входа сервиса появляется ссылка «О продукте» на сайт. Адрес сайта фронтенд получает при сборке из обязательной настройки (та же `SITE_ORIGIN`). Без неё сборка падает. После выхода из редактора человек по-прежнему попадает на экран входа, но с него можно перейти на сайт.

## Scope

- `.github/workflows/deploy.yml`: сборка и проверка сайта, отправка файлов, проверка адресов сайта после деплоя.
- `deploy/deploy.sh`: проверка наличия файлов сайта и переключение `site/current`.
- `deploy/Caddyfile`: блок `soavtor.app` вместо переадресации.
- `web/`: ссылка на сайт на экране входа, `SITE_ORIGIN` в настройках сборки (`web/vite.config.ts`, `web/src/app/config.ts`), проверка сборки `deploy/check_web_build.sh` при необходимости.
- `README.md` («Deploy by release»), `.agents/skills/deploy-platform/SKILL.md`, `example.env`, `AGENTS.md`: сайт теперь выкладывается.
- Мастер-спеки `runtime` (деплой и обратный прокси), `web/site` (выкладка), `web/app` (ссылка на экране входа) через дельту.
- На сервере разово: каталог `/srv/authorled/site/` с правами пользователя `deploy`. В GitHub: переменные `SITE_ORIGIN` и `SITE_APP_URL` в Environment `production`.

## Non-goals

- Яндекс Метрика на сайте: нужны правка политики ПДн и решение про cookie, это отдельный интент.
- Изменения текстов, блоков и вида сайта: их ведёт `site-landing-v2` и исключение OpenSpec для текстов и картинок `site/`.
- Перенос сервера и почты в РФ, уведомление Роскомнадзора, публикация оферты и тарифов (`payments-tochka`, `backlog-stage-2.md` п. 3).
- Переадресация после выхода из сервиса сразу на сайт: адрес выхода обязан быть на домене сервиса (`web/src/app/config.ts`), экран входа остаётся.
- Приглашение в бету из заявки одной кнопкой; кэширование и CDN для сайта.

## Constraints (из контекст-пака)

- Без fallback: нет переменной сборки, файлов сайта для тега или сайт не прошёл проверку — деплой останавливается с понятной ошибкой.
- Код выкатывается только релизом GitHub из `main`; на сервере ничего не правится руками, кроме разового каталога.
- Наружу открыты только порты 22, 80 и 443; маршрут заявки ограничен по частоте и размеру тела, текст заявок не пишется в логи (мастер-спека `api/beta-requests`).
- На домене сайта из API доступен только маршрут заявки: токены, MCP и остальные `/os/` там не отвечают.
- Персональные данные из формы — по 152-ФЗ: заявки хранятся на сервере в Финляндии в рамках принятого риска закрытого тестирования (`05-security-and-compliance.md`, решение владельца 2026-11-08); перед открытым запуском сервер переносится в РФ.

## Acceptance criteria

- После релиза `https://soavtor.app/` открывает главную сайта, `https://www.soavtor.app/<путь>` переадресует (`301`) на `https://soavtor.app/<путь>`, `https://app.soavtor.app/` открывает сервис.
- Неизвестный адрес на `soavtor.app` отвечает страницей 404 с кодом 404.
- Заявка с формы на `soavtor.app` сохраняется в ядре и видна в `./scripts/usage.sh prod beta-requests`.
- `https://soavtor.app/os/agents` и другие пути API, кроме заявки, не отвечают API.
- На экране входа сервиса есть ссылка на сайт, она ведёт на `https://soavtor.app/`.
- Релиз без `SITE_ORIGIN` или `SITE_APP_URL` останавливается до выкладки, сервер не меняется.
- Ручной запуск деплоя с тегом прошлого релиза возвращает и сайт той версии.
- `./scripts/validate.sh` проходит.

## Risks

- **Персональные данные из открытого интернета.** Форма собирает почты и имена незнакомых людей на сервер в Финляндии. Риск принял владелец 2026-11-08 до переноса сервера в РФ; согласования с ИБ нет, уведомления Роскомнадзора ещё нет.
- **Спам в заявках.** Открытый маршрут без входа; ограничения частоты и размера уже есть в ядре, капчи нет.
- **Медленная загрузка из России.** До сервера в Финляндии канал узкий (`web-first-load.md`); сайт с кадрами и скриншотами может открываться долго. Бюджет скриптов главной это смягчает, но не снимает.
- **Сайт падает вместе с сервисом.** Один сервер и один Caddy: деплой с простоем делает недоступным и сайт.
