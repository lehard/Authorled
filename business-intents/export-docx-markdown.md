# Бизнес-интент: экспорт DOCX и Markdown, импорт Markdown

Статус: решение владельца 2026-11-09 взять в ближайшие задачи; очередь 1, порядок 3 из 5. OpenSpec change ещё не создан. Владелец: lehard. Обновлено: 2026-11-09.
Рамки: ADR-005 (экспорт Fountain, FDX, DOCX, Markdown; импорт DOCX и TXT), мастер-спеки `web/screenplay-editor`, `api/story-import`; ADR-001/ADR-004 (редактор экспортирует, ядро импортирует).

## Why

Выход без потерь — одно из ядер исследования (`openspec/context/_raw/research/Любимые фичи/Сводка.md`, тема 7; `Сводка-лидеры.md`, тема 5): альтернативу Final Draft прощают, только если она чисто выгружается, а редакторы и корректоры ждут Word. Экспорт DOCX есть у 13 из 21 продукта (IO-07). Возможность выгрузить всё и уйти — часть доверия (тема 4). Markdown подтвердил владелец 2026-10-28 (ADR-005).

Что есть в коде (сверка 2026-11-09):
- экспорт Fountain, FDX и печать (`web/src/editor/exporters/`, меню «Экспорт» в `ExportItems.tsx`);
- импорт DOCX и TXT читается по правилам Fountain (`agno/core/importers/plain.py`), список типов — `MANUSCRIPT_TYPES` в `web/src/data/files.ts`.

## What Changes

1. **Экспорт DOCX сценария** в сценарном формате: тот же шрифт, отступы элементов, разрывы страниц и титульный лист, что у печати. Файл открывается в Word и Google Docs без съехавшей разметки.
2. **Экспорт Markdown** — вся история одним файлом: титул, логлайн, синопсис, документы библии (персонажи, локации, миры), заметки и текст сценария читаемым видом. Это выгрузка «забрать всё с собой».
3. **Импорт Markdown.** Файл `.md` принимается как рукопись и читается по правилам Fountain, как TXT: `#` становятся актами и секвенциями, `*курсив*` и `**жирный**` — разметкой.

## Scope

- `web/src/editor/exporters/`: `docx.ts` и `markdown.ts`; пункты в `ExportItems.tsx`. Библиотеку для DOCX выбрать в design (например, npm `docx`), закрепить точную версию.
- Экспорт Markdown берёт документы истории через `web/src/data/`, без нового маршрута, если данные уже есть у клиента.
- `agno/core/importers/plain.py` и `agno/core/files.py`: тип `.md` (проверка ClamAV как у всех); `MANUSCRIPT_TYPES`.
- Спеки: `web/screenplay-editor` (экспорт), `api/story-import` (Markdown).

## Non-goals

- EPUB и FB2 — интент `export-epub-fb2.md`, очередь 2.
- Экспорт PDF файлом: PDF сейчас сохраняется через диалог печати браузера (IO-08).
- Импорт PDF (IO-04).
- Обратный импорт Markdown-выгрузки целой истории с документами библии: импорт берёт только текст сценария.

## Constraints (из контекст-пака)

- Редактор экспортирует, ядро импортирует (ADR-001/ADR-004).
- Без запасных путей: элемент сценария, которому нет соответствия в DOCX, — ошибка экспортёра в разработке, а не тихий пропуск.
- Новая зависимость фронтенда — точная версия в `web/package.json` и `package-lock.json`.

## Acceptance criteria

- DOCX демо-сценария открывается в Word и Google Docs; заголовки сцен, реплики, ремарки и переходы стоят на своих отступах; число страниц отличается от печати не больше чем на одну.
- Markdown демо-истории содержит логлайн, синопсис, все документы библии и весь текст сценария; заметки помечены как заметки.
- Файл `.md` с `# Акт 1`, заголовками сцен и репликами импортируется в драфт с актом, сценами и репликами.
- `./scripts/validate.sh`, `./scripts/dev.sh test` и `npm run check:editor` проходят.

## Risks

- Пагинация DOCX считается Word, а не нами: страницы могут разойтись с печатью. Не обещать совпадение страниц.
- Markdown — не формат сценария: читаемый вид реплик (имя прописными, реплика с отступом) выбрать в design.
- Размер библиотеки DOCX в сборке; грузить её только при экспорте.

## Open Questions

- Экспорт Markdown — один файл или архив с файлом на документ. Предложение — один файл.
