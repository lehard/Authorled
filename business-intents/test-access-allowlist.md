# Бизнес-интент: белый список пользователей на время тестирования

Статус: решения согласованы с владельцем 2026-11-06; OpenSpec change: `openspec/changes/archive/2026-11-06-test-access-allowlist` (реализовано и заархивировано 2026-11-06). Владелец: lehard. Обновлено: 2026-11-06.
Рамки: мастер-спека `auth` («Регистрация», «Вход фронтенда», «Blueprints»), `auth/blueprints/30-authentication-flow.yaml`.

## Why

На время тестирования сервер должен быть доступен только людям, которых назвал владелец (владелец, 2026-11-06). Сейчас спека требует обратного: «Регистрация MUST быть открыта всем». Сервер публичный, поэтому без ограничения зарегистрироваться сможет любой, кто найдёт адрес.

## What Changes

1. **Список разрешённых почт.** Настройка окружения `AUTH_ALLOWED_EMAILS` хранит почты через запятую. Сравнение идёт без учёта регистра.
2. **Регистрация только по списку.** Поток `authorled-enrollment` отказывает почте не из списка и не отправляет ей код. Текст отказа: регистрация сейчас доступна только по приглашению.
3. **Вход без изменений.** Люди из списка регистрируются сами и входят обычным путём: почта, код из письма. Вход настоящий, быстрых кнопок на сервере нет.
4. **Изменение списка.** Чтобы добавить человека, владелец меняет настройку на сервере и пересоздаёт контейнеры Authentik. Новый релиз не нужен.
5. **Обязательная настройка.** Если `AUTH_ALLOWED_EMAILS` не задана, Authentik не стартует с понятной ошибкой. Значение `*` открывает регистрацию всем и используется локально и после тестирования.

## Scope

- `auth/blueprints/30-authentication-flow.yaml`: проверка почты по списку в потоке регистрации.
- `auth/compose.yaml`: передача настройки.
- `example.env`, `README.md`.
- Спека `auth`: требование «Регистрация».
- `web/src/auth/`: показ отказа на экране регистрации, если он сейчас не показывает ошибку шага.

## Non-goals

- Экран управления списком.
- Приглашения по ссылке и письма-приглашения.
- Отзыв доступа у уже зарегистрированных: это блокировка пользователя в Authentik.
- Роли по списку: все получают группу `screenwriters`, как при обычной регистрации.

## Constraints (из контекст-пака)

- Только `agno/app/auth/` читает токены, а этот интент меняет только Authentik: коду API список не нужен.
- Конфигурация воспроизводится на пустой схеме через blueprints, без ручных шагов в интерфейсе.
- Нет запасных путей: пустая или отсутствующая настройка не открывает регистрацию молча.
- Репозиторий публичный: реальные почты не коммитятся ни в код, ни в спеки, ни в этот интент. Они живут только в настройках сервера.
- Сборка продакшена не содержит быстрых кнопок входа.

## Acceptance criteria

- Почта из списка регистрируется и входит по коду из письма.
- Почта из списка в другом регистре проходит.
- Почта не из списка получает отказ и не получает письма; пользователь не создаётся.
- Без настройки Authentik не стартует, ошибка называет `AUTH_ALLOWED_EMAILS`.
- Со значением `*` регистрация открыта, как сейчас.
- После смены настройки и перезапуска Authentik новая почта проходит.
- `./scripts/check_auth_boundary.sh` и `./scripts/validate.sh` проходят.

## Risks

- **Обход потока.** Проверка стоит в потоке регистрации. Администратор Authentik может создать пользователя в обход, это допустимо.
- **Перечисление почт.** Отказ не должен отличаться для разных почт вне списка.
- **Применение blueprint.** Значение попадает в Authentik при применении blueprint. Нужно проверить, что перезапуска достаточно.
