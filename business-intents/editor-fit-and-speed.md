# Бизнес-интент: лист сценария на ноутбуке, сворачиваемый чат, карточки не поверх текста, быстрое открытие истории

Статус: решения согласованы с владельцем 2026-11-08: масштаб листа и сворачиваемый чат — в ответ на обход редактора, способ для карточек и план ускорения из трёх шагов — подтверждены отдельно; способ ускорения API — запись трасс Agno пакетами — выбран при `/opsx:propose`. Change `editor-fit-and-speed` создан, выполнен и архивирован 2026-11-08 (`openspec/changes/archive/2026-11-08-editor-fit-and-speed/`); проверки на сервере — после релиза (раздел «Workflow follow-up» в его `tasks.md`). Владелец: lehard. Обновлено: 2026-11-08.
Рамки: ADR-006 (окно истории из трёх колонок, чат справа на всех экранах — меняется), ADR-002 (свои маршруты ядра), мастер-спеки `web/workspace` («Окно истории», «Текст сценария», карточки комментария и предложения), `web/screenplay-editor`, `api/stories`.

## Why

Обход редактора 2026-11-08 (Playwright, ширина окна 390–1920 px, светлая и тёмная темы) показал четыре проблемы, которые нельзя исправить мелкой правкой.

1. **Сценарную страницу почти никто не видит.** Лист с настоящей геометрией (US Letter, разрывы страниц, номера сцен слева и справа, номер страницы) включается, только когда средняя колонка шире 840 px (`@container (max-width: 840px)` в `web/src/editor/styles.css`). При навигаторе 284 px и чате 360 px это окно от ~1530 px. На ноутбуках 1280–1512 px автор всегда видит сплошной лист без страниц и номеров сцен, хотя страница сценария — главная единица счёта хронометража.
2. **На ширине 900–1100 px колонка листа всего 290–450 px.** Сценарий читается тесно: реплики по 2–3 слова в строке, панель инструментов в две строки. Чат по ADR-006 и спеке виден всегда, поэтому места не освободить.
3. **Карточки комментариев и предложений закрывают текст.** Когда у листа нет поля справа (почти всегда, см. п. 1), карточка ложится поверх строк, в том числе соседних с местом правки.
4. **История открывается 3–6 секунд.** Локально редактор появляется через ~4,2 с. Замеры:
   - один запрос к API идёт ~80 мс, но 8 параллельных `GET /api/v1/me` — 624 мс: API обрабатывает запросы по очереди, а не одновременно;
   - при открытии уходит 21 запрос, из них повторы: список драфтов и заметок по 4 раза (живые и корзина читают один адрес, плюс двойной монтаж React в разработке), `/me` 3 раза, текст, комментарии и предложения по 2 раза;
   - комментарии и предложения запрашиваются только после того, как редактор смонтирован (на 3,7 с), а не вместе с текстом.

## What Changes

- **Лист масштабируется под колонку.** Когда колонка уже страницы, лист показывается целиком в меньшем масштабе с той же геометрией: страницы, разрывы, номера сцен и страниц. Сплошной лист без страниц остаётся только там, где масштаб получился бы слишком мелким (телефон; порог — в design).
- **Чат сворачивается на десктопе.** В шапке колонки чата кнопка «Свернуть»; свёрнутый чат — узкая полоса справа с кнопкой соавтора, освободившееся место получает лист. Состояние запоминается для автора между открытиями. «Обсудить в чате» на карточке предложения и вопрос соавтору из выделения разворачивают чат. На узком экране чат остаётся листом снизу.
- **Карточки не перекрывают текст.** Есть место справа от листа — карточка там, на уровне своей строки. Места нет — карточка встаёт под строкой с правкой и сдвигает текст ниже, а не ложится поверх.
- **История открывается быстрее:**
  - найти и убрать причину, по которой API обрабатывает параллельные запросы по очереди;
  - читать каждый адрес один раз: живые записи и корзина драфтов и заметок из одного ответа, `/me` один раз за окно;
  - запрашивать комментарии и предложения вместе с текстом, не дожидаясь редактора.

## Non-goals

- Ручной зум листа (Ctrl+колесо, поле «100%»): только масштаб под ширину колонки.
- Сворачивание навигатора.
- Мобильная раскладка (до 900 px): навигатор кнопкой и чат листом снизу остаются как есть.
- Кэширование истории между открытиями и офлайн-режим.
- Ускорение рендера длинного сценария в самом редакторе.

## Constraints (из контекст-пака)

- Цвета, тени и шрифты только из токенов дизайн-системы (`./web/scripts/check_web_tokens.sh`); нативных подсказок нет (`check:native-ui`).
- Печать и экспорт строятся из документа, а не из экрана: масштаб на них не влияет.
- Одна инстанция API (CLAUDE.md, «Production and saved state»): ускорение не за счёт второго процесса.
- Без запасных путей: сбой загрузки показывается ошибкой окна, как сейчас.

## Acceptance criteria

- На окне 1280×800 и 1440×900 «Текст сценария» показывает страницы с разрывами, номерами сцен и номером страницы; на 390 px — сплошной лист, как сейчас.
- Клик, выделение, меню выделения, автоподстановка и карточки попадают в нужное место при любом масштабе листа.
- Чат на десктопе сворачивается и разворачивается; после перезагрузки остаётся в том же состоянии; «Обсудить в чате» разворачивает его.
- Открытая карточка комментария или предложения не закрывает ни одной строки текста на ширинах 1024, 1280 и 1440 px.
- Запрос к API не ждёт записи трасс; 8 параллельных `GET /health` внутри контейнера API отвечают быстрее 100 мс (уточнено 2026-11-08 при `/opsx:update`: в одном процессе API запросы, занимающие процессор, параллельно не идут).
- При открытии истории каждый адрес API запрашивается один раз (в сборке без двойного монтажа React); редактор с комментариями и предложениями появляется в продакшен-сборке быстрее 1,5 с (проверяется на сервере после релиза).
- `./scripts/validate.sh` и `./scripts/dev.sh test` проходят.

## Risks

- **Масштаб и координаты ProseMirror.** CSS `zoom` и `transform: scale` по-разному влияют на `coordsAtPos`/`posAtCoords`, позицию меню выделения, списка подсказок и карточек. Способ выбирается в design с проверкой клика и выделения на масштабе 60–90%.
- **Поправка ADR-006.** Свёрнутый чат меняет обещание «соавтор всегда рядом»; нужна заметная кнопка разворота.
- **Причина очереди в API неизвестна.** Кандидаты: асинхронная прослойка AgentOS или проверка токена с блокирующим вызовом, один поток `uvicorn --reload`, прокси Vite. Если причина в Agno, правка возможна только настройкой, без обхода фреймворка (CLAUDE.md).
- **Карточка, сдвигающая текст**, двигает строки под курсором мыши при открытии; нужна плавность или открытие только по клику.
