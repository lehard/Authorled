# Бизнес-интент: поиск по всей истории

Статус: решение владельца 2026-11-09 взять в ближайшие задачи; очередь 1, порядок 4 из 5. Способ поиска, место на экране и инструмент соавтора согласованы 2026-11-09. OpenSpec change: `openspec/changes/project-search`. Владелец: lehard. Обновлено: 2026-11-09.
Рамки: ADR-002 (свои маршруты без LLM под `/api/v1/`), мастер-спеки `web/workspace`, `web/screenplay-editor`, `api/stories`, `api/core`, `api/agents`.

## Why

Поиск по всему проекту есть у 7 из 21 разобранного продукта (ED-23, `openspec/context/_raw/research/Конкуренты/Фичи.csv`). Справочник рядом с текстом и рукопись из сцен — первые два ядра исследования (`Любимые фичи/Сводка-лидеры.md`): когда документов, сцен и заметок много, без поиска по всему автор их теряет.

Как это сделано у других (разбор 2026-11-09): в Final Draft и Fade In поиск только внутри сценария; в Scrivener одна строка поиска по проекту ищет в тексте, заголовках, синопсисах и заметках и показывает список документов; в Obsidian и VS Code результаты сгруппированы по файлам с кусочком текста. Все они ищут по точному вхождению: автор ищет имя, предмет или реплику и хочет попасть именно туда.

Что есть в коде (сверка 2026-11-09): поиск и замена внутри текста сценария с областью «во всём тексте», «в заголовках сцен», «в действии» и другими (`web/src/editor/plugins/find.ts`, кнопка ⌘F на панели редактора), с прокруткой к совпадению. По документам, заметкам и другим драфтам поиска нет. Соавтор читает документы, заметки и сценарий только целиком (`agno/agents/coauthor_tools.py`), искать по истории он не умеет.

## What Changes

1. **Одна строка поиска по всей истории**: текст сценария текущего драфта, документы (логлайн, синопсис, персонажи, локации, миры, свои документы), заметки и синопсисы сцен.
2. **Место на экране — левая панель (навигатор)**: поле «Поиск по истории» под названием истории, над деревом документов; ⌘K ставит в него курсор. ⌘F остаётся поиску в редакторе. Пока поле пустое, видно дерево; с 2 символов на месте дерева по мере ввода появляются результаты; Esc или крестик в поле возвращают дерево, как возврат из списка драфтов. На телефоне поиск там же, в выезжающей левой панели.
3. **Результаты списком по группам** («Сцены», «Документы», «Заметки»): название и кусочек текста вокруг совпадения, совпадение подсвечено.
4. **Переход по клику**: документ или заметка открываются в центре с выделенным совпадением; сцена открывается в редакторе на этой сцене, и открывается строка ⌘F с тем же запросом, так что дальше автор листает совпадения или заменяет уже внутри сценария.
5. **Как ищем**: по подстроке, регистр и «ё/е» не различаются, так же, как поиск в редакторе. Поиск идёт по сохранённой версии: не сохранённую ещё правку в открытом редакторе находит только поиск внутри редактора.
6. **Соавтор ищет тем же поиском**: инструмент `search_story` только читает и вызывает ту же функцию ядра; на просьбу «найди все сцены с ножом» соавтор отвечает найденными сценами, не читая историю целиком. Подтверждения автора он не требует, потому что ничего не меняет.
7. Существующий поиск и замена внутри сценария (⌘F) не меняются, кроме открытия с запросом из пункта 4.

## Scope

- Ядро `agno/core/`: одна функция поиска по истории (текущий драфт, его документы, заметки истории); текст сценария извлекается из JSON в Python, как разбор по строкам у соавтора (`_lines` в `coauthor_tools.py`). Индексов и отдельных поисковых сервисов нет.
- Маршрут `GET /api/v1/drafts/{id}/search?q=…` (в коде маршруты историй — `projects` и `drafts`, а поиск идёт по драфту) в `agno/app/api/` (без LLM), с проверкой доступа к проекту, как у всех маршрутов историй (`body.py`).
- Соавтор: инструмент `search_story` в `agno/agents/coauthor_tools.py` поверх той же функции ядра и строка о нём в промпте `agno/skills/coauthor/SKILL.md`.
- `web/src/data/`: запрос поиска; `web/src/screens/project/Navigator.tsx`: поле и список результатов; `web/src/editor/ScreenplayEditor.tsx`: открытие строки ⌘F с заданным запросом на нужной сцене.
- Спеки: `api/stories` (маршрут), `web/workspace` (поиск по истории в навигаторе), `web/screenplay-editor` (открытие поиска с запросом), `api/agents` (инструмент соавтора).

## Non-goals

- Замена по всей истории: только поиск. Замена остаётся внутри текста сценария.
- Регулярные выражения (ED-24).
- Поиск по другим драфтам и по сохранённым версиям.
- Поиск по смыслу через эмбеддинги: он не находит точное слово, подсветить нечего, а каждое сохранение пришлось бы пересчитывать. Вопросы по смыслу закрывает соавтор, читая найденное.
- Отдельный поисковый сервис (Meilisearch, Elasticsearch) и индексы: история весит сотни килобайт, полный проход укладывается в миллисекунды.
- Склонения имён: позже как опция «искать все формы слова» на морфологии из `name-morphology.md` (BI-12).

## Constraints (из контекст-пака)

- Свой маршрут — только для действия без LLM, добавляется `attach_api` до монтирования MCP (ADR-002).
- Ответы об ошибках — `application/problem+json` через `Problem`.
- Изоляция данных: поиск видит только истории, к которым у автора есть доступ (`can_access_project`); соавтор ищет только в истории своего разговора.
- Без запасных путей: пустой или слишком короткий запрос (меньше 2 символов) отклоняется понятной ошибкой, а не возвращает всё.
- Список инструментов соавтора статичен (AgentOS 3.1.10 отказывает инструментам, собранным на каждый запуск).

## Acceptance criteria

- В демо-истории поиск имени персонажа находит его сцены, его документ и заметки, где он упомянут, по группам.
- Поиск «ежик» находит «Ёжик».
- Поле в навигаторе: ⌘K ставит в него курсор; с 2 символов вместо дерева видны результаты; Esc возвращает дерево.
- Клик по результату в сцене открывает редактор на этой сцене с открытой строкой ⌘F, запросом и выделенным совпадением; по документу или заметке — открывает их с выделенным совпадением.
- Запрос из одного символа отклоняется ошибкой.
- Соавтор на просьбу «найди все сцены, где есть <предмет из демо-истории>» вызывает `search_story` и называет эти сцены.
- Автор не находит ничего из чужой истории (тест на изоляцию в `agno/tests/`).
- `./scripts/validate.sh` и `./scripts/dev.sh test` проходят.

## Risks

- Текст сценария хранится JSON-ом: совпадение внутри разметки (комментарий, предложение правки) должно находиться в тексте, а не в служебных полях.
- Поиск по сохранённой версии может не найти только что набранное в открытом редакторе; это записанное ограничение, а не ошибка.
- Соавтор может по привычке читать историю целиком вместо поиска: строка в промпте говорит, когда искать.
