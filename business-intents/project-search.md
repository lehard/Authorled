# Бизнес-интент: поиск по всей истории

Статус: решение владельца 2026-11-09 взять в ближайшие задачи; очередь 1, порядок 4 из 5. OpenSpec change ещё не создан. Владелец: lehard. Обновлено: 2026-11-09.
Рамки: ADR-002 (свои маршруты без LLM под `/api/v1/`), мастер-спеки `web/workspace`, `web/screenplay-editor`, `api/stories`, `api/core`.

## Why

Поиск по всему проекту есть у 7 из 21 разобранного продукта (ED-23, `openspec/context/_raw/research/Конкуренты/Фичи.csv`). Справочник рядом с текстом и рукопись из сцен — первые два ядра исследования (`Любимые фичи/Сводка-лидеры.md`): когда документов, сцен и заметок много, без поиска по всему автор их теряет.

Что есть в коде (сверка 2026-11-09): поиск и замена внутри текста сценария с областью «во всём тексте», «в заголовках сцен», «в действии» и другими (`web/src/editor/plugins/find.ts`), с прокруткой к совпадению. По документам, заметкам и другим драфтам поиска нет.

## What Changes

1. **Одна строка поиска по всей истории**: текст сценария текущего драфта, документы (логлайн, синопсис, персонажи, локации, миры, свои документы), заметки и синопсисы сцен.
2. **Результаты списком по группам** (сцены, документы, заметки) с кусочком текста вокруг совпадения. Клик открывает документ и выделяет совпадение; для сцены — переход к ней в редакторе, как при поиске в тексте.
3. Регистр и «ё/е» не различаются.

## Scope

- Маршрут `GET /api/v1/stories/{id}/search?q=…` в `agno/app/api/` (без LLM) и поиск в ядре `agno/core/` по таблицам истории, с проверкой доступа к проекту, как у всех маршрутов историй (`body.py`).
- `web/src/data/` и `web/src/screens/project/`: строка поиска и список результатов; переход к совпадению через существующий поиск редактора.
- Спеки: `api/stories` (маршрут), `web/workspace` (поиск по истории).

## Non-goals

- Замена по всей истории: только поиск. Замена остаётся внутри текста сценария.
- Регулярные выражения (ED-24).
- Поиск по другим драфтам и по сохранённым версиям.
- Поиск по смыслу через эмбеддинги.
- Склонения имён (BI-12) — после выбора морфологии.

## Constraints (из контекст-пака)

- Свой маршрут — только для действия без LLM, добавляется `attach_api` до монтирования MCP (ADR-002).
- Ответы об ошибках — `application/problem+json` через `Problem`.
- Изоляция данных: поиск видит только истории, к которым у автора есть доступ (`can_access_project`).
- Без запасных путей: пустой или слишком короткий запрос отклоняется понятной ошибкой, а не возвращает всё.

## Acceptance criteria

- В демо-истории поиск имени персонажа находит его сцены, его документ и заметки, где он упомянут, по группам.
- Поиск «ежик» находит «Ёжик».
- Клик по результату в сцене открывает редактор на этой сцене с выделенным совпадением; по документу — открывает документ.
- Автор не находит ничего из чужой истории (тест на изоляцию в `agno/tests/`).
- `./scripts/validate.sh` и `./scripts/dev.sh test` проходят.

## Risks

- Текст сценария хранится JSON-ом: искать по нему в PostgreSQL или в Python — решается в design. На больших историях проверить скорость.
- Совпадение внутри разметки (комментарий, предложение правки) должно находиться в тексте, а не в служебных полях.

## Open Questions
